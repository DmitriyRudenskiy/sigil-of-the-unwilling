# ui-grid-review

Инструменты: `scripts/ui_grid.py`, `scripts/ui_diff.py`, `game/tools/ui_dump.gd`.
Канон съёмки — [[CAPTURE-HELPER]], правило меры — D-228 (`docs/DECISIONS.md`).

## Чего здесь нет

Пиксельного вердикта. Между макетом и живым экраном SSIM/«сходство» считают
сходство шрифтов и палитры, а контента не видят: замер 2026-10-26 — пустое окно
против макета даёт 0.2932 SSIM / 77.35% пиксельного сходства, настоящий кадр
инвентаря против того же макета — 0.2918 / 78.77%, то есть пустой кадр «лучше».
Поэтому `ui_diff.py` не печатает PASS и не имеет порога остановки: он отвечает на
«какие ячейки сдвинулись», а решение — разбор кадра глазом (AGENTS.md «UX-review
машинным зрением»). Проверка полноты экрана — реестр носителей, не пиксели.

## Шаг 1 — кадр

Канонический канал один: `CAPTURE_SCENE` + `CAPTURE_SETUP` поверх живого хоста
(команда — [[CAPTURE-HELPER]] «Команда воспроизведения»), кадры в
`~/.local/share/sigil-reserve/<имя>/`, пиксели в git не идут (D-185).

`game/tools/ui_dump.gd` годится для быстрой разметки дерева, но кадр им не снимается:
экран без состояния (`city == null`, герой без рюкзака) рисует заглушку, и её
приемка ничего не доказывает.

## Шаг 2 — одна сетка на кадр и на макет

```sh
python3 scripts/ui_grid.py ~/.local/share/sigil-reserve/<имя>/frame.png --out /tmp/g.frame.png
python3 scripts/ui_grid.py reference/12_inventory_parchment_sheet.jpeg --out /tmp/g.ref.png
```

`--cols/--rows` у обоих обязаны совпадать (дефолт 10×10), иначе «D5 в макете» и
«D5 в кадре» — разные прямоугольники. Макет никогда не ресайзят под кадр и
наоборот: сетка долевая, сравниваются адреса, а не пиксели.

## Шаг 3 — разбор глазом, расхождения адресами

Каждое расхождение читается с приближения, а не с уменьшенного кадра:

```sh
python3 scripts/ui_grid.py frame.png --cell D4 --zoom 3 --out /tmp/c.D4.png
```

Затем открыть кадр и макет-источник и пройтись по ячейкам: состав, места, текст и
иконки, пустые слоты, выход за кадр, читаемость. Формулировка расхождения —
«в D5 кнопка, в макете D4», «подпись в H7 обрезана по правому краю».

## Шаг 4 — кто владеет областью

```sh
cd game && Godot --path . --script tools/ui_dump.gd -- \
    --scene=res://scenes/ui/artifact_inventory_screen.tscn --width=1920 --height=1080 \
    --cell=D5
```

TSV: путь от окна, класс, прямоугольник, якоря, `text=`, `theme=`. Рекурсия идёт
сквозь `CanvasLayer`, пересечение — а не «центр внутри»: так находится и полоса
армии, у которой в ячейке только край. `--all` печатает невидимое и нулевое (ровно
тот случай, когда «текст в модели есть, на экране его нет» — D-228 п.7). Пустой
дамп — exit 3 с деревом классов, а не молчаливый ноль.

## Шаг 5 — дельта «до/после»

```sh
python3 scripts/ui_diff.py --before /tmp/prev/frame.png --after /tmp/now/frame.png \
    --out-dir /tmp/diff1 --cell D5
```

Валидно только для кадров одного канона (разный размер — отказ, не ресайз).
Смысл проверки: правка целилась в D5, а тронула ещё и C5/D6 — значит задето
общее. Полный список тронутых ячеек — в `report.json`.

## Шаг 6 — вердикт в треде

Кадр-доказательство (путь в reserve + манифест текстом), путь к макету, расхождения
по ячейкам с диспозицией (устранено / отложено с задачей / принято владельцем) и
по каждой AC спеки PASS/FAIL. Публикация — после ux-review, не до.

## Гигиена

- `ui_dump.gd` поднимает живой Godot с autoload `McpInteractionServer` → порт 9090.
  Не запускать одновременно с MCP-гейтом; чужие процессы не трогать.
- Нужен дисплей: `--headless` даёт exit 2 (dummy rasterizer, чёрный кадр).
- На хосте с дисплеем меньше канона окно выйдет 1836×1025 и т. п. — инструмент
  печатает об этом предупреждение, и прямоугольники такого прогона не сопоставимы
  с кадрами канона.
- `python3 scripts/ui_grid.py --self-check` — проверка математики сетки и меры
  (меняется после правки `cell_bbox` / `_box_blur`).
