# content-audit

Носитель реестров — `docs/QUESTIONS.md`, `docs/DECISIONS.md`; машина состояний —
`scripts/gdd_gate.py`. Полный контракт фаз: [[19-gdd-workflow]].

## Шаг 0 — ре-грундинг (обязателен, D-274)

```
python3 scripts/gdd_grounding.py
```

Дайджест ≤400 строк, приоритет отсечки `⚑ → ⏳ → 🔴`. «Перечитать целиком» на 2,62 МБ
доков неисполнимо; имитация чтения — причина, по которой предыдущий контур встал на
проходе 3.5.

## Классификация дыр

| Тип | Что это | Действие |
| --- | --- | --- |
| онтология | сущность/термин назван, но не определён | запись в `docs/QUESTIONS.md` (`[agent]`/`[human]`, приоритет, варианты) + `docs/00-glossary.md` после ответа |
| противоречие | две секции говорят несовместимое | красная строка в отчёте + вопрос владельцу, если затрагивает видение (`⚑`) |
| число | параметр без значения | строка `docs/07-balance.md` §10, не вопрос |

Один уточняющий вопрос на дыру. `⏳ **Предварительное (рекомендация).**` — если
ответ не меняет видение, работать на рекомендации, не дожидаясь (правило «БЕЗ СТОП»).

## После аудита

Секция: `draft → audited`. Переходы и полноту новых записей проверяет
`python3 scripts/gdd_gate.py` (рост бэклога реестров краснит).
