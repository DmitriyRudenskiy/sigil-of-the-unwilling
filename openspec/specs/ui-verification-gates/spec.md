# ui-verification-gates Specification

## Purpose

Headless-верификация UI без живого прогона: адаптивный layout на фиксированном
наборе разрешений, сверка контраст-канона палитры темы с таблицей UI style
guide и качество UI-ассетов (альфа, 9-slice, ореолы) — три гейта, каждый с
непосредственно проверяемым результатом (тест/exit-код).

## Requirements

### Requirement: Адаптивный UI layout
Ключевые UI-экраны игры SHALL сохранять корректный layout на фиксированном
наборе разрешений 1280×720, 1920×1080, 2560×1440, 3440×1440 и 3840×2160: каждый
графический элемент остаётся внутри границ вьюпорта, непреднамеренные
перекрытия элементов отсутствуют. Экраны, корректность которых зависит от
игрового состояния (без него сцена не рендерится), в обязательный набор не
входят, но механизм исключения обязан быть явным и зафиксированным.

#### Scenario: Элементы в границах вьюпорта
- **WHEN** экран из обязательного набора отображается на любом из 5 разрешений
- **THEN** rect каждого элемента находится внутри границ вьюпорта
- **AND** допуск выхода за границы составляет не более 2 px

#### Scenario: Нет непреднамеренных перекрытий
- **WHEN** два соседних (sibling) элемента экрана перекрываются
- **THEN** перекрытие допустимо только для осознанных оверлеев (затемнение, тултипы) из явного списка исключений
- **AND** перекрытие остальных пар >20% площади меньшего элемента фиксируется как нарушение

#### Scenario: Экран с игровым состоянием исключён явно
- **WHEN** экран не может корректно отрендериться без игрового состояния
- **THEN** его исключение зафиксировано в списке с причиной
- **AND** незарегистрированное исключение не допускается (скрытый пропуск = нарушение)

### Requirement: Контраст-канон палитры
Контрастные отношения текста и графических элементов UI SHALL соответствовать
правилу: текст — не менее 4.5:1, нетекстовое состояние/граница — не менее 3:1.
Готовые канон-пары, зафиксированные в таблице UI style guide §1.2, SHALL
совпадать с пересчётом из живых значений палитры темы: любое изменение
палитры без пересчёта таблицы обнаруживается проверкой.

#### Scenario: Пара канона совпадает с палитрой темы
- **WHEN** проверка пересчитывает контраст канон-пары из живых значений палитры темы
- **THEN** полученное значение совпадает со значением из таблицы UI style guide §1.2
- **AND** расхождение фиксируется как нарушение (дрейф канона)

#### Scenario: Текст ниже порога
- **WHEN** контраст пары «текст на подложке» в канон-наборе ниже 4.5:1
- **THEN** проверка падает с указанием пары и фактического значения

#### Scenario: Нетекстовое состояние ниже порога
- **WHEN** контраст пары «состояние/граница на фоне» ниже 3:1
- **THEN** проверка падает с указанием пары и фактического значения

### Requirement: Качество UI-ассетов
UI-ассеты (кнопки, слоты, иконки, 9-slice-панели) SHALL проходить формальные
проверки качества: у ассетов с прозрачным фоном — прозрачные углы, у 9-slice-
панелей — однородная центральная зона, пригодная к растяжению, по краям
полупрозрачной альфы — отсутствие тёмных ореолов. Проверка выполняется
скриптом с exit-кодом: нарушения дают ненулевой выход, чистый набор — ноль.

Область скола по углу (чамфер сигнатурной формы плитки, арт-библия §4.1) из
проверки ореола исключается — антиалиасинг диагонали не является дефектом
автокропа (T-156, вариант (а), 2026-10-24). Размер скола обязан быть
**измерен по альфе самого ассета** и подтверждён диагональной силуэтой, а не
переписан из манифеста: у скола край силуэта у угла уходит внутрь под 45°, у
ореола над прямым краем — нет. Исключение действует только в измеренной зоне у
угла; прямые рёбра проверяются полностью, ассет без сколов исключений не имеет.
Сам гард обязан иметь самопроверку на мутациях: синтетический ореол на прямом
краю ловится, синтетический чамфер — нет.

#### Scenario: Угол ассета не прозрачен
- **WHEN** ассет, ожидаемый с прозрачным фоном, имеет непрозрачные угловые пиксели
- **THEN** скрипт сообщает файл и завершается с ненулевым exit-кодом

#### Scenario: Центр панели «занят»
- **WHEN** центральный тайл 9-slice-панели не однороден (дисперсия выше порога)
- **THEN** скрипт сообщает файл с измеренным значением и завершается с ненулевым exit-кодом

#### Scenario: Тёмный ореол на краю альфы
- **WHEN** полупрозрачные пиксели по краю ассета имеют почти чёрный цвет (ореол)
- **THEN** скрипт сообщает файл и количество образцов ореола и завершается с ненулевым exit-кодом

#### Scenario: Чистый набор ассетов
- **WHEN** все ассеты проходят три проверки
- **THEN** скрипт завершается с exit-кодом 0 и перечисляет проверенные файлы

#### Scenario: Скошенный угол — не ореол
- **WHEN** полупрозрачные почти чёрные пиксели лежат на диагонали скола угла, размер которого измерен и подтверждён силуэтой
- **THEN** ассет проходит проверку ореола, exit-код не меняется

#### Scenario: Ореол у ассета без сколов
- **WHEN** у ассета с прямоугольными углами (измеренный скол 0) по краю найдены почти чёрные полупрозрачные пиксели
- **THEN** скрипт сообщает файл и количество образцов и завершается с ненулевым exit-кодом

#### Scenario: Гард проверяет себя
- **WHEN** запущена самопроверка скрипта (`--self-test`)
- **THEN** синтетический ореол на прямом краю обязан быть найден, синтетический чамфер-AA — не найден, у прямоугольника без сколов исключений не измерено
- **AND** при любом ином исходе самопроверка завершается с ненулевым exit-кодом
