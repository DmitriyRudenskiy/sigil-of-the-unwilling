## Purpose

Определяет, как игра получает уникальные иконки артефактов: поштучную генерацию
по внешнему генерирующему сервису (ComfyUI) из утверждённого спека, постобработку
к бюджету ассетов, машинную проверку результата и порядок выкладки в репозиторий.

## Requirements

### Requirement: По-id генерация иконок артефактов

Иконка артефакта SHALL генерироваться для конкретного id реестра, а не для слота:
каждый id набора получает собственный рисунок. Источник рисунка — внешний
генерирующий сервис (ComfyUI), вход — префикс-промпт арт-библии + субъект и
акцентный цвет, объявленные для id в спеке ассетов.

#### Scenario: Генерация id из набора

- **WHEN** для id из набора запускается генерация
- **THEN** промпт собран из префикс-промпта библии и описания субъекта этого id
- **AND** результат сохраняется как `assets/artifacts/<id>.png`

#### Scenario: Генератор недоступен

- **WHEN** эндпоинт генерации не отвечает или отдал ошибку
- **THEN** прогон завершается явной ошибкой с именем id
- **AND** в репозиторий НЕ кладется ни процедурная, ни предыдущая замена молча

#### Scenario: Набор задан списком, а не перебором слотов

- **WHEN** запускается генерация набора
- **THEN** обрабатываются только id из списка набора
- **AND** ни один id вне списка не перезаписывается

### Requirement: Бюджет и формат результата

Каждая сгенерированная иконка SHALL проходить машинную проверку: канвас 64×64,
грид 8, содержимое с отступом 8 px, PNG-32 (RGBA), вес ≤ 6 КБ. Несоответствие —
падение прогона, а не предупреждение. Прозрачность фона НЕ требуется: фоном
иконки артефакта канон считает `#281c0f` (см. design.md — решение конфликта
`docs/15` §2 и [[13-art-bible]] §8.3).

#### Scenario: Файл весит больше бюджета

- **WHEN** сохранённая иконка превышает 6 КБ
- **THEN** прогон падает с именем файла и фактическим весом
- **AND** файл не попадает в рабочее дерево как результат прогона

#### Scenario: Формат не по бюджету

- **WHEN** у файла канвас ≠ 64×64 или это не RGBA PNG
- **THEN** проверка считает файл негодным и прогон падает

### Requirement: Окантовка тира — уровень ячейки, не пикселей иконки

Рамка редкости SHALL рисоваться при отображении (тема/ячейка), а не запекаться в
пиксели файла иконки. Смена rarity в данных не должна требовать перегенерации
ни одного файла.

#### Scenario: Редкость изменена в данных

- **WHEN** у артефакта меняется rarity
- **THEN** файл его иконки остаётся прежним
- **AND** рамка и искры меняются вместе с темой ячейки

### Requirement: Контакт-лист как артефакт ревью

Перед выкладкой набора SHALL собираться контакт-лист всего сета иконок
артефактов (живые + новые) на тайле `#281c0f` с наложенными рамками тиров,
в масштабах 1× и 2×. Ревью набора = ревью контакт-листа, а не 29 отдельных
файлов.

#### Scenario: Контакт-лист собран

- **WHEN** генерация набора завершена
- **THEN** контакт-лист содержит все id сета, каждый со своей рамкой тира
- **AND** по нему проверяется контраст текста/подложки и плотность RELIC

#### Scenario: Интеграция до приёмки

- **WHEN** контакт-лист не принят владельцем
- **THEN** файлы набора в `game/assets/artifacts/` не выкладываются

### Requirement: Согласованность id ↔ файл в обе стороны

Набор SHALL проверяться в обоих направлениях: файл без потребителя и id реестра
без файла. Для id-резолвящихся загрузок (`artifacts/%s.png`) id без файла —
падение гейта, а не находка постфактум.

#### Scenario: Достижимый id без иконки

- **WHEN** id достижим в игре (например, куётся) и файла его иконки нет
- **THEN** гейт падает со списком таких id

#### Scenario: Уникальность рисунка

- **WHEN** два id набора имеют одинаковый md5 содержимого
- **THEN** гейт падает (дубль не считается выполненным)

### Requirement: Интеграция отдельным PR после приёмки

Выкладка принятых иконок SHALL быть отдельным от генерации PR: все замены
плейсхолдеров — одним коммитом, маппинг в коде не меняется, за ним следует
переимпорт и смок экрана инвентаря артефактов.

#### Scenario: PR интеграции

- **WHEN** набор принят и выкладывается
- **THEN** PR содержит файлы иконки и ничего из генерационной обвязки
- **AND** после реимпорта проходят смок инвентаря и GdUnit-сета артефактов

#### Scenario: Плейсхолдеры группы

- **WHEN** в группе дублей заменяется часть id
- **THEN** группа не остаётся в смешанном состоянии: либо заменён весь сет,
      либо не заменён ничего
