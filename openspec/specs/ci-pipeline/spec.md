# ci-pipeline Specification

## Purpose
Определяет оркестрацию гейта CI-2 (раскладка по job'ам, маппинг
вердикта, инвариантность гейт-семантики) и требования к его
производительности (wall time, параллельные MCP-воркеры, кэши
setup).
## Requirements
### Requirement: Параллельная раскладка гейта
Workflow CI-2 SHALL выполнять уровни гейта в отдельных параллельных
job'ах: `static` (checkers + lint + DOCS-LINKS), `gdunit` (GdUnit4),
`mcp` (MCP e2e), плюс финальный job `verdict` (`needs`: все три,
`if: always()`) с CI-2 Stability (D-174) и итоговой 4-уровневой
строкой (D-147).

#### Scenario: Зелёный ран
- **WHEN** все уровни прошли
- **THEN** workflow завершён success
- **AND** wall time рана ≤ 3 мин

#### Scenario: Падение одного уровня
- **WHEN** один из уровней упал
- **THEN** workflow завершён failure
- **AND** упавший уровень виден по job-конклюжону без тела лога
- **AND** job `verdict` отработал (stability-счётчик не потерян)

#### Scenario: Прогон на push и PR
- **WHEN** push или PR на любую ветку
- **THEN** запускается полный набор job'ов (без сокращений по
  типу события)

### Requirement: Инвариантность гейт-семантики
Пересборка workflow SHALL сохранять все действующие политики:
состав уровней (4), exit-код политику (GdUnit4 0/101 = зелёный;
pytest 0 = зелёный; checkers и docs-links — ноль ошибок = зелёный),
ретрай-политику CI-1(12) (до 3 попыток MCP на раннер-окружение),
артефакты логов (balance-report, ci2-gate-logs), concurrency-группу
(`ci2-${{ github.ref }}`, cancel-in-progress).

#### Scenario: Никаких пропусков уровней
- **WHEN** запущен любой ран workflow
- **THEN** все 4 уровня исполнены (статус каждого уровня явен)
- **AND** ни один уровень не заменён более дешёвым

#### Scenario: Ретраи сохранены
- **WHEN** MCP-уровень упал на раннере с runner-окружением
- **THEN** повтор до 3 попыток (как до пересборки)
- **AND** лог каждой попытки сохранён в артефакт

### Requirement: Параллельные MCP-воркеры
MCP e2e-секция SHALL поддерживать параллельный прогон тестовых
файлов через pytest-xdist (`dist=loadfile`) с числом воркеров из
переменной `MCP_WORKERS` (дефолт 1 — локальный прогон без
изменений; CI: 3). Каждый воркер SHALL использовать уникальный
интеракционный порт `9090 + индекс_воркера` через переменную
окружения `MCP_PORT` (дефолт 9090; конвенция домашней Godot-
стороны `tools/mcp/mcp_interaction_server.gd`).

#### Scenario: Воркер получает свой порт
- **WHEN** запущен прогон с `MCP_WORKERS=3`
- **THEN** воркеры gw0/gw1/gw2 используют порты 9090/9091/9092
- **AND** godot-инстансы воркеров не блокируют друг друга на порту

#### Scenario: Локальный прогон без изменений
- **WHEN** запущен `run_tests.sh` без `MCP_WORKERS`
- **THEN** прогон идёт в одном воркере на порту 9090
- **AND** поведение идентично доведения (один Godot на тест)

#### Scenario: Один X-дисплей на всех воркеров
- **WHEN** запущен прогон с N воркерами без заданного DISPLAY
- **THEN** поднимается один Xvfb на свободном дисплее (существующий
  скан :97 → :91–:98)
- **AND** все воркеры используют его (X поддерживает нескольких
  клиентов)

### Requirement: Настраиваемый интеракционный порт
MCP-сервер (node, вендорный `godot-mcp`) SHALL читать интеракционный
порт из `MCP_PORT` с дефолтом 9090. Godot-сторона (домашний
`tools/mcp/mcp_interaction_server.gd`) уже читает `MCP_PORT`
(цепочка: env → ProjectSettings `mcp/port` → 9090) — изменений не
требует. Значение по умолчанию SHALL сохранять совместимость со
всеми существующими запусками.

#### Scenario: Порт по умолчанию
- **WHEN** `MCP_PORT` не задан
- **THEN** node-сервер коннектится на 9090, игра слушает 9090

#### Scenario: Порт из окружения
- **WHEN** `MCP_PORT=9091`
- **THEN** node-сервер коннектится на 9091
- **AND** игра слушает 9091

### Requirement: Кэширование setup
Workflow SHALL кэшировать: `node_modules` MCP-аддона (key от
package-lock.json), pip-venv MCP-тестов (key от python-версии и
списка пакетов), Godot-бинарь (key от версии). Кэш SHALL промахивать
безопасно (при промахе — установка как раньше).

#### Scenario: Повторный ран с тёплым кэшем
- **WHEN** кэш setup существует для данного key
- **THEN** setup-шаги job'а `mcp` занимают ≤ 15с (с ~31с)

#### Scenario: Промашка кэша
- **WHEN** key кэша не найден (новый lock-файл/версия)
- **THEN** установка идёт как доведения, кэш сохраняется на будущее
- **AND** ран не падает из-за кэша
