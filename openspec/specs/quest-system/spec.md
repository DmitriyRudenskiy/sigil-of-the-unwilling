# quests Specification

## Purpose

Определяет систему квестов: генерация, типы, отслеживание прогресса, награды, провалы и квестовые цепочки. Квесты дают игроку цели, контекст и вознаграждение за действия в мире.

## Requirements

### Requirement: Типы квестов
Система SHALL поддерживать 4 базовых типа квестов: убийство (уничтожить N юнитов), сбор (собрать N ресурсов), доставка (передать предмет NPC), эскорт (сопроводить NPC из A в B). Каждый тип имеет уникальные условия завершения.

#### Scenario: Квест на убийство
- **WHEN** игрок принимает квест "Убить 10 волков"
- **THEN** система отслеживает убитых волков
- **AND** при достижении 10 квест завершается с наградой

#### Scenario: Квест на сбор
- **WHEN** игрок принимает квест "Собрать 5 трав"
- **THEN** система отслеживает собранные травы в рюкзаке
- **AND** при сдаче ресурсы списываются, квест завершается

#### Scenario: Квест на доставку
- **WHEN** игрок получает предмет для доставки
- **THEN** должен достичь NPC-получателя в другом городе
- **AND** при доставке предмет исчезает, награда выдаётся

#### Scenario: Квест эскорт
- **WHEN** игрок соглашается сопроводить NPC
- **THEN** NPC следует за героем или движется по маршруту
- **AND** если NPC погибает — квест провален

### Requirement: Генерация процедурных квестов
Квесты SHALL генерироваться процедурно из пулов: цели (враги, ресурсы), локации (города, узлы карты), награды (золото, опыт, предметы). Сложность квеста зависит от кольца угроз (кольцо 1 — простые, кольцо 3 — эпические).

#### Scenario: Генерация квеста в городе
- **WHEN** игрок посещает город впервые за N ходов
- **THEN** генерируется 1–3 новых квеста от жителей
- **AND** квесты соответствуют уровню города и кольцу

#### Scenario: Сложность по кольцу
- **WHEN** квест генерируется в кольце 1
- **THEN** цели — дикие животные, ресурсы — базовые
- **AND** награда пропорциональна сложности

#### Scenario: Уникальность квестов
- **WHEN** генерируются новые квесты
- **THEN** дублирующиеся активные квесты не создаются
- **AND**已完成 квесты могут повторяться через N ходов

### Requirement: Отслеживание прогресса
Каждый активный квест SHALL хранить прогресс выполнения (текущее значение / целевое значение). Прогресс обновляется при соответствующих действиях игрока (убийство, сбор, перемещение).

#### Scenario: Обновление прогресса
- **WHEN** игрок убивает врага по квесту
- **THEN** счётчик квеста увеличивается на 1
- **AND** UI показывает обновлённый прогресс

#### Scenario: Частичное выполнение
- **WHEN** игрок собрал 3 из 5 трав
- **THEN** квест остаётся активным
- **AND** прогресс сохраняется при загрузке сейва

#### Scenario: Несколько квестов
- **WHEN** игрок выполняет 5 активных квестов одновременно
- **THEN** каждый трекится независимо
- **AND** награды выдаются по мере завершения

### Requirement: Награды и последствия
Завершение квеста SHALL давать награду: опыт героя, золото, предметы, репутацию с фракцией. Провал квеста (превышение времени, гибель NPC) влечёт последствия: потеря репутации, штраф золотом, блокировку повторных квестов.

#### Scenario: Награда за квест
- **WHEN** игрок завершает квест успешно
- **THEN** получает опыт, золото и +репутацию
- **AND** квест перемещается в журнал завершённых

#### Scenario: Превышение времени
- **WHEN** квест с таймером не выполнен за N ходов
- **THEN** квест провален
- **AND** репутация с фракцией снижается на 10

#### Scenario: Гибель NPC
- **WHEN** NPC эскорта погибает в бою
- **THEN** квест провален немедленно
- **AND** игрок получает штраф репутации −20

### Requirement: Квестовые цепочки
Квесты SHALL образовывать цепочки: завершение одного квеста открывает следующий. Цепочки имеют ветвление: выбор игрока влияет на доступные квесты и репутацию с фракциями.

#### Scenario: Линейная цепочка
- **WHEN** игрок завершает квест "Часть 1"
- **THEN** становится доступен квест "Часть 2"
- **AND** NPC упоминает продолжение в диалоге

#### Scenario: Ветвление цепочки
- **WHEN** игрок выбирает сторону в конфликте
- **THEN** открывается ветка квестов этой фракции
- **AND** ветка вражеской фракции блокируется

#### Scenario: Финал цепочки
- **WHEN** игрок завершает финальный квест цепочки
- **THEN** получает уникальную награду (предмет, технология)
- **AND** цепочка помечается завершённой в журнале

### Requirement: Журнал квестов
Интерфейс SHALL предоставлять журнал квестов с фильтрами (активные, завершённые, проваленные), деталями каждого квеста (описание, цель, прогресс, награда) и трекингом активной цели на карте.

#### Scenario: Просмотр активных квестов
- **WHEN** игрок открывает журнал квестов
- **THEN** видит список активных квестов с прогрессом
- **AND** может выбрать квест для трекинга на карте

#### Scenario: Детали квеста
- **WHEN** игрок кликает на квест в журнале
- **THEN** видит полное описание, цель, награду
- **AND** кнопку "Сдать квест" (если выполнен)

#### Scenario: Трекинг на карте
- **WHEN** игрок выбирает трекинг квеста
- **THEN** цель квеста подсвечивается на карте
- **AND** компас указывает направление
