# dev-verification-loop Specification

## ADDED Requirements

### Requirement: Полный гейт выполняется один раз перед публикацией

`game/run_tests.sh` SHALL запускаться один раз в конце смены — как подтверждение
работоспособности перед публикацией `main` — и SHALL NOT использоваться как
обратная связь внутри шага разработки. Требование «зелёный гейт до push» этим
не отменяется: меняется частота прогонов, а не условие публикации.

#### Scenario: Шаг разработки проверен быстрым средством

- **WHEN** агент заканчивает шаг правки (код, данные, сцена, документация)
- **THEN** проверяет его целевым средством: один файл GdUnit, один pytest-узор,
  self-check инструмента, `gdlint` или `check_docs_links.py`
- **AND** `game/run_tests.sh` в этом шаге не запускается

#### Scenario: Смена заканчивается публикацией

- **WHEN** работа над сменой закончена и впереди push в `main`
- **THEN** запускается ровно один полный `game/run_tests.sh`
- **AND** его вердикт (статистика GdUnit, MCP-секция, известные красные тесты со
  ссылками на тикеты) приводится в отчёте

#### Scenario: Гейт нельзя отменить ссылкой на директиву

- **WHEN** смена заканчивается без зелёного прогона
- **THEN** код и ассеты не публикуются
- **AND** в отчёте прямо сказано, что гейт не выполнялся

### Requirement: Экран доступен отдельному инструменту разработки

Для экрана, с которым ведётся работа, SHALL существовать запускаемый инструмент в
`game/tools/`, поднимающий **только эту сцену** (с нужным состоянием) и пишущий
кадр, — без полного прогона игры, без MCP-сервера и без порта 9090.

#### Scenario: Кадр одной сцены без всей игры

- **WHEN** нужен кадр экрана (например инвентаря) для шага правки
- **THEN** инструмент запускается одной командой с путём сцены `res://…` и
  получает кадр за секунды, а не за минуты полного прогона
- **AND** процесс живёт коротко и не занимает MCP-порт

#### Scenario: Состояние экрана задаётся фикстурой

- **WHEN** экран без игрового состояния не показывает содержимое
- **THEN** состояние подставляется фикстурой из `game/tools/capture/` по имени
- **AND** вызов с именем, под которое не лежит файл, падает, а не снимает пустой экран

#### Scenario: Неговый кадр отвергается, а не пишется

- **WHEN** съёмка идёт без дисплея (`--headless` → dummy rasterizer), сцена не
  загрузилась или кадр получился пустым
- **THEN** инструмент завершается с ненулевым кодом и внятным сообщением
- **AND** PNG не появляется, потому что чёрный кадр — не доказательство

### Requirement: Кадр разработки не подменяет канонический кадр

Кадр, полученный инструментом разработки, SHALL NOT считаться каноническим:
доказательством канонического размера, состояния и воспроизводимости остаётся
путь `game/tests/mcp/capture.py` с проверкой кадра и манифестом.

#### Scenario: Вердикт по канону

- **WHEN** выносится вердикт по ux-review или по AC, где важен канон кадра
- **THEN** кадр взят канальным съёмщиком и описан манифестом (размер, sha256,
  состояние)
- **AND** кадр из `game/tools/` помечен как вспомогательный или не упомянут вовсе

#### Scenario: Граница записана в носителе

- **WHEN** инструмент разработки документирован
- **THEN** в носителе (скилл, `docs/mvp/CAPTURE-HELPER.md`) названа граница
  «разработка → tools, вердикт → канальный съёмщик»
- **AND** второй путь не изобретается молча
