Замеры этого дерева (`main` @ `45ddbf3a`, машина владельца, 2026-11-02) — они же
основное ограничение дизайна:

| Что | Стоимость | Объём |
| --- | --- | --- |
| `godot --headless --path game --import` (тёплый кэш) | 7.2 с | — |
| GdUnit: старт движка + 5 сюит (`tests/unit/theme`) | 2.5 с | 5 файлов |
| GdUnit `tests/unit` | 121 с | 2755 тестов (0.04 с/тест) |
| GdUnit `tests/functional` | 73 с | 294 теста (**0.25 с/тест**) |

Отсюда: 60–75% времени гейта — живой Godot (MCP), а не модульные тесты; внутри
GdUnit дорогие — функциональные (6× дороже модульного на проверку). «Быстрый
прогон» обязан вырезать MCP, а не юниты.

Что уже есть и переиспользуется вместо нового:

- **Метрика и рэтчет.** `scripts/testmap.py` считает файлы/функции, дыры покрытия,
  группы слияния и межфайловые дубли тел; `--check` — красный уровень
  `scripts/doc_gates.sh` (T-227 С-5). Текущий замер: 388 файлов / 3664 функции,
  80 дыр, 28 групп слияния (151 файл), 0 дублей тел.
- **Карантин флейков.** `game/tests/mcp/quarantine.txt`
  (`<подстрока nodeid>\t<срок>\t<причина>`, просроченная строка валит прогон,
  активных записей нет).
- **Гигиена.** `game/tests/orphan_allowlist.txt` (18 строк), сканер пустых assert
  (`scripts/ci2_vacuous_asserts.py`), сканер путей узлов (T-296).
- **Общие помощники.** `tests/helpers/base_test.gd` (386 потребителей),
  `factories.gd` (9), `wait_helpers.gd` (1), `theme_carrier_guard.gd`;
  pytest-фикстуры `mcp` / `battle_scene` / `world_scene` / `full_game` /
  `full_cycle` в `tests/mcp/conftest.py`.

Средства фильтрации, которые даёт раннер: GdUnit4 6.2.1 принимает `-a <путь>`
(включить, несколько раз, каталог рекурсивно) и `-i <путь>` (исключить по
подстроке `source_file`); **тегов в CLI нет** (`GdUnitTestCIRunner.gd`, реестр
опций). pytest маркеров не объявляет (`pytest.ini` в проекте отсутствует),
используются только `timeout`/`parametrize`/`skipif`.

Два факта, которые меняют постановку запроса:

1. «Дубли тестов» в наборе кончились: межфайловых дублей тел 0 (С-1 свёл два
   настоящих). Разрастание идёт по носителю — 28 групп, 151 файл, это остаток
   T-227 С-3, и сводить его надо там, а не здесь. Дублируется другое: 76 файлов
   держат свои `func _make_*` (82 билдера) при 9 потребителях общего
   `factories.gd`.
2. `tests/functional/test_compile_all.gd` на этой машине **красен в изолированном
   прогоне** (`Parse Error: Unexpected "if" in class body`), потому что скан
   обходит `res://`, исключив только `.git/.godot/addons/tools/tests`, и
   натыкается на gitignored огрызок `game/tmp/fixture_hero4.gd`. Вердикт теста
   зависит от мусора в рабочем дереве: в артефактах гейта (другая машина) он
   зелёный. Изоляция слоёв вскрывает этот класс дефектов — и обязана быть
   сделана так, чтобы вскрывать их, а не прятать.

## Goals / Non-Goals

**Goals:**

- Три слоя с известной ценой и одной точкой входа; `full` побитово остаётся тем
  же прогоном, что сегодня.
- Ни один тест не выпадает из всех слоёв (проверяется равенством сбора).
- Подготовка живёт в помощниках там, где она реально повторяется; число проверок
  не падает (рэтчет testmap + леджер).
- Флейки изолируются существующим механизмом карантина, а не удалением.

**Non-Goals:**

- Сведение файлов по носителям (T-227 С-3), триаж 80 дыр (С-4), гарды темы (С-2б).
- Ускорение MCP e2e (воркеры, порты, readiness) — это `ci-pipeline` и D-166-семья.
- Новые раннеры, теги, отчёты, дашборды; изменение CI-раскладки (CI — зона
  владельца, гейт локальный).
- Покрытие «в процентах» и метрики исполняемых строк.

## Decisions

**D1. Слой = каталог + штатная фильтрация, не тег и не манифест.**
`tests/smoke/` включается `-a res://tests/smoke`; `fast` = `-a res://tests
-i res://tests/slow`; `full` = `-a res://tests`. Альтернативы: (а) теги — в
GdUnit4 6.2.1 CLI их нет, значит патч вендора; (б) манифест «список файлов слоя»
— расходится с деревом в первый же день и не краснеет, когда файл переименовали;
(в) отдельный конфиг-файл GdUnit (`-conf`) — прячет выбор слоя в настройки,
которые никто не читает. Для pytest — маркеры `smoke`/`slow` и `-m`, потому что
каталог для MCP-тестов означает переезд 35 файлов с общими фикстурами.

**D2. `game/run_tests.sh --tier=<smoke|fast|full>`, дефолт `full`.**
Ни один существующий вызов (CI, `report.sh`, чужие сессии) не меняет поведения.
Отчёт слоя печатает заголовок `TIER: <имя>` и строки `NOT MEASURED: <уровень> —
<причина>`: молчание уровня — тот же дефект, что жёлтый без причины (D-265, T-281).
Слои не печатают слово `GATE`, чтобы `fast` нельзя было прочитать как
публикационный вердикт.

**D3. Критерий переезда в `slow` — замер, а не имя каталога.**
Шаг 1 даёт per-suite таблицу (`--durations` для pytest, `Total execution time` и
per-suite строки GdUnit), в `slow` едут сюиты дороже порога 2 с/проверка и всё,
что грузит живые сцены. Порог — константа в доке с датой замера, а не «на глаз».

**D4. `smoke` — 6–8 headless-сюит критичного пути, `--import` не пропускается.**
Состав: загрузка `main_menu`/`world`/`battle`, сейв-раундтрип схемы T-110,
инвариант «нет немых ключей эффектов» (D-197), один канон-якорь баланса
(T-041). Нижняя граница бюджета — 7.2 с импорт + ~2.5 с старт сюиты, то есть
30 с достижимы с запасом; импорт не вырезается: протухший кэш глобальных
классов даёт «красный» прогон по причине среды, а это ровно то, с чем борется
D-265.

**D5. Карантин GdUnit = тот же формат, что у MCP.**
`game/tests/quarantine.txt`, `<подстрока пути сюиты>\t<ГГГГ-ММ-ДД>\t<причина>`,
читается `run_tests.sh` и транслируется в `-i`; просроченная строка краснит
прогон, активная — печатается поимённо. Альтернатива «свой YAML» — вторая
конвенция там, где первая уже работает и проверяется.

**D6. Счётчик локальных билдеров живёт в `testmap.py`, а не в новом отчёте.**
Новая метрика `local_builders` (файлы с `func _make_*` / всего билдеров) плюс
строка в базлайне: рэтчет, красный уровень и команда уже есть (С-5), новый
инструмент не нужен. Цель среза — 76 → ≤ 25 файлов, без изменения числа
`func test_*`.

**D7. `test_compile_all` сканирует только версионированное дерево.**
Скан идёт по каталогам из явного списка (`scripts/`, `assets/`, `data/`,
`scenes/`) либо по `git ls-files`, а не по всему `res://`; `tmp/` и `reports/`
исключены явно. Иначе «быстрый прогон» краснеет от чужого огрызка в `tmp/`, и
первый же слой начинает воевать с рабочим деревом вместо кода.

## Risks / Trade-offs

- **Переезд файлов двигает базлайн testmap** (приписывание к носителю идёт по
  пути/имени) → базлайн переписывается в том же диффе строкой в сообщении, по
  конвенции С-5; ухудшение без строки — красный.
- **Порядок исполнения меняется** (GdUnit обходит пути по алфавиту) → вскроются
  order-зависимые тесты, сегодня скрытые общим прогоном → они и есть цель:
  починка или карантин со сроком, откат переезда только если починка дороже
  среза.
- **Двойная работа с T-227 С-3** (переезд по носителям vs по слоям) → слои
  трогают только `smoke/` и `slow/`; 27 групп слияния в этом срезе не
  перемещаются вообще.
- **Бюджет 30 с на шареной машине** может не держиться (соседние прогоны, X) →
  в доке фиксируется замер с датой и машиной; превышение — не красный гейт,
  а строка `TIER BUDGET: smoke 41s / 30s (замер 2026-11-02)`, чтобы цифра не
  стала легендой.
- **Маркеры pytest без реестра** дают `PytestUnknownMarkWarning` и молча
  опечатки в `-m` → `pytest.ini` с `markers = smoke, slow` заводится тем же
  диффом, что и первый маркер.
- **Общий `factories.gd` = общая точка отказа**: правка билдера ломает 25+
  файлов → переезд порциями «один носитель за дифф», после каждого — `fast`.

## Migration Plan

1. Замер и таблица (per-suite время, стоимость MCP-фикстур) → `docs/mvp/TEST-MAP.md`,
   ветка не заводится, коммит в `main`.
2. `--tier` + `pytest.ini` + `tests/smoke/` (пустой каркас + 6 сюит) + карантин
   GdUnit + фикс `test_compile_all` (D7). `full` обязан совпасть со старым
   прогоном по числу собранных тестов.
3. Переезд дорогих сюит в `tests/slow/` по таблице замера, порциями.
4. Переезд билдеров в помощники, по одному носителю за дифф; счётчик
   `local_builders` в testmap.
5. Флейки — в карантин; стиль/именование — только там, где файл уже трогался;
   доки (README-секция команд, AGENTS.md § «Верификация»), `--write-baseline`.

Откат любого шага — `git revert` диффа: перемещение файлов обратимо, флаги
дефолтятся в прежнее поведение.
