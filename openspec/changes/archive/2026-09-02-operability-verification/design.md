## Context

Проект уже умеет **проверять** себя, но не умеет **чинить** в рамках одного прогона:

- `run_all_ci_checks.sh` — компиляция, scene-рефы, валидация спеллов, тайлкеты, юнит-тесты. Не гоняет сцены end-to-end и не ловит ошибки/предупреждения консоли в режиме «запусти игру».
- `check_console_clean.sh` — гоняет сценарии 1–5 и сканирует консоль на ошибки/предупреждения (с allowlist из `docs/CONSOLE_ALLOWLIST.md`), но только **проверяет**, не чинит.
- `play_scenario.sh` — одиночный сценарий через socket-сервер (порт 9095).
- Скил `godot-run-and-fix` — умеет запускать, захватывать `/tmp/godot_*.log` и чинить по шаблонам, но не оркестрирует все точки входа вместе.
- `run_godot` (AGENT.md, 8.1) — hang-preventing обёртка (`sleep + kill`, так как на macOS нет `timeout`).

Godot-запуски нельзя оставлять без таймаута (на macOS повесившийся main-loop держит хенчар ~5000 с). Реестр `global_script_class_cache.cfg` строится только редактором — без него `-s`-скрипты падают с `Could not find type`.

## Goals / Non-Goals

**Goals:**
- Сводный runner `game/tools/shell/run_operability.sh`, гоняющий все точки входа (сцены + сценарии + тесты).
- Run-and-fix цикл (run → capture → scan → fix → verify) на шаблонах скила `godot-run-and-fix`.
- Переиспользование существующих гейтов и allowlist — без дублирования.
- Вердикт «чисто/грязно» + отчёт `/tmp/operability_report.md`.
- Каждый запуск Godot — под hang-preventing обёрткой.

**Non-Goals:**
- Не менять гейт чистоты (`check_console_clean.sh`) и CI (`run_all_ci_checks.sh`) по смыслу — только вызывать их.
- Не вводить воркфлоу-правило «гейт в конце цикла» — это отдельный цикл `agent-run-and-debug`.
- Не править игровую логику/баланс — цикл только ловит и чинит регрессии консоли, а не улучшает механики.
- Не переопределять таксономию маркеров/allowlist — берём из существующих источников.

## Decisions

1. **Оркестрация через bash-скрипт, вызывающий существующие гейты.**
   Runner вызывает `play_scenario.sh` (сценарии), `check_console_clean.sh` (console-clean для 1–5), `run_all_ci_checks.sh --tests` (юнит-тесты) и SceneTree-скрипты для сцен. Это даёт переиспользование вместо копирования логики.

2. **Сцены гоняются SceneTree-скриптом с `_init()` + `quit()`, а не `--scene` напрямую.**
   Каноничный раннер из AGENT.md (правило 9): скрипт гарантированно завершается (`quit()`), что критично для автоматического прогона и таймаута.

3. **Run-and-fix цикл замыкается на шаблонах скила `godot-run-and-fix`.**
   Runner ловит находки (повторяя таксономию ошибок/предупреждений из `check_console_clean.sh`), применяет шаблоны исправления скила, повторяет точку входа. Цикл завершается, когда точки входа чисты.

4. **Allowlist — единый источник (`docs/CONSOLE_ALLOWLIST.md`).**
   Runner читает паттерны из того же файла, что и `check_console_clean.sh`, чтобы «чистота» определялась одинаково.

## Risks / Trade-offs

- **Зависание сцен** — решается обёрткой `run_godot` + `kill`; каждая точка входа имеет свой таймаут.
- **Долгий общий прогон** (сцены + 7 сценариев + тесты + авто-загрузка реестра) — возможны минуты; каждый запуск изолирован по таймауту, провал одной точки не рвёт весь отчёт.
- **Кэш/импорт** — как в CI: авто-загрузка реестра, инструкция `rm -rf game/.godot` при странных ошибках.
- **Ложные срабатывания** — приложение само логирует `SaveManager: parse error …`; в маркеры провала включают только строки с префиксами Godot (`SCRIPT ERROR:`, `Failed to load script`, `E 0:`), а не внутренние логи.
