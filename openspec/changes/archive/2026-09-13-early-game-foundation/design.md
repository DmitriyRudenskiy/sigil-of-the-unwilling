# Design: early-game-foundation

## Context

Текущее состояние (установлено аудитом кода):

- `HeroArmyController._init_default_army()` создаёт 8 стартовых стеков (~300 юнитов).
- `WorldEventRouter._on_resource_extracted` кладёт добычу узлов в стратегический пул героя (`hero.add_strategic_resource`). Пул **не имеет потребителей** — `remove_strategic_resource()` нигде не вызывается. Магия ест отдельную ману (`HeroMagic`).
- `CityData.storage` (Dictionary) — мёртвая структура, никто её не пополняет. Цепочки зданий (grain→flour→bread, ore+wood→tools) работают от `ResourceContext` города.
- Город: `CITY_LEVEL_MAX = 5` (GameNumbersCity), повышение по `ProsperitySystem` (процветание + население + число зданий). Здания (15 в `buildings.json`) не гейтятся уровнем города; `BuildingDefs._req` описывает уровни *здания* (industry/followers), а не гейты *города*.
- «Нанять» в CityScreen = `FollowerSystem.recruit` (переезд NPC-последователя), не военный найм.
- `MapSpawner`: враги — случайные 1–3 стека из случайной из 7 фракций `FACTION_SETS` (драконы/элементали возможны у старта).
- `assets/data/races_classes.json` (Pathfinder: 6 рас × 16 классов, абилки, трейты) уже в ассетах; `RaceClassRegistry` существует (используется FollowerSystem).
- У героя есть `HeroCombatComponent` (HP), но нет личной атаки; в бою герой — бонусы к армии (`BattleController.set_hero_bonuses`), без армии боец не представлен.
- GDScript 4.7: без tuple-деструкции в for, без `@warningignore`; `HexGridOverlay.gd` — 2-пробечный отступ; gdUnit headless viewport 0×0.

## Goals / Non-Goals

**Goals**
- Играбельный ранний цикл: соло-герой → сбор → выгрузка → строительство → найм → рост.
- Все новые данные в JSON/константах, не захардкожены в логике.
- Каждая capability покрывается gdUnit-тестами; ранний цикл — e2e-проверкой.

**Non-Goals**
- Ребаланс боевой системы (98.5% защиты) — отдельный change (`balance-core`), он калибрует числа, рождённые здесь.
- Настроение/потребности жителей, объединённые здания, Престиж 1–11, Тлеющий Город, расы городов — отложены.
- Новые спрайты/анимации — используются существующие (`UnitSprites`).

## Decisions

### D1. Классы героя: 6 боевых, каждый = статы + 1 эффект
- **Выбор:** Воин (+АТК/ОБР), Следопыт (+движение, +урон по животным), Плут (+крит), Жрец (самолечение), Чародей (стартовый spell), Друид (животные кольца 1 убегают).
- **Почему не 16 из `races_classes.json`:** 16 персональных балансов для калибровки — неоправданно; 6 закрывают архетипы (танк/разведка/дамаг/саппорт/кастер/специалист).
- **Источники данных:** расы — существующий `races_classes.json` (6 рас, ability_adjustments → маппинг на АТК/ОБР/HP/движение); классы — новый `assets/data/hero_classes.json` (6 записей: base stats + эффект-ключ).
- **Альтернатива:** взять 16 классов и дать каждому только статы без эффектов — отклонено (нет идентичности).

### D2. Личный бой героя = отдельный боец на доске, не «бонус к армии»
- **Выбор:** при пустой (и не только) армии герой представляет себя боецом `hero_unit` в бою: HP из `HeroCombatComponent`, АТК/ОБР из класса+расы, движение как юнит. Смерть бойца-героя в бою = герой ранен (HP 1 в мире, армия остаётся), не мир-смерть.
- **Почему:** существующий `set_hero_bonuses` без армии не даёт героям роли; «бонус к ни к чему» — мёртвая механика.
- **Риск:** интеграция с `BattleState` (добавить геройский слот) — митигируется тем, что геройский боец — особый `BattleUnit` с флагом, не новый тип юнита.

### D3. Рюкзак = компонент героя, общий лимит по сумме единиц
- **Выбор:** `HeroBackpackComponent`: `Dictionary {resource_id: amount}`, `capacity := 12` (+ телега рынка +N). Переполнение: кладётся остаток, узел всё равно считается собранным (игрок не застревает).
- **Почему не лимит на тип:** общий лимит проще и создаёт реальные решения (что везти); «лимит на тип» отклонён как избыточный.
- **Удаление автопула:** `WorldEventRouter._on_resource_extracted` → рюкзак вместо `hero.add_strategic_resource`. `add/remove_strategic_resource` остаются в HeroController (сейв-совместимость старых слотов), но мир их не пишет.

### D4. Выгрузка в город — действие героя в CityScreen
- **Выбор:** кнопка «Выгрузить» в CityScreen (герой в городе): весь рюкзак → `city.storage`. Частичная выгрузка — вне v1 (ponytail: одна кнопка, решаем позже по фидбеку).
- **Почему:** `city.storage` уже сериализуется в `CitySerializer` — структура живёт, остаётся наполнить.

### D5. Тиры оружия = множитель статов стека при найме, тир хранится в стеке
- **Выбор:** `UnitStack` получает `weapon_tier: int` (0=T1, 1=T2, 2=T3); статы масштабируются в `UnitRegistry.make_recruit_stack(key, tier)`: T2 = ×1.6 (округление в большую сторону), T3 = ×1.6×1.66 ≈ ×2.66. Т3 добавляет тег `magic_weapon`.
- **Почему не отдельные юнит-ключи (wood_swordsman/...):** ×3 каталог юнитов ×3 спрайтов ради одного множителя; тир в стеке — одно поле.
- **Формулы** — из ATTs-канона (0★→2★ = +60%, 2★→3★ = +66%), зафиксированы в GameNumbers.

### D6. Гейты зданий = поле `min_city_level` в buildings.json + проверка в CityBuildingService
- **Выбор:** каждое здание получает `min_city_level`; `UniqueBuilding.Def` добавляет поле; проверка в строительстве и в UI (серое + «нужен уровень N»).
- **Уровни города 1–11:** `CITY_LEVEL_MAX := 11`; пороги `ProsperitySystem.level_pop_req/level_buildings_req` уже параметричны по уровню — расширяем константы (краткие шаги), формулы не трогаем.
- **Расписание v1:** казармы 1, ферма/мельница 1, стрельбище 3, рынок/таверна 2–3, рудник/кузница 4–5, конюшня 6, библиотека 7, стены 7, школа/усадьба 8, храм/site 9–10, торговый пост II 10. Остальное — 1–4 по теме (еда ранняя).

### D7. Военный найм — новая ветка CityService + панель в CityScreen
- **Выбор:** `CityService.recruit_military(city, hero, unit_key)` — проверяет: герой в городе, здание-источник строено (mapping: barracks→melee-цепочка, range→ranged, library→mage-цепочка, stables→cavalry), ресурсы хранилища (стоимость = gold + ресурсы по тиру), army-кап (константа). Создаёт стек через `UnitRegistry.make_recruit_stack(key, tier)` в `HeroArmyController.army`.
- **Продвижения по уровню здания:** уровень здания выбирает юнит в цепочке (barracks L1→swordsmen, L2→pikemen, L3→halberdier; range L1→archers, L2→centaur, L3→elf; library L1→mages, L2→magus, L3→archmages; stables L1→cavalry, L2→lancer, L3→champions). Цепочки — константа в GameNumbers или buildings.json.
- **Почему не через существующий `recruit_followers`:** последователи — NPC с трейтами, другой контур (религиозно-бытовой), смешивать нельзя.

### D8. Кольца угрозы = дистанция от старта при генерации, не runtime-пересчёт
- **Выбор:** в `MapSpawner` при спавне врага: кольцо = `hex_distance(cell, start_cell)` против двух порогов (константы RING1_RADIUS/RING2_RADIUS). Пулы: `THREAT_ANIMALS = [wolves, gremlin]`, `THREAT_HUMANOIDS = [goblins, gnoll, lizardman, hobgoblin, orc, ogre]`, `THREAT_MONSTERS = [troll, minotaur, hydra, stone_golem, air_elemental, fire_elemental, red_dragon, ...]` (состав — константы, не 7 FACTION_SETS целиком).
- **Почему география, не время:** игрок выбирает, когда рисковать; время (враждебность) влияет на *размер* стаи, не тир — см. D9.
- **Старт:** точка старта героя = точка появления на карте (уже есть в MapGenerator как spawn-клетка героя — сверить при реализации).

### D9. Враждебность и сезоны — глобальный счётчик в WorldController
- **Выбор:** `hostility: int` растёт на +1 каждые N ходов (константа); размер стэка = базовый `randi_range(1, 3)` + `hostility // 10` (кап 6). Сезон: `SeasonSystem` (новый, RefCounted/static или компонент WorldController): cycle [Drizzle(×1.2), Clear(×1.0), Storm(×0.4)], по K ходов на сезон; множитель применяется в `EconomicTurnProcessor` (производство) и в усилении врагов при Буре (+1 юнит в стэк / статы +10% — выбор по калибровке, в v1: +1 юнит).
- **Почему не ATTs-время-в-минутах:** игра пошаговая; сезоны — по ходам.

### D10. Данные в JSON, логика статическая
- `assets/data/hero_classes.json` (новый): 6 классов.
- `assets/data/buildings.json`: +3 здания (range, library, stables), +`min_city_level` у всех, +`military_chain` у военных.
- `assets/data/races_classes.json`: не трогать (6 рас уже есть).
- Новые константы — в `GameNumbersWorld`/`GameNumbersCity`/`GameNumbersHero` (существующее разделение).

## Risks / Trade-offs

- [Бой «герой без армии» ломает инварианты BattleState (ожидалась не пустая сторона)] → геройский боец — флагом в существующей модели; e2e-тест соло-боя в `tests/mcp`; инварианты `BattleState` проверять через существующие тесты.
- [Старые сейвы без рюкзака/класса/тиров] → дефолты при десериализации: класс = Воин, рюкзак = {}, tier = 0; версия сейва бэкампается по существующей схеме `WorldStateSerializer`.
- [Соло-герой vs кольцо 1: волки могут убить одиночку] → это и есть первый баланс-вопрос; статы волков (4/10/6/1) против Воина калибруются в `balance-core`; в v1 друид/жрец страхуют.
- [Удаление автопула меняет экономику городов, завязанных на `resource_extracted` сигнал] → сигнал остаётся (UI/миникарта слушают), меняется только получатель.
- [CITY_LEVEL_MAX 5→11 ломает существующие тесты уровня] → тесты обновляются в рамках change; пороги 6–11 подбираются монотонно.
- [Пропуск: частичная выгрузка, случайные чертежи, 16 классов, население-расы] → сознательно (YAGNI), зафиксировано в Non-Goals/отложено.

## Migration Plan

1. Фазы коммитятся по capability (hero-identity → hero-logistics → city-tech-tree → world-threat-rings), каждая с тестами зелёной.
2. Ролбэк — `git revert` по коммитам фаз; сейв-совместимость вперёд не гарантируется (ранняя игра), назад — через дефолты D-решений.
3. E2E-проверка раннего цикла после 4-й фазы: MCP-сценарий «новая игра → сбор 3 узлов → выгрузка → казарма → найм мечника → бой с волком».

## Open Questions

- Точный состав `THREAT_MONSTERS` (полный список из ~90 юнитов отобрать по силе) — решается при реализации D8 по статам, не меняет spec.
- Цена найма и army-кап — числа для калибровки, не меняют spec.
- Видимость сезона в UI (ярлык в AdventureUI) — минимальный, форма при реализации.
