## Context

Движением героя управляет `HeroMovementController` (Dijkstra/A* pathfinding, float-ходы, стоимость местности):
- `_full_path(cell)` — полный путь без обрезки по ходам; для врага — до контактной клетки.
- `_get_affordable_path(cell)` — путь, обрезанный по `move_points`.
- `on_map_clicked(cell)` — 1-й клик: превью пути + `reach_preview_changed` (подсветка MarkerLayer); 2-й клик: подтверждение → `_start_moving()`.
- `_move_next_step` / `_on_step_complete` — пошаговое анимированное движение (tween); остановка при `move_points <= 0` или блокировке пути.
- Контакт с врагом: `_is_contact_position` → `hero_moved` → бой (WorldBattleCoordinator).

Старт нового хода: `HeroController.end_turn()` → `_reset_time_and_movement()` — сбрасывает `move_points` в дневной максимум и вызывает `end_turn_movement()` (сейчас очищает путь). Именно здесь начинается новый ход.

Подсветка: `MarkerLayer.show_markers(hero_cell, mp, dist_map)` — GREEN (остаток ≥ 1), YELLOW (остаток < 1), RED — фронталь непроходимой местности. Связка: `reach_preview_changed` → `WorldEventRouter._on_reach_preview_changed` → `WorldUIManager.show_reach_markers`.

В бою уже есть привычка игроку: «красная окрестность — ходов не хватает». Подсветка доступности на карте должна следовать той же логике.

## Goals / Non-Goals

**Goals:**
- Хранить запланированный маршрут (`planned_path`) между ходами.
- Автоходить по маршруту в начале хода (после сброса ходов), шагами до цели или исчерпания ходов.
- Подсвечивать клетки с нехваткой ходов красным, достижимые — зелёным/жёлтым.

**Non-Goals:**
- Изменение самого pathfinding/стоимости местности.
- Редактирование маршрута по точкам (waypoint-редактор) — только «проложить до цели и зафиксировать».
- Изменение логики боя/контакта.

## Decisions

**D1. Состоятельный 2-й клик.**
`on_map_clicked` (2-й клик) ведёт себя по состоянию:
- `planned_path` пуст → фиксация: сохраняем `_full_path(target)` (необрезанный) как `planned_path`, чтобы маршрут охватывал несколько ходов; герой не двигается сразу.
- `planned_path` не пуст → немедленное движение вперёд (`_start_moving()`, как сейчас).
`_get_affordable_path` остаётся для превью «здесь и сейчас».
*Альтернатива*: один режим клика — либо только фиксация, либо только движение (запрос требует обоих).

**D2. Автоход — из хука старта хода.**
В `HeroController._reset_time_and_movement()`, после сброса `move_points`, вызывать `movement.auto_follow_at_turn_start()`. Метод: если `planned_path.size() >= 2` и герой не в цели — `path = planned_path.duplicate()`, `_start_moving()`; в цели — очистить `planned_path`. `end_turn_movement()` перестаёт безоговорочно очищать путь, если есть зафиксированный маршрут.
*Альтернатива*: отдельная кнопка «идти по маршруту» — но запрос «автоматически в начале хода», поэтому триггер от старта хода.

**D3. Синхронизация остатка маршрута при остановке.**
В `_on_step_complete` (остановка по `move_points <= 0`) и при естественном завершении пути (`path` дошёл до цели) записывать остаток обратно в `planned_path` (`path` без головы = клетки вперёд). Цель достигнута → `planned_path` очищен.
*Альтернатива*: терять остаток при остановке — герой каждый ход шёл с нуля (против многоходовости).

**D4. Красный цвет — фронталь недостаточности ходов.**
В `MarkerLayer.show_markers` расширить красный: теперь красный = клетки-соседи достижимых, в которые нельзя попасть за текущий бюджет (непроходимы ИЛИ не хватает ходов). Зелёный/жёлтый — достижимые. Это повторяет боковую привычку «красная окрестность — ходов не хватает».
*Альтернатива*: оставить красный только за непроходимой местностью — тогда «не хватает ходов» визуально не показан (запрос не выполнен).

**D5. Деградация при исчезновении цели.**
Если по времени автохода цель стала недостижима (путь исчез / заблокирован), автоход останавливается штатно, `planned_path` сохраняется, новый ход не запускается, пока маршрут не перефиксирован. Падение запрещено.

## Risks / Trade-offs

- **[D2] Герой автоматически пойдёт в начале хода.** → Митигация: маршрут можно отменить (`cancel_pending`); автоход только если маршрут зафиксирован.
- **[D2/D3] Анимированное движение (tween) стартует внутри `end_turn()`.** → Митигация: tween асинхронен, запускается после логики хода; не менять порядок `end_turn()`.
- **[D4] Красным станет больше клеток (весь фронталь зоны).** → Митигация: красный рисует только кольцо границы доступности (как в бою), не всю дальнюю карту.
- **Save/Load.** → Митигация: `planned_path` включить в сериализацию героя (см. tasks).
- **[D5] Динамическая блокировка пути (враги/события) во время автохода.** → Митигация: `_move_next_step` уже останавливается при INF-клетке; D5 покрывает исчезновение цели.

## Migration Plan

1. Добавить `planned_path` и `auto_follow_at_turn_start()` в `HeroMovementController`.
2. Подписать `HeroController._reset_time_and_movement()` на автоход; pass-through для фиксации/отмены.
3. Изменить `MarkerLayer.show_markers` (красный-фронталь) — проверить, что зелёный/жёлтый не изменились.
4. Включить `planned_path` в сериализацию героя.
5. Верификация `game/tools/shell/run_operability.sh` → `CLEAN`.
6. Откат: отменить коммит цикла; маршрут опционален, ломать существующее движение (боты `move_to_cell`) не меняем.

- **Старт автохода:** в начале хода (по спецификации); немедленное движение — отдельным 2-м кликом при зафиксированном маршруте (см. D1). Открытый вопрос снят.
- **Порог зелёный/жёлтый:** сохранить существующий (остаток ≥ 1.0 → зелёный)? (Дефолт — сохранить.)
