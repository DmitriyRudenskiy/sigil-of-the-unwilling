# Design: Аудит документации и тестов

## Context

См. proposal.md — мотивация. Ограничивающий контекст:

- `docs/` — 41 `.md` в 7 областных папках + `docs/README.md` (индекс) и
  `docs/CONSOLE_ALLOWLIST.md`; main-спек `documentation` требует, чтобы индекс
  мапсил **каждый** документ и не было dangling-ссылок.
- `game/tests/` — 80 `.gd`: раннер `run_tests.gd` (рекурсивный подбор `test_*.gd`,
  явный skip-список, теги, `--list`-режим), `test_base.gd`, `debug_load.gd`,
  папка `fakes/`.
- CI — 5 шагов: `compile_all`, `check_scene_refs`, `spell_validation`,
  `check_tileset`, `unit_tests` (`game/tools/shell/run_all_ci_checks.sh`).
- Main-спеки — только `audio` и `documentation`; 16 активных changes с delta-
  спеками (покрытия системами в спеках нет — это часть картины покрытия).
- Рабочее дерево dirty: 418 unstaged-удалений (WIP пользователя) и untracked
  WIP-файлы. `timeout` в macOS недоступен — Godot-запуски через фоновый процесс +
  `sleep`/`kill`.

## Goals / Non-Goals

**Goals:**
- Верифицируемый отчёт: каждый finding воспроизводим (файл:строка / команда)
- Полнота: покрыты и ссылки, и покрытие, и структура (см. D4)
- Аудит не меняет поведение проекта — только новый отчёт + запись в индексе

**Non-Goals:**
- исправление найденного (следующий change), дописание тестов, переписывание доков
- семантическая рецензия всего содержания всех 41 файлов (только спот-чек по
  ключевым системам — D2)
- аудит untracked WIP-файлов (не в дереве, не в индексах)

## Decisions

**D1. Отчёт живёт в `docs/misc/audit-docs-tests-2026-08-31.md`.**
Main-спек `documentation` требует индексации каждого документа; отчёт внутри
`docs/` остаётся открытым после архивации change. Альтернативы: (а) только в
каталоге change — утонет в `archive/`; (б) в корне — ломает организацию по
областям. `misc/` — существующая область для отчётов/вспомогательных документов.
Обязательная сторона: запись в `docs/README.md` (иначе сам же специк нарушается).

**D2. Метод: статический анализ + два контролируемых read-only Godot-запуска.**
- Ссылки: извлечение md-ссылок, `res://`-путей и текстовых путей к файлам из
  доков → резолв против **рабочего дерева**; классы/autoload — из
  `class_name` в `game/scripts/`, `[autoload]` и `project.godot`.
- `run_tests.gd --list` headless — фактический набор тестов, которые раннер
  подбирает; diff против `*.gd` на диске → «осиротевшие» файлы.
- Качество: эвристики (тест-метод без assert, `assert(true)`, print-only,
  `await`/таймеры во flaky-кандидатах).
- Спот-чек содержания: turn pipeline, battle, city/economy, magic, world —
  сверка описания с фактическим кодом по 3–5 фактам на систему.
- Все скрипты-помощники — в `tmp/` (gitignored), не коммитятся.

**D3. Базовая точка аудита — рабочее дерево, а не HEAD.**
418 удалений — намеренный WIP: само удаление не является finding'ом. Но документ,
ссылающийся на файл, отсутствующий на диске, — finding «стale reference»
(цель ссылки мёртва для читателя и для агента). Untracked WIP вне аудита.
Метаданные отчёта фиксируют снимок `git status` на момент аудита.

**D4. Структура отчёта и приоритизация P0–P2.**
Разделы: резюме → документация (ссылки, индекс, покрытие системами,
противоречия) → тесты (матрица покрытия, осиротевшие, качество, CI) → таблица
findings (ID `F-<n>`, приоритет, область, finding с файлом:строкой, рекомендация)
→ приложение (методология, сырые данные сканов).
Критерии приоритета:
- **P0** — ломает onboarding/CI: битые `res://`/файловые ссылки в доках, тесты,
  которые раннер не подбирает, полное отсутствие покрытия у критичных систем
  (save/load, battle state, turn pipeline)
- **P1** — stale-содержимое, дыры индекса, слабые ассерты, flaky-тесты
- **P2** — дубли, противоречия по формулировкам, nice-to-have
Каждый finding вручную подтверждён перед попаданием в отчёт (эвристики дают
кандидатов, не вердикты).

**D5. Частичное исключение из «только отчёт»:** единственная правка существующего
файла — индексная запись `docs/README.md` (необходима для консистентности
main-спека `documentation`). Все остальные правки доков/тестов — за рамками.

## Risks / Trade-offs

- [Статика не видит семантическую устарелость] → отчёт честно ограничивает
  scope: ссылки/покрытие/структура + спот-чек 5 систем (D2); остаток помечен
  «не проверено семантически».
- [`run_tests.gd --list` сам сломан/неполон] → фолбэк: ручной перечисление
  `test_*` + сравнение с CI-логом; расхождение между декларацией и фактом —
  отдельный finding.
- [Рабочее дерево изменится во время аудита (WIP пользователя)] → снимок
  `git status` в метаданных отчёта; findings привязаны к этому снимку.
- [Ложные срабатывания эвристик засорят отчёт] → каждое finding подтверждено
  вручную (D4); сырые сканы — только в приложении.
- [Godot-запуск мутирует `.godot`-кэш] → запуски read-only (`--list`,
  compile-check); кэш gitignored, не влияет на дерево.

## Migration Plan

Отката не требуется: отчёт — новый файл, индекс — одна запись. Откат = удаление
объектов. Повторный запуск аудита в будущем — новый change с новым отчётом
(имя с датой), старый отчёт остаётся как срез истории.
