# Design

## Context

`campaign_training_service.gd` реализует: `available_training_actions` (действия из `campaign_building_catalog.json` — поле `training` зданий), class-gates (`_approved_class` по `mvp_catalog.json`), расовые тиры, PARTY_CAPACITY = 5, валидация стоимости по `ResourceRegistry.CAMPAIGN_MVP_IDS`. Q-M55→(б)/D-189 канонизировали тренировку (пометка «механика TBD» снята). Не реализованы: SM рекрута (PAUSED/STANDING), резидентная модель K-A5, паузы при разрыве сети. Данные расходятся с GDD (C-12, C-13).

## Goals / Non-Goals

**Goals:** формализовать канон §3.3; SM рекрута с паузами (пауза ≠ отмена); резидентная модель статусов (K-A5); синк данных (C-12/C-13) — документ ведёт код, но K-R2-реестр (3 ресурса) — канон для стоимости.

**Non-Goals:** наём (Q18: попутчики тренируются, не нанимаются), резерв STANDING как пост (Post-MVP), «петля мастерства/профессии» (1.0), статы волшебника (T-041 — баланс-конфиг Ф4).

## Decisions

- **SM рекрута на экземпляре, не на здании**: рекрут = {building_uid, class_id, progress, state}; пауза = проверка сети здания каждый тик (building destroyed/sold → PAUSED; rebuilt → TRAINING, таймер сохраняется). Пауза ≠ отмена: стоимость не возвращается, прогресс не сбрасывается.
- **STANDING в MVP = Post-MVP**: пул = партия (Y1), партия ≤5; при полной партии рекрут не создаётся (UI: «что освободит слот»). Пост STANDING — 1.0 (резерв юнитов).
- **Резидентная модель K-A5**: один житель = один статус (Child/Worker/Mentor/Recruit/Fighter/Hero/Party-in-field); призыв = вакансия (производство роли останавливается до заполнения); население — непрерывная величина (K-M12: min(жильё, floor(прод/сутки / k_pop))). Реализация — в `population_system.gd` (T-040).
- **Данные позиций**: код = источник для стоимости (K-R2: 3 ресурса food/wood/iron; оружие = товар Layer-2, не ресурс — C-12). GDD-таблица «10 оружия» — устаревшая (не синхронизирована с K-R2). Волшебник (третий базовый боец K-M15) — T-041: статы в баланс-конфиге Ф4; до этого training-действие wizard не генерируется.
- **Маска классов тренировки**: GDD = 6 (fighter/ranger/cleric/wizard/rogue/paladin), код = 3 (fighter/ranger/cleric) — C-13; до Ф4 код остаётся 3, маска 6 — требование для 1.0-синка.
- **Порог населения 10 на юнит** — [ПРЕДЛОЖЕНИЕ] (ждёт автора); в MVP — конфиг с пометкой.

## Risks / Trade-offs

- [C-12/C-13: расхождение GDD vs код по данным] → документ ведёт код (T-127-принцип), но K-R2-реестр — канон: оружие из стоимости исключено; синк GDD-таблицы — docs-задача.
- [T-041: статы волшебника не заданы] → wizard-тренировка не генерируется до Ф4; базовые 3 в MVP фактически = fighter/ranger/cleric (код) — расхождение с K-M15 (fighter/ranger/wizard) зафиксировано.
- [Порог 10 на юнит — предложение] → не канон; конфиг с пометкой [ПРЕДЛОЖЕНИЕ], вердикт автора.
- [Паузы усложняют сейв] → рекрут-экземпляр сериализуется целиком (building_uid, class_id, progress, state); миграция fail-fast.
