## ADDED Requirements

### Requirement: Логика цикла героя тестируется изолированно
Логика HeroLifecycleSystem (смерть, выбор преемника, перерождение, воскрешение,
запись в летопись, освобождение трупа) SHALL покрываться тестами, которые
НЕ инстанцируют WorldController (headless, система + duck-стабы + реальный
Node2D-корень).

#### Scenario: Смерть с преемником
- **WHEN** в изолированном тесте эмитится hero_died у героя с годным преемником
- **THEN** pending-преемник выставлен, DeathSequence открыт, труп освобождён (если нет города воскрешения)

#### Scenario: Перерождение
- **WHEN** в изолированном тесте выбран «Знак переходит»
- **THEN** преемник установлен как активный герой, hero_successor эмитирован, в Chronicle запись outcome "succession"

#### Scenario: Смерть без преемника
- **WHEN** hero_died у героя без годного преемника
- **THEN** труп освобождён, запись в летопись не создаётся

#### Scenario: Терминальная сессия
- **WHEN** session.is_terminal() == true и герой умирает
- **THEN** преемник не выбирается, показывается только последовательность смерти

#### Scenario: Воскрешение
- **WHEN** игрок выбирает «Воскресить» при наличии города с великим храмом
- **THEN** герой воскрешён (revive_at, resurrected_once), pending-преемник освобождён, hero_successor не эмитирован

### Requirement: Дисциплина стабов
Тесты подсистем SHALL использовать duck-стабы, реализующие только члены, к
которым система обращается; стабы SHALL храниться в tests/ без class_name
(preload-константы). Тест, которому понадобился живой WorldController, —
нарушение: либо сценарий переносится в L3-тест связки (один файл), либо
исправляется шов.

#### Scenario: Стаб ловит расхождение
- **WHEN** система начинает обращаться к члену, отсутствующему в стабе
- **THEN** L2-тест падает (Invalid get/set)

#### Scenario: Живой мир — один тест
- **WHEN** проверяется связка с реальными подсистемами
- **THEN** используется test_worldcontroller_succession_wiring.gd (единственный
  тест с реальным WorldController)

### Requirement: Headless-ловушки задокументированы
docs/howto/TESTING.md SHALL описывать: пирамиду L1–L4, правила дисциплины
стабов, headless-особенности (явный `_ready()` для отсоединённых узлов,
`_ready` не fires при синхронном add_child в headless, авто-имена runtime-узлов
Godot 4.7).

#### Scenario: Новый тест по документации
- **WHEN** разработчик пишет новый тест подсистемы по TESTING.md
- **THEN** он получает рабочий headless-паттерн без проб и ошибок
