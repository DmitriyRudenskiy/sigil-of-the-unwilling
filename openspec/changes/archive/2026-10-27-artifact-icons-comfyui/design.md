## Context

Вид иконки артефакта сегодня определяется **слотом**: `gen_artifact_icons.gd`
рисует форму по `art.slot`, отсюда 12 групп md5-дублей (23 id) и 6 id без файла
вовсе. Загрузчик — `artifact_inventory_screen.gd:417`, `res://assets/artifacts/%s.png`
по id; маппинга нет и не будет. Бюджет класса — 64×64, PNG-32, ≤ 6 КБ
([[13-art-bible]] §8.2); вес существующих процедурных файлов 0.3–1.8 КБ, то есть
бюджет выставлен по им, и AI-растр в него не влезает без квантования.

Спеки: `docs/15` §2 (29 строк «субъект + акцентный цвет»), §3 (контакт-лист),
§5 (гейт по данным пройден). Префикс-промпт — [[13-art-bible]] §«Префикс-промпт».
Внешняя зависимость — ComfyUI, эндпоинт отдаёт владелец. Мотивация — proposal.md.

## Goals / Non-Goals

**Goals:**
- 29 уникальных иконок, проходящих машинный гейт, и контакт-лист всего сета.
- Конвейер повторяемый и детерминированный по id (перегенерить один id, не весь сет).
- Этапы, не зависящие от ComfyUI, готовы и проверены **до** появления эндпоинта.

**Non-Goals:**
- Рамки тира в пикселях (это тема ячейки), UI-обвязка инвентаря, правки кода игры.
- Иконки вне 29-ки (в т.ч. 31 живая — только в контакт-листе, не перегенерация).
- Замена процедурных генераторов других классов (ресурсы/здания/школы).
- Автоматический приём результата человеком — ревью всегда владелец.

## Decisions

**1. Четыре стадии, ComfyUI изолирован в одной.**
`manifest → generate (адаптер) → postprocess+gate → contact-sheet`.
Стадии 1, 3, 4 исполняются локально и без сети; адаптер — единственный файл,
знающий про эндпоинт. Причина: генерация заблокирована внешним ресурсом, а
проверка бюджета/формата/уникальности и контакт-лист нужны независимо и
проверяемы уже сейчас. Альтернатива «один скрипт end-to-end» — блокировала бы
всё локально проверяемое доменом владельца.

**2. Вызов ComfyUI через HTTP API (`POST /prompt`, опрос `/history/<id>`,
забор `/view`), эндпоинт и токен — только из окружения.**
Альтернативы: WebSocket-прогресс (не нужен, жмём батч реджект-файлом),
`comfy-cli`/локальный запуск сервера (чужая машина/модели — не наш ресурс),
ручной прогон воркфлоу в UI (оставлен **деградированным режимом**: тот же
postprocess читает каталог PNG, который выложил владелец, — путь от этого не
меняется).

**3. Фон иконки — непрозрачный `#281c0f`, маттинга нет.**
Конфликт входных данных: `docs/15` §2 требует «PNG-32 с альфой», а канон
иконки артефакта [[13-art-bible]] §8.3 — «тёмный фон `#281c0f`, гравюрный
силуэт по центру»; generic-префикс «transparent background» написан для всех
ассетов сразу. Берём §8.3 как частный канон класса: SD-модель альфу не отдаёт,
значит «с альфой» означало бы маттинг (birefnet/rembg) — отдельный источник
артефактов на 64 px (ореолы, съеденные края). Плюс контакт-лист и контраст-режим
§4.5 смотрятся только на тайле `#281c0f`, то есть фон и так ожидаемый. Формат
остаётся PNG-32 (RGBA), альфа канал есть и он непрозрачен — бюджет не режет.
Альтернатива, если владелец настоя на прозрачности: matting-нода в его же
воркфлоу, наш постпроцесс не меняется.

**4. Постобработка: Python + PIL (уже установлен), новых зависимостей нет.**
Каскад: area-downscale 1024→256→64 (один шаг `LANCZOS` на сильном уменьшении
алиасит) → квантование к палитре библии (`#281c0f`, `#8a6a3a`/`#9e7738`,
`#7a100c`, `#e8d5a8` + промежуточные ступени) → `PNG optimize`. Причина
квантования: бюджет 6 КБ задан по процедурным файлам 0.3–1.8 КБ, сырой AI-растр
64×64 RGBA весит 8–20 КБ. Альтернатива `pngquant` — точнее, но его нет в
окружении; если квантование PIL не уложит в бюджет, добавляем его одним шагом.

**5. Манифест `game/tools/icons/manifest.json` — единственный источник списка.**
29 записей `{id, subject, accent, rarity}`; переносится из `docs/15` §2 руками
один раз. Парсить markdown-таблицу гейтом — отказ: хрупко, таблица человекочитаема
и меняется чаще кода. Вместо этого гейт сверяет множества: `manifest ⊆ registry`,
все id уникальны, файлов набора ровно 29.

**6. Затравка детерминизма — FNV-1a от id**, та же конвенция, что
`ScenarioTargets.seed_for` в MCP-тестах. Перегенерация одного id воспроизводима,
дрейф стиля между прогонами гасится, а не лечится пересъёмкой всего сета.

**7. Размещение: `game/tools/icons/` (Python), результат — в `out/`, он в gitignore.**
В `game/assets/artifacts/` файлы попадают только PR интеграции (спек-требование).
Генерационная обвязка в PR интеграции не едет.

**8. Гейт `check_icons.py` — шесть проверок, падение по первой же:**
канвас 64×64; PNG RGBA; вес ≤ 6144 Б; md5 уникален внутри сета; id манифеста
живут в `artifact_registry`; **нет ни одного достижимого id реестра без файла**
(обе вселенные — урок, легший в `asset-audit` SKILL.md Phase 3).

## Risks / Trade-offs

- **AI-растр не влезает в 6 КБ даже после квантования** → ступени: палитра 32→16
  цветов → постеризация → pngquant. Если и это мимо — бюджет пересматривает
  владелец, мы не «тихо» кладём 12 КБ: гейт красный, решение оформлено.
- **Стиль разъезжается по 29 прогонам** → фиксированная затравка на id, один
  префикс, приём только по контакт-листу, перегенерация точечная (одного id).
- **Форма воркфлоу/аутентификация ComfyUI неизвестны до выдачи эндпоинта** →
  изолировано в адаптере; есть деградированный режим «владелец прогнал — мы
  читаем каталог». Ни спецификация, ни разбивка задач от этого не меняются.
- **Гравюра на 64 px превращается в кашу** → контакт-лист 1× и 2×; если каша —
  это находка ревью до выкладки, а не после.
- **Регресс веса у 31 живой иконки** → контакт-лист их тоже содержит, гейт
  прогоняется по всему каталогу, а не только по новинкам.

## Migration Plan

1. Стадии 1/3/4 + гейт — локально, зелёные на пустом `out/` и красные на
   заведомо бракованном файле (проверка самого гейта).
2. Выдача эндпоинта → прогон 29 (или деградированный режим) → `out/` + контакт-лист.
3. Ревью владельца по контакт-листу → точечные перегенерации.
4. PR интеграции: 29 файлов одним коммитом → `--import` → смок
   `artifact_inventory_screen` + GdUnit-сета артефактов → полный `run_tests.sh` локально.
5. После мержа — перегенерация реестра аудита (`docs/12` остаётся snapshot).

Откат: PR интеграции — один revert-коммит (данные, кода не касается);
генерационная обвязка в `game/tools/icons/` безвредна и может остаться.

## Open Questions

- Точное воркфлоу/чекпойнт/сэмплер ComfyUI — решаются в момент выдачи эндпоинта,
  вне пределов адаптера на них ничего не завязано.
- Судьба 23 вытесненных плейсхолдеров (удалять или оставить до полного сета) —
  `docs/15` §4 отвечает «до полного сета»; пересмотра не требуется.
