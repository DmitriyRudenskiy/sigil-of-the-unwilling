# Proposal: Dynamic World & Crisis System (RimWorld/Frostpunk Style)

## Overview
Внедрение системы динамических событий и кризисов для создания бесконечного, глубокого геймплея.
- **Из RimWorld**: Процедурная генерация историй, долгосрочные тренды, уникальные характеристики городов.
- **Из Frostpunk**: Система дилемм с серьезными последствиями, невозможность игнорировать критические события, моральный выбор.

## Goals
1. Создать бесконечный цикл игры через генерацию новых вызовов.
2. Заставить игрока принимать сложные решения (нельзя просто нажать "Пропустить ход" в кризис).
3. Ввести систему "Законов/Постановлений" (как в Frostpunk) для долгосрочного развития.
4. Реализовать систему репутации и недовольства населения как реакцию на выборы.

## Goals (Non-Functional)
- События должны быть разнообразными и непредсказуемыми.
- Решения должны иметь долгосрочные последствия.
- Система должна масштабироваться с ростом города.

## Scope
- `game/scripts/systems/event_manager.gd`: Ядро системы событий.
- `game/scripts/systems/crisis_manager.gd`: Логика кризисов и блокировки хода.
- `game/scripts/data/event_database.gd`: База данных событий и сценариев.
- `game/ui/dialogs/event_dialog.tscn` + `.gd`: UI для выбора решений.
- Интеграция с системой сохранения (сохранение истории событий).

## Technical Approach
- **State Machine**: События имеют состояния (Active, Resolved, Failed).
- **Weighted Random**: Выбор событий зависит от контекста (ресурсы, сезон, репутация).
- **Blocking Input**: В режиме кризиса ввод игрока ограничивается только окном выбора.
- **Data-Driven**: События описываются в JSON/Resource файлах для легкого добавления нового контента.

## Acceptance Criteria
- [ ] При наступлении кризиса кнопка "Конец хода" блокируется.
- [ ] Игрок обязан выбрать один из вариантов решения.
- [ ] Выбор влияет на минимум 2 параметра города (ресурсы, население, закон).
- [ ] События генерируются бесконечно, усложняясь со временем.
- [ ] История событий сохраняется и может быть просмотрена.

## Risks
- Слишком частые события могут утомить игрока.
- Баланс последствий должен быть тщательно настроен.
- Сложность реализации системы сохранения истории.
