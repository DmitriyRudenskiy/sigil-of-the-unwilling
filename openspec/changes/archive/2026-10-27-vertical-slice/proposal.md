# Proposal

## Why

MVP (MVP-scope) — proof-of-fun: серый прототип, 21 ход, ~3 сессии; цель — доказать, что цикл `увидел → двинул → решил → построил → снабдил → пережил рейд` (01-core-loop) fun to play. Вертикальный срез = интеграция всех механик в играбельную 21-ходовую кампанию: предыгра → 21 ход (бит-скрипт 1/7/14/17/21) → финал. Интеграция не реализована: `main.gd` минимальный (без tutorial/3-day goals/бит-скрипта), регион-граф отсутствует (region-graph-map), SM навигации отсутствует (mvp-ui-flow).

## What Changes

- Фиксирует вертикальный срез: играбельная 21-ходовая кампания (proof-of-fun, серый прототип, ~3 сессии).
- Фиксирует бит-скрипт 21 хода: каркас в MVP (ходы 1/7/14/17/21); ход 3 «слух» — строка той же бит-схемы с пометкой Post-MVP (K-M9); угрозовые строки — только директивы (K-R3).
- Фиксирует арки: 1–6 выживание → 7–13 железо, первый рейд (ход 7) → 14–20 районы и пережившие (K-M10: «Ветеран» — статус пережившего бойца, Q-M56→(а), D-189) → ход 21 крупный рейд-проверка.
- Фиксирует метрики валидации core loop (01-core-loop): TTFD ≤ 30 с, action rate 8–15/5 мин, доля решений ≥ 60%, закрытость цикла ≥ 70%, aha-момент ≤ 10 мин, сессия 35–50 мин, D1 35%+, D7 15%+.
- Фиксирует fail-states цикла (01-core-loop): голод партии (1 еда/персонаж/переход, ёмкость 10 еды; Q-M70→(а), Q-M75→(б)), гибель всей партии = единственный конец кампании (Q-M68→(а), D-190).
- Фиксирует: 1 ход = 1 сезон = 20 дней (Q-M26); кампания = 21 ход = 420 дней; тик — деление дня (1 день = 4 тика [ПРЕДЛОЖЕНИЕ Q6] ⇒ 80 тиков/ход), игроку не виден.
