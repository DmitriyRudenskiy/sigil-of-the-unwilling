# Design: autopilot-scenario-matrix

## Context

- `BalanceProbe` (`scripts/probe/BalanceProbe.gd`) — существующий
  автопайлот: 60 ходов, "выживи и развивайся" (добыча, постройка,
  найм, бои), детерминированный seed, JSON-отчёт. Паттерн: `start_probe`,
  `_step()` на ход, `_fail`/`_finish`, `_snapshot`.
- MCP-сервер (порт 9090) — headless-управление Godot из pytest
  (`tests/mcp/conftest.py`: fixtures `mcp`, `full_game`, `full_cycle`).
- `AutoBalancer` (`scripts/balance/auto_balancer.gd`) — симуляции +
  корректировки (ранняя игра); здесь — потребитель отчёта матрицы.
- 11 классов: `hero_classes.gd` (barbarian, fighter, monk, paladin,
  priest, druid, cipher, wizard, ranger, rogue, chanter).
- Города: `City`/`CityFactory` (город-точка); поселения
  (`settlement-system`) — отдельный change, может не быть готов.
- Баланс-рамка: balance-core — герой доживает 60 ходов, endgame
  RUNNING; MCP-проба детерминирована.

## Goals / Non-Goals

**Goals:**
- 5 ролевых политик автопайлота (собиратель, путешественник,
  городостроитель, торговец, приключенец) с целью и метрикой.
- Драйвер 5×11 = 55 детерминированных прогонов (headless, MCP).
- JSON-отчёт: метрики на клетку, аномалии (weak/strong),
  versatile/specialist.
- Отчёт — машиночитаемый вход для AutoBalancer.

**Non-Goals:**
- Авто-подкрутка (AutoBalancer применяет — существующее).
- 11×11 боев классов друг с другом.
- Визуализация (JSON + консоль).
- Мультиплеер/сетевые прогоны.

## Decisions

### D1: Роли — политики над общим автопайлотом (паттерн BalanceProbe)

`ScenarioPilot` — базовый пайлот (движение, добыча, бой, поворот
ходов — переиспользует логику BalanceProbe); каждая роль — класс-
политика с `pick_action(state) -> action` и `goal_met(state) -> bool`
+ `metrics(state) -> Dictionary`.

- **Почему:** BalanceProbe уже доказал паттерн (детерминизм, seed,
  JSON); роли — только политика выбора действия, не новый движок.
- **Альтернатива:** 5 отдельных пайлотов — отклонено: дублирование
  базовых действий (движение/бой/добыча).

### D2: Прогон сценария — новый Godot-процесс на сценарий

Каждый из 55 прогонов — отдельный headless-запуск Godot (MCP), как в
`conftest.py` (`full_game` fixture). Матрица — pytest-тест, который
циклом поднимает/роняет Godot.

- **Почему:** изоляция состояния (герой/мир не перетекают между
  сценариями), детерминизм, параллельность в будущем.
- **Альтернатива:** один процесс, reset между сценариями — отклонено:
  `session_reset` не гарантирует чистоты (остатки тумана/событий).

### D3: Метрики — в данных сценария, пороги — в конфиге

Цели ролей (X ресурсов, Y дней, A→B, X золота, население/защита) —
`scripts/data/scenario_targets.gd` (const-таблица). Пороги аномалий
(N% weak/strong, M% specialist) — конфиг (`GameSettings`/json), не
хардкод.

- **Почему:** балансировка = правка чисел, не кода.
- **Альтернатива:** пороги в коде — отклонено: каждый ребаланс —
  перекомпиляция логики.

### D4: City fallback — канонический матричный сценарий Городостроителя

Роль Городостроитель в основной матрице работает через City в настоящем
world-сценарии вместе с героем и общими ресурсами. Settlement остаётся отдельной
архивированной симуляцией: без адаптера к world/hero/shared-ledger она не
считается готовой заменой матричной интеграции. При необходимости её можно
проверять отдельным вне-матричным профилем; подключение к миру потребует
отдельного адаптера/change.

- **Почему:** матрица проверяет поведение роли в игровом контексте, а не только
  автономную модель; низкие 3/11 — достоверный сигнал для дальнейшего баланса.
- **Альтернатива:** считать standalone Settlement успешной интеграцией —
  отклонено, так как это потеряло бы связь с миром, героем и общими правилами.

### D5: CI — выборка, полная матрица — маркер `slow`

По умолчанию (CI) — 1 роль × 3 класса (выборка: representative
class per role) = ~5–15 прогонов; полная 55 — маркер
`pytest -m matrix` (локально/ночью).

- **Почему:** 55 headless-прогонов × ~минута = долго; CI не может
  ждать. Выборка ловит регрессии, полная матрица — глубинный баланс.
- **Альтернатива:** всегда 55 — отклонено: CI-таймаут.

### D6: Отчёт — JSON + консольная таблица, файл в tmp

`tests/mcp/reports/scenario_matrix_<timestamp>.json` + вывод
5×11 таблицы в stdout. AutoBalancer читает JSON (путь — аргумент).

- **Почему:** JSON — машиночитаемый вход; таблица — человек
  видит аномалии сразу.
- **Альтернатива:** HTML-дашборд — отклонено (non-goal).

## Risks / Trade-offs

- **55 прогонов — долго** (D2/D5): митигировано выборкой в CI;
  параллельные процессы — upgrade path (но детерминизм seed
  сохраняется).
- **Автопайлот ≠ человек**: пайлот играет "по политике", не
  оптимально; баланс, найденный пайлотом, — нижняя граница
  (если пайлоту плохо — игроку точно плохо). Принято.
- **Цели ролей требуют проверки на механиках**: цели Собирателя,
  Путешественника и City-Городостроителя откалиброваны по 55-клеточной
  baseline; Торговец и Приключенец остаются нерешёнными из-за 0 сделок и 0
  убийств соответственно.
- **Зависимость от MCP-стабильности**: MCP уже держит 27 тестов;
  матрица — тот же канал, новый риск минимален.

## Migration Plan

1. Фаза 1: `ScenarioPilot` (базовый) + 1 роль (Собиратель) + 3
   класса — прогон, отчёт.
2. Фаза 2: остальные 4 роли (Путешественник, Торговец,
   Приключенец, Городостроитель-дефолт City).
3. Фаза 3: драйвер матрицы (55/выборка), JSON-отчёт, пороги.
4. Фаза 4: баланс-отчёт (weak/strong/versatile/specialist), вход
   для AutoBalancer.
5. Фаза 5: калибровка целей по первому полному прогону;
   Городостроитель на settlement (если готов).

## Baseline calibration (2026-10-08)

Полный детерминированный прогон 55/55 завершился без технических ошибок;
отчёт: `tests/mcp/reports/scenario_matrix_20261008T052706Z.json`.

- **Собиратель:** `rare_goal` 20 → 10. Медиана добычи — 5; 5/11 классов
  достигли 10, против 3/11 при цели 20.
- **Путешественник:** дистанция 25 оставлена; цель биомов 3 → 2. В baseline
  6/11 дошли A→B, все 6 прибывших прошли не менее 2 distinct биомов. Успех
  требует прибытия и минимального числа биомов.
- **Городостроитель (City fallback):** население 30 → 8 (максимум в baseline
  10; два класса достигли 8 при уровне 2), цель зданий для нормированной метрики
  4 → 2 (медиана 2). Цель требует population + city level.
- **Торговец:** gold 1000 оставлен: все 11 прогонов дали 0 сделок (медиана
  капитала 64); снижать планку сейчас означало бы принять неторговый доход за
  торговлю. Сначала нужен ремонт торговой политики/потока.
- **Приключенец:** 5 убийств оставлено: все 11 прогонов дали 0 убийств; сначала
  требуется исправление/проверка боевой политики, а не снижение цели до нуля.

## Matrix after calibration (2026-10-08)

Повторный полный прогон: 55/55 клеток, 0 технических ошибок;
`tests/mcp/reports/scenario_matrix_20261008T061949Z.json`.
Медианные scores: collector 60, traveler 100, trader 7.76, adventurer 0,
builder 50. Цели достигнуты: collector 5/11 (rare ≥ 10), traveler 6/11
(arrival + ≥ 2 biomes), trader 0/11, adventurer 0/11, builder 3/11
(population ≥ 8 + city level ≥ 2). У Торговца по-прежнему 0 сделок;
у Приключенца — 0 убийств; у Городостроителя медиана населения 3.

## Open Questions

- Settlement для Городостроителя остаётся возможным дополнительным
  вне-матричным профилем; если понадобится связь с миром и героем, сделать её
  отдельным адаптером/change, не заменяя City-критерий основной матрицы.
- Торговец: исправление торговой политики/потока до калибровки цели золота.
- Приключенец: выяснить причину 0 убийств до калибровки kill_goal.

## Regression 5.4 (2026-10-08)

- GdUnit4: 2291 тест, 0 ошибок / падений; exit 101 только из-за 173
  orphan-предупреждений (разрешённая политика проекта).
- MCP: 55 passed, 1 skipped, 1 deselected; дополнительная opt-in матрица
  прошла 55/55 с 0 ошибками.
- 60-ходовая проба seed `20260913` завершилась на ходу 47 смертью героя и
  0 добытых ресурсов; оба результата записаны как баланс-предупреждения, а не
  технические ошибки. Это не подтверждает достижение survival-цели RUNNING.
