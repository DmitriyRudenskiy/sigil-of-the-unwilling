## Context

Шаг 4 (коммит `098631b8`) перевёл стартовый экран на сгенерированную
виджет-графику: `game/tools/build_ui_kit.py` рисует 9-слотные тайлинги и
пилюли полос, `game/scripts/ui/ui_kit.gd` собирает из них Theme,
`game/scripts/ui/ui_style.gd` чинит масштабирование. Экран боя тогда был только
перекрашен steel-комплектом; макет 11 требует другого материала (тёмная
бронза/золото) и других форм (карточки, слоты очереди, круглые медальоны).

Инвентарь по макету снят попиксельно и зафиксирован в `inventory-mockup-11.md`
(палитра, геометрия, слоты→действия, разрывы макет↔модель). Дизайн ниже —
реализация этого инвентаря.

## Goals / Non-Goals

**Goals:**
- Боевой HUD состоит из узлов, соответствующих макету 11: две карточки юнитов,
  лента очереди хода, нижняя панель медальонов, кольцо таймера.
- Геометрия и палитра — из инвентаря (логические пиксели 1920×1080).
- Узлы управляются данными: карточка показывает активного юнита, лента —
  `turn_queue`, медальоны — существующие сигналы.
- Отсутствие данных = узел не рендерится (заглушек-чисел нет).

**Non-Goals:**
- Боевые правила (ход, урон, фланги, таймер хода как механика).
- Портреты юнитов: используются существующие `assets/units/*.png`; рисовать
  новые портреты не входит.
- Анимации ленты очереди (сдвиг при ходе) — статичное состояние.
- Иконы фракций/заклинаний макета — используются существующие иконки ресурсов,
  новые не рисуются.

## Decisions

### D1 — Медальоны и бронзовые плиты рисует `build_ui_kit.py`, второй палитрой

**Выбор:** генератор получает палитру параметром; кроме стального комплекта
экрана старта выпускается боевой бронзовый (`battle_plate_*`, `battle_pill_*`,
`medallion_*`, `queue_slot_*`) по меркам из инвентаря.
**Альтернатива:** одна стальная палитра на все экраны — отклонено: спека
требует соответствия макету того экрана, где виджет применяется; макет 11
бронзовый.
**Альтернатива:** нарисовать PNG в редакторе — отклонено: тот же источник
истины, что у шага 4, изменения дёшевы.

### D2 — Карточки юнита: две, активный слева, зеркальная плита справа

**Выбор:** `unit_card_left` = `BattleState.active_unit`; `unit_card_right` =
текущая цель (наведение/выбор), при отсутствии цели — не видна. Состав:
портрет (`assets/units/<id>.png`), имя, пилюля HP с числом, пилюля маны с
числом.
**Альтернатива:** одна карточка — отклонено: макет рисует две.
**Альтернатива:** правая карточка = герой — отклонено: у героя нет портрета
юнита и стекового HP, а макет показывает стек (`11985/11995`).

### D3 — Полоса маны = пул маны героя стороны, не «маны юнита»

У юнита маны нет (`HeroMagic.mana_current/mana_max` — ресурс героя). Полоса
показывает пул стороны активного юнита и подписана как мана героя.
**Альтернатива:** не рисовать вторую полосу — отклонено: макет её показывает,
и данные в бою есть (`_hero_magic` уже передаётся в UI для книги заклинаний).
**Альтернатива:** выдумать ману юнита — отклонено: меняет боевую модель.

### D4 — Кольцо таймера показывает инициативу активного юнита

Таймера хода в модели нет. Кольцо рендерится с реальным числом
`get_initiative()` активного юнита; настоящее время хода — отдельное решение
владельца (зафиксировано в инвентаре как дивергенция).
**Альтернатива:** кольцо без числа (пустой декор) — отклонено: макет обязывает
число, декоративное число = ложь.
**Альтернатива:** ввести таймер хода — отклонено: меняет правила боя вне
мандата UI-задачи.

### D5 — Лента очереди: `turn_queue`, мёртвые исключены, активный подсвечен

Слот = портрет юнита + число инициативы; порядок = `turn_queue` с текущей
позиции; подсветка активного = золотая рамка. Размер слота и шаг — из
инвентаря (65×68, шаг 71.6).
**Альтернатива:** показывать всю очередь от начала — отклонено: макет
показывает будущее, прошедшие ходы уже не значимы.

### D6 — Медальоны = существующие сигналы, ничего не удаляется

Левый ряд: Menu (`settings_requested`), Surrender (`retreat_requested`),
Skip (`skip_requested`). Правый ряд: Spell Book (`spellbook_requested`),
Ranged (`attack_mode_requested`), Wait (`wait_requested`),
Defense (`defend_requested`). Rescue не рендерится — действия нет.
**Альтернатива:** сохранить прежние `Button`-подписи — отклонено: макет рисует
медальоны с подписью под ними.

### D7 — Раскладка HUD: абсолютные координаты инвентаря внутри Control-слоя

**Выбор:** узлы позиционируются в логических пикселях по инвентарю
(`anchor` + `offset`), root-слой — `canvas_items` + stretch (как на старте).
**Альтернатива:** `VBoxContainer`-раскладка как сейчас — отклонено: макет
задаёт абсолютные позиции (карточки в углах, лента по центру, медальоны в
углах), контейнер их не воспроизводит.

## Risks / Trade-offs

- [Абсолютные координаты не масштабируются под другие разрешения] → stretch
  `canvas_items` уже в проекте; проверка на 1920×1080 (MCP e2e), остальные
  разрешения — не регрессия текущего состояния.
- [Портрет юнита может отсутствовать для части `unit_id`] → узел скрыт, если
  текстуры нет; тест фиксирует «нет ассета — нет узла».
- [Правая карточка зависит от наведения, которого может не быть] → при
  отсутствии цели карточка скрыта; тест проверяет обе ветки.
- [Кольцо с инициативой читается как таймер] → дивергенция зафиксирована в
  инвентаре и TICKETS; меняется только по решению владельца.

## Open Questions

- Нужен ли настоящий таймер хода (механика) — вопрос владельцу, не UI.
- Правая карточка: цель атаки или выбранный юнит игрока? Реализовано «цель»,
  уточняется по playtest.
