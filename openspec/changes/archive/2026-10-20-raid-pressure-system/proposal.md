# Proposal

## Why

GDD 02-mechanics §3.8 — рейды по функции давления (K-T5/K-R3, 2026-10-02): без календаря, порог = накопитель давления. Реализовано в основном: `threat_system.gd` (давление, SM IDLE→CHARGING→INBOUND→STRIKE→RESOLVED→COOLDOWN, тиры, зима, цель по сортировке). Расхождение с каноном: per-ресурсные капы (документ: еда ≤40%, железо/оружие ≤30% за рейд — Q-M58→(в), D-189) vs единый `loss_cap_fraction = 0.3` в коде (T-127). Инертные ключи `raids.json` (visibility_formula/target_score/target_weights) не читаются кодом (09-risks).

## What Changes

- Фиксирует: рейды без календаря (K-T5) — рейд = пересечение порога накопителя давления.
- Фиксирует функцию давления (02e4 §13.2, K-R3): Base(city) = 4.0; Wealth = clamp(1 + 0.005×запасы, 0.5, 2.0); аномалия (крюк, MVP = 1.0); рост региона после cooldown 1 + 0.05×ходов; глобальные фазы {1:1.0, 2:1.25, 3:1.5, 21:2.0}.
- Фиксирует тиры (K-T5): пороги 30/100/250; power 15/30/60 (R6); defense: барраки 0.2, иначе 0 (R6); loss = power × (1 − defense).
- Фиксирует SM рейда: IDLE→CHARGING→INBOUND (прибытие через N ходов)→STRIKE→RESOLVED→COOLDOWN (3 хода)→IDLE.
- Фиксирует директивы (K-R3): первый рейд ≈ ход 7 (floor, tutorial-тир), финальный рейд к ходу 21 (floor, тир 3); floor-директивы не ломаются «все районы разрушены» (cooldown ×2 вместо).
- Фиксирует капы: per-ресурс per-рейд в пределах хода: еда ≤40%, железо/оружие ≤30% (Q-M58→(в), D-189). [Расхождение с кодом: единый 0.3 — T-127.]
- Фиксирует цель: score = 0.5×видимость + 0.3×уязвимость; видимость в MVP = константа 1 (Q-M54→(в)); тай-брейк меньший id (детерминизм); MVP: случайный из 3 ресурсов (веса 0.5/0.3/0.2).
- Фиксирует сезоны (Q-M27/Q-M29): 4 сезона, season_index = (turn−1) % 4, ход 1 = весна; зима = каждый 4-й ход (4/8/12/16/20); production_mult {весна 1.0, лето 1.2, осень 1.0, зима 0.4}; enemy_mult зима 1.25.
- Фиксирует: герой в городе → бой (CR 1/2/6); герой в походе → авто-рейд (defense = здания 13.3).
- Фиксирует FS: AFK-каскад — капы per-рейд, нет цепного коллапса; все районы разрушены → город выживает: производство −50%, частота рейдов −50% (cooldown ×2).
- Фиксирует EC: рейд по зданию на ремонте → ×0.5 к RUINED району; рейд по клетке героя → бой, победа → −50% последствий.

## Contradictions

- **C-4 (docs vs code, T-127):** per-ресурсные капы (еда ≤40%, железо/оружие ≤30% за рейд — Q-M58→(в), D-189) vs единый `loss_cap_fraction = 0.3` (`threat_system.gd:46`, `raids.json loss_cap_per_day`). Документация ведёт код; реализация капов — задача 2.1.
- **C-5 (инертные данные):** `raids.json` ключи `visibility_formula`/`target_score`/`target_weights` не читаются кодом (09-risks) — пометить «1.0, не читается» или реализовать (задача 3.1).
- **C-17 (docs vs code, уточнение):** 02-mechanics §3.8 «цель: случайный из 3 ресурсов (веса 0.5/0.3/0.2)» vs `threat_system.gd` (цель по score = 0.5×видимость + 0.3×уязвимость, видимость = константа 1). В MVP эквивалентно (видимость константа → score = константа → тай-брейк id), но формулы разные; синк — задача 3.1.
