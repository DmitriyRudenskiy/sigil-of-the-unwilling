## Context

Текущее состояние курсора:

- **Мир**: системный курсор без изменений; ввод в `WorldInput.gd` (зум, клик, отмена).
- **Бой**: `BattleView.CursorOverlay` (Node2D, `_draw`) рисует курсор сам — меч (ATTACK),
  стрела (RANGED), палка (SPELL), ботинок (MOVE), ретикула (DEFAULT). Это не картинки,
  а векторный `_draw`; переключение через `BattleController._input.set_cursor_mode(...)`.
- **Ассеты**: `game/assets/cursors/cursor_01.png … cursor_31.png` — 31 картинка 128×128,
  вырезанные с фона (`game/tools/extract_cursors.py` из sprite-sheet). Никто их не
  подключал; неизвестно, какой рисунок за какой режим.

Хотят: ботинок при ходьбе, рука при сборе, два воина при атаке — с возможностью задать
размер/картинку через пользователя, если подходящих ассетов нет.

## Goals

- Ввести единый `CursorController`, переключающий системный курсор по контексту.
- WALK (ботинок) — пока герой движется по миру.
- COLLECT (рука) — при сборе ресурсов.
- ATTACK (два воина) — в бою в режиме атаки.
- Размер/картинка/hotspot — конфигурируемые; при отсутствии ассета — запрос к пользователю.
- Сохранить бой-курсор `CursorOverlay` и вердикт `run_operability.sh` = CLEAN.

## Decisions

### D1: `CursorController` как autoload
`CursorController` подключается как autoload (как `GameEventBus`) и управляет курсором
глобально, чтобы мир и бой видели один источник истины. Режимы: `DEFAULT, WALK, COLLECT,
ATTACK`. Хранит карту `Dictionary[mode -> {texture, hotspot}]`.

### D2: Определение контекста
- **WALK**: подписка на `HeroMovementController` (флаг `is_moving`, переключение в
  `_start_moving`/`_stop_moving`), либо опрос `is_moving` в `_process`. При старте →
  `WALK`, при остановке → `DEFAULT`.
- **COLLECT**: подписка на `GameEventBus.resource_extracted` (триггер сбора); после
  короткой задержки/окончания анимации сбора → `DEFAULT`.
- **ATTACK**: подписка на смену режима атаки боя. `BattleController` уже вызывает
  `set_cursor_mode(ATTACK)`; добавить сигнал/событие, которое `CursorController` ловит.

### D3: Системный курсор vs бой-курсор
Системный курсор (`Input.set_default_mouse_cursor`) и нарисованный `CursorOverlay` —
разные слои. В бою `CursorOverlay` рисует свой символ поверх; системный курсор «два
воина» может как заменять, так и дополнять оверлей — **решает пользователь** (Open
Question). По умолчанию: в бою системный курсор не глушит оверлей (оверлей приоритетен
визуально).

### D4: Конфигурируемые ассеты + запрос у пользователя
Пути/размер/hotspot каждого режима вынесены в конфиг (`CursorController`). Если под режим
нет картинки (или существующие `cursor_01..31.png` не подходят по содержанию/размеру),
реализация **останавливается** и запрашивает у пользователя: (1) нужный размер,
(2) какие именно картинки за какой режим. Это прямое требование пользователя
(«если нет картинок — проси какой размер нужен»).

## Risks

- **Конфликт с боем**: системный курсор в бою может дублировать/глушить `CursorOverlay`.
  Митигация: D3 (чёткое разделение слоёв), настройка по умолчанию.
- **Неидентифицированные ассеты**: `cursor_01..31.png` unnamed. Митигация: D4 — запрос у
  пользователя, не угадываем.
- **Hotspot**: у RPG-куроров точка клича обычно у «конца» (ботинок/наконечник). Неправильный
  hotspot = ощущение сдвига. Митигация: hotspot параметризован, подбирается с пользователем.
- **COLLECT по event bus**: `resource_extracted` может_fire часто (по ресурсу). Митигация:
  включить/выключить курсор по фазе сбора, а не по каждому событию.

## Migration

1. Создать `CursorController.gd` (autoload) с картой режимов и `set_mode()`.
2. Подключить определение WALK (движение героя) и COLLECT (`resource_extracted`).
3. Подключить ATTACK (сигнал режима атаки из `BattleController`).
4. При отсутствии ассетов — запрос к пользователю (размер + картинки).
5. Проверить `run_operability.sh` (CLEAN) + автотесты переключения курсора.
