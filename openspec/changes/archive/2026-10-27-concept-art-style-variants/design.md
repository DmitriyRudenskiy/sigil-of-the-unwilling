# Design: concept-art-style-variants

## Context

Стилевой канон записан (`docs/13-art-bible.md` — семейства A «хром», B2 «Знак», B3 «книга», C «карта/бой»,
D «здания»; `docs/17-ui-style-guide.md` — компоненты UI), референсы лежат в
`/Users/user/Downloads/Новая папка с объектами 40` (9 изображений + образец шрифта + два woff2).
Пикселей, собранных из этого канона семейством «одна картинка на сюжет», в проекте нет.

**Каталог референсов не однороден по манере — и это главное, что он диктует дизайну** (разобрано визуальным обзором 2026-10-15):

| --- | --- | --- |
| `…43738974…png` | стратегическая hex-карта | ручная живопись, тёплая, изометрия |
| `…43136546…jpeg` | 12 персонажей | стилизованный комикс/мультяшок, ~7 голов, насыщенный |
| `…780027871…jpeg` | 12 зданий | ручная живопись, уютная, тёплая солома |
| `…66761829…jpeg` | тёмный ритуальный круг | тёмный кинематографичный ключ-арт |
| `…70213325…png` | 11 медальонов-знаков | тёмный чеканный металл + светящийся глиф |
| `…76934150…jpeg` | бой на hex-карте | ручная живопись |

Отсюда правило владельца: **новый кадр обязан повторять стиль одного из этих изображений**. Единого
«стиля проекта» в референсах нет, поэтому якорь может быть только «на категорию» — см. D8.

Внешний GPU-хост `192.168.0.230` проверен живым прогоном (smoke-тест скилла `comfyui-image-mcp`):

| Что | Значение |
| --- | --- |
| ComfyUI HTTP | `http://192.168.0.230:8188` (`/history`, `/view`, `/upload/image`, `/queue`) |
| MCP | `http://192.168.0.230:9000/mcp`, `ComfyUI_MCP_Server 1.30.0`, 23 инструмента |
| Krea-2 turbo, 512², 8 шагов | 24 с |
| Qwen Image 2.1 t2i, 512², 25 шагов | 60 с |
| Qwen Image 2.1 edit | 165 с |
| RealESRGAN ×4 / SeedVR2 / birefnet / SAM3 | 4 / 6 / 5 / 2 с |

Замеренные особенности сервера, на которые дизайн обязан нарваться:

1. `asset_url` из ответов MCP отдаётся как `http://127.0.0.1:8188/view?...` — с другой машины недоступен.
2. Имена файлов вывода на сервере не уникальны (`upscaled_00001_.png`) — на шаренном сервере файл
   перетирается чужой очередью.
3. `rembg` возвращает RGB с чёрным фоном (не прозрачность); Qwen edit принудительно отдаёт ~1024².
4. Ошибка «model not found» называет модель по умолчанию, а не запрошенную.

Машина: диск 96 % занято, свободно 8,8 ГБ. `mcp` (Python SDK) и Pillow установлены.

## Goals / Non-Goals

**Goals:**

- Один прогон даёт 5 полностью укомплектованных вариантов стиля на общем списке сюжетов — сравнимые между
  собой, потому что различается только стилевая часть запроса.
- Прогон возобновляем с любого места и переживает перезапуск сервера и собственной машины.
- Результат проверяем машиной до того, как на него смотрит человек: размер, белизна фона, непустота,
  полнота манифеста.
- Повтор прогона по тем же файлам воспроизводит картинки (затравка выводится из идентификатора артефакта).

**Non-Goals:**

- Игровые ассеты: ни `game/assets/**`, ни тема, ни StyleBox, ни `game/tools`-пайплайн с гейтом
  провенанса. Концепт-арт — материал для решения, а не ассет.
- Постобработка: ни апскейл, ни SeedVR2, ни вырезание фона, ни нарезка на спрайты. Белый фон и 1024² —
  потолок требований; раскрой — отдельная задача после выбора варианта.
- Выбор победителя. Конвейер готовит сравнительный борд; вариант выбирает владелец.
- Одновременная генерация нескольких картинок (сервер шарится, 12 ГБ VRAM, MCP всё равно сериализует).

## Decisions

### D1. Две модели, а не одна — и каждая прогоняет один и тот же промпт

**Правило владельца (2026-10-15):** модель не делит категории. Персонаж не может делаться одной моделью,
а интерфейс — другой; каждый промпт тестируется и в Krea-2, и в Qwen Image 2.1. Модель поэтому
выбирается **прогоном** (`--model`), проба гоняет каждый промпт через обе (`probe_models`) и выдаёт
отдельный борд на каждую модель; полный прогон идёт в одной модели — по итогам бортов.

Замер по-прежнему в пользу разницы по времени: Krea-2 turbo даёт 1024² за ~80 с, Qwen Image 2.1 — за
~170 с, экран интерфейса ~65 с против ~170 с. Но решает не оно: выбирать скорость в ущерб сравнению
значит молча отказаться от самого сравнения.

**Снятая альтернатива:** `ui_model = krea2` (интерфейс в быстрой модели, остальное в Qwen). Экономия
~20 мин на полном прогоне ценой того, что сравнить модели не на чём и правило владельца нарушено.

**Побочный эффект:** у инструмента Krea-2 нет параметра негативного запроса — негатив варианта для неё
домешивается в конец позитивного запроса (`..., no photorealism, no text`), у Qwen уходит в
`negative_prompt`. Различие закрыто в генераторе, на формулировку промпта не влияет.

### D2. Загрузка байтов через ComfyUI HTTP, а не через `asset_url`

За статусом обращаемся к MCP (`get_job`), за байтами — напрямую в `/history/<prompt_id>` → `/view` с
`192.168.0.230`. Это решает одновременно обе серверные особенности: localhost-хост в `asset_url` (п. 1) и
перетирание файлов чужой очередью (п. 2) — имя файла берётся из истории конкретного задания сразу после
его завершения.

Альтернатива — переписывать хост в `asset_url`: короче, но не закрывает п. 2.

### D3. Затравка из идентификатора артефакта

`seed = crc32("<variant>/<category>/<id>") % 2**31`. Один и тот же артефакт воспроизводится при любом
порядке и любом числе перезапусков, без состояния между прогонами. Альтернатива — случайная затравка,
записанная в манифест: повтор прогона рисовал бы уже другие картинки.

### D4. WEBP q82 вместо PNG

Канон ассетов для AI-арта (`docs/13-art-bible.md` §8.1) — WEBP q80–85. 385 файлов по ~150 КБ ≈ 60 МБ
против ~500 МБ в PNG при 8,8 ГБ свободных. Точность для концепт-обзора избыточна; если вариант выберут и
пойдут в ассеты, генерация повторится уже в ассет-пайплайне.

### D5. Белый фон — проверяемое требование, порог калибруется по эталону

Для изолированных категорий кадр проверяется: ровно 1024×1024, доля **почти-белого** (каждый канал ≥ 235)
в рамке 24 px ≥ 60 %, средняя яркость в диапазоне 25…235 (отсекает и чёрный фон, и выбитый в белый
объект). Систематический провал варианта по белизне — это результат обзора (например, «Тёмный собор» тянет
фон в чёрный), а не тихо проглоченный дефект.

Замер эталона заставил переписать формулировку дважды:

1. «Доля чистого 255» — у самого эталона персонажей она **1 %** (фон светлый, с мягкими тенями).
   Под таким воротчиком канон не прошёл бы собственную приёмку. Порог — почти-белый ≥ 235 (у эталона 98 %).
2. «Объект не должен занимать кадр» по плотности центрального окна — ложные падения: изометрическое здание
   с чистой рамкой и плотным центром — валидный ассет. Требование «не касается рамки» вычитается из той же
   рамки 24 px, отдельная проверка плотности не нужна.

### D8. Эталон стиля — на уровне категории, вариант двигает только технику

Правило владельца: новый кадр повторяет стиль одного из изображений каталога референсов. Так как каталог
не однороден (см. Context), якорь живёт в категории: `categories.<cat>.reference` — файл-эталон,
`categories.<cat>.style` — его словесное описание (манера, материалы, свет). Формулировка варианта —
только дельта техники рендера (линия, заливка, финиш), без слов о сюжете, пропорциях, палитре и материалах.
Запрос: `style категории (эталон) → дельта варианта → frame категории (формат кадра) → subject`.

Доказательство раунда 1 (пять вариантов рисовались без пер-категорийного якоря, по одному глобальному
«базовому» описанию): у двух вариантов пропорции уехали в ~4 головы при ~7 у эталона, у одного палитра
ушла в розовый, у двух фигура впритык к рамке. Общее описание семейства удерживает «мультяшность»,
но не удерживает ни пропорции, ни материалы — их держит только конкретный эталон категории.

Альтернативы: (а) один глобальный базовый clause — проверено, не держит; (б) вариант = выбор эталона —
тогда здания рисовались бы по мультяшному эталону персонажей и бросали свой; (в) img2img/ipadapter по
эталону — снимает вопрос словесной формулировки, но это уже серверный рабочий процесс, вне Non-Goals.

### D9. Отсев сохраняется, повтор меняет затравку

Кадр, не прошедший машинную проверку, переносится в `concept_art/_reject/` под именем
«модель__вариант__категория__id» (не удаляется): без него нечем итерировать формулировки, а в дереве
вывода его нет — требование «fail не остаётся как готовый» соблюдается. Повтор при провале воротчика
обязан менять затравку (`seed + номер попытки`): тот же запрос с той же затравкой ComfyUI отдаёт из кэша
за 0.2 с тем же кадром, то есть повтор был имитацией работы.

### D6. Выход — вне git, как `reference/*`

`concept_art/` в `.gitignore` по тому же основанию, что и `reference/*` (в репозитории — карта и тексты,
не чужие/сгенерированные пиксели). В git попадают каталог (`spec.json`), генератор, README и
`docs/18-concept-art-variants.md`: этого достаточно, чтобы прогон повторить с нуля.

Паттерн обязан быть заякорен (`/concept_art/`): неанкоренный `concept_art/` матчит любую директиву с таким
именем и глушит `scripts/concept_art/` — генератор, каталог и тесты становятся невидимы для git
(проверено `git check-ignore -v`, инцидент 2026-10-15).

### D7. Один файл генератора, без новых зависимостей

`scripts/concept_art/generate.py`: MCP-клиент (`mcp.client.streamable_http` + `ClientSession`), очередь
артефактов, загрузка, проверка, манифест, контактный лист (Pillow). Отдельных пакетов на «пул задач»,
«хранилище манифеста» или «фреймворк промптов» — нет: у всего по одному потребителю.

## Risks / Trade-offs

- **[8–10 ч генерации на шаренном GPU]** → прогон в фоне с логом и возобновлением по файлам; перезапуск
  продолжает с первого отсутствующего файла; `--variant/--category/--only` дают маленький дымный прогон
  раньше полного.
- **[Сервер перезагрузится / выгрузит модель посреди прогона]** → сюжет помечается `fail` с текстом ошибки,
  прогон идёт дальше, повтор дозаполняет пробелы. Ни один сюжет не теряется: манифест знает полный список.
- **[Стилевой сдвиг внутри варианта]** → стилевая формулировка эталона категории стоит первой и одинакова
  для всех сюжетов категории, затравка детерминирована, стилевой борд (кадр рядом с эталоном) показывает
  разброс до того, как наработано 385 файлов.
- **[Эталоны противоречат друг другу]** → противоречие разрешено на уровне категории, а не прогона:
  здания рисуются по зданию, курсоры по курсорам. Смешение манер внутри одного кадра — дефект обзора,
  фиксирующий, что формулировка категории описала не свой эталон.
- **[Текст на экранах UI — каша]** → принято для концепт-стадии: экраны оценивают компоновку, хром и
  иерархию, а не надписи. Читаемый текст — задача ассет-пайплайна, не концепта.
- **[Krea-2 без негативного запроса]** → часть дисциплины стиля теряется; компенсируется негативом в
  позитивном запросе и дымным прогоном на 6 сюжетах до запуска полного.
- **[Модели снимут с сервера]** → имена чекпойнтов вынесены в `spec.json`; замена модели — правка данных,
  не кода.
- **[Диск]** → только WEBP, ~60–90 МБ; PNG-промежуточные файлы не сохраняются.

## Migration Plan

Аддитивно, откат — удалить `concept_art/` и `scripts/concept_art/`.

1. `spec.json` + генератор + README (в ветке `feat/concept-art-variants`).
2. Стилевой борд: по одному сюжету каждой категории во всех пяти вариантах, каждая строка начинается с
   эталона категории → машинные проверки + `read`-обзор → правка формулировок категории/варианта.
3. Дымный прогон: 6 сюжетов (по одному на категорию) в одном варианте → машинные проверки + `read`-обзор.
4. Полный прогон в фоне (`nohup`, лог в `concept_art/generate.log`), периодическая сводка `ok/skip/fail`.
5. Контактные листы по вариантам → обзор владельца → правка `docs/18-concept-art-variants.md` с решением.

## Open Questions

- Какой из пяти вариантов (или какая смесь) становится каноном — решается только по готовому борду.
- Что делать с категориями, у которых своего эталона в каталоге нет (часть сюжетов units — например,
  юниты боя — референсом не покрыты): брать ближайший по манере или просить у владельца новый референс.
- Нужен ли выбранному варианту апскейл/раскрой на спрайты — зависит от ответа выше и от того, пойдёт ли он
  в `game/tools`-пайплайн.
