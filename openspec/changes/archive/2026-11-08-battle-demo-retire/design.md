## Goals / Non-Goals

**Goals:**

- уникальные носители получают по одному дому в основном проекте, двойников не
  становится больше;
- `battle-demo/` исчезает из дерева и из реестра корня, Q-M139 закрывается;
- ни одна живая спек-способность не описывает удалённый каталог;
- гейты после разреза не хуже, чем до (`doc_gates`, `gdd_gate`, `ci2`,
  `check_repo_layout`, `run_tests`).

**Non-Goals:**

- слияние боевой модели стенда в `game/scripts/battle/` — она противоречит
  канону бескубиковой лестницы K2 (`docs/02d-combat-core.md`,
  `dnd-battle-ladder`), а `design-brief.md` стенда сам открещивается от чисел
  основной игры;
- перенос 42 тестов стенда: они проверяют её же боёвку и её же HUD;
- переименование способности `battle-demo-sprites` — каталог `openspec/specs/`
  переименовывать нечем (RENAMED в дельтах — про требования), а имя чинится
  одной строкой в Purpose, которую правят прямо в сведённом спеке;
- судьба способности `turn-battle-core` (см. риск R4) — выносится Q-M140;
- правка исторических носителей и `docs/mvp/HERO-ANIM.md` в части того, что там
  описано как сделанное.

## Decisions

**D1. Правило разделения — есть ли у носителя потребитель в основном проекте.**
Есть → переезжает. Двойник того, что в проекте уже лежит → удаляется. Чужая
модель, противоречащая канону → не переносится, остаётся в истории git. Правило
однократное и проверяемое (сравнение md5, `git grep`, таблица `ANIMATED`), а не
«что жалко».

**D2. Куда именно переезжает уникальное.**

| Носитель | Дом | Почему не иначе |
|---|---|---|
| `assets/portraits/` | `scripts/character_kit/portraits/` | в игре их никто не грузит; в `game/assets/` это осиротевший ассет с обязательной строкой `PROVENANCE.md` ни ради чего |
| `assets/sprites/cutthroat/` | `scripts/character_kit/sprites/cutthroat/` | то же: силуэта в `ANIMATED` нет; вердикт девятого листа и так лежит в `runs/` |
| `tools/build_sprite_frames.gd` | `game/tools/build_sprite_frames.gd` | единственный шаг, обязанный идти из-под Godot, и работает он деревом игры (`res://assets/sprites/…`); `game/tools/` — его законное место |
| `assets/reference/walk-sample.png` | `scripts/character_kit/runs/walk-sample.png` | это образец, приписанный к записи прогонов, а не позиция канона стиля D-319 |
| `docs/`, `CHANGELOG.md` | `docs/archive/battle-demo/` | запись отдельного проекта обязана остаться трэкаемой; `.reserve/` для этого не годится — там файлов в индексе нет |

**D3. `scripts/character_kit/` перестаёт знать про стенд.** Корень `STAND`
удаляется из `paths.py` вместе-с проверкой самопроверки (инвариант становится
строже: ни один путь пакета не содержит `battle-demo`). Конкретные потребители:
`audit_sprites.py` (`SPRITES` → `game/assets/sprites`, `unit_ids()` → из
`spec.json["characters"]`, а не из `glob("*.tres")` стенда),
`build_sprite_frames.py` (`SPRITES` → туда же), `gen_kit.py` (`PORTRAITS` →
носитель конвейера, `SHOTS` → вывод), `spec.json` (`portraits_dir`). Строка
`battle-demo` остаётся только в исторических записях (`runs/*.json`, `runs/*.log`,
вердикты) — идентификаторы записей не переписываются (прецедент D-320).

**D4. Архивная зона документов — исключение по образцу `docs/bank/` (D-102), а не
`ARCHIVE_LOGS`.** Механизм `ARCHIVE_LOGS` ключуется базовым именем файла, а имена
стенда (`architecture.md`, `design-brief.md`, `glossary.md`, `decisions.md`) —
общие: завтра живой документ с таким именем выпадет из графа молча. Архивная
зона — одна константа в `scripts/check_docs_links.py` рядом с `BANK_DIR` плюс
три потребителя, которые её читают (`gen_docs_index.py`, `gdd_gate.py`,
`audit_docs_vs_code.py`); без неё 21 файл без фронтоматтера красят `doc_gates` и
сдвигают базлайны `gdd_gate`.

**D5. Спеки: две выводятся, одна правится, одна не трогается.** Механика
вывода — `REMOVED` c `Reason`/`Migration`; при синхронизации каталоги
`openspec/specs/battle-demo-ui/` и `openspec/specs/roster-lineups/` удаляются
(спека без требований не бывает). `battle-demo-sprites` остаётся и живёт —
её предмет (комплект кадров) никуда не делся, — а в Purpose дописывается строка,
что имя историческое: прежний носитель комплекта — выведенный `battle-demo/`.

**D6. Два коммита, не один.** Первый — переезд носителей и переадресовка ссылок
(откатывается `git revert`, ничего не теряет). Второй — `git rm -r battle-demo`
(откатывается независимо: `git revert` возвращает папку, переезд не трогает).
Иначе отмена удаления тянула бы за собой отмену переезда.

## Risks / Trade-offs

- **R1. Удаляется ~1900 строк боёвки и 42 теста.** Восстановление —
  `git show <sha>:battle-demo/scripts/combat/combat_state.gd` либо `git revert`
  второго коммита. Модель не «теряется», а перестаёт притворяться наработкой
  основного проекта: её тесты молча проверяли бы формулу, которую игра не
  использует.
- **R2. Тест стенда `test_sprite_tracks.gd` не портируется сознательно.** Он
  требует пять дорожек по четыре кадра у каждого юнита; в игре уже есть
  `game/tests/unit/ui/test_battle_figures_animated.gd` с сознательно более
  слабым контрактом (`hit` необязательна — у `priest` её нет) и проверкой
  зацикливания. Портирование стендового теста красило бы игру по известной
  причине. Реестр `INCOMPLETE` при этом остаётся в единственном носителе —
  `scripts/character_kit/audit_sprites.py`.
- **R3. `ui_read_judge.py` теряет источник новых кадров** (съёмку вели
  `capture_*.gd` стенда). Он остаётся средством пересмотра уже снятых кадров из
  `character_kit/artifacts/screenshots/`; чек-лист спеки `battle-demo-ui`
  переезжает в README конвейера, чтобы судья не остался без текста приёмки.
- **R4. `turn-battle-core` описывает доканонный бой и спорит с `dnd-battle-ladder`.**
  Удаление девяти требований — решение владельца, а не следствие удаления папки:
  спек не называет ни одного файла стенда. Поднимается Q-M140 `[human]`.
- **R5. Архив стенда выпадает из индекса `docs/00-INDEX.md`.** Это цель (он не
  живые доки), но находимость падает: в `docs/18-system-map.md` и
  `scripts/character_kit/README.md` остаётся строка-адрес, где искать запись.
- **R6. Реакция гейтов на новые пути предсказана, а не измерена.** `test_compile_all`
  сканирует `res://` по каталогам верхнего уровня, `check_asset_provenance`
  сверяет провенанс кадров, `gdd_gate` ведёт базлайны по докам: все три
  прогоняются после разреза, результат пишется в задачи числом, а не «должно
  быть».
