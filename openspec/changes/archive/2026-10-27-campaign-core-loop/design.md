# Design: campaign-core-loop

## Context

Post-pivot кампания (2026-10-02, K-канон) переопределила core loop: 21 ход вместо «бесконечного цикла», ход = сезон, 6 фаз вместо «3 фаз» (01-core-loop в v3-формулировке). Реализация уже есть: `TurnDriver` (T-010: 21 ход, бит-каркас; T-122: production после threats), `WorldSeasons` (Q-M27/Q-M29), `TurnScheduler` (тик), `ThreatSystem` (фазы угроз). Остатки: метрики (телеметрия), AFK-капы (T-127), инвариант «≥2 глагола».

## Goals

- Формализовать канон 01-core-loop как OpenSpec-требования (источник истины для будущих изменений).
- Разграничить: что уже реализовано (dead tasks), что — реальные задачи.
- Зафиксировать метрики как требования (измерение — за телеметрией, не за симуляцией).

## Non-Goals

- Не менять порядок фаз (канон Q-M31/T-122 не трогается).
- Не вводить caravans/diplomacy (post-MVP no-op слоты).
- Не описывать UI (mvp-ui-flow), рейды (raid-pressure-system), партию (party-characters).

## Decisions

1. **TurnDriver — единственный носитель порядка фаз** (T-010/T-122). Никаких обходных «фаза вне драйвера».
2. **Метрики = телеметрия событий**, а не расчёт внутри симуляции: события `action{type, choice_count}`, `loop_closed`, `replan_after_tooltip` пишутся в лог сессии; отчёт — post-hoc анализ (playtest). Headless-симуляция метрики не считает (нет «игрока»).
3. **Статус кампании** — три значения: `ongoing` / `defeat` (wipe партии — единственный путь, Q-M68→(а), D-190; голод ведёт к концу через гибель партии, −2 к атакам) / `victory` (пережить рейд хода 21, R5).
4. **Бит-каркас K-M9** — ходы 1/7/14/17/21 фиксированные story beats; ход 3 «слух» — строка той же бит-схемы с пометкой Post-MVP.
5. **Детерминизм I1**: ГСЧ только из campaign seed; боевое разрешение и выбор цели рейда — без RNG (K2).

## Risks and contradictions

- **C-4 (docs vs code, T-127):** per-ресурсные капы AFK (еда ≤40%, железо/оружие ≤30% за рейд — Q-M58→(в), D-189) vs единый `loss_cap_fraction = 0.3` (`threat_system.gd:46`, `raids.json loss_cap_per_day`). Документация ведёт код; реализация капов — в `raid-pressure-system`.
- **C-11 (docs vs docs):** `MVP-scope.md` «район создан — источник Престижа (500 — баланс-конфиг)» vs K-M16 + 02-mechanics §3.5 «район создан — не источник Престижа (самокоррекция K-M1)». Канон = K-M16; строка `MVP-scope.md` устарела — синк в docs (реестр TBD).
- Метрики D1/D7 не измеримы headless — deferred до playtest (критерий MVP, MVP-scope).
- «≥2 доступных глагола» — инвариант UI, проверяется в `mvp-ui-flow` (smoke-чек-лист).
