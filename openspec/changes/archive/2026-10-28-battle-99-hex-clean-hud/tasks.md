## Отклонения и поправки, сделанные при сводке (2026-10-28)

Задачи закрыты не буквально по тексту, а по назначению; три расхождения зафиксированы здесь,
чтобы архив не врал:

1. **Носитель кадра (5.1).** Файл `game/tools/capture/battle_background.gd` не заводился:
   состояние боя поднимает уже существующая фикстура `game/tools/capture/battle_field.gd`,
   местность фона в ней читается из `CAPTURE_TERRAIN` — один носитель на три кадра
   (снег/болото/fallback) вместо трёх копий. Для задачи 1.3 добавлен
   `game/tools/capture/battle_field_max.gd` (максимальный состав).
2. **Ориентация расстановки (1.2, сценарий спеки).** Сценарий «Размещение при начале боя»
   унаследовал из базовой спеки «игрок снизу, враг сверху», чего код не делает:
   `battle_state_builder.gd:66-67` ставит атакующего к колонке 0, обороняющегося к
   `BW − 1`. Текст сценария исправлен в дельте **до** архивации (кадр `b99_max_snow.png`:
   по 7 стеков у левого и правого краёв).
3. **Снятый таймер дожил в спеке поля.** В списке возможностей предложения removal для
   `tactical-combat` не было, но требование «Таймер игрокового хода» называет поимённо
   `turn_time_limit`, удалённый задачами 2.1–2.2. В дельту добавлена секция
   `## REMOVED Requirements` с этим требованием, `proposal.md` приведён в соответствие.
4. **Починка двух главных спек.** `openspec/specs/battle-hud/spec.md` и
   `openspec/specs/battle-ui/spec.md` оказались конкатенацией дельт прошлой архивации
   (заголовок `## ADDED Requirements` внутри главной спеки), из-за чего archive отказывался
   применять дельты, а все требования были невидимы для `validate`. Заголовки сведены к
   `## Requirements`, добавлены `# … Specification` и `## Purpose` — содержательных правок
   требований починка не содержит (проверено `git diff`: только заголовки и Purpose).
