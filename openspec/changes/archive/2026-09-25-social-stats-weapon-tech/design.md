# Design: social-stats-weapon-tech

## Context

- Статы героя: `HeroBuildProfile.get_stats(race_id, class_id)` → 4 боевых
  стата (`attack/defense/spell_power/knowledge`) из `base_stats` + бонусы
  рас (`hero_races.gd`), классов (`hero_classes.gd`), культур,
  бэкграундов. `HeroStatsComponent` сериализует `stats: Dictionary`.
- Имиграция: `ReputationSystem.process_migration(city)` — поток
  `MIGRATE_IN_PER_TURN` при репутации ≥ порога и наличии места в pop_cap.
  Модификатора личности нет.
- Найм: `CityService.recruit_military(city, building, hero)` — чек
  ресурсов, тир оружия = `weapon_tier_for_city(city.level)` (1/2/3),
  стек = `RECRUIT_BATCH_SIZE`; cap — `HERO_ARMY_MAX_STACKS`.
  `FollowerSystem.recruit` — найм последователей.
- Здания: `BuildingDefs` — есть `smithy`, `mine`, `market`, `barracks`;
  «печь» как отдельного здания нет (smithy покрывает).
- Артефакты: `ArtifactRegistry._register(id, name, slot, rarity, modifiers,
  special_effect, two_handed, gold, description, combat={})` — тиров
  материалов нет; есть `Rarity` (MINOR/…).
- Сделки в городе: `CityScreen` (buy_cart, стройка, рекрут) — фиксированные
  цены, проверок нет.
- RNG: глобальные + city rng через `RandomNumberGenerator`
  (seed-детерминизм в balance-core — все броски идут через управляемый rng).
- Зависимость: `attribute-weight-system` (не реализован) вводит
  `Artifact.weight`, `LoadCalculator` — веса материалов/артефактов общие.

## Goals / Non-Goals

**Goals:**
- 8 статов (4 боевых + int/wis/cha/luk) с распределением рас/классов.
- Обман в важных городских сделках: процентная формула, роли
  wis/cha/luk, 4 степени последствий.
- Таблицы cha: иммиграция, cap отряда, качество найма, проверки найма.
- 5 тиров оружия из технологий (здания+ресурсы), статы в ковке.
- Детерминизм: все новые броски — через управляемый RNG (seed).

**Non-Goals:**
- Полная крафтовая система (чертежи, производство в реальном времени) —
  только каталог тиров + ковка/покупка с бросками качества.
- d20-система как основной: основной механизм — процентная формула обмана
  и d20-проверки найма (как в ТЗ); таблицы сложностей — данные.
- Уникальные магические артефакты тира 5 — только каркас (каталог),
  контент можно наращивать без кода.
- Перестройка UI (только новые строки/значки в существующих экранах).

## Decisions

### D1. 8 статов в одном `base_stats`, социальные — вне боя
Добавляем `int/wis/cha/luk` в `HeroBuildProfile.base_stats` (дефолт 2) +
бонусы рас/классов/культур/бэкграундов в существующих таблицах.
- Почему не отдельный компонент: один словарь статов — один сериализатор,
  один UI, одна точка бонусов; бой не трогается (бой берёт
  attack/defense/spell_power/knowledge — `get_battle_bonus` не меняется).
- Альтернатива: отдельные `SocialStatsComponent`. Отклонено: дублирует
  модель, раздваивает сейв и UI.
- `get_battle_bonus()` остаётся только боевым. Новые статы читаются
  мирными системами через `HeroStatsComponent.get_stat("cha")` и т.п.

### D2. Обман: процентная формула + степени, один `DeceptionCheck`
Статик-модуль `DeceptionCheck.roll(rng, int_, wis, cha, luk, base_pct,
trap_level) -> {deceived, severity, note}`:
- `chance = clamp(base + (10 − int_) * 4 − max(wis−10, cha−10, luk−10, 0) * 2, 5, 85)`.
- Если roll < chance → обман; severity: лёгкий/средний по степени
  превышения, критический при провале на 5+ (д20-слой: `1d20 + int +
  компенсация vs trap_dc`, провал 5+ = серьёзный/критический).
- Роли: wis — шанс «узнать заранее» (отдельный бросок до сделки, даёт
  отказ без потерь или −1 ступень severity); luk — шанс полной отмены
  обмана/раскрытия (выгода); cha — честная цена при успешной сделке
  (скидка).
- Почему статик как `LogisticsCalculator`/`LoadCalculator`: один источник
  правил, unit-тесты без сцены, все системы зовут его.
- Точки вызова: покупка дорогого/договор/сомнительное задание в
  `CityScreen`/`CityService`; мелкая торговля ресурсов — НЕ проверяется
  (anti-noise).
- Альтернатива: только d20. Отклонено: процентная формула из ТЗ
  предсказуемее для баланса и UI (игрок видит шанс).

### D3. Харизма: таблицы в GameNumbers + один `LeadershipCheck`
`GameNumbers.SOCIAL_CHA_TABLES` (массивы): иммиграция-modifier,
max_stacks, recruit_quality. `LeadershipCheck`:
- `immigration_modifier(cha) -> float` — множитель на
  `MIGRATE_IN_PER_TURN` (округление вверх при ≥0; при cha ≤ 5 —
  доп. отток с шансом).
- `max_army_stacks(cha) -> int` — заменяет фикс
  `HERO_ARMY_MAX_STACKS` (константа остаётся как fallback/дефолт).
- `recruit_check(rng, cha, reputation, offers, difficulty) -> outcome`
  (успех/отказ/слухи/крит-провал) — d20 по ТЗ.
- `recruit_quality(cha) -> quality` — модификатор статов стека при
  найме (отчаявшиеся → ×0.8, элита → ×1.25 и шанс уникального).
- Точки: `ReputationSystem.process_migration` (множитель),
  `CityService.recruit_military` (cap + check + качество).
- Альтернатива: формула (cha−10)×5% как в «краткой версии» ТЗ. Отклонено:
  таблица из ТЗ выразительнее (явные пороги 1/2/3/7 отрядов) — данные,
  не магия.

### D4. Тир оружия: `WeaponTechService` из зданий, не уровней
`WeaponTechService.city_weapon_tier(city) -> int`:
- 1 — по умолчанию; 2 — есть `smithy` (или «верстак»-аналог) lvl ≥ 1;
  3 — smithy lvl ≥ 2 + уголь + руда в стоке; 4 — smithy lvl ≥ 3 + сталь;
  5 — редкие материалы + прокачанные чертежи.
  («Печь/кузнец» — smithy уровней 1–3; отдельного здания не добавляем —
  ponytail: уровни существующего здания дают ту же прогрессии.)
- Заменяет `weapon_tier_for_city(level)` в `recruit_military` (эта функция
  остаётся как fallback для городов без hero-контекста).
- Каталог тиров: `WeaponCatalog` (статик-данные) — материалы (вес,
  прочность, урон-бонус) и изделия по тирам; `ArtifactRegistry` получает
  `tier` у артефактов-оружия (поле `tier: int = 1`).
- Связь с attribute-weight-system: `Artifact.weight` заполняется из
  `WeaponCatalog` при регистрации (дерево 1.0, камень 1.5, железо 2.0,
  сталь 1.8, редкое 2.5).
- Альтернатива: 5 отдельных зданий (верстак/печь/кузница/…). Отклонено:
  одно здание с уровнями = меньше данных и UI, та же играбельная
  прогрессия.

### D5. Ковка/качество: броски через `WeaponTechService.forge()`
`forge(rng, item_id, stats) -> {artifact, quality, notes}`:
- `wis` — шанс распознать подделку при покупке/приёме (изделие
  ниже качества: скидка/возврат);
- `luk` — шанс «удачной ковки» (качество +1) и редкий материал;
- `int` — шанс изучения технологии (переход тира) ускоряется/удешевляется;
- `cha` — найм кузнеца через `LeadershipCheck` (качество мастера →
  качество ковки).
- Детерминизм: все броски принимают `rng` аргументом (pattern
  balance-core).

### D6. Миграция сейва
`HeroStatsComponent.deserialize`: отсутствующие `int/wis/cha/luk` →
дефолт из base_stats расы/класса (пересчёт `HeroBuildProfile.get_stats`),
не хардкод 2. Формат сейва расширяется обратно-совместимо (новые ключи).

## Risks / Trade-offs

- [Обман дёргает баланс-пробу (проба покупает телегу/строит)] → мелкая
  торговля не проверяется (D2); MCP-проба с фикс-сеидом — контроль
  регрессии (60 ходов RUNNING).
- [8 статов раздувают таблицы рас/классов] → новые статы только у
  осмысленных рас/классов (маг/жрец +wis, плут +luk, бард-подобный +cha;
  остальные — дефолт). Одна правка на таблицу, данные не код.
- [Тир из уровней → из технологий ломает позднюю игру, где город lvl 9+] →
  `weapon_tier_for_city` остаётся как max(fallback, tech_tier):
  поздний город не деградирует, ранний не получает железо из воздуха.
- [Камертон хаизмы: cap 1–7 отрядов vs текущий HERO_ARMY_MAX_STACKS] →
  берём max(cha_cap, 3) как минимум, чтобы баланс-проба (3–4 отряда)
  не сломалась при низкой хаизме.
- [Крит-провал найма = «враждебность/донос» — новый негативный контент] →
  v1: только репутация −N и сообщение; бунты/нападения — из v1 (ponytail:
  полный набор негативных событий при cha 1–5 можно добавить позже
  данными).

## Migration Plan

1. Статы: `base_stats` + бонусы + миграция сейва (D1/D6) — сейв-совместимо.
2. `DeceptionCheck` + точки в сделках (D2).
3. `LeadershipCheck` + таблицы + иммиграция/cap/найм (D3).
4. `WeaponTechService` + `WeaponCatalog` + `Artifact.tier` + веса (D4/D5).
5. UI: статы в экране героя, шанс обмана/штрафы в городе.
6. Регрессия: все unit-тесты, MCP-проба 60 ходов RUNNING, калибровка
   коэффициентов.

Rollback: change откатывает коды; формат сейва обратно-совместим
(новые ключи игнорируются старой версией), откат безопасен.

## Open Questions

- Точные значения базовых шансов/сложностей и весов материалов —
  калибруются под баланс-пробу (спецификация не меняется).
