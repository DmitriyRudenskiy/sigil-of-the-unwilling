# Design: TerraScape hex city-builder

> **Статус: SUPERSEDED (2026-10-04).** Этот дизайн отдельного режима не реализуется; актуальная граница интеграции — `campaign-city-building-economy`.

## Context

Godot 4.7 проект «Sigil of the Unwilling». Режим TerraScape — новая
самодостаточная песочница (см. proposal.md). В проекте уже есть:
`scripts/core/hex_utils.gd` (осевые координаты, расстояние, соседи),
`scripts/core/hex_draw.gd` (отрисовка гексов), конвенция данных в JSON
(`game/data/`), GdUnit4-тесты headless, UI-паттерны (`ui_manager`,
модальные экраны). Существующие `settlement-*`/`city-*` системы не
трогаем.

## Goals / Non-Goals

**Goals:**
- Игровая логика (скоринг, слияния, общество, сезоны) — чистые
  детерминированные модули, тестируемые headless GdUnit4.
- Данные (27 зданий, 7 объединённых, 7 видов, уровни 1–11) — JSON,
  без хардкода статов в скриптах.
- Один сценарий запуска из главного меню; режим не зависит от
  world/city-систем и их autoload'ов.

**Non-Goals:**
- Полная версия: World Map, Cornerstones/Orders как карточки-бонусы,
  открытие колод за репутацию, торговля/Blightrot — только заготовки
  данных (таблица уровней уже в спеке).
- Интеграция с hero/боевой системой, сейвы режима — позже.
- Реальные ассеты пиксель/изометрии: пока глиф-фолбэк и векторные
  иллюстрации.

## Decisions

1. **Структура**: корневой узел `TerraScapeMode` (сцена
   `game/scenes/terrascape/terrascape.tscn`) владеет подсистемами:
   `RiteSystem` (партия, топливо, костёр/Очаг, дневной тик сезона 0),
   `MapGen` (52 клетки + биомы + фичи), `BuildingCatalog` (JSON),
   `ScoreEngine` (RefCounted, чистые функции), `MergeSystem`,
   `SocietySystem`, `SeasonClock`, `TerraScapeUI`.
   Альтернатива — autoload'ы: отклонено, режим изолирован, autoload'ы
   нужны только на всё приложение.
2. **Скоринг как чистая функция**: `ScoreEngine.score(building, field)
   -> Dictionary {total, breakdown}` — без побочных эффектов; полный
   пересчёт всего поля при любом изменении (52 клетки — O(n·r²)
   ничтожен). Альтернатива — инкрементальные дельты: отклонено,
   сложность не окупается на 51 клетке; дельты для UI считаем
   сравнением «до/после».
3. **Детерминизм**: один `RandomNumberGenerator` на режим с явным
   seed (seed карты и seed симуляции — разные поля); никаких
   `randf()`/`randi()` и `rng.randomize()` после установки seed
   (урок флейки `test_event_balance_probe`). Все `_ready`-инициализации
   — до первого сезона.
4. **Гексы**: переиспользуем `hex_utils.gd` (axial, cube distance) и
   `hex_draw.gd`. Поле — предвычисленный список 52 пар координат
   (ядро 4 + кольца 10/16/22), генератор карты не нужен.
5. **Данные**: `game/data/terrascape/buildings.json` (27+7 зданий со
   статами GDD §3.2/§4.1/§0.5), `species.json` (7 видов, §5.1),
   `levels.json` (1–11), `rite.json` (спутники, ранги навыков, заказы
   обряда, §0). Формат — плоские записи, валидация при
   загрузке (тест-твин `test_crisis_events.gd`).
6. **Три стиля — стратегия рендера**: интерфейс `BuildingRenderer`
   с тремя реализациями: `VectorRenderer` (draw_* команды —
   «параметрический SVG» Godot'ом без импорта SVG), `SheetRenderer`
   (пиксель/изо-лист 4×4, нарезка `AtlasTexture`, hex-clip через
   `CanvasItem` clip + зум 1.22), `GlyphRenderer` (фолбэк).
   Переключение — сигнал UI, данные не зависят от стиля.
7. **Обряд огня**: `RiteSystem` — отдельная подсистема с собственным
   дневным тиком (сезон 0, без авто-таймера): инвентарь партии
   (6 вязанок), заготовки (Лес +1 доска/день = 2 вя, Болото +3
   камыша/день = 3 вя), состояние огня (костёр: бак 3, расход 1/день;
   Очаг: бак 6 + 9×Склады R2, расход 3/сезон, Шторм 6; Пылает/Тлеет/
   Угли), аура в формулу покоя через `SocietySystem` (по жилью в R2,
   не по работе). Календарь: 1 сезон = 3 дня; после основания дни
   уходят под капот (производство/день ×3 = за сезон) — в коде это
   просто переключение такта `SeasonClock` с «дни» на «сезоны».
   Маг/Друид — данные навыков (ранги, пороги XP) в `rite.json`,
   эффекты — хуки в `RiteSystem`/`SocietySystem`.
   Альтернатива — абстрактный «выбор зоны сбора» без токена партии:
   отклонено (GDD рекомендует полноценный токен, ~1 неделя работы).
8. **Тесты**: unit (GdUnit4, headless) — обряд (состояния огня, тление
   и угли, жар Мага, заготовки, аура), скоринг (формула, дубли,
   self-штрафы, adj через «×4»), слияния (рецепты, BFS-связность ×4,
   перенос работников), общество (жильё жаб, ёмкость нужд, формула
   покоя, Преданность), сезоны (шторм/3, слава, караван, уровни).
   UI/визуал — deferred (headless не верифицирует), по конвенции
   проекта.

## Risks / Trade-offs

- [Полный пересчёт при каждом действии] → на 52 клетках <1мс; если
  вырастёт — инкремент (запас в design, не в коде).
- [Обряд вводит второй такт времени (дни/сезоны)] → единый `SeasonClock`
  с двумя режимами (day/season); детерминизм сохраняется, т.к. такт
  ручной (T), без таймеров.
- [Векторные иллюстрации 29 зданий — большой объём draw_* кода] →
  генеративный подход: общий каркас (крыша/стены/деталь) + параметры
  на здание; точное совпадение с HTML-прототипом не требуется.
- [Пиксель/изо-листы отсутствуют] → глиф-фолбэк держит режим играбельным;
  `SheetRenderer` пишется под таблицу `SPRITE_POS`; при отсутствии
  файла — автоматический глиф-фолбэк.
- [Специфика «от клетки до клетки» для многоклеточных зданий] →
  расстояние считается как минимум по всем парам клеток двух зданий;
  покрыто unit-тестами на «×4» и кварталах.

## Migration Plan

Новый режим — без миграции. Rollback: удалить пункт меню и каталоги
`scenes/terrascape/`, `scripts/terrascape/`, `data/terrascape/`.

## Open Questions

- Откуда возьмутся пиксель/изо-листы (`terrascape_a.png`,
  `terrascape_b.png` из прототипа) — перенести из HTML-прототипа или
  нарисовать заново; не блокирует старт (глиф-фолбэк).
- Рамка «~1000 очков = победа» — показывать ли soft-goal в UI
  прототипа (песочница формально не заканчивается).
- Dev-тоггл «мгновенное основание» для тестов скоринга (GDD §0, вопрос 2)
  — решить при реализации `RiteSystem`.
- Баланс Лес 2 вя/день vs Болото 3 вя/день: оставить паритет через
  плотность хранения досок (GDD §0, вопрос 4) — не блокирует, числа в
  JSON.
- Камыш в full: кровля жилья / циновки (GDD §0, вопрос 3) — не
  блокирует прототип.
