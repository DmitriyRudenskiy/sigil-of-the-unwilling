# GDD phase workflow as a repo-carried process

## Why

Четырёхфазный контур (аудит → углубление → гриль-петли → фиксация) в этом репо
**уже проходил, но не был закреплён носителем**: в git висят теги `v3-grilled`,
`v3-grilled-3.5`, `v3-grilled-3.5bis`, `v3-grilled-pass3`, `v3-grilled-pass4`,
`grill-v3-pass-5`, `grill-v3-round-3.5` — три с лишним прохода третьего гриля
собыли, а `v1-audited`, `v2-deepened`, `v4-locked` не существуют вообще (21 тег,
проверено `git tag`). Контур жил в промпте сессии и умер вместе с ней: ни одна
из 12 названных в методе компетенций не описана в репозитории как воспроизводимый
шаг.

Второе расхождение — реестры разошлись с формой, которую метод предполагает.
Замеры 2026-10-26 (`docs/`, `main 02bf81ce`):

| Что требует метод | Что в репо | Мера расхождения |
| --- | --- | --- |
| `Q-<NN> [agent\|human] 🔴/🟡/🟢` | `docs/QUESTIONS.md`, таблица 5 колонок, id `Q-M1…Q-M102` | строк-вопросов 115; маркер типа есть у **35** (31 `[human]`, 4 `[agent]`), приоритетных эмодзи — **0**, статуса `⏳` — **0** |
| `## D-<NN>` с полями Контекст / Решение / Отвергнутые / Каскад / Статус | `docs/DECISIONS.md`, таблица из **3** колонок, `D-1…D-269` | строк 169; слов «Отвергнутые»/«Каскад» — **3** вхождения; `⏳` — **0**; `⚑` — **0** |
| `R-<NN>` в `09-risks.md` | тот же файл, прозаические строки | нумерованных рисков **0** из 12 строк |
| состояния секций `draft → audited → deepened → verified → locked` | frontmatter `status:`, 49 файлов | `audited`/`verified`/`locked` — **0**; словарь гейта (`scripts/check_docs_links.py:26`) их **не содержит**, то есть новая запись с `status: audited` **красит** док-гейт |
| «перечитай ЦЕЛИКОМ `gdd/`, DECISIONS.md, CHANGELOG.md» каждый вход | `gdd/` нет, есть `docs/` | объём: `docs/*.md` — 15 701 строка / 2,62 МБ, реестры — ещё 1,54 МБ, `docs/mvp/TICKETS.md` — 0,80 МБ. Полный перечитать на каждом входе физически нельзя (это больше ёмкости контекста), а «прочитать по памяти» = то, из-за чего контур и умер |
| 12 навыков по фазам | `~/.pi/agent/skills/` | есть **6** (`grill-with-docs`, `to-questionnaire`, `triage`, `hindsight-coding-agent`, `wait-what`, `to-tickets`); нет **6** (`content-audit`, `verification-before-completion`, `loop-me`, `create-epics`, `changelog`, `consistency-check`) |
| `0× TODO / FIXME / ???`, битых wikilinks нет | `scripts/check_docs_links.py` | уже выполняется и зелёный (99 заметок); TODO/FIXME/??? в `docs/` — **0** |
| эпики и тикеты с `blocked-on` | `docs/mvp/EPICS.md` (8 эпиков), `docs/mvp/TICKETS.md` (`T-1…T-222`) | пометок `blocked-on` — **0**: связь «тикет ждёт решения D-xx» никем не носится |

Третье расхождение — правило «без СТОП» работает по факту (агент применяет
рекомендацию и закрывает вопрос `D-###`), но **не различим в реестре**: ни одна из
169 записей `DECISIONS.md` не помечена как «предварительное, ждёт дизайнера», хотя
таких заведомо много. Дизайнер, возвращаясь, не видит, что именно требует его
внимания первым делом, — а это ровно то, ради чего ⏳/⚑ и вводятся.

## What Changes

- **Носитель — репозиторий, не чат.** Фазы описаны пятью тонкими локальными
  навыками (`.pi/skills/`), которые не переписывают существующие, а ссылаются на
  уже живущие носители: `consistency-check` — это `scripts/audit_docs_vs_code.py`
  (закрыт сегодня, `docs-code-sync`), `to-tickets` — `docs/mvp/TICKETS.md` +
  `docs/mvp/EPICS.md`, `changelog` — `docs/CHANGELOG.md` + док-гейт.
- **Ре-грундинг = генерируемый дайджест, а не «прочитай всё».** Скрипт
  `scripts/gdd_grounding.py` печатает состояние реестров и секций (счётчики,
  ⏳/⚑-хвост, открытые 🔴/🟡, последние записи) в лимите нескольких сотен строк
  вместо 2,6 МБ.
- **Машина состояний секций встраивается в док-гейт**: `audited`/`verified`/`locked`
  добавляются в `ALLOWED_STATUSES`, переходы валидируются, `canon` остаётся
  легаси-синонимом `locked` (11 файлов переписывать не нужно).
- **Реестры дополняются, а не переписываются.** Новая форма полей обязательна для
  новых записей, старые закрываются ratchet-бэклогом (тот же механизм, что
  `scripts/audit_docs_vs_code.allowlist`, — он доказал, что монотонное сжатие
  работает лучше большой чистки).
- **Связь «тикет ждёт решения» появляется впервые**: строка `blocked-on: D-xxx`
  в записи `TICKETS.md`, проверяться будет тем же сверщиком.

## Capabilities

### New Capabilities

- `gdd-phase-workflow`: четырёхфазный контур проработки GDD, закреплённый в
  репозитории — фазы, состояния секций, реестровые поля, ре-грундинг, верификация
  с доказательствами, теги и правило «ответ человека не блокирует работу».

### Modified Capabilities

- Нет: ни одна из 61 специки основного контура не меняет поведения. `docs-code-sync`
  (сверка доков с кодом) остаётся отдельной способностью — новый процесс её
  вызывает, но не переопределяет.

## Impact

- **Документация:** новые `docs/19-gdd-workflow.md` (фазы, состояния, что где
  лежит), `docs/mvp/EPICS.md` и `docs/mvp/TICKETS.md` получают поле `blocked-on`,
  `docs/09-risks.md` — нумерацию `R-##`, `docs/QUESTIONS.md`/`docs/DECISIONS.md` —
  обязательные поля для новых записей.
- **Инструменты:** `scripts/gdd_grounding.py` (новый), `scripts/gdd_gate.py`
  (новый: состояния секций + полнота новых реестровых полей + `blocked-on`),
  `scripts/check_docs_links.py` (расширение `ALLOWED_STATUSES`).
- **Навыки:** пять новых файлов в `.pi/skills/` (`content-audit`,
  `verification-before-completion`, `loop-me`, `create-epics`, `changelog`) —
  каждый указывает на существующий носитель и команду, а не дублирует её.
- **Код игры:** не затрагивается. `game/` в этом изменении не меняется, поэтому
  GdUnit-гейт остаётся обязателен только как регрессивная проверка чистоты дерева.
- **Риск процесса:** контур может снова остаться промптом. Компенсация — всё,
  что метод требует проверять, либо исполняется скриптом, либо имеет носитель в
  `docs/`; «прочитать и сделать» не остаётся ни одного пункта.
