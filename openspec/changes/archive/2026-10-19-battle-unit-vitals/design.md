## Context

Боевая модель резолвит урон и смерть в `scripts/systems/battle_action_resolver.gd`
(`kill_unit` — единственная точка убийства, `revive_unit` — воскрешение,
`do_skip` — пропуск хода, `state.check_end()` — условие победы). Ходом игрока
управляет `scripts/systems/battle_turn_executor.gd`. D&D-мост —
`scripts/battle/dnd/battle_bridge.gd`; профиль персонажа —
`scripts/battle/dnd/combatant_profile.gd` (ability scores —
`scripts/battle/dnd/ability_scores.gd`).

Два уже написанных и **никому не известных** модуля ложатся в задачу как есть:
`scripts/battle/dnd/death_saves.gd` (`DNDDeathSaves`: HEALTHY/DYING/STABLE/DEAD,
`roll()`, `stabilize()`, `heal()`, константы `MAX_SUCCESSES/MAX_FAILURES = 3`) и
`scripts/battle/dnd/ability_check.gd` (проверка характеристики DC).

## Goals / Non-Goals

**Goals:**
- У D&D-персонажа есть пул маны, вычисляемый из Intelligence.
- У персонажа есть уровень, доезжающий из определения до сохранений.
- Игроковый ход ограничен временем, истечение = автопропуск.
- Персонаж на 0 HP умирает постепенно; союзник может его спасти.
- Победа считается по «нечем действовать», а не по «все убиты».

**Non-Goals:**
- Мана обычных стеков (юнит без профиля маны не имеет — это правило, не
  недоделка).
- Влияние уровня на боевые формулы (только отображение).
- Таймер хода ИИ и синхронный многопользовательский таймер.
- Анимации умирающего/спасения, озвучка, иконки статуса.
- Новая механика траты маны персонажем вне уже существующих заклинаний боя.

## Decisions

### D1 — Мана = `5 × (2 + INT-модификатор)`, кламп ≥ 5, только у профиля

**Формула:** `mana_max = maxi(5, 5 * (2 + DnDAbilityScores.modifier(INT)))`.
INT 10 (+0) → 10, INT 16 (+3) → 25, INT 8 (−1) → 5.
**Обоснование чисел:** базовая цена заклинания в `HeroMagic.get_mana_cost` —
`base_mana`, по умолчанию 5; нижняя граница 5 означает «любой персонаж с
профилем может колдовать хотя бы один раз», верхняя ограничена только INT.
**Альтернатива (отклонена):** `2 × уровень + INT-мод` — завязывает ману на
уровень, который в этом же change'е объявлен display-only.
**Альтернатива (отклонена):** общая мана героя — именно её владелец отменил
для персонажей («мана зависит от интеллекта»).

**Платёж:** D&D-персонаж платит **своей** маной; юнит без профиля — маной
героя (существующий путь `_hero_magic.spend_mana`). Возврат при неудачном
касте — в тот же пул, откуда списали.

### D2 — `level: int = 1` проходит по всей цепочке профиля

`DnDCharacterDef.level → DnDCombatantProfile.level → to_dict/from_dict`,
default 1. Поле display-only.
**Альтернатива (отклонена):** выводить уровень из max_hp/CR — придумывает
число, которого нет в данных.

### D3 — Таймер: состояние в `BattleState`, тик в исполнителе хода

`BattleState.turn_time_limit: int = 30`, `turn_time_left: float`,
`turn_timer_running: bool`. Исполнитель хода: на старте игрокового хода
`arm_turn_timer()`, на конце — выключить; `tick_turn_timer(delta)` вызывается
из `_process` контроллера боя; истечение → тот же путь, что `do_skip`
(пользовательский «пропуск» уже ведёт себя так).
Модальное окно (книга заклинаний, настройки, результат) ставит
`turn_timer_running = false` на время открытия.
Ходы ИИ таймер не вооружает.
**Альтернатива (отклонена):** `SceneTreeTimer`/`Timer`-нода в UI — состояние
утекло бы из модели, тесты стали бы тайминговыми и хрупкими.
**Альтернатива (отклонена):** 0 = без таймера — макет требует кольцо с числом.

### D4 — 0 HP у персонажа = DYING, не смерть

В `kill_unit` добавляется ветка: `unit.is_dnd_character()` →
`down_unit(state, unit)`: HP = 0, `death_saves = DNDDeathSaves.new()` (состояние
DYING), юнит **остаётся** в сетке и в очереди, но `can_act() == false`.
В начале его хода вместо действия — `death_saves.roll(state.dnd_rng)`:
3 успеха → STABLE, 3 провала → DEAD (тогда обычный `kill_unit`).
Stack-юниты идут прежним путём (счётная модель, `alive = false`).
**Альтернатива (отклонена):** мгновенная смерть как раньше — тогда Rescue
нечем делать, а `DNDDeathSaves` остаётся мёртвым кодом.

### D5 — Rescue = действие, а не заклинание

`request_rescue(target)`: требуется ход игрока, смежность (как ближняя атака),
цель — союзник в состоянии DYING. Резолв: `ability_check` характеристики
заклинателя (INT/WIS/CHA — высшая модификация) против DC 10; успех →
`stabilize()`; натуральный 20 → `heal(1)`. Трата — единственное действие хода.
**Альтернатива (отклонена):** «воскрешение мёртвого раз за бой» — в бою мёртвый
персонаж труп по D&D-правилу, а `resurrection` в проекте — кампейн-механика
города за золото (`death_sequence.gd`), не боевое действие.
**Альтернатива (отклонена):** Rescue как заклинание из книги — требует, чтобы у
героя было выученное заклинание; медальон в макете стоит в ряду действий.

### D6 — Победа: «стороне нечем действовать»

`check_end()` переходит с «все мертвы» на «нет ни одного юнита, который может
действовать»: умирающий, стабилизированный, мёртвый и отступивший — выведен.
Стеки считаются по-прежнему по `get_count() > 0`.
**Риск:** бой может закончиться «вничью по истощению» — обе стороны без
боеспособных. Тогда побеждает сторона, у которой больше живых (существующая
логика ничьих в `check_end`, если её нет — фиксируется как поражение
атакующего, как при отступлении).

## Risks / Trade-offs

- [Меняется семантика смерти — заденет существующие тесты] → правим только
  тесты D&D-ветки; stack-ветка не тронута, её тесты — регресс-страховка.
- [Персонаж стал «неубиваемым» через DYING] → 3 провала = смерть; стабилизиро-
  ванный юнит всё ещё выведен из боя и для победы его нужно добить.
- [Таймер 30 с может резать длинные ходы] → число вынесено в константу
  `TURN_TIME_LIMIT` и в `BattleState`, тюнится одной строкой.
- [Двойная казна маны (персонаж/герой) может запутать] → платёж определяется
  наличием профиля, тестом зафиксирована обе ветки.
