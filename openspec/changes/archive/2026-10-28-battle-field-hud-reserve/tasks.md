# battle-field-hud-reserve — задачи

- [x] **1. Запас читается с полос HUD.** `BattleUI.hud_bands() -> Vector2` —
      `get_global_rect()` полос `hero_cards`, `initiative_bar`, `bottom_bar`
      (`scenes/ui/battle_ui.tscn`). Бейдж таймера хода сознательно не резервируется
      (остаток → `T-230`).
- [x] **2. Внедрение приёмника хостом.** `BattleController._apply_hud_reserve()` →
      `BattleView.set_hud_reserve(top, bottom)`; вызов после первого кадра (до
      раскладки прямоугольники полос пусты) и перед каждой пересборкой камеры.
- [x] **3. Формула.** `avail_y = vp.y − top − bottom`; `z = min(vp.x/field.x,
      avail_y/field.y)`; центр сдвигается на `(top − bottom) / (2·z)`.
      `avail_y <= 0` → `push_error` + четверть кадра (молчаливый ноль зума —
      невидимый дефект). Множитель `field_fit_scale` и `BATTLE_LOWRES_*` сняты.
- [x] **4. Тест и батарея.** `test_battle_field_fit_720p.gd` → `test_battle_field_fit.gd`
      (6 кейсов: связка «панель ↔ запас», правка панели двигает запас, нижняя граница
      поля выше панели при 1080p, доля ≤ 0.8 при 720p, сдвиг = `(bottom − top)/2z`,
      нулевой запас = плотная вписка). `tools/mut_battle_fit.sh` переписана:
      M1′…M6′ — все красные (проверено прогоном 2026-10-27).
- [x] **5. ux-review машинным зрением.** Кадры `battle-hud-reserve-1080/`
      (`3cbb505b…`) и `battle-hud-reserve-720/` (`6641a989…`), замер по оливковому
      тайлу: 1080p — поле 155..921 (доля **0.710**, было 1.000), 720p — 103..614
      (**0.711**); верх поля совпадает с нижней границей верхних полос (155 / 103).
- [x] **6. Решение в реестре.** `D-279` (механизм снят, носитель числа переехал в сцену).
- [x] **7. Синхронизация живой спеки и архив смены** — `openspec archive
      battle-field-hud-reserve` перенёс смену в `openspec/changes/archive/` и сам
      подставил MODIFIED-текст в `openspec/specs/mvp-ui-flow/spec.md` (2026-10-28).
