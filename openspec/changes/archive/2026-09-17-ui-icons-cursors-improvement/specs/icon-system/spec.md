# icon-system Specification

## Purpose

Определяет систему иконок для игрового интерфейса: библиотеку иконок для ресурсов, зданий, потребностей героя, школ магии; инструменты генерации иконок в едином стиле; интеграцию с UI компонентами.

## ADDED Requirements

### Requirement: Категории иконок
Система SHALL предоставлять иконки для 4 основных категорий: ресурсы (8 базовых + 6 редких), здания (12 типов), потребности героя (3 типа), школы магии (4 типа). Каждая иконка должна быть в двух размерах: 32x32 и 64x64 пикселей.

#### Scenario: Иконки ресурсов
- **WHEN** игра отображает ресурс в UI
- **THEN** используется иконка из `res://assets/ui/icons/resources/{id}.png`
- **AND** иконка соответствует цвету из ThemeConfig

#### Scenario: Иконки зданий
- **WHEN** игра показывает здание в городе
- **THEN** используется иконка из `res://assets/ui/icons/buildings/{id}.png`
- **AND** стиль иконки согласован с темой игры

#### Scenario: Иконки потребностей
- **WHEN** отображается потребность героя (отдых, общение, вдохновение)
- **THEN** используется иконка из `res://assets/ui/icons/needs/{id}.png`
- **AND** цвет иконки отражает статус (норма/критично)

#### Scenario: Иконки школ магии
- **WHEN** показывается принадлежность заклинания к школе
- **THEN** используется иконка из `res://assets/ui/icons/schools/{school}.png`
- **AND** цвет соответствует C_SCHOOL_* из ThemeConfig

### Requirement: Генерация иконок
Иконки SHALL генерироваться процедурно через скрипты-генераторы по аналогии с gen_artifact_icons.gd. Генераторы используют базовые формы (круг, квадрат, треугольник) и цветовую схему из ThemeConfig.

#### Scenario: Генерация иконок ресурсов
- **WHEN** запускается gen_resource_icons.gd
- **THEN** создаются PNG файлы для всех ресурсов из ResourceDef
- **AND** цвета соответствуют C_RES_* из ThemeConfig

#### Scenario: Генерация иконок зданий
- **WHEN** запускается gen_building_icons.gd
- **THEN** создаются иконки для всех типов зданий
- **AND** форма иконки отражает назначение здания

#### Scenario: Обновление иконок
- **WHEN** изменяется цветовая схема в ThemeConfig
- **THEN** повторная генерация обновляет все иконки
- **AND** стиль остаётся согласованным

### Requirement: Загрузка и кэширование
Система SHALL кэшировать загруженные текстуры иконок для производительности. Повторные запросы одной иконки возвращают кэшированную текстуру.

#### Scenario: Первое получение иконки
- **WHEN** запрашивается иконка ресурса впервые
- **THEN** система загружает PNG файл
- **AND** сохраняет в кэш

#### Scenario: Повторное получение иконки
- **WHEN** запрашивается та же иконка повторно
- **THEN** возвращается кэшированная текстура
- **AND** загрузка с диска не происходит

#### Scenario: Очистка кэша
- **WHEN** происходит смена уровня/сцены
- **THEN** кэш иконок может быть очищен
- **AND** память освобождается

### Requirement: Fallback иконки
Если иконка не найдена, система SHALL предоставлять fallback иконку (универсальный значок "вопрос" или пустой слот). Fallback иконка должна быть загружена всегда.

#### Scenario: Отсутствующая иконка
- **WHEN** запрашивается несуществующая иконка
- **THEN** возвращается fallback иконка
- **AND** в лог пишется предупреждение

#### Scenario: Ошибка загрузки
- **WHEN** файл иконки повреждён
- **THEN** используется fallback
- **AND** ошибка логируется

### Requirement: Интеграция с Registry
ResourceRegistry, ArtifactRegistry, BuildingDefs SHALL предоставлять методы get_icon(id: StringName) -> Texture2D, возвращающие текстуры иконок.

#### Scenario: Получение иконки ресурса
- **WHEN** вызывается ResourceRegistry.get_icon(&"gold")
- **THEN** возвращается Texture2D иконки золота
- **AND** иконка готова к отображению в TextureRect

#### Scenario: Получение иконки здания
- **WHEN** вызывается BuildingDefs.get_icon(&"smithy")
- **THEN** возвращается Texture2D иконки кузницы
- **AND** размер соответствует контексту
