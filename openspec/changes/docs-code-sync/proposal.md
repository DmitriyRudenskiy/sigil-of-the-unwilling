# docs-code-sync: синхронизация документации с кодом игры (Godot 4.7)

## Why

Документация описывает игру, а не репозиторий: проверить её утверждения сейчас
нечем. Аудит 2026-10-26 (`scripts/audit_docs_vs_code.py`, прогон по `main`
`1b0db8e9`) измерил расхождение, а не оценил его:

| Факт кода | Сколько в коде | Упомянуто в docs/ | Не упомянуто |
| --- | --- | --- | --- |
| автозагрузки (`project.godot [autoload]`) | 15 | 10 | **5** (SoundManager, Spellbook, TemplateBootstrap, Units, Spells) |
| действия ввода (`[input]`) | 5 | 0 | **5 — весь input map** |
| сцены (`game/scenes/**/*.tscn`) | 51 | 31 | **20** |
| классы (`class_name` вне `addons/`) | 405 | 159 | **246** |
| верхнеуровневые ключи сейва (`mvp_save_schema.gd`) | 10 | — | формат сейва описан словами, не по коду |

Частные следствия, каждое из которых ломает один из критериев приёмки:

- **Управление не описано ни в одной заметке так, чтобы его можно было сверить**:
  в игре ровно пять действий — `camera_up`, `camera_down`, `camera_left`,
  `camera_right`, `mute`; в `docs/07-ui-ux.md` и `docs/14-ux-battle-hud.md`
  горячие клавиши перечислены словами («Tab», «Esc»), имена действий input map
  не названы нигде, то есть связать «док ↔ project.godot» нечем.
- **Формат сохранений описан по памяти**: в `mvp_save_schema.gd` ключи `campaign`,
  `city`, `major`, `map`, `minor`, `party`, `population`, `prestige`, `resources`,
  `sign`; прозы «как устроен сейв» это не проверяет, а часть заметок описывает
секции, которых в схеме нет.
- **Есть описания систем, которых в коде нет** (например, панель решения события:
  `assets/ui/panels/decision_panel.tscn` и `crisis_panel.tscn` в репо отсутствуют,
  работает fallback из `UIManager`; зафиксировано в Q-M83/T-132, но в
  UX-заметках панели живут как факты).
- **Обратная сторона та же**: из 405 классов игры 246 не названы ни в одной заметке,
  поэтому «пройти по документам и понять систему» сегодня невозможно — приходится
  читать код, то есть доки перестали быть входной точкой.

Причина не в лени авторов, а в отсутствии механизма: `check_docs_links.py`
проверяет связность wikilink-графа и кириллицу в именах, но не то, что
`Services` — это автозагрузка, а `battle_view.tscn` лежит в `scenes/`.
Расхождение накапливалось молча, потому что его нечем red-гейтить.

## What Changes

1. **Гейт сверки** — `scripts/audit_docs_vs_code.py` (уже написан в этом change,
   прогоняется из корня репо): читает факты из `project.godot`, `game/scenes/`,
   `game/scripts/`, `mvp_save_schema.gd` и проверяет в обе стороны — «ссылка дока
   разрешается в код» (красный всегда) и «факт кода назван в доках» (красный для
   автозагрузок, действий ввода, сцен и ключей сейва; классы — по убывающему
   allowlist-бэклогу, иначе гейт годами висел бы жёлтым и его бы отключили).
2. **Карта систем** — `docs/18-system-map.md`: автозагрузки с ответственностью,
   границы слоёв (core / systems / campaign / city / world / ui / probe), каналы
   сигналов, где живёт сейв и кто его пишет. Это основа правок, а не ещё одна
   заметка: ссылки в остальных документах ведут на неё.
3. **Реверс-доки по секциям «устарело/отсутствует»**: управление (из `[input]`),
   список и роли автозагрузок, пайплайн сцен и кто их поднимает, формат сейва по
   фактической схеме, слой событий (`crisis_event_system.gd` + fallback-панели).
   В каждом утверждении — источник: файл и символ.
4. **Сверка имён** — классы, ноды, сцены, хоткеи, пути: результат — пустой вывод
   гейта, а не «на глаз».
5. **CHANGELOG** — что обновлено и почему (с цифрами аудита до/после).

## Impact

- Docs: новые `docs/18-system-map.md`; правки `docs/07-ui-ux.md`, `docs/08-tech.md`,
  `docs/01-core-loop.md`, `docs/02-mechanics.md`, `docs/17-ui-style-guide.md`,
  `docs/CHANGELOG.md`; сверяются остальные заметки `docs/`.
- Scripts: `scripts/audit_docs_vs_code.py` (новый гейт), `.gitlab/.github` не
  затрагиваются — CI по директиве владельца агент не поллит.
- Код игры: **не меняется**. Change документационный; если реверс вскроет поведение,
  которого в коде нет, оно не «дописывается», а регистрируется тикетом (D-224:
  решение за владельцем).
- Риски: соблазн «покрасить гейт» массовым упоминанием имён в одном списке —
  поэтому требование к документированию сформулировано как «имя названо рядом с
  ответственностью», а проверка для классов ведётся по allowlist, который может
  только сокращаться.
