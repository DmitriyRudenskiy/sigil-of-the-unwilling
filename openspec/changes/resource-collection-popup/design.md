## Context

На карте героя есть два пути сбора ресурса:
- **Богатые узлы** (`ResourceNodeManager.try_extract`) — после добычи испускают глобальный `GameEventBus.resource_extracted(cell, resource_id, amount)`.
- **Простой сбор** (`WorldInteractionController.collect_resource_at`, команда `COLLECT_HERE` из `SocketController`) — сейчас только убирает ноду и игнорирует количество, без видимой обратной связи.

Иконки ресурсов поставляются заказчиком (спрайт/атлас), маппинг `resource_id → текстура/регион` — данные. Готовые паттерны окон: `ArtifactChestDialog.gd` (модальное окно: margin→vbox→title→separator→preview→кнопки) и `AdventureUI._on_options` (маленький `popup_centered`).

## Goals / Non-Goals

**Goals:**
- Дать видимую обратную связь при сборе: маленькое центрированное окно (картинка + количество + OK).
- Работать на обоих путях сбора, не ломая поток игры/сохранение.
- Переиспользовать существующие паттерны UI и звук `resource_collected`.

**Non-Goals:**
- Анимированные «летящие» числа / частицы (только статичное окно).
- Автосоздание текстурных инок ресурсов (спрайт поставляется заказчиком).
- Самоисчезающий toast без OK (OK остаётся обязательным).
- Изменение логики экономики/добычи (окно только читает результат).

## Decisions

**D1. Хук — глобальный `GameEventBus.resource_extracted`, унифицирующий оба пути.**
Богатые узлы уже испускают этот сигнал с `(cell, resource_id, amount)`. Простой сбор (`collect_resource_at`) расширем выпуском того же сигнала (с `resource_id` и количеством из ноды/картки клетки). Окно подписывается один раз на `GameEventBus.resource_extracted` → единая точка появления для обоих путей.
*Альтернатива*: подписывать окно на каждый путь отдельно — больше мест, риск рассинхрона.

**D2. Владелец окна — координатор в `AdventureUI` (overlay-слой).**
`AdventureUI` уже координарует все панели и умеет создавать модалки (`_options_popup`), живёт на `layer=10`. Окно создаётся лениво (lazy, как `_options_popup`) и показывается `popup_centered`.
*Альтернатива*: `WorldEventRouter` — но он не UI-координатор и не держит слои/звук UI так же чисто.

**D3. Картинка — текстурная иконка из спрайта/атласа (предоставляет заказчик).**
Заказчик предоставляет спрайт/атлас инок ресурсов. Окно мапит `resource_id → текстура/регион` (данные-словарь, не хардкод) и показывает текстуру в `TextureRect`. Маппинг вынесен в данные, чтобы менять его без правки логики; формат атласа (один спрайт с регионами vs отдельные PNG) — детали реализации, резолвятся по факту поставки спрайта (см. Open Question).
*Альтернатива*: эмодзи (Label, `font_size` ~48) — ноль ассетов, но хуже по качеству и не соответствует требованию заказчика о текстуре.

**D4. Модалка: закрытие по OK и/или авто-исчезание (~4 с).**
Зеркало `ArtifactChestDialog`: margin(vbox) → image + name/amount label → OK-кнопка. `popup_centered` с небольшим размером. Закрытие по двум триггерам: нажатие OK и таймер авто-исчезания (~4 с). Оба триггера работают параллельно (OK остаётся обязательным элементом интерфейса, авто-исчезание — удобство).
*Альтернатива*: только OK (без таймера) — проще, но менее удобно; авто-тост без OK — против запроса.

**D5. Деградация при неизвестных данных.**
Если `resource_id` не резолвится в текстуру или amount `0` — показать placeholder-иконку и `0`, не падать.

## Risks / Trade-offs

- **[D1] Простой сбор не знает `resource_id`/количество.** `collect_resource_at` сейчас работает по `res_type` (индекс эмодзи) из `WorldSpawner`. → Митигация: в `collect_resource_at` брать тип/количество из ноды клетки (WorldSpawner/маппинг res_type→название); если не резолвится — деградация по D5.
- **[D2] Окно может перекить игровые панели.** → Митигация: отдельный overlay-слой, `popup_centered` в зоне, не закрывающей критичные кнопки; специка: панели остаются доступны.
- **[D3] Маппинг `resource_id → текстура` зависит от формата спрайта заказчика.** → Митигация: маппинг — данные (словарь), формат атласа резолжится по факту поставки без правки логики и спеки.
- **[D4] Модалка блокирует фон.** → Митигация: короткое время показа (авто-исчезание ~4 с), OK легко нажимается; окно на своём overlay-слое.

## Migration Plan

1. Реализовать `ResourceCollectPopup` (Control) + маппинг `resource_id → текстура/название`.
2. Подписать координатора (AdventureUI) на `GameEventBus.resource_extracted`.
3. Расширить `collect_resource_at` выпуском сигнала с `resource_id`/количеством (путь простого сбора / `COLLECT_HERE`).
4. Показать окно по событию; OK закрывает + таймер авто-исчезания.
5. Верификация `game/tools/shell/run_operability.sh` → `CLEAN`.
6. Откат: отменить коммит цикла (окно/подписки); логики экономики не меняли.

## Open Questions

- **Формат спрайта инок.** Один спрайт/атлас с регионами (нужны координаты/размеры регионов на ресурс) или отдельные PNG на каждый ресурс? Определяется по поставке заказчиком; маппинг `resource_id → текстура/регион` остаётся данными.
- **Точные ID ресурсов.** Какие `resource_id` из `ResourceRegistry` реально используются на карте, чтобы маппинг инок покрывал все возможные для сбора ресурсы (богатые узлы + простой сбор).
