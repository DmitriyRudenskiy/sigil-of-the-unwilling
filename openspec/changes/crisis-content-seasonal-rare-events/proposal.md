# Proposal: crisis-content-seasonal-rare-events

**Status:** Open (propose)
**Scope-out from:** `dynamic-world-crisis-system` (задачи 2.4 «сезонные события» и 2.5 «редкие события» — JSON-контент не написан; система-контейнер готова)

## Why

Механика кризисов реализована (`crisis_event_system.gd`, `world_seasons.gd`, загрузчик `game/data/events/*.json`: 8 crisis + 10 event файлов, `events_database.json`). Но контентная матрица неполная: события не имеют сезонной вариативности (Seasons: spring/summer/autumn/winter уже существуют как `season.gd` + `WorldSeasons.season_name()`), и нет редких событий с низким весом. Это content-цикл без изменений ядра — чистые данные + минимальные расширения схемы.

## What Changes

- Расширение схемы события в JSON: поля `seasons: []` (допустимые сезоны), `weight` (шанс появления), `rarity: common|rare`.
- **Сезонные события:** ≥8 новых JSON (например, половодье весной только при flood-рельефе, неурожай летом, осенняя распутица, зимние морозы — часть пересекается с существующими `crisis_07_flood`, `event_10_cold`, которые получат теги сезонов).
- **Редкие события:** ≥4 JSON с `rarity: rare`, вес ≤0.05 (комета, затмение, драконье нашествие, золотая жила).
- Роллер выбора событий учитывает сезон и вес (минимальная правка селектора в crisis/event системе + тесты детерминизма по seed).

## Capabilities

### Modified Capabilities
- `crisis-events` (delta из dynamic-world-crisis-system): требование «селектор событий учитывает сезон и вес» — ADD при sync.

## Impact

- Данные: `game/data/events/*.json` (+12 файлов, +теги у 18 существующих), схема в загрузчике
- Код: селектор событий (одна функция) + unit-тесты; ядро не меняется
- Баланс: частота кризисов не должна вырасти — веса нормируются, проверка через balance_probe
- Сейвы: не затрагиваются (события stateless до триггера)

## Acceptance Criteria

- [ ] 1. Схема JSON принимает seasons/weight/rarity, старое содержимое валидно без изменений (backward compat)
- [ ] 2. Селектор никогда не выдаёт летнее событие зимой (детерминированный тест по seed)
- [ ] 3. Редкие события наблюдаемы статистически (≥1 за ~200 ходов симуляции) и не чаще weights-лимита
- [ ] 4. Общий темп кризисов в допуске balance_probe
- [ ] 5. Полный прогон зелёный; delta synced; цикл архивирован
