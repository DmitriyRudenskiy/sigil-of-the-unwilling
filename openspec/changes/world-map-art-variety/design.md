## Goals / Non-Goals

**Goals:**

- Карта не читается как «одна клетка»: мера «не паттерн» зелёная, порог зафиксирован.
- Семь слоёв вместо двух; дороги, горы, лес и добыча имеют визуальный носитель.
- Пиксель сделан существующим контуром, прошёл §8.5 и провенанс; партия воспроизводима.
- Приёмка машинная и не молчит: файлы + живой рендер, находки не лечатся порогом.

**Non-Goals:**

- Перекраска живых зданий и 95 юнитов под новый канон (ждёт вердикта Q-M89, отдельный
  тикет), экран города, боевая тайл-графика.
- Кадровая анимация (вода, листва, дым), сезонная перекраска террейна, зима/осень.
- Новые биомы и правки генерации террейна (высоты, разломы, кластеры лесов — как есть).
- Изменение экономики добычи: меняются **правила размещения**, а не выработка.

## Decisions

### 1. Полоса карты меряется с канонического кадра экрана кампании

Носителем палитры карты назначается `reference/10_map_campaign_town.jpeg`: экран
кампании и есть карта, и это единственный канонический носитель, изображающий её же.

*Альтернативы.* (а) Полоса `C′` (живые здания + старый `world_tiles.webp`) — держит
едиобразие с юнитами на карте, но закрепляет тёплую меру, которую новый канон (кадры
`09…12`) объявляет дрейфом, и консервирует именно тот атлас, который меняем. (в) Две
полосы по сцене — верно, но требует правила выбора и двойной приёмки; это содержание
Q-M89, а не этого среза. *Цена решения:* юниты на карте могут оказаться теплее новой
земли → ловится мерой контраста силуэта, лечится тикетом перекраски, а не молча.

### 2. Вариант тайла = низкочастотная маска + хэш клетки, в модель и сейв не пишется

`variant = mask(cell, seed)` — где маска даёт пятна (2–4 клетки одного варианта
рядом), а хэш разрешает коллизии соседей (сосед ≠ сосед). Пересчёт при каждой
отрисовке из `(cell, seed)`, состояние не хранится.

*Альтернативы.* Чистый хэш клетки даёт «конфетти» — пестрящий ковер вместо земли;
Perlin-поле, записанное в модель, — правдоподобнее, но лезет в сейв и в `save-migration`
ради пикселя; случайный бросок рантайма ломает детерминизм картинки после загрузки.

### 3. Переходы — ручной замкнутый набор + тест полноты, не Godot terrain sets

Атлас строится кодом (`TileAtlas.build()`), поэтому набор переходов остаётся
декларативным (`TRANSITION_ART` + повороты альтернативных тайлов), а полнота
доказывается тестом: генерируется карта, покрывающая все допустимые пары соседств, и
проверяется, что переход есть для каждого направления.

*Альтернатива* — terrain sets движка (autotiling): покрывает комбинации автоматически,
но для гексов требует разметки в редакторе, которую нельзя ни сгенерировать из кода, ни
прогнать headless-мерой, а сборка тайлсета у нас и так рантайм-код.

### 4. Детали — отдельный overlay-слой, а не «база с примесью»

База остаётся чистой и перевыпускается без перевыпуска деталей; плотность и набор
деталей — константы. Дешевле итерировать и то и другое по отдельности.

### 5. Материал биомa: один бесшовный холст → N вариантов оборачивающим кроем

Рисуется материал в 512² (≈6× тайла), делается бесшовным (offset 50 % + зашивка шва
либо зеркальная сборка), затем из него выкраиваются 4 окна **с.wrap-семантикой**:
всякое окно бесшовного холста бесшовно по построению. Варианты получают
статистически одинаковую фактуру, а не четыре разных угадывания модели.

*Альтернативы.* Четыре независимых промпта на биом (разная фактура = «не та земля»);
процедурный шум из палитры (математически бесшовен и дёшев, но плоский на вид — им
делаем overlay-детали, если генератор недоступен).

### 6. Объекты — изолированные спрайты с якорем по нижнему краю

Деревья, скалы, ресурсные постройки, подложки стеков: 1024², прозрачный фон, автокроп,
2–3 размера на тип, тень — отдельный элемент под объектом. Якорь по нижнему краю
клетки нужен y-sort'у слоёв объектов.

### 7. Ресурсы по биомам — таблица в конфиге, старые сохранения не переигрываются

`game/data/config/biome_resources.json` получает таблицу «биом → допустимые типы
ресурсов» (структура `{"biomes": {биом: [имена типов]}}`); спавн (`place_resources`,
v2) выбирает один тип из списка биома клетки, доля «своих» биомов (`home_share`)
и количество по типам печатаются в отчёте генерации (`resource_report`).
Старые сохранения: уже открытые узлы не трогаются, новые партии — по новым правилам
(версия сохранения 8→9, `generator_version` 1→2). *Альтернатива* — пересоздать
раскладку при загрузке: детерминированно, но игрок теряет привычную карту и добычу
ради пикселя.

*Маппинг (классические id 0..6; STONE=7 на карте не спавнится — городская автовыдача):*
`forest`/`dense_forest` → `[wood]`; `snow` → `[ore, crystal, gems]`; `sand` →
`[ore, crystal, gems]`; `grass` → `[gold, ore, crystal, gems, wood]`; `swamp` →
`[mercury, sulfur]`. Группы спеки маппятся на id (в классическом каталоге нет отдельных
дичи/продовольствия/скота/трав): продовольствие/скот → `gold` (равнины — торговые
земли), травы → `mercury`/`sulfur` (алхимические болота).

*Решение по балансу (9.5):* проходимые высоты — только SNOW (0.9% клеток; MOUNTAIN
непроходима). Строгая привязка «камень/руда → только SNOW» давала руду 0.1/карту при
базовых 11.3 — кампания ломалась. Поэтому группа камня/руды расширена на SAND
(пустыня: песчаник/камни) и GRASS (равнины: кремень/отвалы) — геологически оправдано,
спека не запрещает (она требует только: лес→дерево без руды, высоты→камень/руда,
непроходимые→ничего). Итог (50 сидов, `tools/diag_biome_resources.gd`): камень/руда
12.7/карта (база 11.3 — не хуже), wood 6.8 (база 3.7), gold 3.4 (база 3.7),
mercury/sulfur ~0.9 (база ~3 — алхимическая ниша редче; флажок владельцу). Числа —
данные, не код: правка таблицы не требует правки спавнера.

### 8. Туман войны для объектных слоёв — модуляция, а не второй атлас

База остаётся с `FOG_SOURCE_ID` (уже работает), объектные слои затемняются
модуляцией цвета узла: второй набор спрайтов «в тумане» удвоил бы ассеты и бюджет.

### 9. Гейты: файловый чекер + снимок живого рендера

`scripts/check_map_art.py` (файлы атласа и объектов: seamless, разрешение, имена,
палитра, вес, контраст силуэта) и MCP e2e-тест, снимающий `world.tscn` и прогоняющий
меры «не паттерн», палитру и читаемость по пикселям экрана. Файлы зелёные ≠ рендер
зелёный: раскладка — отдельный источник дефектов.

Мера «не паттерн» = доля различных клеток-тайлов кадра + корреляция кадра с его
сдвигом на вектор решётки (периодичность). Пороги калибруются прогоном **на текущем
состоянии** — гейт обязан покраснеть на карте из одного тайла на биом, иначе он меряет
не то, ради чего затевался.

### 10. Порядок внедрения: атлас → слои → данные

Каждый шаг с собственным зелёным прогоном: атлас с вариантами заметен без новых слоёв,
слои заметны со старым атласом, привязка ресурсов к биомам — отдельный диф с
баланс-прогоном. Откат любого шага — откат одного шага.

## Risks / Trade-offs

- [Диффузная модель мылит на 82 px] → материал в 6× + unsharp перед квантованием;
  в гейт добавлена мера резкости (энергия границ), падает на «каше».
- [Земля новая, юниты старые → карта «разноцветная»] → контраст-мера силуэта ловит
  только читаемость, вкус остаётся за вердиктом владельца; тикет перекраски
  регистрируется сразу, а не после мержа.
- [Рост атласа (10 биомов × 4 варианта + переходы + детали)] → бюджет: webp q85,
  сторона ≤ 2048, вес ≤ 1.5 МБ, тест веса в чекере; при переполнении — второй лист,
  а не даунскейл.
- [Комбинаторный взрыв переходов] → переходы только для пар, реально встречающихся на
  карте; тест-замыкание валит и недостающий переход, и «мёртвый» тайл без соседа.
- [Привязка ресурсов к биомам сузит руду/камень → кампания непроходима] → метрика
  доли и количества по типам в отчёте генерации + действующий баланс-прогон
  (`balance-probe`) до мержа; выработка не трогается.
- [ComfyUI недоступен / нет X-дисплея на шарящейся машине] → гейт печатает
  `SKIPPED (причина)` (конвенция MCP-секции), партия откладывается; overlay-детали
  допускают процедурный fallback без смены спеки.
- [Семь слоёв → просадка FPS на большой карте] → замеры до/после на 60×60, слои
  отключаемы признаком; при просадке — объединение базы и стыков (решение фиксируется,
  а не делается молча).

## Migration Plan

1. Новый атлас и объекты кладутся рядом со старыми (`tiles/world_map_atlas.webp` +
   `objects/`), старый файл остаётся до зелёного гейта; путь — константа.
2. `TileAtlas.build()` читает новый атлас, при его отсутствии — старый + `push_error`
   (спека `world-map-tile-atlas`, «Резервный атлас»).
3. Версия сохранения: +1; загрузчик прежней версии не переигрывает раскладку ресурсов
   (спека `terrain`), новая генерация идёт по таблице биомов.
4. Откат — смена константы пути атласа и отключение новых слоёв признаком; данных не
   ломается ничего.
