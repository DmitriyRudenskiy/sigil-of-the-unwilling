## Why

В репозитории есть большой пошаговый/тактический бой основного проекта
(`openspec/specs/tactical-combat`), но нет ни одного изолированного носителя,
который проверял бы весь путь «спрайт из ComfyUI → анимированный юнит →
пошаговый бой → боевой UI» целиком и без участия человека. Такой носитель нужен
как полигон конвейера: девять персонажей из `Новая папка с объектами 2` должны
быть нарисованы MCP-ом, приняты машинной проверкой и отыграны в бою, а весь
визуальный контроль — выполнять агентом, а не владельцем.

## What Changes

- **Новый самодостаточный Godot 4.7-проект `battle-demo/`** (свой `project.godot`,
  `assets/`, `data/`, `scenes/`, `tests/`, `docs/`, `artifacts/`, `CHANGELOG.md`).
  Основной `game/` не трогается ни на один файл.
- **Девять спрайт-листов** (по одному на персонажа из директории-источника):
  PNG с альфа-каналом, кадр 512×512, анимации `idle` / `walk` / `attack` /
  `hit` / `turn` («стоит / идёт слева направо / наносит удар / принимает удар /
  поворачивается») по 4–8 кадров, общий pivot «низ-центр», единый масштаб,
  нейминг `char_<side>_<name>_<anim>_<NN>.png`. Гибель — не анимация: юнит
  замирает в последнем кадре и обесцвечивается.
- **Генерация через ComfyUI** (`192.168.0.230`) — кадр редактированием
  изображения (`qwen-image 2.1 image edit`) по **кадру-источнику персонажа** и
  **DWPose-карте позы** (скелет извлекается `dwpose-cli.py` из кадра-источника
  своего же персонажа и правится с сохранением его пропорций), а не по текстовому
  описанию внешности; прогон — свой
  раннер с `POST /prompt`, возобновляем (готовый кадр не перерисовывается),
  сбои логируются, а не проглатываются.
- **Пошаговое боевое ядро без нод** (`UnitStats`, `Action`, `StatusEffect`,
  `TurnQueue`): очередь по инициативе, формула урона, статусы, условия
  победы/поражения. ATB и real-time не делаются.
- **Два набора по 7 юнитов** (данные `.tres`, не код): пул игрока = 8 персонажей,
  набор A = юниты 1–7, набор B = юниты 2–8; враг — девятый, общий для обоих
  боёв. Выбор набора — перед боем; смена набора не требует правок кода.
- **Боевой UI**: HP-бары над юнитами, полоса порядка ходов, панель способностей,
  селектор набора A/B, экран результата; всё синхронно с `CombatState`.
- **Автономная визуальная приёмка**: скриншоты всех ключевых состояний боя
  снимаются скриптом в `artifacts/screenshots/`, а оценку «стиль / артефакты
  генерации / читаемость UI» выполняет агент-читатель (vision-чтение кадра по
  чек-листу) с сохранённым отчётом. Формулировок «покажите пользователю» нет.
- **Вне скоупа:** аудио, полировка (hit-stop, частицы, тряска), сюжет, уровни,
  локализация, мультиплеер, сохранения, лайв-опс.

## Capabilities

### New Capabilities

- `battle-demo-sprites`: девять спрайт-листов обязаны соответствовать стилевому
  контракту и техническим требованиям (размер кадра, альфа, число кадров,
  pivot, нейминг) и проходить программный аудит плюс визуальную проверку
  агента-читателя с сохранённым отчётом.
- `turn-battle-core`: пошаговые боевые правила — инициатива, действия хода,
  урон, статусы, победа/поражение — живут в чистой модели и полностью
  покрываются тестами; бой 7+1 проходит от старта до экрана победы.
- `roster-lineups`: составы наборов A/B — данные; набор ровно из 7 юнитов пула,
  враг присутствует всегда, A∪B покрывает все 8 юнитов пула, ядро боя работает
  с любым составом без правок.
- `battle-demo-ui`: боевой HUD (HP, полоса ходов, панель способностей, селектор
  набора, экран результата) обязан оставаться синхронным с состоянием боя в
  обоих наборах и проходить читаемость по автоматическим скриншотам.

## Impact

- **Код/ассеты:** только новое дерево `battle-demo/`. `game/`, `docs/`,
  `scripts/` не изменяются.
- **Почему отдельное дерево, а не пути из ТЗ (`docs/decisions.md`,
  `CHANGELOG.md`, `data/`, `project.godot` в корне):** проверено на этой машине —
  `docs/decisions.md` на case-insensitive APFS раскрывается в существующий
  `docs/DECISIONS.md` (реестр решений), `CHANGELOG.md` и `data/` в корне тоже
  заняты. Запись по пути из ТЗ молча перезаписала бы реестр решений и корневой
  changelog. Все артефакты демо лежат под `battle-demo/`, имена — как в ТЗ.
- **Тестовый фреймворк:** GdUnit4 (уже аддон `game/addons/gdunit4`, уже
  заведён headless-раннер), а не GUT из ТЗ — отклонение зафиксировано ADR
  (`battle-demo/docs/decisions.md`), потому что второй фреймворк в проекте —
  лишний раннер, лишний гейт и лишняя точка отказа.
- **read-агент:** в этой среде нет инструмента субагентов, поэтому «ридер» —
  тот же агент, читающий кадр vision-инструментом `read` и пишущий отчёт в
  `battle-demo/docs/`. Протокол (вход/выход/3 итерации/known-issues) сохраняется.
- **Внешние зависимости:** ComfyUI `192.168.0.230:8188` через MCP `comfy-mcp`
  (проверен: инструменты зарегистрированы); Godot 4.7 локально; исходники —
  `/Users/user/sigil-of-the-unwilling-slop/Новая папка с объектами 2`
  (9 файлов, 1024²/2048², альфы нет ни у одного — альфу даёт генерация).
- **Документация:** отчёты и ADR — внутри `battle-demo/docs/`, чтобы не
  попадать в Obsidian-граф `docs/` (фронтматтер + `check_docs_links.py`).
- **Связанные тикеты/разрывы:** `docs/mvp/TICKETS.md` — при появлении расхождений.
