# Design

## Context

`threat_system.gd` реализует: функция давления (Base=4.0, Wealth=clamp(1+0.005×запасы,0.5,2.0), аномалия=1.0, рост 1+0.05×ходов, фазы {1:1.0,2:1.25,3:1.5,21:2.0}), SM (IDLE/CHARGING/INBOUND/STRIKE/RESOLVED/COOLDOWN), тиры (пороги 30/100/250, power 15/30/60 — raids.json, K-T5/R6), defense (барраки 0.2), директивы 7/21 (K-M9/K-R3, BIT_TURNS), зима (enemy_mult 1.25, WorldSeasons), цель (score = 0.5×видимость + 0.3×уязвимость, видимость = константа 1, тай-брейк id — I1). `raids.json`: `loss_cap_per_day = 0.3`, инертные ключи `visibility_formula`/`target_score`/`target_weights` (09-risks).

## Goals / Non-Goals

**Goals:** формализовать канон §3.8; per-ресурсные капы (T-127: еда ≤40%, железо/оружие ≤30%); cooldown ×2 при «все районы разрушены»; пометка инертных ключей.

**Non-Goals:** авто-режим боя (dnd-battle-ladder), карта (region-graph-map), «видимость» как механика (MVP = константа 1, Q-M54→(в); 1.0: формулы), аномалии (крюк, MVP = 1.0).

## Decisions

- **Давление вместо календаря (K-T5, 2026-10-02)**: рейд = пересечение порога накопителя; календарь (каждые N ходов) — legacy.
- **Per-ресурсные капы (Q-M58→(в), D-189)**: еда ≤40%, железо/оружие ≤30% за рейд (в пределах хода). Код: единый `loss_cap_fraction = 0.3` (T-127) — расхождение C-4; реализация капов — задача 2.1.
- **Цель (C-17)**: документ «случайный из 3 ресурсов (веса 0.5/0.3/0.2)» vs код (score = 0.5×видимость + 0.3×уязвимость, видимость = константа 1). В MVP эквивалентно (видимость константа → score константа → тай-брейк id); синк формул — задача 3.1.
- **Директивы (K-R3)**: floor (первый ≈ ход 7, финальный к ходу 21) — не ломаются «все районы разрушены» (cooldown ×2 вместо).
- **Сезоны (Q-M27/Q-M29)**: 4 сезона, season_index = (turn−1) % 4, ход 1 = весна; зима = 4/8/12/16/20; production_mult {1.0/1.2/1.0/0.4}; enemy_mult зима 1.25.
- **Герой в городе → бой** (CR 1/2/6); герой в походе → авто-рейд (defense = здания 13.3).
- **AFK-каскад (FS)**: капы per-рейд, нет цепного коллапса; все районы разрушены → город выживает (производство −50%, частота −50% = cooldown ×2).
- **EC**: рейд по зданию на ремонте → ×0.5 к RUINED; рейд по клетке героя → бой, победа → −50% последствий.

## Risks / Trade-offs

- [C-4: per-ресурсные капы vs единый 0.3] → документ ведёт код; реализация капов — задача 2.1 (T-127).
- [C-5: инертные ключи raids.json] → пометка «1.0, не читается» или реализация (задача 3.1); не дублировать формулы.
- [C-17: формула цели] → в MVP эквивалентно; синк формул — задача 3.1.
- [Аномалия = 1.0 (крюк)] → не реализована (MVP = 1.0); 1.0: формулы аномалий.
