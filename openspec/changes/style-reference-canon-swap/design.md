# Design: style-reference-canon-swap

## Context

См. `proposal.md` — Why. Здесь — только состояние, которое формирует подход.

- **Реестр стиля двухслойный.** Пиксели лежат в `reference/` и **исключены из git**
  (`.gitignore`: `reference/*` + `!reference/INDEX.md`), в git — только карта и тексты
  `docs/13`, `docs/17`. Следствие: «удалить референсы из проекта» для пикселей =
  удалить локально, и git их не вернёт.
- **Карта = единственный указатель.** `reference/INDEX.md` (57 строк) связывает
  каноническое имя ↔ исходник в архиве `___STYLE_BOOK/for_local_agent/` ↔ категорию ↔
  лицензию. Нумерация 01–57 — порядок сортировки того архива; на неё ссылается
  замороженный аудит `docs/12-asset-audit.md` (status `snapshot`) и его CSV-реестр.
- **Документы стиля ссылаются на номера.** `docs/13-art-bible.md` rev2: §4.6 (замеры
  57 файлов), §10 (карта семейств по номерам), §10.2 («файлы 14/15 остаются в
  reference как доказательство отрицательного решения»), §12 (свип провенанса против
  `reference/` 55 + `___STYLE_BOOK/` 105). `docs/17-ui-style-guide.md` §2 — типографика
  (PT Serif + PT Mono, OFL, три файла в `game/assets/fonts/`).
- **Что приехало вместо (замерено на машине, 2026-10-14):**

  | Файл владельца | Мера | Что это |
  |---|---|---|
  | `1.jpeg` | 2048×2028, 1.3 МБ | лист юнитов/ресурсов/предметов/зданий: яркая живопись, сочный зелёный, тёплый свет |
  | `amber-meadow_a_Make_font.png` | 2208×1152, 3.8 МБ | титульный леттеринг «SIGIL OF THE UNWILLING»: золотая антиква с засечкой-шипом, тёмный фон |
  | `1791443738974-…png` | 1672×941, 4.3 МБ | экран города: гексы с золотым свечением + тёмная панель с золотом (русский UI) |
  | `1791970213325-…png` | 1254×1254, 2.7 МБ | лист «Знаков»: круглые кованые медальоны со светящимся глифом |
  | `1791966761829-…(1).jpeg` | 2048×2048, 348 КБ | ритуальный круг семи знаков на чёрном (алтарь, изометрия) |
  | `1791981172260-…jpeg` | 2496×1664, 1.1 МБ | коллаж 4 экранов: герой/инвентарь, бой на гексах, карта приключений, меню с портальным «Знаком» |
  | `fa-light.woff2` | 7.5 КБ | **Font Awesome 6 Pro Light 6.7.2**, 68 глифов / 67 кодовых точек, лицензионной записи внутри нет |
  | `fa-solid.woff2` | 6.2 КБ | **Font Awesome 6 Pro Solid 6.7.2**, 68 глифов / 67 кодовых точек, лицензионной записи внутри нет |

- **Проверено:** Godot 4.7.2 импортирует `.woff2` как `FontFile`
  (`importer="font_data_dynamic"`, проба `--import` на копии файла) — конвертации в
  ttf/otf не требуется. `scripts/check_asset_provenance.py` не считает `.woff2`
  медиа (`MEDIA_EXT` без него) — шрифт в `game/assets/fonts/` пройдёт мимо чекера
  провенанса.

## Goals / Non-Goals

**Goals:**

- В `reference/` — ровно новый комплект; карта описывает его целиком; старый комплект
  отсутствует и не всплывает.
- `docs/13-art-bible.md` rev3 и `docs/17-ui-style-guide.md` не содержат ни одного
  утверждения о файле, которого больше нет, и ни одного номера 01–57 без пометки
  «вытеснено».
- Канон стиля остаётся проверяемым: карта ↔ диск, и ни один шаг не требует
  смотреть «на глаз».

**Non-Goals:**

- `game/` — тема, UI-сцены, `game/assets/fonts/`, иконочные ассеты. Носители
  подключаются после решения по лицензии (билет ASSET-3), по образцу D-184
  («документ → приёмка → фаза»).
- Перекраска живых ассетов под новый комплект. Пересчёт полос — это таблица
  расхождений, а не санкция на правку пикселей.
- Архив `___STYLE_BOOK/for_local_agent/` (вне репо, не «проект») — не удаляется,
  только перестаёт быть ссылкой канона.
- `docs/12-asset-audit-registry.csv` — не переписывается.

## Decisions

### 1. Именование: своя нумерация `01…08` + семантическое имя

`01_sheet_units_resources_items_buildings.jpeg`, `02_title_lettering_gold_serif.png`,
`03_city_hex_screen_ru.png`, `04_sheet_sign_medallions.png`,
`05_ritual_circle_seven_signs.jpeg`, `06_collage_ui_four_screens.jpeg`,
`07_fa6_pro_light.woff2`, `08_fa6_pro_solid.woff2`.

Альтернативы: (а) исходные имена владельца (`1791966761829-01a13988-….jpeg`) —
не читаются ни человеком, ни grep; (б) продолжить старую нумерацию с 58 —
правдоподобная ложь о преемственности: номера 01–57 живут в замороженном аудите,
и «58» будет прочитан как часть того же архива. Исходное имя сохраняется отдельным
полем карты, поэтому связь с поставкой владельца не теряется.

### 2. Пиксели по-прежнему не в git; карта получает md5 каждой строки

Политика `reference/*` в `.gitignore` сохраняется (альтернатива «коммитить канон»
— +13 МБ бинарей в истории репо ради файлов, которые агент всё равно не читает
пикселями). Чтобы канон, живущий вне git, не стал недоказуемым, каждая строка карты
несёт **md5 файла**: дрейф пикселя виден по изменению строки в diff, а удаление
комплекта — по удалённой строке. Это же ответ на «а что тут лежало до замены»:
содержимое карты предыдущей ревизии (git history) остаётся доказательством.

### 3. Форматы не перекодировать

Файлы копируются побайтово (JPEG остаётся JPEG). Старая политика rev2 гнала всё в
WEBP q82; для комплекта из 8 файлов это потеря ровно того, что утверждено глазами:
канонический пиксель перестаёт быть побитовым, а экономия (несколько МБ вне git)
ничего не даёт. Побочный плюс: md5 из строки 2 совпадает с md5 файла владельца.

### 4. Типографика: три роли, ни одного нового файла в репо

| Роль | Канон | Носитель сегодня |
|---|---|---|
| Титул/бренд | золотая антиква из `02` (засечка-шип, вытянутый контраст) | **нет файла** — есть только леттеринг-образец PNG |
| Body / числа | PT Serif + PT Mono (OFL, кириллица) — без изменений | `game/assets/fonts/` (3 файла) |
| Служебные глифы UI | Font Awesome 6 (Solid — активный, Light — вторичный) | `reference/07,08` (вне git), в `game/assets/fonts/` **не кладутся** |

Основание не трогать body-роль: PT Serif — единственный носитель с полной кириллицей,
OFL и уже подключённый в теме; UI по-русски (см. `03` — «Мой Город», «ПОСЕЛЕНИЕ»).
Trajan-подобные антиквы кириллицы не несут, поэтому титульная роль **ограничивается
носителями, где она физически возможна** (логотип, титульный экран, EN-заголовки),
а русские заголовки остаются на PT Serif Bold до появления кириллического
дисплей-файла. Альтернатива «заменить всё на дисплейную антикву» отклонена: она
неисполнима на кириллице и ломает посчитанные WCAG-контракты `docs/13` §4.2.

Шрифт в репо не добавляется до закрытия вопроса о правах (FA **Pro** — платная
подписка; Free-набор закрывает те же 67 точек почти целиком, но требует атрибуции
CC BY 4.0). Причина не прятать FA в `reference/` навсегда: `reference/` — эталон,
а не хранилище зависимостей; ASSET-3 решает, что именно едет в `game/assets/fonts/`
(там же — добавить `.woff2` в `MEDIA_EXT` чекера провенанса).

### 5. Что делать с записями rev2 про удалённые файлы

Решение переживает файл: формулировка «отвергнуто: кожа + красное тиснение +
скруглённые слоты» остаётся в §10.2, ссылка на `14/15` заменяется на «вытеснено
комплектом 2026-10-14, доказательство — запись D-184, не файл». §4.6 пересчитывается
по новому комплекту (тот же метод: 8-кластерное квантование, lum/sat по семействам),
и результат кладётся в документ числом, а не словом «ярче». §12 помечается:
эталонная сторона свипа удалена, потолок метода зафиксирован, **ASSET-1 не закрыт**
(чужой пиксель лежит в `game/assets/textures/resources.png`, а не в `reference/`).

### 6. Замороженный аудит — одна строка шапки, не переписывание

`docs/12-asset-audit.md` (status `snapshot`) и его CSV построены на нумерации 01–57.
По конвенции реестров снимок не редактируется; чтобы читатель не пошёл искать
несуществующие файлы, в шапку добавляется одна строка «комплект 01–57 вытеснён
2026-10-14, канон — `reference/INDEX.md`» и `date` в frontmatter. CSV не трогается.

### 7. Гарант — отдельный скрипт, не CI-шаг

`scripts/check_reference_index.py` в стиле `check_asset_provenance.py`
(stdlib, regex-строка, ненулевой выход при находках): парсит таблицы
`reference/INDEX.md`, проверяет уникальность имён, существование файла на каждой
строке, наличие строки на каждом файле `reference/`, легальность статуса и
наличие md5. В `scripts/ci2_checkers.sh` **не добавляется**: CI-2 работает по
git-индексу, а пикселей там нет — чекер был бы вечно зелёным (тот же класс
соображения, что уже вынес `addons/` и `openspec/` из CI-шага про `.import`).
Запускается локально рядом с `check_docs_links.py`.

### 8. Граница change: что в него сознательно не вошло

Внешний план (`add-style-canon-v2`, написан по несуществующей структуре репо) разобран
по пунктам; принята из него одна вещь — приоритет эталона над документацией
(требование в `specs/style-reference-archive/spec.md`). Остальное — сюда не переносится:

- **Нератифицированные пороги** («замена документа при >30% противоречий», «чек-лист
  из 7 пунктов с порогом ≥4/5») не принимаются: ни одно решение этого change не
  опирается на измерение «доли противоречий». Если пороги понадобятся — они становятся
  отдельной записью `docs/DECISIONS.md`, а не метрикой в требовании.
- **Пути и имена** внешнего плана (`docs/art-bible.md`, `docs/asset-spec.md`,
  `docs/design-system/ui-tokens.md`, `docs/asset-audit.md`, `docs/archive/`,
  `art/canon/`) в репо отсутствуют. Действуют фактические `docs/13`, `docs/15`,
  `docs/17`, `docs/12-asset-audit*` и `reference/`; снапшоты не перемещаются
  (конвенция реестров — снимок остаётся на месте со `status: snapshot`).
- **Capability `game-art-direction` не является живой**: в `openspec/specs/` её нет
  (дельта rev2 жила в незакоммиченном каталоге и была удалена), поэтому требования
  арт-направления живут только в `docs/13-art-bible.md`, а любое новое — `ADDED`.
- **Новые документы будущего контура** концепт-арта именуются по конвенции репо:
  `docs/18-style-canon.md` (паспорт стиля: замеры, роли носителей) и
  `docs/19-concept-registry.md` (реестр статусов концептов) — латиница, `NN-topic.md`,
  обязательный frontmatter (`title`/`tags`/`status`/`date`), wikilinks без пути,
  прогон `python3 scripts/check_docs_links.py`. Ни один из них в этом change
  не создаётся.

### 9. Продакшн-пайплайн генерации — отдельное change, и его предусловие не выполнено

Генерация концептов (comfyui, seed/workflow, жизненный цикл draft → review →
approved/rejected, аудит canon/drift/remake) — не канон документации, поэтому
выведена за объём: иначе зелёные документы оказываются связанными с несуществующей
инфраструктурой. Проверено на машине 2026-10-14: **ComfyUI нет** — ни MCP-сервера
(`~/.pi/agent/settings.json` секции mcp не содержит; `~/.minimax/mcp/mcp.json` —
matrix/playwright/cu/trash, `~/.lmstudio/mcp.json` пуст), ни установки
(`~/ComfyUI`, `/Applications/ComfyUI*` отсутствуют, `comfy`/`comfyui` не в PATH,
на 8180–8189 никто не слушает). Имя «comflyui» в переписке — опечатка от ComfyUI.
Прежде чем заводить change, владельцу нужно закрыть: (П1) ComfyUI установлен и доступен
через MCP; (П2) статус текущего UI-канона (на нём висят открытые UI-4/UI-5/UI-6),
политика git для эталонов, состав первой партии концептов.

## Risks / Trade-offs

- **[Пиксели старого комплекта теряются безвозвратно]** → до удаления в карту
  предыдущей ревизии заносятся имена + md5 всего 55-файльного комплекта, а в PR —
  путь исходного архива; возврат возможен из `___STYLE_BOOK/` (он не трогается).
- **[«Новый комплект ярче» ⇒ все живые ассеты вдруг вне канона]** → §4.6 даёт
  измеренные полосы и таблицу «токен ↔ референс ↔ решение»; расхождение живых
  ассетов — строка таблицы с билетом, а не молчаливая перекраска.
- **[FA Pro без прав уедет в репо]** → файлы живут только в `reference/` (вне git),
  в `game/assets/` не копируются; ASSET-3 + вопрос в `docs/QUESTIONS.md` блокируют
  подключение до решения владельца.
- **[Документы останутся с номерами 01–57]** → grep-проход `reference/|референс[0-9 ]|№[0-9]`
  по `docs/*.md` как задача, и `check_docs_links.py` (битые wikilinks) как гейт.
- **[Карта начнёт расходиться сразу после PR]** → гарант + md5 в строке; расхождение
  ловится до коммита, а не через месяц.
- **[Один человек смотрит на 8 файлов и решает стиль]** → документ фиксирует, что
  именно взято с каждого носителя (поле «для чего»), и что осталось открытым
  (радиусы, «Знак», школы магии) — спор сводится к строке карты, а не к вкусовщине.

## Migration Plan

1. Копирование 8 файлов в `reference/` с каноническими именами; сверка md5 и мер.
2. Перезапись `reference/INDEX.md` (8 строк + словарь статусов + «почему не в git»);
   в diff карты — хвост со старыми именами/md5 вытесненного комплекта (строка 2).
3. Удаление 55 старых пикселей из `reference/`; `git status` чист (пиксели не в git) —
   доказательство удаления = листинг PR.
4. Документы: `docs/13` rev3 → `docs/17` → реестры (`DECISIONS` D-185/D-186,
   `CHANGELOG`, `QUESTIONS`, `TICKETS` ASSET-3) → строка шапки в `docs/12-asset-audit.md`.
5. Гарант `scripts/check_reference_index.py` + прогоны: гарант,
   `python3 scripts/check_docs_links.py`, `game/run_tests.sh` (ожидание — без
   изменений: `game/` не тронут).
6. **Откат:** документы — `git checkout`; пиксели — повторное копирование из папки
   владельца (обратимый шаг 1). Шаг 3 необратим только для локальной копии, поэтому
   он идёт после шага 2.

## Open Questions

- Какой именно файл шрифта стоит за леттерингом `02` (или это нарисованный логотип),
  и есть ли у него кириллица — Q-M38, носитель: ASSET-3.
- Font Awesome Pro (права/подписка) против Free-набора с атрибуцией — Q-M39,
  носитель: ASSET-3.
- Новый «Знак» (круглый кованый медальон, `04`/`05`) против формулы §9.2 rev2 —
  подтверждается ли формула или переписывается под медальон — решает владелец при
  приёмке rev3; документ фиксирует обе формулы как «до/после», не выбирая молча.
- Скругления на `03`/`06` (скруглённые панели и слоты) против §6 «радиусы 0–2 px» —
  Q-M40: менять правило или считать мокап вне канона формы.
