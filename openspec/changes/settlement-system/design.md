# Design: settlement-system

## Context

- Прототип: `.claude/commands/opsx/proposal-settlement-system.md`
  (PR #4) — 7 видов, Resolve, здания/рецепты, репутация-победа,
  Forest Hostility + штормы, Smoldering City meta, Prestige.
- Текущая игра: герой-вылазки (`HeroController`, армия, города-точки
  `City`/`Borough`). Поселений-поселенцев нет.
- Hex-кластер поселения (ядро 4 тайла + кольца 1–3) — сестринский
  change `city-hex-layout-prototype`; если не готов, поселение
  деградирует до одной клетки (дефолт-миграция того же change).
- Паттерны кодовой базы: статические системы с явным state (Dictionary,
  `QuestSystem`/`FactionReputation`), данные в `scripts/data/*.gd`
  с const-таблицами, сейв через сериализаторы (`CitySerializer`,
  `WorldPersistence`), GdUnit4 unit + MCP-интеграция.
- Игровая рамка: balance-core — герой доживает 60 ходов, endgame
  RUNNING; MCP-проба — детерминированная.

## Goals / Non-Goals

**Goals:**
- 5 видов (human, beaver, lizard, harpy, fox) со статистиками прототипа.
- Караван ≤ 3 видов → поселение на hex-кластере.
- Resolve + 4 потребности (еда/одежда/жильё/сервис), уход при 0.
- Здания: Hearth (уровни 1–3), Warehouse, 5 лагерей, производство
  (1 рецепт), жильё (Shelter 3 / дома 2), автопереселение.
- Репутация-победа, Forest Hostility + штормы, 2 условия поражения.
- Smoldering City: Citadel-ресурсы + перманентные апгрейды + meta-сейв.

**Non-Goals (из прототипа, отложены):**
- DLC-виды (frog L9, bat L11), Rainpunk-движки, Small Warehouses,
  Trading Post/Amber, Prestige 1–10, карты/биомы, glade-события в
  деталях, Firekeeper, туториал.

## Decisions

### D1: Поселение — отдельная сущность мира, не City

`Settlement` (RefCounted + state Dictionary) в `scripts/settlement/`,
отдельно от `City`/`Borough`. Города (City) остаются героической
системой; поселения — свой цикл (Resolve/репутация/штормы).

- **Почему:** City — 11+ процессоров (экономика, население, tech
  tree); вшивать поселенцев в City = риск для 1605 тестов. Отдельная
  сущность = изолированный diff, свои тесты, свой MCP-сценарий.
- **Альтернатива:** расширить City — отклонено: City не имеет
  поселенцев/Resolve, дублирование было бы полным.

### D2: Статические системы с явным state (паттерн QuestSystem)

`SettlementResolve`, `SettlementBuildings`, `SettlementReputation`,
`SmolderingCity` — RefCounted + статические функции, state —
Dictionary. Поселенец — Dictionary в `settlement.state.settlers`.

- **Почему:** детерминизм MCP-проб, лёгкий сейв (JSON-ready),
  тесты без сцены.
- **Альтернатива:** Object-поселенцы — отклонено: сериализация
  и мок-тесты сложнее.

### D3: Поселение на hex-кластере через city-hex-layout-prototype

Поселение занимает `core_cells` (4 тайла) + кольца 1–3: hearth в
`center`, жильё в радиусе hearth, лагеря/производство в кольцах.
Если change не готов — `core_cells` = `[center]` (дефолт-миграция
того же change покрывает это).

- **Почему:** один источник геометрии, не два. Поселение не изобретает
  свою сетку.
- **Риск:** зависимость от сестринского change. Митигация:
  дефолт `[center]` — поселение работает и без кластера.

### D4: Цикл поселения = 1 игровой день (ход)

"Цикл" прототипа (Resolve, голод, производство, стройка) = 1 ход
`on_day_passed` GameManager. Интервалы перелома "2:00" / "1:40" —
переводятся в ходы (2:00 → каждый 2-й ход, 1:40 → каждые 1–2 хода
по таблице вида).

- **Почему:** у игры нет внутридневного времени; ход — единичный
  тик. Перевод в ходы сохраняет ритм прототипа.
- **Последствие:** "год" для Hostility = N ходов (константа,
  дефолт 30).

### D5: Репутация-победа — отдельный endgame-режим

Победа поселения (метр репутации) — новый endgame наравне с
существующим: `SettlementReputation.victory_reached(state)`.
Поражение — 2 условия (нет поселенцев / нестабильность).

- **Почему:** не ломать существующий endgame героя; поселения —
  отдельный режим (MCP-сценарий "поселение доживает").
- **Альтернатива:** репутация поселения = репутация города —
  отклонено: разные системы (городская репутация уже занята
  `ReputationSystem`).

### D6: Smoldering City — отдельный meta-сейв

`SmolderingCity` state хранится в отдельном файле/разделе сейва
(не в `WorldPersistence` прогона). Апгрейды — const-таблица
(`scripts/data/smoldering_upgrades.gd`) + список купленных.

- **Почему:** meta переживает прогоны; смешивание с сейвом поселения
  сломало бы "новая игра".
- **Альтернатива:** отдельный save-файл — отклонено: один сейв,
  отдельный ключ `smoldering_city`.

### D7: Данные видов/зданий — const-таблицы

`settlement_species.gd` (статистика 5 видов из прототипа),
`settlement_buildings.gd` (здания, рецепты, стоимость, требования
уровня). Числа — из прототипа 1:1; TBD (bat, fox/frog/bat houses)
не включены (non-goal).

## Risks / Trade-offs

- **Зависимость от city-hex-layout-prototype** (D3): митигирована
  дефолтом `[center]`.
- **Масштаб**: 5 spec-файлов, ~40 сценариев. Митигация: tasks
  разбиты по фазам, каждая фаза — зелёные тесты.
- **Баланс**: числа прототипа не калиброваны под ходы (D4).
  Митигация: MCP-сценарий "поселение доживает до шторма" как
  баланс-проба; константы в GameNumbers-файле поселения.
- **Прототип-пропасти** (bat stats, цены домов): осознанно не
  заполняем — non-goals, таблица расширяется.

## Migration Plan

1. Фаза 1: виды + караван + поселение-сущность (без кластера —
   дефолт).
2. Фаза 2: Resolve + потребности + уход.
3. Фаза 3: здания (hearth, warehouse, лагеря, производство, жильё).
4. Фаза 4: репутация + Hostility + штормы + победа/поражение.
5. Фаза 5: Smoldering City + meta-сейв.
6. Фаза 6: hex-кластер (после city-hex-layout-prototype) + MCP-
   сценарий + регрессия.

## Open Questions

- Перевод интервалов перелома "2:00" / "1:40" в ходы — точные
  значения (дефолт: 2:00 → 2 хода, 1:40 → 1 ход).
- "Год" для Hostility: N ходов (дефолт 30).
- Целевое значение метра репутации (дефолт 100).
- Доля ресурсов, уходящая в Smoldering City при поражении (дефолт
  50%) / победе (дефолт 100%).
