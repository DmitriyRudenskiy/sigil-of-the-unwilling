# Design: settlement-system

## Context

- Прототип: систематизированное описание (расы, здания, развитие;
  7 видов, Demand/Decadence, Prestige, Smoldering City) +
  `.claude/commands/opsx/proposal-settlement-system.md` (PR #4).
- Текущая игра: герой-вылазки (`HeroController`, армия, города-точки
  `City`/`Borough`). Поселений-поселенцев нет.
- Hex-кластер (ядро 4 тайла + кольца 1–3) — сестринский change
  `city-hex-layout-prototype`; дефолт `[center]` до его готовности.
- Паттерны: статические системы с явным state (Dictionary,
  `QuestSystem`/`FactionReputation`), данные в `scripts/data/*.gd`
  const-таблицами, сейв через сериализаторы, GdUnit4 + MCP.
- Рамка: balance-core (герой доживает 60 ходов), MCP-проба
  детерминирована.

## Goals / Non-Goals

**Goals:**
- 7 видов (5 основных + frog/bat DLC; bat статистика TBD).
- Караван ≤3 → поселение на hex-кластере.
- Resolve + 4 потребности (числа +4..+10, coats/boots), голод/перерыв,
  Firekeeper, уход при 0.
- Здания: Hearth L1–3, Warehouse, 5 лагерей, производство (1 рецепт,
  6 зданий), жильё (Shelter/Big Shelter/дома + цены + улучшения 2
  уровня), сервис/Unified, Small Hearth/Warehouse, Trading Post,
  Rainpunk.
- Demand/Decadence, Hostility + glade + штормы, Prestige 1–10,
  победа/2 поражения.
- Smoldering City: Citadel-ресурсы, апгрейды, ункилоки, meta-сейв.

**Non-Goals:**
- Статистика bat (TBD), карты/биомы/трансформация ландшафта,
  Prestige с remote-механиками, бонус "Кооперация" (3+ лисы, TBD),
  туториал.

## Decisions

### D1: Поселение — отдельная сущность мира, не City

`Settlement` (RefCounted + state Dictionary) в `scripts/settlement/`.
Города (City) — героическая система; поселения — свой цикл.

- **Почему:** City — 11+ процессоров; вшивание поселенцев = риск для
  1605 тестов. Изоляция = свой diff, свои тесты, свой MCP-сценарий.
- **Альтернатива:** расширить City — отклонено: City не имеет
  поселенцев/Resolve.

### D2: Статические системы с явным state (паттерн QuestSystem)

`SettlementResolve`, `SettlementBuildings`, `SettlementReputation`,
`SmolderingCity` — RefCounted + статические функции, state —
Dictionary; поселенец — Dictionary в `state.settlers`.

- **Почему:** детерминизм MCP-проб, JSON-ready сейв, тесты без сцены.

### D3: Hex-кластер через city-hex-layout-prototype

Поселение занимает `core_cells` (4 тайла) + кольца 1–3: Hearth в
`center`, жильё в радиусе hearth, лагеря/производство в кольцах.
До готовности change — `[center]`.

### D4: Цикл поселения = 1 игровой ход

"Цикл" прототипа = 1 ход `on_day_passed`. Break Interval "2:00"/
"1:40" → ходы: 2:00 → каждый 2-й ход, 1:40 → каждый ход, 2:30 →
каждые 2 хода (frog, до калибровки). "Год" для Hostility — N ходов
(константа, дефолт 30).

- **Почему:** у игры нет внутридневного времени; ход — единственный
  тик.
- **Риск:** ритм прототипа (минуты) ≠ ходы; калибровка по
  MCP-сценарию.

### D5: Demand/Decadence — механика репутации вида

Каждый вид генерирует репутацию, когда средний Resolve вида > Demand
вида. За каждое очко репутации максимальный порог Demand снижается
на Decadence → репутация доступнее со временем (декаданс: вид
"разбалтывается").

- **Почему:** точные определения из прототипа (6.3); это ядро
  экономики репутации, не просто "средний Resolve".
- **Последствие:** high-Demand виды (human/beaver, 30) дают
  репутацию позже, но Decadence (+4/+2) быстрее снижает порог.

### D6: Prestige — конфигурация сложности, не отдельный режим

Prestige 1–10 — набор негативных модификаторов (const-таблица
`prestige_modifiers`), включаемых после победы на базовой сложности.
Каждый — отдельный флаг + числовой эффект в соответствующей системе.

- **Почему:** модификаторы точечные (цена, потребление, скорость) —
  встраиваются в существующие формулы, не новый движок.

### D7: DLC — флаг доступа, не отдельный код

frog/bat — виды в таблице с флагом `dlc: "keepers_of_the_stone" /
"nightwatchers"`. DLC = purchased-флаг в meta-сейве. Bat без
статистики зарегистрирован, но `available()` = false до заполнения
данных.

- **Почему:** ункилоки (SC L9/L11) уже в таблице; DLC — просто
  условие доступности, не другая система.

### D8: Данные — const-таблицы 1:1 из прототипа

`settlement_species.gd` (7 видов, статистика из таблицы 1.1),
`settlement_buildings.gd` (здания, рецепты, цены домов, ункилоки),
`smoldering_upgrades.gd` (апгрейды, уровни), `prestige_modifiers`
(1–10). TBD (bat, цены fox/frog/bat houses) — заглушки с
`available: false`.

## Risks / Trade-offs

- **Масштаб**: 5 capability, ~30 сценариев, 7 фаз. Митигация: фазы
  независимы, каждая — зелёные тесты; продвинутые здания (фаза 6)
  можно отложить.
- **Данные-пробелы** (bat, цены домов): заглушки, не блокируют
  основные виды.
- **Ритм прототипа ≠ ходы** (D4): калибровка по MCP-сценарию;
  константы в `GameNumbersSettlement`.
- **Зависимость от city-hex-layout** (D3): дефолт `[center]`.
- **Prestige после победы** (D6): в первой итерации — только
  базовая сложность; Prestige включается флагом после первой победы.

## Migration Plan

1. Фаза 1: виды (7, bat заглушка) + караван + сущность поселения.
2. Фаза 2: Resolve + потребности (числа) + голод/перерыв + Firekeeper.
3. Фаза 3: здания (hearth, warehouse, лагеря, производство, жильё).
4. Фаза 4: Demand/Decadence + Hostility/glade + штормы +
  победа/поражение.
5. Фаза 5: Smoldering City + ункилоки + meta-сейв.
6. Фаза 6: продвинутые (улучшения домов, сервис/Unified, Small
  Warehouse, Trading Post, Rainpunk) + Prestige.
7. Фаза 7: hex-кластер (после city-hex-layout) + MCP-сценарий +
  регрессия.
