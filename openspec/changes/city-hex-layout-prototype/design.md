# Design: city-hex-layout-prototype

## Context

- `CityData.center: Vector2i` — единственный "тайл города". Здания и
  boroughs живут в отдельных массивах (`buildings`, `boroughs`) со своими
  клетками; сам центр — только якорь (метки, туман, `MapSpawner._ln_cells`).
- Застройка: `CityBuildingService.first_free_build_cell` — обход
  `HexUtils.ring(center, r)` от `r=1` до `building_max_distance()`, где
  `CityService.building_max_distance = BUILDING_MAX_DIST_BASE + (level-1)`,
  cap `PROSPERITY_MAX_RADIUS`.
- Карта: `MapRenderer` рендерит тайлы по `terrain_grid`; города на карте —
  одна метка (`MarkerLayer.set_city_markers`, `MinimapOverlay` по
  `city.center`). `CityScreen` — текстовая панель (без hex-вида города).
- Туман: `VisibilityMap` — `city.center` в `sight_sources`
  (радиус `FOG_CITY_SIGHT`).
- Прототип (chat.z.ai, ссылка с авторизацией, содержимое недоступно
  агенту): "центр города — четыре шестиугольника с тремя кольцами вокруг".
  Детали формы ядра и зональности колец — Open Questions в proposal.

## Goals / Non-Goals

**Goals:**
- Ядро города = 4 тайла (`core_cells`), вычисляются из `center`.
- Buildable-зона = ядро + кольца 1–3, фиксированно (не от уровня).
- Кластер виден на карте (процедурная окраска тайлов).
- Старые сейвы загружаются без миграционного скрипта.

**Non-Goals:**
- Рендер отдельных зданий в тайлах (архитектура прототипа).
- Зональное назначение колец (жилые/производство/фермы).
- Изменение CityScreen, Borough, tech tree, экономики.

## Decisions

### D1: Форма ядра — ромб 2×2 (4 тайла вокруг center)

`core_cells = {center, center+(1,0), center+(0,1), center+(1,1)}`
(скошенные соседи в hex-координатах проекта — "ромб" из 4 клеток,
включающий center).

- **Почему:** "четыре шестиугольника" — минимальная связная группа из 4
  клеток; ромб 2×2 симметричен относительно center и не требует выбора
  ориентации. Альтернатива "центр + 3 соседа" (трилистник) отклонена:
  асимметрична, требует выбора направления.
- **Уточнение по прототипу** (Open Question 1) может поменять форму —
  изолировано в `CityFactory.core_cells_for(center)`, одна функция.

### D2: `core_cells` вычисляется, а не хранится как источник истины

`CityData.core_cells` — кэш; источник — `center` + функция
`CityFactory.core_cells_for()`. В сейв пишется (для отладки и будущих
нерегулярных ядер), при загрузке пересчитывается и сверяется.

- **Почему:** миграция старых сейвов бесплатна (D4); нет дублирования
  состояния, которое может расстроиться.

### D3: Buildable-зона = кольца 1–3 вокруг center, ядро исключено

`CityService.building_max_distance()` возвращает константу 3
(`GameNumbersCity.CITY_RING_MAX = 3`). `first_free_build_cell` — тот же
обход колец, только `max_d` фиксирован; клетки ядра считаются занятыми
(`cell_is_built` расширяется: `core_cells.has(cell)` → true).

- **Почему:** минимальный diff — логика обхода колец уже есть; меняется
  только источник радиуса и проверка занятости.
- **Последствие:** города высокого уровня теряют расширение радиуса —
  это осознанный возврат к прототипу; tech tree (что можно строить)
  остаётся привязанным к уровню.
- **Риск:** существующие сейвы с зданиями за кольцом 3. Миграция: здания
  вне зоны при загрузке остаются в массиве (не ломают сейв), но
  `first_free_build_cell` их не учитывает. Регрессия покрыта
  MCP-пробой 60 ходов.

### D4: Миграция — ленивая, в `CitySerializer.deserialize`

Если в данных нет `core_cells` (или пусто) — вычисляется из `center`.
Если есть — принимается как есть (но сверяется с `center`).

- **Почему:** без миграционных версий сейвов; `data.get("core_cells", [])`
  — один `if`.

### D5: Рендер — процедурная окраска в MapRenderer, без новых текстур

`MapRenderer` при отрисовке тайла проверяет: тайл в `core_cells` какого-то
города → цвет ядра; в кольцах 1–3 → цвет застройки. Кэш "тайл → город"
пересчитывается при `cities_changed` (как `_ln_cells` в MapSpawner).

- **Почему:** текстур — нет в проекте под города; палитра TileAtlas
  достаточно. Полноценный визуал прототипа — отдельный change после
  получения деталей.
- **Альтернатива:** отдельные Sprite2D на тайлы — отклонено: больше
  нод, тот же результат до появления текстур.

### D6: Туман и метки — без изменений

`center` остаётся в `sight_sources` и `set_city_markers`. Кластер
появляется/исчезает вместе с видимостью центра (радиус
`FOG_CITY_SIGHT` ≥ 3 при текущих константах — проверить в тестах).

## Risks / Trade-offs

- **Здания за кольцом 3 в старых сейвах** (D3): не ломают сейв, но
  "висят" вне зоны. Принято: MCP-проба + unit-тест миграции.
- **Потеря расширения радиуса с уровнем**: города 10+ уровня
  ограничиваются 3 кольцами. Осознано (прототип). Если баланс пострадает
  — константа `CITY_RING_MAX` одна точка изменения.
- **Прототип не виден агенту**: форма ядра и зонализация — дефолты.
  Уточнение = правка `core_cells_for()` + константы, без перестройки.

## Migration Plan

1. `core_cells` в `CityData` + `CityFactory.core_cells_for()` +
   `CitySerializer` (ленивая миграция).
2. `CityService.building_max_distance()` → `CITY_RING_MAX`; ядро занято
   в `cell_is_built`.
3. Рендер кластера в `MapRenderer` (+кэш).
4. Тесты: ядро, зона, миграция, рендер-кэш; GdUnit4 + MCP 60 ходов.

## Open Questions

- Форма ядра (ромб vs трилистник) — по прототипу.
- Зональность колец — по прототипу (сейчас: равномерная).
- `FOG_CITY_SIGHT` покрывает ли кольцо 3 при текущих константах.
