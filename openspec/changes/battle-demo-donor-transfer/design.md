## Context

Стенд — отдельный Godot-проект (1.9 ГБ, 1386 файлов в индексе, свой
`project.godot`, `run_tests.sh`, `addons/`, 42 теста), в заголовке которого
написано: «Основной проект (`../game`) этого демо не касается». В перечне корня
он помечен «ждёт решения (Q-M…)».

Что в нём на самом деле не переехало:

| носитель | объём | можно перенести отдельно? |
|---|---|---|
| `tools/*.py` | 17 файлов, 2676 строк | да — взаимно импортируются, от движка не зависят |
| `tools/workflows/*.json` | 11 графов + README | да — их читает `comfy.py` |
| `tools/*.gd`, `*.tscn` | 8 файлов | нет — грузят `res://scenes/battle.tscn`, `res://data/rosters/` |
| `scripts/combat/`, `view/`, `scenes/`, `data/` | боевая модель | нет — конфликтует с каноном (см. proposal) |
| `assets/` 652, `addons/` 517, `artifacts/` 48 | кадры, чужое, вывод | кадры уже копии в `game/assets/` |

Ограничение, которое определяет всё: `repo-layout` требует, чтобы весь Python вне
игрового кода жил в `game/tools/` или `scripts/`, а каталогов-убежищ в дереве не
было.

## Goals / Non-Goals

**Goals.** Один дом у конвейера; запуск из корня репо без второго проекта;
воспроизводимость на свежем клоне либо честная пометка «невоспроизводимо, вот
почему»; машинная приёмка кадра остаётся частью прогона.

**Non-Goals.** Не слияние боевых моделей — у канона бескубиковая лестница K2, у
стенда своя формула и собственный калибровочный горизонт. Не переезд `.gd`
инструментов, сцен, `.tres`-данных и тестов стенда. Не решение Q-M139 — смена
только убирает у варианта «(в) удалить» аргумент «единственный носитель». Не
оптимизация 1.9 ГБ.

## Decisions

**Дом — `scripts/character_kit/`, а не `game/tools/`.** `scripts/` по `repo-layout`
— хостовый Python с рабочей директорией корня репо; `game/tools/` — инструменты,
гоняемые `--path game` и обращающиеся к `res://`. Конвейер читает и пишет файлы по
путям хоста и ходит в ComfyUI по HTTP, к `res://` не обращается ни разу.
Прецедент уже есть: `scripts/concept_art/` — второй ComfyUI-путь этого же
репозитория. *Отвергнутые:* (а) `game/tools/` — враньё о границе, которую только
что отстоял `repo-structure-cleanup`; (б) новый `tools/` в корне — каталог-убежище,
прямо запрещён тем же требованием; (в) копировать, оставив оригинал в стенде, —
«генераторы ассетов не живут в двух домах»; (г) `pip`-пакет — зависимостей у
репозитория нет ни для одного инструмента, одна библиотека не окупается.

**Единственный корень путей — модуль `paths.py` пакета; `parents[N]` и зашитая
строка `"battle-demo"` из инструментов уходят.** Замер 2026-11-09 (группа 1
задач) показал, что `ROOT` значит разное в разных файлах: `parents[1]` у
`audit_sprites.py`, `build_sprite_frames.py`, `gen_contact_sheet.py` даёт корень
**стенда**, `comfy.py` берёт `parents[2]` — корень **репозитория**,
`ui_read_judge.py` — `parent.parent`, а `mirror_anim.py`, `gen_kit.py`,
`gen_beast.py`, `gen_log.py` и другие зашивают строку `"battle-demo"` в путь
(12+ мест). Перенос одних файлов молча перенаправил бы вывод в `scripts/` —
проверка импортов этого не ловит. Поэтому `paths.py` даёт четыре имени:
`REPO`, `KIT` (носители рядом с кодом), `OUT` (вывод прогона, берётся из
`spec.json` и разрешается от корня — ровно как `concept_art/generate.py`) и
`STAND` (стенд, пока жив, — единственный способ назвать его извне). *Отвергнутые:*
(а) оставить `parents[N]`, подобрав смещение — та же мина при следующем переезде;
(б) переменная окружения под вывод — у `concept_art` её нет, лишний орган без
спроса; (в) писать вывод в стенд — конвейер тогда снова обязан стендом.

**Носитель переезжает, вывод — нет.** Граница проходит по git: в индексе у стенда
44 МБ (код, 11 графов, `spec.json`, `assets/poses` — 224 скелета DWPose,
`portraits` 20, `reference` 2, `a_pose_v2` 2, `beasts` 2, запись прогонов
`artifacts/*.json|md` 48), а 1,7 ГБ (`clips` 814 МБ, `clips-apose` 784 МБ,
`gen` 135 МБ, `kit`, `a_pose`, `screenshots`) — вне индекса. Носители едут
`git mv` в `scripts/character_kit/` (внутри репозитория — истории не добавляют
байта), вывод уезжает в `<корень>/character_kit/` под правило `.gitignore` по
образу `/concept_art/`. Промежуточные кадры сегодня — единственный экземпляр в
рабочем дереве и не в git: тот же класс риска, из-за которого из дерева уже
вынесли стиль-референсы (D-192 → D-319). *Отвергнутые:* (а) считать вывод
носителем и нести 1,7 ГБ в git — против D-185 и `repo-layout` «вывод прогонов не
попадает в дерево»; (б) оставить вывод в стенде — перенесённый код снова читает
стенд, требование «без стенда» остаётся ложью; (в) удалить вывод — это результат
платных GPU-прогонов, регенерация не оплачена.

**Конечная точка конвейера задаётся спекой, а не соседством.** `assets/sprites`
остается в стенде: его читает его рантайм (`battle_unit_view.gd`,
`data_library.gd`, тесты), и у игры уже есть своя копия кадров. Поэтому «кадр
собирается без стенда» значит «без Godot-проекта стенда»: конвейер как хостовый
Python работает, а куда лечь финальным спрайтам, говорит `spec.json`. Пока жив
стенд — `STAND/assets/sprites`, после решения Q-M139 путь меняется в одном месте.

**Связь из стенда в `scripts/` рвётся хак, а не переносится.** `gen_beast.py:32`
делает `sys.path.insert(0, <корень>/scripts/concept_art)` — инструмент стенда уже
зависит от конвейера игры через подстановку пути. После переезда оба живут в
`scripts/`, и зависимость становится обычным импортом пакета.

**Перенос через `git mv`, одним коммитом, с переадресацией ссылок в том же
коммите.** История файлов сохраняется, а состояние «оригинал удалён, ссылки
указывают в пустоту» не попадает в историю. Ссылки ищутся grep'ом по
`battle-demo/`, `docs/`, `openspec/specs/`; часть из них — текст живых спек
(`battle-demo-sprites`), и они правятся дельтой этой смены.

**`dwpose_cli.py` переезжает невоспроизводимым инструментом с паспортом.**
Пакет `dwpose` в репозитории отсутствует (`git ls-files` даёт только сам
`dwpose_cli.py`), веса детектора — сотни мегабайт. Решение: в README пакета —
точный источник, версия и команда установки, а сам инструмент помечается
невоспроизводимым на свежем клоне; приёмка смены обязана этот паспорт найти.
*Отвергнутые:* вендорить веса в git (тот самый класс решения, из-за которого в
репо нет пикселей — D-185); удалить инструмент (требование «Поза кадра задаётся
скелетом этого персонажа» живёт и остаётся, извлекать скелет станет нечем);
молча переездать сломанным — нарушает новое требование о воспроизводимости.

**Приёмочные судьи едут тем же пакетом.** `audit_sprites.py` и `ui_read_judge.py`
вызываются тем же прогоном и в основном проекте аналогов не имеют; выносить их в
`scripts/` отдельными файлами — дробить один носитель на девять.

**Один self-check вместо переезда 42 тестов.** Тесты стенда проверяют его боевую
модель и его UI — то, что не переезжает. От конвейера остаётся одна проверка:
собрать кадр из синтетического входа и сверить, что приёмка на поломанном входе
возвращает `fail`. Падающая проверка дешевле, чем перенесённый suite, который
нечему проверять.

## Risks / Trade-offs

- **Битые ссылки внутри стенда** → grep по `battle-demo/` в задачах + проверка
  состава; стенд теряет `.py`, но его `run_tests.sh` их не вызывал (тесты — `.gd`).
- **`.gd`-инструменты стенда могут дёргать перенесённый Python** → проверено:
  вызовов нет, но `build_sprite_frames.gd` требует план, который пишет
  переносимый `.py` (`artifacts/sprite-plan.json`) — рукопожатие файлом через
  границу переноса. Правится тем, что план лежит по пути из `paths.py`, а
  сообщение об отсутствии плана в `.gd` переадресуется.
- **Конвейер переезжает нерабочим в целом** (он две недели не гонялся из стенда) →
  прогон хотя бы одного шага на синтетическом входе входит в приёмку; если шаг не
  проходит, смена фиксирует это как результат, а не маскирует.
- **Два ComfyUI-пути в одном `scripts/`** (`concept_art/` и `character_kit/`) →
  осознанно: у них разные входы и разные графы, слияние = переписывание
  воспроизведённых прогонов. Разводка — в README пакета.

## Migration Plan

1. Проверить независимость `.py` от сцен и отсутствие вызовов из `.gd` (блокатор).
2. `git mv` кода, графов и носителей в `scripts/character_kit/`; правка
   внутренних импортов не требуется (плоский каталог, импорты по имени модуля),
   правка путей — требуется (см. решение про `paths.py`).
3. Вывод прогонов уезжает из дерева в `<корень>/character_kit/` под `.gitignore`.
3. Переадресация ссылок: доки, спеки дельтой, README стенда (новая команда
   запуска из корня).
4. README пакета: назначение, команда прогона, паспорт `dwpose`, чем отличается
   от `concept_art/`.
5. Self-check + гейты (`check_repo_layout`, `check_docs_links`, `doc_gates`,
   `openspec validate --all --strict`).

Откат — `git revert` одного коммита: файлы возвращаются в стенд вместе со
ссылками.
