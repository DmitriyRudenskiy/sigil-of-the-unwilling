## Context

Герой описывается системой внутренних потребностей в `demographics/Character.gd`
(`NEED_KEYS = [&"hunger", &"rest", &"social", &"belief"]`). Потребность
`&"belief"` и связанные с ней теги/черты в `demographics/TraitRegistry.gd`
носят религиозный контекст, который противоречит секулярной идентичности
проекта. Смерть от «выгорания» потребности реализована в
`demographics/DemographicTurnProcessor.gd` (`_death_cause` → `&"despair"`).

Задача — заменить `belief` на секулярное `inspiration`, сохранив всю
механику потребности и петли жизни героя.

## Goals / Non-Goals

**Goals:**
- Заменить идентификатор потребности `&"belief"` → `&"inspiration"` во всём коде.
- Переформулировать теги черт: `belief` → `inspiration`, убрать религиозный тег `faith`.
- Переименовать/переформулировать черты под секулярный смысл с сохранением эффекта.
- Заменить причину смерти `&"despair"` → `&"burnout"`.
- Обеспечить миграацию сохранений со старой статикой.
- Обновить локализацию и тесты.

**Non-Goals:**
- Не меняем формулу восстановления/смерти и пороги (`DEATH_STREAK`) — только имена/смысл.
- Не трогаем другие потребности и их механику.
- Не проектируем следующие циклы (Наследование, Раса×Класс) — только определяем «путь» как секулярную идентичность сборки.

## Decisions

1. **Чистый swap StringName `&"belief"` → `&"inspiration"`.**
   _Почему:_ минимальная площадь изменения, не вводим новый тип статики —
   потребность уже ходит по той же петле, что hunger/rest/social.
   _Альтернатива:_ ввести отдельную статистику — отклоняем, избыточно.

2. **Теги черт: `belief` → `inspiration`; `faith` убираем; `soul`/`sigil` → `soul`/`legacy`.**
   _Почему:_ тег — это метка для фильтрации/семантики, а не механический параметр.
   Религиозный `faith` семантически схватываем под `inspiration`.

3. **Названия черт меняем, механический эффект (модификатор и знак) оставляем.**
   _Почему:_ требование specs — эффект сохраняется, меняется только имя/описание.
   Это минимизирует риск для тестов, которые могут ссылаться на эффект.

4. **Причина смерти `&"despair"` → `&"burnout"`.**
   _Почему:_ секулярный смысл «выгорания»; механически тот же streak-порог.

5. **Миграция сохранений в `core/SaveData.gd` / `core/SaveManager.gd`.**
   _Почему:_ BREAKING-изменение идентификатора потребности. При загрузке
   старой игры поле `belief` должно перенестись в `inspiration`, иначе у героя
   пропадет одна из потребностей.

## Risks / Trade-offs

- [Разорванные ссылки на `&"belief"` где-то вне охвата] → поиск по репозиторию
  всех вхождений `belief`/`despair` до правок; добавление задачи в чеклист.
- [Тесты ссылаются на старые названия/теги черт] → обновление тестов в том же цикле.
- [Миграция сохранений пропущена] → добавляем явную задачу миграции и тест
  «load old save → inspiration present».
- [UI рендерит название потребности по тегу] → обновление отображения RU-текста.

## Migration Plan

1. Найти все вхождения `belief`, `despair`, религиозных тегов/названий черт (grep по репозиторию).
2. Заменить идентификатор потребности и причину смерти в `Character.gd`, `DemographicTurnProcessor.gd`.
3. Обновить теги и названия черт в `TraitRegistry.gd`.
4. Добавить миграацию в `SaveData.gd`/`SaveManager.gd`.
5. Обновить UI-отображение потребностей и черт (если есть).
6. Обновить тесты и локализацию.
7. Прогнать валидатор заклинаний и полный набор тестов (`run_all_ci_checks.sh`).

**Rollback:** откат — возврат изменений в затронутые `.gd`-файлы и удаление
миграции; идентификатор `belief` восстанавливается как ранее.

## Open Questions

- Нужен ли обратный маппинг «старое название черты → новое» для уже рождённых последователей в сохранённых играх (черты тоже могут сохраняться)?
