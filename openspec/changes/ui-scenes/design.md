## Context

Весь UI проекта собирается в коде. Типичная схема (на примере
`ArtifactInventoryScreen.gd`, самый тяжёлый — 64 `add_child`/`.new()`):

- `_ready()` → `_build()` чистит детей и строит дерево: `CenterContainer` → `Control`-окно
  942×706 → под-панели (Left/Right/Side/Bottom), каждая со своим `StyleBoxFlat`.
- Позиционирование — абсолютное через `_set_offsets()` (`custom_minimum_size` + `offset_*`),
  размеры/координаты «по макету» (HTML-мокап).
- Стили — `_stylebox(border, radius, center, bg, inset)` вручную, цвета-константы
  (`WIN_BG`, `OUTLINE`, `SLOT_BG`, `RED_BG`, `TEXT_GOLD` и т. д.), **глобальной темы нет**.
- Динамическое содержимое (статы, рюкзак, слоты куклы, навыки) пересобирается в `_refresh()`.

Аналогично: `BattleUI` (top/bottom panel, инициатива, кнопки действий,
`BattleSpellbookPanel`), `InfoPanel`, `ResourcesPanel`, `ArmyPanel`, `SkillsPanel`,
`CityPanel`, `ToolsPanel`, `MinimapPanel`, `SettingsScreen`, `ArtifactChestDialog`,
`ResourceBar`, `AdventureUI`.

Боевая книга (`BattleSpellbookPanel.gd`) — `extends Control`, в `_refresh()` чистит
`Button`-ы и заново строит кнопки заклинаний из `HeroMagic.spellbook`.

Хотят: перевести UI на сцены, чтобы стилизацию можно было кастомизировать без кода,
верстать окна в редакторе и держать единый стиль.

## Goals

- Перевести на сцены два приоритетных окна: **инвентарь** и **книза заклинаний**.
- Сделать **аудит** всего динамического UI с классификацией и приоритетом перевода.
- Ввести **общую тему/стилизацию**, которую сцены подтягивают — правки в редакторе/теме.
- Перевести на сцены оставшийся UI по приоритету из аудита.
- Сохранить текущий вид/поведение и вердикт `run_operability.sh` = CLEAN.

## Decisions

### D1: Гибридный подход «сцена = скелет + стиль, код = данные»
Сцена (`*.tscn`) верстает статический скелет и стиль: панели, слоты, иконки-плейсхолдеры,
лейблы с позицией/размером/стилем. Динамическое содержимое (статы, рюкзак, список
заклинаний, инициатива, слоты армии) подтягивается в рантайме из `HeroController`/
`HeroMagic`/`SpellRegistry`. Это даёт и верстку в редакторе, и живые данные.
Обоснование: состав списков неизвестен на этапе верстки; скелет в сцене, наполнение — в коде.

### D2: Единый root-подход для сцен
- Инвентарь: root — `Control` со скриптом `ArtifactInventoryScreen`; сцена держит
  `CenterContainer`/окно/панели, скрипт сохраняет `_build()`-логику подтяжки данных в
  `_refresh()`/`set_hero()`.
- Книга: root — `Control` со скриптом `BattleSpellbookPanel`; сцена держит контейнер и
  плейсхолдеры кнопок, `_refresh()` заполняет их из данных.

### D3: Общая тема как источник стилей
Ввести ресурс темы `game/assets/theme/game_theme.tres` (или переиспользуемый набор
`StyleBox`-ов в `game/assets/theme/styles/`) с повторяющимися стилями: `panel`, `slot`,
`button`, `label_gold`, `label_light`, радиусы/отступы. Сцены ссылаются на тему через
`theme_override`/`add_theme_stylebox_override`, а не хардкодят `StyleBoxFlat`.
Обоснование: единый стиль + правка в редакторе/теме без кода — прямая цель цикла.
Цвета берутся из существующей палитры (`WIN_BG`, `OUTLINE`, `SLOT_BG`, `RED_BG`,
`TEXT_GOLD`), чтобы вид не изменился.

### D4: Приоритет перевода из аудита
Аудит классифицирует каждую панель:
- **статический скелет** (панели/окна с фиксированной версткой) → полный перевод в сцену;
- **динамический список** (кнопки заклинаний, инициатива, слоты рюкзака) → сцена-контейнер
  + стиль из темы, наполнение в коде;
- **гибрид** (инвентарь) → скелет в сцене, данные в коде.
Перевод выполняем в порядке приоритета аудита; низкоприоритетные/мелкие (напр.
`ResourceBar`) — по остаточному принципу.

### D5: Сохранение абсолютной вёрстки
Поскольку текущий UI опирается на абсолютные координаты «по макету», сцены повторяют
те же `offset`/размеры (942×706 и т. д.). При желании позже можно перейти на
`Control`-лейаут, но в этом цикле — сохраняем геометрию 1 в 1.

## Risks

- **Регрессия геометрии**: неточность в сцене → окно «поъедет». Митигация: скриншот-
  эталон «до/после» и сравнение.
- **Двойное определение стилей**: код может продолжать харкодить `StyleBoxFlat`. Митигация:
  в D3 тема — единственный источник, код только подтягивает из темы.
- **uid-файлы сцен** усложняют дифф. Митигация: сцены добавляются как новые файлы.
- **Динамические списки** не свести к одной сцене. Митигация: D1 (контейнер в сцене,
  наполнение в коде).

## Migration

1. Аудит → `docs/systems/UI_AUDIT.md` (классификация + приоритеты) + ссылка в `docs/README.md`.
2. Ресурс темы `game/assets/theme/game_theme.tres`.
3. Сцена инвентаря `game/scenes/ui/ArtifactInventoryScreen.tscn` + перенос логики в `.gd`.
4. Сцена книги `game/scenes/ui/BattleSpellbookPanel.tscn`.
5. Перевод приоритетных панелей по аудиту.
6. Проверка `run_operability.sh` (CLEAN) + скриншоты «до/после».
