## Context

Размещение армий — чистые данные в `BattleState._build_units` (вызывается из `place_army` в `BattleController.start_battle`). Текущая формула:

```gdscript
var sx := 2 if is_atk else BW - 3     # 2-колонный блок: атк x=2..3, защ x=14..15
var row := (i / 2) * 2 + 1            # ступенчатые нечётные ряды 1,3,5,7,9
unit.cell = Vector2i(sx + (i % 2), row)
```

Параметры поля: `BW=17`, `BH=11`, odd-r гексы (нечётные ряды сдвиг вправо). В odd-r **одна колонка с последовательными рядами уже соседна** (соседь `(0,±1)` есть в таблицах для чётных и нечётных рядов) → колонка образует связную линию.

Просмотр: `BattleView` рисует спрайты по `_tile_map.map_to_local(unit.cell)`, значит размещение — только в данных, правка view не нужна.

Лимит: `BATTLE_MAX_UNITS_PER_SIDE = 7` → колонка из 7 юнитов влезает в 11 рядов.
Препятия спатнятся в `x ∈ [4, BW-5]` → краевые колонки `x=0` и `x=BW-1` препятствий не содержат.

## Goals / Non-Goals

**Goals:**
- Размещать все юниты стороны в одну вертикальную колонку.
- Размещать её максимально близко к краю (атк — лево, защ — право).
- Располагать юниты вплотную, в порядке входных стэков.

**Non-Goals:**
- UI редактирования построения (формации).
- Горизонтальная линия / другие формации.
- Изменение pathfinding, боя, генерации препятствий.

## Decisions

**D1. Одна колонка у края.**
Размещать в колонку `col = 0 if is_atk else BW - 1`, ряды последовательно `row = i`.
*Альтернатива*: 2-колонка (как сейчас) или горизонтальная линия. — выбрано «в одну линию» по запросу.

**D2. Порядок рядов — сверху вниз, по входному списку.**
`i-й` стэк → ряд `i` (ряд 0, 1, 2, …).
*Альтернатива*: вертикальный центр. — выбрано простота + детерминизм; эстетика центра — Open Question.

**D3. Размещение остаётся в `BattleState._build_units`, view не трогается.**
`BattleView` читает `unit.cell`, поэтому визуал линии гарантирован без правки view.

**D4. Защитный обход занятых/препятствий.**
Клетка колонки занята → взять следующую свободную в той же колонке. (На практике края чисты, но защита от будущих изменений.)

## Risks / Trade-offs

- **[D1] Краевые гексы `x=0`/`x=BW-1` могут резаться камерой/UI.** → Митигация: проверить `run_operability.sh` + скриншот боя; при проблеме сдвинуть на `x=1`/`x=BW-2`.
- **[D2] Выравнивание по верху.** → юниты занимают ряды 0..N-1; возможен визуальный «завал» вверх. → Митигация: Open Question по центру.
- **Инварианты боя (BFS, `check_end`, `_unit_grid`).** → Митигация: меняется только `unit.cell`, инварианты не затрагиваются; прогнать тесты боя.

## Migration Plan

1. Заменить формулу в `_build_units` (D1–D4).
2. Прогнать `game/tools/shell/run_operability.sh` → `CLEAN`.
3. Скриншот боя — подтвердить одну линию у края.
4. Добавить юнит-тест размещения.
5. Откат: отменить коммит цикла; размещение опционально, бой не ломается.

## Open Questions

- **Выравнивание по вертикали:** сверху (ряды 0..N-1, дефолт) или по центру? (На спеку не влияет.)
- **Точная краевая колонка:** `x=0`/`x=BW-1` (дефолт) или `x=1`/`x=BW-2` если гексы режутся камерой? (Проверить при реализации.)
