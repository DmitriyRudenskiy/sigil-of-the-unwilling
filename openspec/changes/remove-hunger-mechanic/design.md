# Design: удаление механики голода

## Контекст

Голод — общая потребность героя (`HeroNeeds`) и горожан
(`DemographicTurnProcessor`) через `Character.NEED_KEYS`. Еда при этом живёт
отдельной жизнью в городской экономике: `City.food_stockpile`, `net_food()`,
`food_consumption()`, флаг `starving` (штраф к `approval()`), порог рождений
`growth_threshold()`, торговля на рынке. Кодовых связей «еда → потребность
hunger» нет, кроме восстановления в `_recovery()`: они уже расходятся
самостоятельно. Механика голода — выживальский слой поверх уже существующей
экономики еды.

**Допущение (требует подтверждения):** формулировка «еда нужна в городе для
поднятия настроения, привлекательности и торговли» трактуется как описание
роли существующих систем, а не как заказ новых:
- «настроение» → `approval()` города (штраф при `starving`);
- «привлекательность» → рост населения (рождения при запасе еды выше порога);
- «торговля» → `MarketSystem` (еда продаётся из склада).

Если нужны отдельные новые статы (mood/attractiveness) — это отдельный
change; здесь они не вводятся.

## Решения

### D1. Голод удаляется из обоих контуров (герой + горожане)

`Character.NEED_KEYS` — общий константный набор. Убирать hunger «только у
героя» требовало бы расщепить набор на два и дублировать цикл тика.
Минимальное и консистентное: `NEED_KEYS = [&"rest", &"social",
&"inspiration"]`, из обоих процессоров вычищаются распад/восстановление/
причина смерти `&"starvation"`. Горожане больше не умирают от голода — их
смертей меньше (exhaustion/isolation/burnout остаются).

### D2. Городская экономика еды — без изменений

`food_yield`, `food_consumption`, `net_food`, `food_stockpile`, `starving`,
рождения, `STARVING_APPROVAL_PENALTY`, рыночная торговля еды — всё остаётся.
Флаг `starving` продолжает влиять только на approval (настроение) и на
экономику, но больше не участвует в тике потребностей (ветка
`city.starving → -0.10` в `_recovery` героя и горожан удаляется).

### D3. Черты

- `hardy` (+0.10 hunger), `appetite` (−0.12 hunger), `iron_stomach`
  (+0.25 hunger) — удаляются (еда больше не влияет на выживание).
- `gorgon_taste` (leg., hunger +0.10 / social +0.10) — перенацеливается в
  чистый social-бонус (+0.10 к общению), тег `"food"` в flavour-тегах
  сохраняется.
- Состав черт 19 → 16; обновить ожидания в `test_trait_registry.gd`
  (количество по редкостям) и любой счётный ассерт.

### D4. Сериализация/старые сейвы

- `HeroNeeds.deserialize` и `Character.deserialize` читают только ключи из
  `NEED_KEYS` → старый ключ `"hunger"` в сейвах v3/v4 просто не читается
  (паттерн уже использован для `belief`→`inspiration`). Версию сейва не
  поднимать.
- `WorldStateSerializer` сериализует `state.needs` циклом по `NEED_KEYS` —
  состав сужается автоматически; GET_STATE-потребности героя: 3 ключа.

### D5. Сценарии и тесты

- `keep_alive()` в `scenario_lib.py` работает с `state.needs` обобщённо
  (`min(needs.values())`) — логика не меняется, только комменты
  (hunger −0.15/день больше нет).
- Сценарии 1–4: без голода прохождение ещё легче; права на циклы не нужны.
- GUT: `test_hero_survival.gd` (17 упоминаний — убрать hunger-ассерты,
  пересчитать city-recovery без hunger), `test_characters.gd` (NEED_KEYS,
  clamp, serialize), `test_demographic_processor.gd` (распад/восстановление/
  starvation-смерть), `test_trait_registry.gd` (состав черт).
- `test_save_v3.gd` — проверить ассерты по составу needs.

### D6. UI и события

- `HeroStatusPanel`: убрать `&"hunger": "🍞"` из `_NEED_ICONS` и «четыре
  потребности» → «три» в комменте/доке.
- `DeathSequence`: убрать `&"starvation": "от голода"`.
- `GameEventBus`: в перечне причин смерти в комменте — убрать
  `"starvation"`, добавить `"burnout"` (сейчас его там нет).
- `HeroController.gd`, `TraitDef.gd`, `scenario_lib.py` — комменты.

### D7. Документация

- `docs/economy/economy_runtime.md` §7 (фаза демографии): распад без hunger,
  причины смертей без starvation (и попутноbelief→inspiration в тексте).
- `docs/systems/city_system.md`: роль еды — экономическая (склад, рождения,
  approval, рынок); «штраф за голод» переформулировать как «штраф за
  нехватку еды (`starving`)» — сам флаг не меняется.
- `docs/concepts/TASK_SOCIAL_AND_BUILDINGS.md` (строка с NEED_KEYS) и
  `docs/concepts/CONCEPT_SOCIAL_RACES.md` (лисы: «умирают от голода» →
  переформулировать под отсутствие голода) — точечные правки.
- `docs/concepts/CONCEPT_CHARACTER_SYSTEM.md` — при наличии упоминаний.

## Риски / взаимодействия

- **Активные change `hero-lifecycle-boundary` и `lifecycle-test-strategy`**
  (обозреватели, 0 задач) касаются тех же файлов (`HeroNeeds.gd`,
  `HeroController.gd`, тесты). Этот change не переименовывает API, только
  сужает набор потребностей — конфликты минимальны, но при реализации
  lifecycle-boundary учитывать 3-ключевой `NEED_KEYS`.
- **Баланс**: герой живёт дольше в поле (нет голода). Сценарии 1–4 —
  расслабление; баланс сценариев не трогаем.
- **Демография**: меньше смертей горожан — популяция растёт чуть быстрее.
  Пригодится пересмотр констант — не в этом change.

## Отвергнутые альтернативы

- **Убрать голод только у героя** — расщепление NEED_KEYS, дублирование
  цикла тика; против идеи «еда нужна только в городе».
- **Ввести новые статы mood/attractiveness** — новый функционал, не
  запрошенный явно; существующие approval/рост/рынок уже закрывают роль.
- **Оставить черты, перенацелив на rest** — семантика «Крепкий: редко
  устаёт» хуже, чем честное удаление food-черт.
