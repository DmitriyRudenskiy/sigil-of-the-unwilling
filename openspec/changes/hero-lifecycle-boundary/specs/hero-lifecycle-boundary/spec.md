## ADDED Requirements

### Requirement: Потребители героя переподключаются через реестр
Все потребители активного героя (бой, взаимодействие, вражеский ИИ, ввод,
шоркаты, роутер, UI, инвентарь, город) SHALL переподключаться прогоном реестра
`register_hero_consumer` в порядке регистрации. В теле установочной функции
подсистемы НЕ должно оставаться жёстких ссылок на конкретные потребители.

#### Scenario: Преемник получил всех потребителей
- **WHEN** выполняется перерождение (преемник устанавливается)
- **THEN** каждый зарегистрированный Callable вызывается с новым героем ровно один раз, в порядке регистрации

#### Scenario: Воскрешение переподключает аналогично
- **WHEN** игрок выбирает «Воскресить» и герой ставится через ту же установку
- **THEN** реестр прогоняется полностью, consumers получают воскрешённого героя

#### Scenario: Новый потребитель — одна строка
- **WHEN** добавляется новый потребитель активного героя
- **THEN** требуется только регистрация Callable координатором; тело установочной функции подсистемы не меняется

### Requirement: Указатель активного героя владеет подсистема
`HeroLifecycleSystem.active_hero` SHALL быть единственным источником активного
героя. `WorldController` SHALL читать/публиковать героя только делегированием в
подсистему; подсистема НЕ должна обращаться к фасаду за указателем (`world.get_hero()`
/ `world.set_hero()` из подсистемы — удалены).

#### Scenario: Фасад делегирует
- **WHEN** любой код вызывает `WorldController.get_hero()`
- **THEN** возвращается `HeroLifecycleSystem.active_hero`

#### Scenario: Отсоединённая система самодостаточна
- **WHEN** подсистема работает без координатора (headless-тест)
- **THEN** она читает/пишет собственный `active_hero` без guard'ов на методы фасада

### Requirement: Единый путь установки героя
Установка героя в мир (в дерево, `setup`, позиция, переподключение потребителей)
SHALL выполняться одной функцией подсистемы для первого героя, преемника и
воскрешённого героя.

#### Scenario: Первый герой
- **WHEN** bootstrap ставит стартового героя
- **THEN** используется та же установочная функция, что и для преемника (через делегат фасада)
