## Context

См. `proposal.md` — «Why» (замеры по комплекту 63 сцен: ориентация pointy-top
подтверждена, дедупликация при пороге ТЗ даёт ноль кластеров, сцены без альфы,
геометрия решётки у каждой сцены своя).

Что в репозитории уже есть и определяет форму решения:

| Носитель | Что в нём | Откуда берётся |
| --- | --- | --- |
| `game/assets/tiles/world_map_atlas.{webp,json}` | 82 px, грид 8×10, 32 базы (8 биомов × 4 варианта) + 48 декалей переходов (биом × сторона) | `scripts/gen_map_art.py --assemble` |
| `game/assets/objects/world_map_objects.{webp,json}` | изолированные объекты (растительность, валуны) + затемнённые двойники для тумана | тот же скрипт |
| `scripts/check_map_art.py` + `game/data/config/map_art_gates.json` | приёмка: бесшовность, «не паттерн», палитра по полосе M, силуэт, форма клетки, «одна ткань» | — |
| `scripts/test_gen_map_art.py` | 11 тестов ассемблера, зарегистрирован в `TESTS` гейта `scripts/doc_gates.sh` | — |

Ограничения движка, которые переписать нельзя:

- клетка — квадрат `GameNumbers.TILE_SIZE = 82` (`game/scripts/constants/game_numbers_map.gd:4`),
  вырезанный по гексу: угловые треугольники прозрачны (`world-map-art-gates`,
  «Форма клетки = гекс движка»); движок рисует её как `TILE_SHAPE_HEXAGON`;
- «координаты читаются только из манифеста» — отдельный реестр координат в скрипте
  уже умирал (`const BASE_COORDS` в `tile_atlas.gd`, D-212);
- семь групп отрисовки (`world-map-layer-stack`), отдельного слоя «детали» нет и
  быть не может без нового предложения (Q-M98 → (б), D-232);
- варианты одного биома — фаза одной ткани, а не независимые рисунки
  (`world-map-tile-atlas` «Варианты базы на биом», `world-map-art-gates`
  «Варианты биома — одна ткань»):
  **именно этот гейт отсекает нарезку сцены один-к-одному**;
- новый атлас вводится, старый не снимается: до зелёного приёма карта обязана
  оставаться работоспособной («Резервный атлас до зелёного гейта»).

## Goals / Non-Goals

**Goals:**

- превращение сцены с нарисованной сеткой в воспроизводимый замер: геометрия,
  исключения, переиспользование, пересборка, вердикт;
- ответ на вопрос «можно ли из этого комплекта получить атлас канонической
  структуры» — числом, а не мнением;
- если можно — пиксели ложатся в существующие листы без новых носителей и без
  правок `TileAtlas`/`MapObjects`;
- если нельзя — зафиксированная причина и хвосты в реестрах, а не «ещё один
  вариант нарезки».

**Non-Goals:**

- не делаем из ТЗ «каркас проекта»: `gridmap.json`, `tileset.json`,
  TexturePacker/Unity-раскладки, zip-архив-сдача — вымысел подрядчика без
  потребителя в этом репозитории (потребители — `tile_atlas.gd` и `map_objects.gd`);
- не режем все 63 сцены «на всякий случай»: отбор подконкрета — часть замера;
- не трогаем модель карты (террейн, стоимость движения, пути, туман) — нарезка
  остаётся чистой визуализацией;
- не заводим пропы «вместо слоя деталей»: растение уже живёт в листе объектов,
  второй носитель для тех же объектов не появляется;
- не решаем вопросы ТЗ §14 «галочкой по умолчанию»: три из них вынесены
  владельцу и закрыты им же (Q-M133…Q-M135 → D-310, см. «Вердикты владельца»);
- не делаем фон конкретной карты: роль комплекта подтверждена (Q-M133 → «всё»),
  но носителя у неё нет — это хвост T-340, а не это изменение;

## Decisions

### D1. Шаг 0 — замеропригодность, победитель выбирается по цифрам

Три пути, из которых выбирается один по замеру, а не по вкусу:

| Путь | Что делает | Что замер показывает заранее |
| --- | --- | --- |
| A. bake-per-cell | по тайлу на клетку, пересборка ≈ оригинал | удовлетворяет «пиксель-в-пиксель» и убивает переиспользование; прямо противоречит «одна ткань» и мере «не паттерн» → **заведомо отклонён**, рассматривается только как доказательство от противного (одна сцена, чтобы померить PSNR-потолок) |
| B. ткань + объекты | из сцены вытаскивается мало вариантов «ткани» биома (одна ткань, разная фаза) и отдельные объекты; переходы остаются декалями носителя | сохранят гейты; сцены используются как материал-донор, а не как карта |
| C. сцена как фон | сцена целиком идёт фоном конкретной карты, тайлмап не участвует | снимает ТЗ целиком, но выводит карту из редактируемости и тумана по слоям |

Замер (все 63 сцены, детерминированный скрипт, реестр в репо) даёт четыре числа на
сцену: дрейф решётки, профиль кластеров при RMS ∈ {2, 8, 16, 32}, PSNR пересборки
пути B, расхождение палитры сцены с полосой M. Порог «путь B годен» формулируется
до прогона и фиксируется вместе с первым замером (`world-map-art-gates`,
«Порог зафиксирован первым прогоном»).

Вердикт владельца (Q-M133 → «всё», D-310): раз ролей три, выбор «один путь»
снят — но это не «делаем всё», а разбор по носителю. B остаётся единственным
путём с готовым носителем (ткань и объекты ложатся в существующие листы),
референс стиля не производится кодом (он измеряется: попадание палитры сцены
в полосу M, шаг 1.5), фон конкретной карты (C) откладывается до появления
подложки. A не становится годным ни при каком вердикте: он противоречит
спецификации носителя, а не вкусу.

### D2. Фитт решётки: подбор периода по линиям + уточнение по вершинам

Наивный подбор по максимуму автокорреляции профиля масок линий (первичная проба
2026-11-04) даёт W = 100…166 px там, где глаз видит 78…105 px: текстурные линии
террейна и сам террейн попадают в тот же диапазон частот. Решение — двухстадийный
детерминированный фитт: (1) coarse-скан пары (W, H) при связи `H = 2W/√3` по
совмещению маски «тёмных тонких линий» с решёткой, (2) уточнение начала координат
и шага минимизацией расхождения по обнаруженным вершинам гексов (угол ≈120°,
локальный максимум линии), результат — целые пиксели. Сцена, у которой остаток
превышает порог, отвергается.

Отклонено: ручная простановка чисел на сцену (63 ручных значения невоспроизводимы
и не переживут пересборки комплекта — тот же класс отказа, что `const BASE_COORDS`);
подбор «по FFT без уточнения» (замер показал неустойчивость).

### D3. Масштаб: ресемплинг один раз, фиксируется в манифесте (Q-M134 → (а), D-310)

Клетка движка — 82×82, нарисованный гекс в сценах — 78…166 px. Требование ТЗ
«ресемплинг запрещён» при нативном размере исходника физически несовместимо с
носителем: ни один тайл не лег бы в `tile_size`. Решение принято владельцем: одно понижающее
преобразование до `GameNumbers.TILE_SIZE` с записью коэффициента в манифест
сцены, никакой интерполяции на
последующих шагах (ни резка, ни сборка, ни атлас). Формулировка ТЗ «нативное
разрешение сохранять» относится к исходнику (он не правится), а не к тайлу.

Отклонено: «менять `TILE_SIZE` под сцену» — тянет за собой всю раскладку карты,
туман, декали дорог и объектов; «кроить 82 из нативного гекса без масштаба» —
даёт обрезанные края и рассогласование с гексом движка.

### D4. Носители не меняются: нарезка — ещё один источник листов

Выход нарезки — те же `world_map_atlas.json`/`world_map_objects.json`-структуры
(`{tile, grid, cells:[…]}`), те же `kind: base|edge` и объект-лист. Новые id
биомов (лава, «смешанный край» ТЗ) не заводятся без носителя: расширять enum
биомов — отдельное предложение с генератором и рендером, а не следствие нарезки.

Отклонено: `tileset.json`/`gridmap.json` как «формат заказчика» — второй источник
координат, у которого нет читателя; он же нарушает действующий запрет на дубли
координат в скриптах.

### D5. Линии сетки удаляются до резки (Q-M135 → (б), D-310)

Политика выбрана владельцем — «удалить», и она применяется к сцене один раз, до
фитта и резки: ремонт по гексу был бы уникален на каждую клетку и уничтожил бы
остатки переиспользования, а разнобой leave/remove внутри сцены даёт клетки с
разной толщиной рисунка. Операция обязана быть детерминированной (маска линий →
ремонт по соседним пикселям гекса), исходник при этом не правится.

Съеденная цена вердикта: удаление меняет измеряемое содержимое, поэтому ранее
снятые числа (0 повторов при СКО ≤ 5, 3–12 пар при RMS ≤ 16) остаются базлайном
«до», а шаг 0 меряет переиспользование уже на материале без линий. Если после
удаления кластеров не прибавится, путь B закрывается именно этим числом.

### D6. Сравнение тайлов — в Lab, по видимой части гекса

Расстояние — RMS по Lab-каналам по маске гекса (не квадрата): угловые области
квадрата — это соседние клетки, в метрике они врут. Представитель кластера —
медианный по кластеру образец. Порог — константа реестра, а не параметр командной
строки (иначе «подбирается» под зелёный вердикт; `world-map-art-gates`, «Запрет
ослабления порогов»).

### D7. Код живёт рядом со сборщиком, тест — в гейте

`scripts/gen_map_art.py --scene-slice --scene=<файл> [--roi=…]` — режим рядом с
`--assemble`, потому что он переиспользует гекс-маску, палитру и реестр порогов.
Проверщик — `scripts/check_map_art.py` (новые меры), тесты —
`scripts/test_scene_slice.py` + строка в `TESTS` `scripts/doc_gates.sh`. Мелкие
одноразовые замеры — тоже файл в репо, а не `/tmp` (урок «локальные артефакты вне
git — не хранилище», D-192).

### D8. Пиксели сцен в git не идут

Комплект 162 МБ лежит вне репозитория и остаётся там: в репо попадают пути
относительно каталога-комплекта, контрольные суммы, отобранные сцены, реестр
замеров и контрольные кадры (gitignored-пиксели рядом с манифестом, D-185).
Путь к комплекту — настройка машины, не строка в репозитории.

## Risks / Trade-offs

- **Фитт решётки не сойдётся на приличной доле сцен** (первичная проба уже
  расходилась с глазомером) → mitigation: сцена без замера дрейфа в порог
  отвергается, отбор подконкрета входит в шаг 0; вердикт по «доле пригодных сцен»
  — тоже результат замера.
- **Путь B съест компромисс «тканевости»**: нормализация ткани из куска сцены —
  процесс без гарантии, можно получить усреднённое месиво → mitigation: мутация
  гейта «одна ткань» и обязательный кадр; при FAIL путь B закрывается, а не
  «дорегулируется» порогами.
- **Палитра сцен не совпадёт с полосой M** → mitigation: существующий
  `--recolor`/режим A-B уже умеет перекраску с замером; перекраска применяется к
  сцене до резки (D5), чтобы все тайлы сцены имели один профиль.
- **Соблазн сдать путь A как «готово»** (пересборка зелёная, карта — мозаика) →
  mitigation: гейты «не паттерн» и «одна ткань» ловят это без нового кода;
  отдельный сценарий в новой мере переиспользования.
- **Трата смены на 63 сцены** → mitigation: шаг 0 идёт по подконкрету (12 сцен,
  покрывающих все пары биомов + однобиомные + лавовые рамки), полный комплект —
  только если подконкрет дал годный путь.
- **Фон конкретной карты (роль C по вердикту «всё») остаётся без носителя** →
  принято осознанно: подложка под семью группами отрисовки — новый носитель, а не
  следствие нарезки; роль записана хвостом T-340, чтобы вердикт не растворился в
  «сделанной» нарезке материала.

## Migration Plan

1. Шаг 0 (замер) ничего не меняет в игре: новые скрипты, новый реестр, старые
   листы на месте.
2. Если победил путь B — новый лист собирается вторым файлом, старый остаётся
   резервным («Резервный атлас до зелёного гейта»): отсутствие нового файла →
   рендер старым листом + ошибка в журнал.
3. Переключение — одна точка (путь листа в `TileAtlas`), откат — та же точка.
4. Зелёный приём = GdUnit + гейт карты + кадр движка с ux-review; публикация —
   по готовности, как обычно (D-224).

## Вердикты владельца (Q-M133…Q-M135 → D-310, 2026-11-08)

- **Q-M133 → «всё».** Комплект — и материал тайлмапа, и референс стиля, и фон
  конкретных карт. Для спеки это не «реализуем три роли», а разбор по носителю:
  материал — это изменение, референс — замер палитры (не код), фон — хвост T-340
  без носителя (Non-Goal, Risks).
- **Q-M134 → (а).** Единственное понижение до `TILE_SIZE` = 82 px с коэффициентом
  в манифесте разрешено (D3). Канон тайла не обсуждается: канон — 82.
- **Q-M135 → (б).** Линии удаляются детерминированным ремонтом до резки (D5); шаг
  0 меряет материал уже без линий, прежние числа — базлайн «до».

## Выбор пути (Q-M137 → (в), D-313, 2026-11-09)

Шаг 0 дал отрицательный ответ на посылку спеки: переиспользования в комплекте нет
ни при одной честной мере (D-312). Q-M137 был заведен с default-положением в самой
строке реестра («агент без ответа выбирает (в)»); ответа нет, блок снят по этому
default ⇒ путь (в), гибрид:

- **террейн (ткань, переходы) — за генератором.** `gen_map_art.py` остаётся
  единственным писателем материи: варианты биома, анимация и переиспользование,
  которых в комплектах нет, при этом не обещаются. Пиксель-в-пиксель с кадрами для
  террейна — не требование.
- **из сцен режется только уникальное по своей природе:** дороги, строения,
  границы, декор. Такой пропс одноразовый, привязан к конкретной карте и не должен
  быть членом набора: к нему не применяются «одна ткань», «покрытие 80 %», «все
  тайлы различны ≠ паттерн».
- **шаг 3 сужается:** не резка всей сцены по гексу, а вырез пропса по маске с
  привязкой к клетке (фитт D-311 остаётся носителем привязки).
- **шаг 4.1 снимается,** шаг 4.2 становится главным результатом спеки и
  расширяется дорогами/строениями/границами.
- **в шаге 5 снимаются** «полное покрытие без дубликатов» и «100 % различных
  тайлов = провал»; остаются дрейф решётки пропса, пиксель рамки, провенанс,
  единство политики линий.
- D1 остаётся в силе как доказательство от противного: путь A по-прежнему не
  становится годным ни при каком вердикте, а (а) и (г) отвергнуты в D-313.
