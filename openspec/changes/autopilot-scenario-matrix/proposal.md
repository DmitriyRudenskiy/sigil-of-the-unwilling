# Proposal: autopilot-scenario-matrix

## Why

Баланс игры проверяется одной MCP-пробой (60 ходов, герой выживает,
`BalanceProbe` — один автопайлот "выживи и развивайся"). Это не
показывает, сбалансированы ли **классы и роли**: воин-собиратель может
быть сильнее мага-торговца, а монах-путешественник проигрывать
варвару в том же сценарии — текущая проба этого не видит.

Нужна **матрица сценариев автоигры (5 ролей × 11 классов = 55
сценариев)**: детерминированный автопайлот гоняет каждый
(класс, роль) по сценарию роли с чёткой целью и метрикой, а
балансировка — это сравнение результатов внутри роли (по классам)
и внутри класса (по ролям).

## What Changes

- **5 ролей-сценариев** (автопайлоты, каждый со своей целью и
  метрикой успеха):
  1. **Собиратель** — накопить X редких ресурсов за Y дней;
     метрика: ресурсы/день, выживание.
  2. **Путешественник** — пересечь карту A→B через опасные биомы;
     метрика: ходы до цели, потери HP.
  3. **Городостроитель** — поселение: население X + уровень защиты Y;
     метрика: население/уровень за N ходов.
  4. **Торговец** — стартовый капитал → X золота через торговлю;
     метрика: золото к концу, маржа.
  5. **Приключенец** — зачистить логово босса / квест гильдии;
     метрика: победа, ходы, потери.
- **11 классов**: barbarian, fighter, monk, paladin, priest, druid,
  cipher, wizard, ranger, rogue, chanter (таблица `hero_classes.gd`).
- **Драйвер матрицы**: MCP-тест (pytest) гоняет 55 сценариев
  headless, собирает метрики в JSON-отчёт.
- **Отчёт баланса**: таблица 5×11 (метрика на клетку), аномалии
  (клетка хуже медианы роли на >N%) помечаются; отчёт — вход для
  `AutoBalancer`.
- **Интеграция с AutoBalancer**: отчёт матрицы — источник данных
  для корректировок (какие классы/роли подкрутить).

## Capabilities

### New Capabilities
- `autopilot-roles`: 5 ролей-сценариев с целью, автопайлотом и
  метрикой успеха
- `scenario-matrix`: драйвер 5×11 матрицы, детерминированные прогоны,
  JSON-отчёт, пометка аномалий
- `balance-report`: отчёт баланса (медианы по ролям/классам, аномалии),
  вход для AutoBalancer

## Impact

- **Код**: `scripts/probe/ScenarioPilot.gd` (базовый автопайлот + 5
  ролевых политик), `scripts/probe/ScenarioMatrix.gd` (драйвер),
  `tests/mcp/test_scenario_matrix.py` (55 прогонов, отчёт)
- **Данные**: `scripts/data/scenario_targets.gd` (X/Y/цели по ролям)
- **Зависимости**: MCP-сервер (порт 9090), `BalanceProbe` (паттерн
  автопайлота), `AutoBalancer` (потребитель отчёта),
  `settlement-system` (роль Городостроитель — если готов; иначе
  город-точка `City` как дефолт)
- **Тесты**: unit (политики ролей, отчёт), MCP (матрица 55 сценариев —
  маркер `slow`, по умолчанию выборка)
- **Не трогается**: геймплей, герой, бои, экономика — матрица только
  читает игру через MCP

## Non-goals

- Авто-подкрутка баланса по отчёту (AutoBalancer применяет
  корректировки — существующая механика, здесь только вход)
- 11×11 (все пары класс×роль в бою друг с другом)
- Сетевые/мультиплеерные прогоны
- Визуализация отчёта (JSON + консольная таблица)
