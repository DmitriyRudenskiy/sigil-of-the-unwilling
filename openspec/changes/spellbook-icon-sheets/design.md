## Context

Замерено на реальном пуле и реальном железе (Apple M2, 16 GB, MPS доступен,
CUDA нет) — это вход в дизайн, а не догадки:

| Факт | Значение |
| --- | --- |
| Файлов в `__spell_book_raw` | **22** (11 книг × 2 съёмки: JPEG 2368×1776, PNG 1760×1328) |
| Раскладка 12 иллюстраций | два разворота по 2 столбца × 3 ряда = **4 столбца × 3 ряда** |
| Сходство «один кадр в двух съёмках» (CLIP cos) | медиана **0.832**, p95 0.909, max 0.939 |
| Сходство разных иллюстраций одной книги | медиана 0.610, p95 0.769, max 0.916 |
| Сходство разных книг | медиана 0.529, p95 0.665, max 0.911 |
| SAM 3.1, промпт `illustration` (22 листа) | масок **12…20**, ровно 12 — на 7 листах, меньше 12 — ни разу |
| Тот же промпт + привязка к ячейке (прототип) | **22/22** листов в режиме `sam`, пустых ячеек 0, aspect боксов 1.00…1.66 |
| SAM 3.1, промпты `icon`/`emblem`/`picture`/`object` | **0 масок** (концепт не срабатывает) |
| Время SAM-инференса | ~0.3–2 с на лист + загрузка чекпоинта 3.3 GB один раз |
| Время CLIP-векторизации 264 кропов | ~2 мин на CPU (батч 32) |
| Сторона квадратного кропа (замер grid-раскроя) | 161 / 243 / 355 px (мин / медиана / макс) |

### ШАГ 0: что именно переиспользуем (прочитано в исходниках)

**`VisionEmbed-CLI/dataset_prep.py`** (монолит `run_pipeline`, 1070 строк):

- вектор: `transformers.CLIPModel.from_pretrained("laion/CLIP-ViT-L-14-laion2B-s32B-b82K")`
  → `processor(images=...)` → `model.get_image_features(**inputs)` (со фолбэком
  на `pooler_output`/`image_embeds`, то есть transformers 5.x переживает) →
  L2-нормировка;
- метрика: косинус `E @ E.T`, расстояние `np.clip(1 − cos, 0, 2)`;
- дедуп: `UnionFind` по `sim >= --dedup_threshold` (дефолт **0.99**) — на нашем
  пуле не склеит ничего (максимум 0.939), поэтому дедуп-порог скрипта не трогаем;
- кластеризация: KMeans, `k = 2..min(--max_clusters, N//2)`, выбор `k` по
  силуэту;
- отбор: `compute_quotas(clusters_meta, N, mode)` → `random.sample` по кластерам
  → `build_selection_for_mode(...)`; внутри — TSP-упорядочивание **внутри
  выбранного набора** (старт от точки, наиболее далёкой от центроида, дальше
  жадный *ближайший* сосед);
- **важно:** родной алгоритм ничто не запрещает класть две похожие картинки в
  один набор — `soft_dup_pairs` только считается в метриках качества. Значит
  антидубль (ШАГ 4 плана) — надстройка над родным отбором, а не его часть.

Два подводных камня при вызове: `load_and_filter_images` отбрасывает файлы с
`min(w, h) < --min_size` (**дефолт 512** — а максимальный наш кроп 355 px, то
есть скрипт молча выбросил бы **все 264**, нужно `--min_size 0`) и молча пропускает имена под `SYNTHETIC_PATTERN`
(`^(item_|file_|img_|sample_)\d+`); имена `<stem>_<01..12>.png` проходят.

**`VisionFlow/src/infrastructure/ai/sam3_client.py`**:

- `SAM3Client(model_path=..., device="auto")` → `ultralytics.models.sam.
  SAM3SemanticPredictor` с `overrides={conf: 0.25, task: segment, imgsz: 644,
  half: False}`; device разрешается в `cuda → mps → cpu`;
- промптинг **текстовый**: `predictor.set_image(pil)` → `predictor(text=[prompt])`
  → маски; точек/боксовый промпт в этой обёртке не используется;
- `crop_image(path, mode="square")` возвращает список временных файлов и сам
  делает квадрат по центру с подложкой `(247,247,247)`;
- для своих промптов и своих имён используется тот же клиент: `set_image` +
  `_predict_prompts([...])` + `_get_mask_bbox(mask)`, а не свой загрузчик.

## Goals / Non-Goals

**Goals:**
- 22 → 264 → 29 листов + 3 остатка, все контрольные числа сходятся.
- Детекция SAM, фолбэк сеткой только там, где SAM не дал 12, и это видно в отчёте.
- Внутри девятки нет пары выше порога; дубль заменён самым далёким кандидатом.
- Первый и последний лист — максимально далёкие центроиды.
- Прототип на одном листе показан и одобрен до полного прогона.

**Non-Goals:**
- Генерация/клонирование арта (`image-clone`, `art-gen`), импорт в Godot.
- Альфа-канал и вырезание по маске: кроп — квадратный кусок страницы.
- Удаление второй съёмки книги из пула: 264 кропа идут в отбор все (требование
  заказчика), дедуплицируется только *соседство внутри девятки*.
- Изменение `dataset_prep.py` и `VisionFlow` — только вызов их кода.

## Decisions

### D1. Детекция: SAM 3.1 через `SAM3Client`, ровно 12 боксов, иначе сетка 4×3

Промпт `illustration` (замер: 12…20 масок, никогда < 12). **Сетка даёт адрес,
SAM даёт бокс** — прототип `proto3.py`, прогон по всем 22 листам:

1. фильтр по площади маски (≥ 0.35 % площади листа) — снимает обломки рамок и
   угловые вензеля;
2. сетка 4×3 восстанавливается **по разрывам центров** масок (3 крупнейших
   разрыва по x, 2 по y) — ни границ страницы, ни ориентации разворота не нужно;
3. в каждую из 12 ячеек берётся **самая большая** попавшая в неё маска — это же
   и есть слияние разрезанного объекта, отдельный NMS/containment-шаг не
   потребовался;
4. ячейка без маски добирается прямоугольником сетки, лист помечается
   `grid-cells:N`; если масок меньше 12 вообще — `fallback-grid`;
5. `detections.json`: лист → 12 боксов, способ, число масок до и после фильтра.

Замер прототипа (все 22 листа): **22/22 режим `sam`**, пустых ячеек 0; у
варианта «12 крупнейших» тот же тест покрывал 11 ячеек на листе
`…ba825cd7be1f` — поэтому выбрана привязка к ячейке, а не топ-12 по площади.
Отношение сторон боксов 1.00…1.66 — квадратизация (D2) обязана быть с клампом.

Почему не сетка сразу (grid-прототип тоже давал 12/12): сетка даёт правильный
*счёт*, но плотный бокс по контенту только у крупных иллюстраций, а по
перекосённой странице режет шапки объектов. Комбинация: SAM считает бокс,
сетка страхует счёт.

`icon`, `emblem`, `picture`, `object` дадут 0 масок — не использовать;
`drawing` шумнее (`13…28` масок).

### D2. Кроп: квадрат по центру бокса, кламп в границы листа

Сторона квадрата = `max(w, h)` бокса, центр сохраняется, координаты зажимаются
в `[0, W] × [0, H]`. Бокс предварительно расширяется на `--pad` (дефолт
**4 %** стороны, с тем же клампом): маска SAM идёт по плотному телу объекта и
срезает мягкое — дымку, свечение, тонкие лучи. Видно на контакт-листах
прототипа: без надстройки обрезаны лучи «звёздного разлома» и кистевой баннер,
на ветряном листе — хвосты вихрей. 4 % хватает на мягкий край и не притягивает
соседний объект. Ничего не досказывается: поля запрещены требованием. Если
бокс прижался к краю и квадрат влезть не может целиком — берётся максимально
внутренний квадрат, а лист попадает в отчёт как `edge-clamped` (там контент
реально у края страницы). Имя — `<stem без расширения>_<01..12>.png`, порядок
нумерации — слева направо, сверху вниз (по центру бокса).

Не переиспользуем `SAM3Client.crop_image`: он кладёт подложку `(247,247,247)`
и пишет во временные файлы — нам нужны детерминированные имена и отсутствие
подложки. Переиспользуется детекционная часть клиента.

### D3. Векторы: функции `dataset_prep.py`, один прогон на 264 кропа

Импорт `dataset_prep` как модуля (`sys.path`), вызов его же кода векторизации
по 264 кропам, `--min_size 0`, батч 32, seed 43. Результат — `embeddings.json`
(264 вектора по 768) + `emb_names.json`. Device — `cpu` (в скрипте `auto` даёт
`cuda → cpu`, MPS он не знает; 2 минуты на CPU — не повод править чужой код).
Повторный прогон при неизменном md5 кропов инференс пропускает.

### D4. Отбор по 9: родной алгоритм, вызываемый повторно по остатку

Каждая итерация по оставшемуся пулу: KMeans + силуэт → `compute_quotas` →
`build_selection_for_mode(mode, N=9)`. Это ровно тот код, что в скрипте; свой
кластерный отбор не пишется. Так как `run_pipeline` — монолит с файловым
входом, для итерации используется связка `load_and_filter_images` + функции
кластеризации/отбора из модуля (те же имена, что в скрипте), а не копия логики.

Параметры: `--max_clusters` 9, `--min_cluster_size` 2 (дефолт 3 на девятке
резает слишком жёстко), `--seed` 43.

### D5. Антидубль внутри девятки: порог + замена самым далёким кандидатом

После родного отбора по 9: пока внутри девятки есть пара `sim > --max-intra-sim`,
худший (второй в паре) заменяется самым далёким от членов девятки неиспользованным
кандидатом, который сам не нарушает порог. Если такого нет — предупреждение в
отчёт, пара остаётся (лучше честное предупреждение, чем бесконечный цикл).

Эмпирика порога на пуле (доля пойманных одноимённых пар / доля ложно
заблокированных разных пар):

| `--max-intra-sim` | ловим «один кадр в двух съёмках» | блокируем разных пар |
| --- | --- | --- |
| 0.90 (старт из плана) | 11.4 % | 0.01 % (5 пар) |
| 0.85 | 41.7 % | 0.10 % (33) |
| **0.80 (дефолт)** | **69.7 %** | 0.38 % (130) |
| 0.75 | 87.9 % | 1.15 % (397) |

Вывод из замера: 0.90 из плана ловит одну пару из девяти. Дефолт — 0.80.

**Дополнительное жёсткое правило (предложение владельцу):** две съёмки одной
книги — это буквально один и тот же объект, и порогом он не берётся (см.
таблицу). Поэтому пары «один лист + одна ячейка» (`same source book, same cell`)
не заносятся в одну девятку **запретом**, а не порогом. Это на 100 % закрывает
«два одинаковых щита из двух съёмок» и стоит одну строку; правило порога
продолжает ловить смысловые повторы из *разных* книг.

### D6. Порядок листов: центроиды, максимум — на края

`centroid_i = normalize(mean(векторов девятки i))`. Пара листов с максимальным
расстоянием `1 − cos(центроид)` ставится на позиции 0 и 28. Остальные 27
раскладываются жадно: на каждой следующей свободной позиции (чередывая с конца)
лист, максимально далёкий от уже поставленных соседей, — так середина монотонно
убывает от краев. Детерминировано: при равенстве выигрывает меньший номер
девятки. Результат — `sheets.json` с порядком и расстоянием центроидов
первого и последнего листа (это число обязано быть максимумом по всем парам).

TSP-упорядочивание из `build_selection_for_mode` остаётся тем, чем оно есть:
порядок *внутри* набора. Порядок клеток 3×3 оно не задаёт (клетки заполняются
по индексу 0…8).

### D7. Склейка и артефакты

Клетка — квадрат фиксированной стороны `--cell` (дефолт **320 px**, одна на все
листы, иначе листы разного размера): кропы 161…355 px приводятся к ней
LANCZOS, квадрат в квадрат, пропорции не искажаются (максимальное увеличение
самого мелкого кропа — 2.0×). Лист = `3 × 320 = 960 × 960`, вставка без зазоров,
рамок и отступов нет.

Артефакты прогона в `reference/spellbook/`: `detections.json`, `crops/`
(264), `embeddings.json` (264), `sheets/` (29), `residual/` (3), `report.md`
(метрики + список фолбэк-листов + максимум сходства внутри каждого листа +
расстояние центроидов первый↔последний). Пиксели gitignored, `INDEX.md` с md5
листов — в репозитории (конвенция `reference/INDEX.md`).

## Risks / Trade-offs

- **SAM не даёт 12 на 15 листах из 22.** Ветка фолбэка — не редкий случай, а
  штатный путь; отчёт обязан показать, какие листы сеткой, и QC-оверлей боксов
  перед полным прогоном.
- **Двадцать девять листов из 264 кропов содержат пары «один и тот же объект из
  двух съёмок» в разных листах.** Это следствие условия «264 кропа → 29 листов»:
  132 объекта представлены дважды, и ни один алгоритм разнообразия не сделает
  их разными. Если дубли в листах нежелательны, решение — резать пул до 132
  (14 листов + 6 остатка), а не порог сходства.
- **Порог 0.80 блокирует 130 «разных» пар** — для однотипного (растительного)
  пула это заметно. Порог в `report.md`, пересбор листов без пересчёта векторов.
- **`--min_size` по умолчанию 512** молча съедает мелкие кропы: параметр
  обязан быть явным (`0`), иначе счёт 264 не сойдётся без внятной ошибки.
- **MPS для SAM, CPU для CLIP** — два разных окружения в одном прогоне; если
  MPS откажет, SAM уходит на CPU и прогон замедляется примерно вчетверо
  (устройство печатается в отчёте).
