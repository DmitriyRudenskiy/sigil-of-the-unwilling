## Context

`docs/` заморожен до MVP (FREEZE, 2026-10-02): изменения только по решению владельца, багфиксу или резолву TBD. Реестры (`DECISIONS.md` — K-/D-/Q-/T-записи, `QUESTIONS.md` — реестр TBD, `BANK.md` + `docs/bank/` — аннулированный контент) — единственные места, куда можно дописывать, не трогая канон-тексты.

Гейт связности — `scripts/check_docs_links.py`: обходит `docs/` рекурсивно, требует frontmatter с `status` из `ALLOWED_STATUSES` (там уже есть `reference`), запрещает кириллицу в именах файлов и путевые wikilinks, резолвит `[[target]]` по **basename**. `docs/bank/` исключён из обхода целиком (D-102), архивные логи — вне графа как источники (D-107).

Корневой `reference/` занят под другое: карта референсов **стиля** (пиксели, в git только `INDEX.md`, см. арт-библия §10). Концепт-вольт `/Users/user/sigil-of-the-unwilling-doc/` — внешний, не в git: 27 контент-файлов (~290 КБ) + 10 сырых чатов (~10.6k строк, много кода чужих прототипов).

## Goals / Non-Goals

**Goals:**

- У у каждой чужой игры, названной референсом в каноне (AtS, TerraScape, HoMM III, D&D 5e, PoE2, Allods), есть носитель данных в репо с provenance и явным «НЕ канон».
- Сверка «вольт ↔ канон» — один реестр с вердиктами и основаниями, а не устная память сессии.
- Дыры, которые вольт вскрыл, видны как пункты реестра TBD, а не как молчание.
- Канон-тексты не изменены ни на строку (кроме одной строки индекса в 00-overview).

**Non-Goals:**

- Не решать, чьи числа канон; не трогать `07-balance`, `02g`, `13-art-bible`, `game/`.
- Не присваивать номера D-* (присваивает только реестр `DECISIONS.md`).
- Не верифицировать данные вольта по вики (источник сам заявляет: вики недоступны, 403/Cloudflare).
- Не переводить чаты в документацию и не чистить их стиль.

## Decisions

**Д1. Зона — `docs/reference/`, а не `docs/bank/` и не корневой `reference/`.**
Банк — это *наш* аннулированный контент, каждая позиция с меткой аннулирования и основанием; AtS/TerraScape/D&D таковыми не являются, и вывод зоны из grep-гейтов (как банка) лишил бы её главного свойства — прослеживаемости «цифра ↔ источник». Корневой `reference/` — про пиксели стиля и почти весь не в git. Остаётся новая зона в `docs/`, внутри действующего чекера, со `status: reference`. Альтернатива «в банк» отклонена ещё и потому, что выемка из банка — отдельная процедура против мандата (AGENTS.md), а референс надо читать свободно.

**Д2. Зона остаётся в графе чекера (не исключаем, как банк).**
Битая wikilink из референса — сигнал («источник переехал»), а не шум. Исключение из обхода потребовало бы править `check_docs_links.py` и сняло бы проверку frontmatter/имён с ~20 новых файлов.

**Д3. Имена файлов — с префиксом источника: `ats-races.md`, `ats-goods.md`, `dnd-races.md`, `poe2-races.md`, `sigil-ats-races.md`.**
Граф чекера ключуется по basename: четыре `races.md` в разных подкаталогах дали бы неоднозначные `[[races]]` и молча ложные резолвы. Подкаталоги при этом сохраняются — они несут категорию (`against-the-storm/`, `terrascape/`, `homm3/`, `allods/`, `dnd/`, `poe2/`, `sigil-ats-prototype/`). Альтернатива «оставить исходные имена» дешевле при импорте, но ломает навигацию в Obsidian.

**Д4. Провенанс-шапка обязательна в каждом импортированном файле** — пять полей: `Источник` (путь в вольте), `Получено` (дата), `Что это` (игра/источник данных), `Сверка` (сверено ли с официальными вики — для AtS-блока честно: нет, 403), `Статус` (референс, НЕ канон Sigil). Без поля `Сверка` импорт AtS-чисел выглядел бы проверенным, хотя сам вольт этого не утверждает. Формат — обычный markdown-блок под frontmatter, не поля frontmatter: чекер проверяет только `status`, а текст сверки длиннее одной строки.

**Д5. `kb/` — карантинный подкаталог, а не референс и не банк.**
`kb/` описывает не-канонический AtS-клон и аудит не Godot-сборки (цитаты кода на JS; браузерный прототип того же городского слоя, расходящийся с 02g §9.3/§11). Он импортируется как исторический первоисточник с шапкой-карантином («не канон Sigil; аудит браузерного прототипа, не Godot-сборки; в `02g`/`07-balance` не переносить»). В банк — нельзя: там нужны метка аннулирования и решение владельца, которого по этому контенту не было.

**Д6. Конфликты — в `docs/reference/CONFLICTS.md`, канон не правится.**
Формат строки: утверждение вольта | канон-репо | основание (K-/D-) | вердикт (`аннулировано вольтом` / `вне канона` / `решения нет`) | куда зарегистрировано. Отдельная таблица — внутренние расхождения самого репо, которые сверка вскрыла (02g §12 «уровни города 1–11 [КАНОН]» против индекса 00-overview и глоссария; `buildings.json` → `min_city_level`): они не из вольта, но вольт их подсвечивает, и молча «чинить» их по канону-из-индекса — значит снять с владельца решение.

**Д7. Дыры — в реестр открытых вопросов `QUESTIONS.md` (нумерация `Q-M<N>`, последний занятый — Q-M37), а не новыми доками.**
Очередь строительства и время постройки, классы населения и назначение рабочих, внутриигровая энциклопедия (Кодекс), естественная убыль в городском слое. Канон-текст под них писать нечем: решения нет, есть только материал из чатов. Пункт реестра — единственный способ не потерять находку и не выдать её за канон. Формата `T1–T10`, упомянутого в AGENTS.md, в `QUESTIONS.md` нет (там `Q-M`-таблица из 5 колонок: # | вопрос | контекст | варианты | блокирует) — расхождение фиксировать в отчёте, AGENTS.md не править без запроса.

**Д8. Чаты (10 файлов) не импортируются.**
~10.6k строк, значительная часть — код чужих прототипов (Godot/JS-конструкторы PoE2 и Pathfinder, HTML-сборка) и повторения уже импортированного. Извлекаются только выводы, уже вошедшие в `kb/` и в `CONFLICTS.md`; путь к вольте фиксируется в README зоны. Альтернатива «положить чаты как есть» добавляет непроверяемый объём и второй, конкурирующий с доками, слой истины.

## Risks / Trade-offs

- [Референсные числа просачиваются в баланс как канон] → в README зоны прямой запрет: «числа отсюда не переносятся в `07-balance`/баланс-конфиги иначе как решение владельца»; ни одна формула канон-доков не ссылается на `docs/reference/`. Отдельного гарда нет (grep-правило) до первого реального случая — ловится ревью диффа.
- [Двойная истина по уровням города так и остаётся] → осознанно: она уже в репо и вне объёма; фиксируется строкой в `CONFLICTS.md` и флагом владельцу. Молчаливая правка одной из сторон хуже.
- [~290 KB импортированного текста, часть которого устаревает вместе с чужими играми] → побайтовый импорт без переписывания (редактируется только шапка), устаревание изолировано статусом `reference` и не трогает канон.
- [Префиксы имён расходятся с именами в вольте] → таблица «файл вольты → файл репо» в README зоны; обратный поиск остаётся возможным.
- [Зона подменяет собой TBD-решения, потому что «уже всё написано»] → реестр конфликтов обязателен к прочтению перед любой правкой городского/расового слоя: это единственная его функция.

## Migration Plan

Docs-only, на feature-ветке; мерж — по действующему протоколу (локальные тесты + ревью диффа владельцем; docs-PR — само-мерж при `check_docs_links.py` pass). Откат — `git revert` коммита импорта, зона самодостаточна и не имеет обратных ссылок из формул.
