## Как читать таблицу

- **Задачи** — счётчик `- [x]` / всех `- [ ]` и `- [x]` в `tasks.md` цикла.
- **Спеки** — перенесены ли дельты цикла в `openspec/specs/`. По конвенции OpenSpec
  главный спек capability появляется (или обновляется) **при архивировании**, поэтому
  «нет главного спека» у активного цикла — норма, а не рассинхрон. Исключение
  отмечено строкой: главный спек уже есть, а требований в нём нет.
- **Что держит остаток** — класс последних незакрытых задач: код агента, вердикт
  владельца, playtest (не снимается headless), CI-раны (зона владельца), внешний
  сервис, чужая сессия.

## Механика архивирования на этой машине

CLI `openspec` (в AGENTS.md указан `/usr/bin/openspec`) **на машине сборки
отсутствует** — `openspec --version` даёт «команда не найдена». Архивирование
выполняется вручную и эквивалентно шагам скилла `openspec-archive-change`:
(1) `tasks.md` — все задачи закрыты или явно помечены снятыми; (2) дельты из
`changes/<name>/specs/` сверяются с `openspec/specs/<capability>/spec.md` и
переносятся; (3) каталог переносится в `changes/archive/YYYY-MM-DD-<name>/`.
Расхождение AGENTS.md и машины зарегистрировано как факт среды, а не как задача
кода (D-166-семья: среда, не репозиторий).
