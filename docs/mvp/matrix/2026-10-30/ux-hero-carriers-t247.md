# Акт инвентаря и опись строк экрана «Герой» (T-247)

**Что это.** Срез не покадровый: T-247 — про состав экрана и его носители, а не
про внешний вид. Кадра здесь нет и быть не может: экран как картинка разобран
в §6.1–§6.10 (`ux-hero-grid-t255.md`, `ux-hero-bands-t257.md`,
`ux-hero-doll-t258.md`, `ux-hero-unit-cards-t306.md` …), а этот срез отвечает на
вопрос «что на экране есть, чем заполняется и где это записано». UX-review
машинным зрением к нему неприменим: пикселей срез не меняет (удалены два PNG,
которые никто не рисовал с D-278).

## 1. Носитель

`game/scenes/ui/artifact_inventory_screen.carriers.csv` — рядом со сценой, как
просила постановка. 44 строки данных, 8 колонок:
`row, mockup_type, mockup, node, asset, data, status, note`.

| Часть шапки | Содержание |
| --- | --- |
| `# COVERAGE artifact_inventory_screen: covered 13 / outside-mockup 7 / missing 1` | арифметика покрытия по строкам-типам |
| `# TYPE NN <тип> = covered\|missing` × 14 | типы строк макета §4; номер держит порядок карты, имя связывает со столбцом `mockup_type` |
| `# ASSET-CENSUS` | записи кита без потребителя и почему они остались |
| `# REMOVED-BY-INVENTORY-ACT` | что снял акт инвентаря |
| `# LEGEND` | словарь статусов и правила `node`/`asset` (семейства `*`, альтернативы `\|`, `-` только при `no-carrier`) |

Инварианты, которые держит тест, а не проза: `covered + missing == 14`;
`outside-mockup` считается по **номерам строк карты** (инстансы одного типа
свёрнуты в семейства), поэтому 7 номеров при 8 строках CSV — строка 12 (мана)
занимает две строки описи, подписи и полосу; каждая строка не-`covered`
содержит ссылку на билет/вопрос/раздел; каждый путь узла резолвится в живой
сцене; каждый `hero/*.png` и конкретный `icons/*.png` лежит на диске; каждая
текстура кита в сцене названа описью.

## 2. Покрытие

| Класс | Число | Что |
| --- | --- | --- |
| типы макета закрыты | 13 из 14 | пергамент, плита, плашка имени, разделитель, блок характеристик, список надетого, фигура, рамка куклы, ячейка сетки, карточка юнита, плитка-кнопка, подсказка предмета, рама портрета |
| тип макета отсутствует | 1 | **строка уровня** (`04`): уровня нет ни у героя, ни у стека отряда — Q-M121, T-306, T-251 |
| строки вне кадра макета | 7 номеров | 12 мана, 13 школа, 19 редкость, 29 кнопки предмета, 30 навыки, 31 построения, 32 «Перевес» |
| строки `no-carrier` | 6 | 5, 6 (уровень/опыт стека), 23–25 (полосы карточки юнита), 27 «?» (журнала квестов в main нет) — скрыты по значению, носителя нет у данных |

Расхождение с планом §5 (mana — «3-й ряд характеристик», навыки/построения —
«ленты у фигуры») задокументировано до этого среза: §6, строки переноса
`BandMana` / `BandSkills`. Опись его не чинит и не прячет — в `note` таких
строк стоит «§5 план; реализация — лента BandSkills».

## 6. Побочный эффект носителя (фиксируем, чтобы не выглядело регрессией)

Godot импортирует любой `.csv` под `game/` как Translation. При смене
содержимого файла импорт печатает `WARNING: CSV file
'res://scenes/ui/artifact_inventory_screen.carriers.csv' does not contain any
translation.` Ни `.translation`, ни загрузки в `TranslationServer` не
происходит: `project.godot` перечисляет только `locale/ru.po` и `locale/en.po`.
Служебный `.import` скрыт уже существующей маской `*.csv.import` в `.gitignore:67`; прецедент
непереводного CSV в проекте — `game/tools/pixelart/style_features.csv`.
