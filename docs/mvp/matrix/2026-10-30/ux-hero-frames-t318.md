# ux-review T-318: трое героев на поле — те же, чей вырез дал владелец

Дыра в верификации была не в кадре, а в связке: контактный лист решает, какой
вариант принят, но в `main` лежали бинарники, и ничто не доказывало, что именно
эти бинарники лист и покрывал. Поэтому у приёмки два носителя — **глаз**
(четыре оси: стиль, лицо, палитра, оружие, оружие первым) и **манифест**
(вариант + sha256 каждого кадра, которые пишет `integrate.py`).

## Как повторить (пиксели в git не идут, D-185)

```
python3 scripts/hero_anim/hero_anim.py <герой> --sheet                 # профили, 4 варианта
python3 scripts/hero_anim/hero_anim.py <герой> --adopt N               # принять профиль
python3 scripts/hero_anim/hero_anim.py <герой> --action <a> --variants 3 --sheet
python3 scripts/hero_anim/hero_anim.py <герой> --action <a> --collect N
python3 scripts/hero_anim/integrate.py <герой>                          # кадры + frames_manifest.json
python3 scripts/hero_identity_audit.py --out tmp/hero-identity-audit-t318.png
python3 scripts/check_hero_frames.py                                    # кадры ↔ манифест
```

Кадр «герой в бою» — фикстурой смены, канал `tools/shot_scene.gd` (Xvfb ровно
1920×1080, поэтому кадр канонический по размеру):

```
godot --path game -s tools/shot_scene.gd -- \
  --scene=res://scenes/battle.tscn --state=battle_hero_frames \
  --out=tmp/shots/t318_battle_hero_frames.png
```

Фикстура возвращает не только `ok`: на каждом атакующем юните она отдаёт
`set` — путь `.sprite_frames.tres`, которым ожил юнит. Это доказательство
сильнее пикселей: «анимация есть» не отличить от «AnimationSprite показывает
вырез владельца», а путь к комплекту отличает.

## Отклонённые варианты и почему

* `knights` turn v03 — после разворота к камере **руки пусты**: то же самое
  чтение «руки опущены», ради запрета которого написан D-297. Дорожка не
  циклична (`LOOP[turn] = 0`), то есть кадр попал бы в бой без всякой отсечки.
* `paladin` turn v03 — то же: головка булавы теряется в камера-фронт.
* `paladin` attack v02, v03 — головка булавы светится зелёным. Рядом с листом
  лежит тот же кадр **с уже применённой маской `HALO`** (её `integrate.py`
  включает только для палидина): у v02/v03 от головки остаётся дыра, то есть
  оружие пропало бы уже в игре, а не на листе.
* `knights` attack v02/v03 — лезвие становится зелёным призраком/исчезает;
  v01 — зелёная воронка по краю, но оружие цело.

## Расхождения, принятые сознательно

* **Щит палидина.** В вырезе он есть, ни в одном из четырёх вариантов профиля —
  нет. Ось «оружие» — булава (она на месте и читаема); щит в четырёх осей не
  входит, расхождение принято, а не замалчивается.
* **`paladin` не виден в бою.** Ключа юнита у палидина в
  `UnitRegistry.UNITS_BASE` нет, в `CharacterFrames.ANIMATED` он не играет
  (HERO-ANIM §«Реестр и приоритет носителей»), поэтому его приёмка — только
  контактный лист. Это не «не проверено»: проверено ровно тем носителем,
  который у героя есть.
* **Формат профиля.** Профили переснятых героев приходят 4:7 и выше
  (`integrate.load_frames` обрезает сверху и снизу по холсту 512), поэтому
  кадр в игре ниже ростом, чем вырез: геометрия ADR-008 (ступни 256,448)
  соблюдается сборкой, а не рисунком.

## Машинная часть приёмки

* `python3 scripts/check_hero_frames.py` → `HERO FRAMES: OK (5 герой(ов),
  300 кадров сверены с манифестом)`.
* Проба зубов на **копии** дерева (реальные кадры не трогались): один
  перевёрнутый байт в `knights_idle_01.png` →
  `knights: knights_idle_01.png не совпадает с манифестом …`,
  `HERO FRAMES: RED (1 расхождений)`, exit 1.
* `python3 -m pytest scripts/test_check_hero_frames.py` — 7 тестов (ok, нет
  манифеста, подменённый кадр, лишний кадр, удалённый кадр, не-герой, два
  героя не затирают друг друга).
* Фикстура на живом бою (кадр 1920×1080): `swordsmen` → `swordsmen.sprite_frames.tres`,
  `knights` → `knights.sprite_frames.tres`, `battle_dwarf` →
  `battle_dwarf.sprite_frames.tres`, у всех `track = idle`, `visible = true`.

## Чего эта смена не делает

Не трогает `swordsmen`/`archers` (их идентичность совпала до правки промпта),
не решает вопрос прав на арт-комплект (ASSET-1, 641–643 позиции из 694–696 без
подтверждения) и не добавляет палидину ключ юнита — это отдельные билеты.

См. также: [[HERO-ANIM]] (конвейер, оси, манифест), билет **T-318** и правило
промпта **D-297** в `docs/DECISIONS.md`, носитель кадров — **D-296**.
