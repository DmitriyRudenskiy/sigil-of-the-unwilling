## Макет-источник

Боевого макета нет ни в репозитории, ни на машине — та же дыра, что уже
зафиксирована оговоркой в задаче 7.x этой же смены и отдельным тикетом
**T-312**. Композиционный референс владельца
(`~/Downloads/Interface_battle/gpt-image-2.5-sunburst_a_Make_the_characters_.jpg`,
1920×1080, md5 `815617d2c77bb8fa765f1876393a1f24`) с машины удалён: в репо
остались только его md5 и **текстовое описание расстановки**, перенесённое в
задачу 3.8 и в тесты. Поэтому сверка велась не с пикселями референса, а с
его записанными правилами (шахматный зигзаг, свободная середина, стороны
смотрят друг на друга) и со спеками `battle-hud` / `battle-ui` /
`battle-field-tilt` / `battle-unit-figures`. Это граница вердикта, а не
отговорка: сравнение «против пикселей референса» сегодня вынести нечем.

## Задача 1.5 — наклон плоскости

Что видно по кадру `t305-tilt-1080.png` (сетка A1..J10):

* **A2..H9** — гексы лежат «на скошенном столе»: соты сплюснуты по вертикали
  одним коэффициентом, ряды сходят к верхнему краю, вертикальные границы
  сот остаются отвесными. Наклон один на поле: обводка доски (`BoardOutline`),
  подсветки (`HighlightOverlay`), курсор и фон тайлмапа дают те же эллипсы,
  разнобоя «часть сот плоская» в кадре нет.
* **A1..J1** и **A10..J10** — полосы HUD; наклонённый прямоугольник поля
  лежит между ними, в полосу верхнего бора соты не вылезают.
* **J1** — медальон-значок без подписи (D-293), **A10..C10 + G10..J10** —
  восемь командных значков 4+4, **центр нижней полосы (D10..F10) пуст** —
  ряд сведён по D-294, тест `test_battle_ui_hud_zones` держит состав.
* **B9**, **J9** — числа урона поверх поля; одновременно не больше восьми
  (`MAX_SIMULTANEOUS_NUMBERS`), в кадре их два.

Расхождения:

1. **I5..J7 — карточка противника лежит поверх поля.** Пластина перекрывает
   шесть сот правого фланга защитника, и бо́льшая её часть — пустой фон:
   текст занимает три строки в I5, ниже — пустой прямоугольник ~2×3 соты.
   Требование «поле целиком в полосе между полосами HUD» (задача 1.4) при
   закрытой карточке не выполняется буквально, а требование «карточка
   противника видна всегда» (`docs/14-ux-battle-hud.md` §«Карточка противника
   видна всегда», D-267) ничего не говорит о праве занимать клетки поля.
   → **отложено с задачей T-324**.
2. **J2, J8 — фигуры правого ряда обрезаны кромкой кадра.** Замер по пикселям:
   белая обводка сот доходит максимум до x=1887 при ширине 1920, то есть
   **соты целиком в кадре**, а спрайт стека (канвас 512, якорь по опоре)
   свешивается за правый край и режется по телу. Мера: обводка — внутри,
   фигура — снаружи. → **отложено с задачей T-325**.

Вердикт 1.5: **PASS с двумя расхождениями, зафиксированными тикетами.**
Сам наклон — соответствующий и единый; ни одного дефекта проекции (двойной
наклон, плоские соты, рассогласованный клик) в кадре нет.

## Задача 3.7 — фигуры обеих сторон и расстановка

Кадр `t305-figures-1080.png`, летняя местность, атакующий — принятые герои
(`swordsmen`, `knights`, `battle_dwarf`), защитник — гоблины:

* **B2/B3, C2/C3, B4/B5** — четыре стека атакующего: лучник, латник с мечом,
  латник с плащом, гном с топором и щитом. Стоят **шахматным зигзагом** по
  колонкам B/C с шагом по ряду — стена у борта не читается, середина поля
  (**D4..G8**) пуста: ровно то правило расстановки, которое 3.8 перенесла из
  референса в `battle_state_builder._build_units`.
* **I2, J2, J3, I8** — стеки защитника у правого фланга, лицом влево;
  атакующий смотрит вправо. Взаимная ориентация сторон держится арт-осью
  (`CharacterFrames.faces_right()`), а не `flip_h` по стороне — тест
  `test_facing_follows_the_art_not_the_side`.
* **Опорная точка.** Ноги каждой фигуры стоят на соте, а не «в воздухе» и не
  «в траве»: кадр согласуется с аудитом `scripts/audit_hero_frames.py`
  (низ силуэта 438–448 при опоре 448, рост 330–384).
* **Z-порядок.** Стека, перекрывающего соседа «наискосок», нет: порядок
  отрисовки по ряду (`unit_z`) читается — нижний ряд всегда поверх.
* **I5..J7** — та же карточка противника, что и в 1.5; в этом кадре она
  дополнительно закрывает гоблина в J3 (видна только подпись «G» над ним).
  Диспозиция — T-324.
* **J2, J8** — подрезка спрайтов правого ряда кромкой кадра; в этом кадре
  у J8 за краем примерно половина фигуры. Диспозиция — T-325.

Расхождения с записанной расстановкой референса: **свободная середина —
соблюдена; зигзаг — соблюдён; стороны смотрят друг на друга — соблюдено;
«пять против пяти» — не соблюдено по причине, внешней к кадру** (в бою
четыре стека атакующего против четырёх защитников: столько задала фикстура
`battle_hero_frames`, а не движок).

Вердикт 3.7: **PASS по композиционным правилам с двумя расхождениями
(T-324, T-325).** Буквальная сверка «против пикселей референса» невозможна —
носителя нет (T-312), правило зафиксировано в этом разделе как граница меры.

## Воспроизведение

```sh
Xvfb :93 &                      # свой дисплей; :96/:97 чужие, не трогать
DISPLAY=:93 godot --path game -s tools/shot_scene.gd -- \
    --scene=res://scenes/battle.tscn --state=battle_field_max \
    --out=tmp/shots/t305-tilt-1080.png
DISPLAY=:93 godot --path game -s tools/shot_scene.gd -- \
    --scene=res://scenes/battle.tscn --state=battle_hero_frames \
    --out=tmp/shots/t305-figures-1080.png
python3 scripts/ui_grid.py game/tmp/shots/t305-tilt-1080.png --out game/tmp/shots/g.tilt.png
python3 scripts/ui_grid.py game/tmp/shots/t305-figures-1080.png --out game/tmp/shots/g.figures.png
```
