## Отвергнутая версия (кадр как причина)

Первая версия среза сняла с §4.8 `theme_type_variation = "TooltipPanel"` и
`"TooltipLabel"` как «молчаливое ничего». Кадр: **7330** отличающихся пикселей в
полосе (59,299)–(679,395); на снимке `sink_48_rejected_crop.png` пластина без золотой
рамки, подпись — белый Label кегля 16. Это сняло бы К-6 с единственного кадра, где он
виден. Причина ложного предположения: Godot резолвит `theme_type_variation` по имени
секции темы, `base_type` нужен только для цепочки отката и редактора (замер
`Theme.get_type_list()` = 82 секции, `ThemeDB.get_default_theme().get_type_list()` =
63 имени). Правка откатана к нулевой дельте, а проверка теперь стоит на самой
пластине: `test_tooltip_section_uses_the_engine_mechanism` требует, чтобы в поддереве
§4.8 кто-то нёс `TooltipPanel` и `TooltipLabel` (мутант M9 батареи).

**Итог:** расхождений кадра нет (0 px по обоим экранам), подсказка §4.8 выведена
настоящим наведением и раскрашена нашей темой до пикселей: рамка пластины
`(138,106,58)` = `border 0.5412/0.4157/0.2275`, фон `(9,11,14)` =
`bg 0.0353/0.0431/0.0549`, самое светлое внутри `(232,213,168)` =
`TooltipLabel/colors/font_color 0.9098/0.8353/0.6588` — то есть и `TooltipPanel`, и
`TooltipLabel` доезжают до живой подсказки, а не только до подписи витрины. Кадр
`tooltip_hover.png` (1920×1080, sha256
`a998b542c10c4ed3c2fdeb8713ea3f305fd17a7654a3af00c0c16fac67240a1c`) и MANIFEST — в

`game/run_tests.sh` (четвёртый уровень), прогон 3/3 зелёные.
