# UX-review: нижняя полоса боевого HUD без `turn_line` (T-310)

Что проверялось: снятие мёртвого виджета не должно было изменить ни одну живую
строку полосы и не должно было сдвинуть геометрию, от которой зависит поле боя
([[14-ux-battle-hud]] §2, T-220).

## Как снято

Канонический канал съёмки ([[CAPTURE-HELPER]]): живой Godot под Xvfb `:96`, сцена
`res://scenes/battle.tscn`, состояние — фикстура `game/tools/capture/battle_hud_full.gd`
(тот же носитель состояния, что у T-241: герой в ростере, `HeroMagic` 12/20, три стека
защиты, снег).

```
CAPTURE_SCENE=res://scenes/battle.tscn CAPTURE_NAME=battle_hud_after \
CAPTURE_OUT=battle-hud-t310 CAPTURE_SETUP=@$PWD/tools/capture/battle_hud_full.gd
```

Кадр: `~/.local/share/sigil-reserve/battle-hud-t310/battle_hud_after.png`, 1920×1080,
SHA-256 `419b51eb0a4687b74713c0ec70c300303227b38b1799ba99d710fa62eeea785a`. Пиксели в
git не идут (D-185), манифест лежит рядом с кадром.
Сравнение: `band_ab.png` — вырез полосы 560..1360 × 890..1000, сверху кадр T-241
(до снятия), снизу этот кадр (после).

## Что показал замер на живых узлах

Проба читала `get_global_rect()` пяти узлов до правки и после неё (тот же кадр,
1920×1080, viewport подтверждён).

| Узел | До | После | Сдвиг |
| --- | --- | --- | --- |
| `bottom_bar` | (0, 920)–(1920, 1080) | (0, 920)–(1920, 1080) | нет |
| `bottom_bar/info_box` | (620, 911)–(1300, 976) | (620, 930)–(1300, 976) | верх +19 px |
| `…/turn_line` | (620, 911)–(1300, 933) | узла нет | −22 px пустой строки |
| `…/log_row` | (620, 933)–(1300, 976) | (620, 930)–(1300, 973) | −3 px |
| `…/log_row/log_line` | (620, 943)–(1262, 965) | (620, 940)–(1262, 962) | −3 px |

Читаются два факта. Первый: `bottom_bar` не изменился, а `hud_bands()` ([[14-ux-battle-hud]]
§2, T-220) берёт высоту именно его, поэтому запас поля боя и тесты `test_battle_field_fit*.gd`
к снятию отношения не имеют — они и прогнаны зелёными. Второй: `info_box` был выше
своего якоря ровно на высоту пустой метки (VBox-контейнер расширяется вверх, `grow_vertical
= 0`), поэтому после снятия строка лога поднялась на 3 px, а не на 22, как можно было
ожидаться от удаления строки высотой 22 px.

Проба — временный MCP-файл (`test_probe_turnline_tmp.py`, в git не пошёл, удалён после
замера; приём тот же, что у мутационных проб: след остаётся в тексте, а не в дереве).
Воспроизводится телом, которое она подавала в `game_eval` после фикстуры состояния:

```gdscript
var battle = get_tree().current_scene
var ui = battle.get_node("BattleUI")
var out = {}
for p in ["bottom_bar", "bottom_bar/info_box", "bottom_bar/info_box/turn_line",
          "bottom_bar/info_box/log_row", "bottom_bar/info_box/log_row/log_line"]:
    var n = ui.get_node_or_null(p)
    if n == null:
        out[p] = "NET_UZLA"
        continue
    var r = (n as Control).get_global_rect()
    out[p] = [r.position.x, r.position.y, r.end.x, r.end.y]
return out
```

Значение `NET_UZLA` в пробе — не ошибка, а утверждение AC: после правки узла быть не
должно. `get_node_or_null` выбран потому, что на несуществующий путь обычный `get_node`
роняет сцену, а не возвращает null.

## Вердикт по кадру

| Пункт | Ожидалось | В кадре | Вердикт |
| --- | --- | --- | --- |
| Строка лога | остаётся на месте, текст читается | «Ваш ход: Wolf (8)», кегль не изменился | PASS (сдвиг 3 px глазом не виден) |
| Кнопка ☰ истории | не сдвинулась | на месте, справа от строки | PASS |
| Пустая строка над логом | исчезла бесследно | различий в текстуре снега и медальонах нет | PASS |
| Медальоны `slot_empty_1/2` | как в T-241 (пустые — намеренно, `battle_ui.tscn:165-167`) | те же | PASS |
| Поле боя, ростеры, карточки | не затронуты | не затронуты (правый край кадра совпадает с T-241) | PASS |

## Чего этот review не измеряет

1. **Пиксельное совпадение кадров до и после.** Межпроцессный дифф непригоден (урок
   T-241: два прогона Godot дают разные кадры анимации, bbox разницы уезжает на поле),
   поэтому сравнение — по геометрии узлов и по вырезу полосы глазами, а не по хешу
   разницы.
2. **Свёрка с макетом.** Протокол ux-review требует макет-источник
   `design/single_window_layout/all_screens_ui.png`, которого нет ни в репозитории, ни на
   машине (**T-312**). Здесь проверялось утверждение «снятие носителя визуально
   инертно», а не «как на макете»: второе по-прежнему нечем проверять.
3. **Звук и playtest** — отложены (нечем снимать).

## Итог

Снятие T-310 — визуально инертная правка: единственный наблюдаемый эффект
(подъём строки лога на 3 px) лежит в пределах округления контейнерной раскладки,
ни одна живая строка полосы не пропала, геометрия, от которой зависит поле боя, не
двинулась. AC тикета закрыты обе: узла в сцене и скрипте нет, §3 и §4.A
[[14-ux-battle-hud]] описывают фактическое состояние.
