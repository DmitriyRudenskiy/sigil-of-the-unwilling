# Матрица сценариев 5×11: прогон, отчёт, история

Автопилот (`ScenarioPilot`) играет пятью ролями — Собиратель, Путешественник, Торговец,
Приключенец, Городостроитель — по одиннадцати классам. Это и есть матрица 55 сценариев из
спека `openspec/specs/scenario-matrix/spec.md`. До **T-238** матрица собиралась руками:
оператор сам запускал `game/tools/matrix_report.gd` по процессу на роль, сам читал строки
и сам переносил цифры в задачи. Инструмент обязал собрано то, что делалось глазами:
план ячеек, полнота отчёта, коды «нет строки», JSON-отчёт, история прогонов и сравнение
с предыдущим.

Два носителя, две ответственности:

| Слой | Файл | Что делает |
| --- | --- | --- |
| Прогон | `game/tools/matrix_report.gd` | один процесс Godot = одна роль × N классов; печатает `MATRIX-*` |
| Драйвер | `scripts/scenario_matrix.py` | план, запуск процессов, разбор, полнота, JSON-отчёт, история, сравнение |

## Единственный список ячеек

```sh
godot --headless --path game -s res://tools/matrix_report.gd -- --list
# MATRIX-CELL|role=collector|class=barbarian|seed=627453632|turns=60
# MATRIX-INV|roles=5|classes=11|cells=55
```

Инвентарь печатается из `ScenarioTargets.role_ids()` × `HeroClasses.CLASSES` — из тех же
таблиц, из которых прогон строит профили. Копия «5×11» в драйвере разошлась бы с игрой при
первой же новой роли, и матрица молча недосчиталась бы строк: ровно этот класс дефекта
(11 штук `error=?` с кодом возврата 0) матрица уже отдавала 2026-10-26. Драйвер читает
инвентарь перед каждым прогоном, сверяет `MATRIX-INV|cells=` с числом строк и краснеет на
дубле пары «роль × класс». Инвариант самого произведения на стороне игры держит
`test_matrix_cell_product_has_no_duplicates` (`tests/unit/probe/test_scenario_pilot.gd`).

## Прогон

```sh
python3 scripts/scenario_matrix.py --list-only                     # только инвентарь
python3 scripts/scenario_matrix.py                                 # выборка: 1 класс на роль
python3 scripts/scenario_matrix.py --cell fighter,collector        # одна клетка
python3 scripts/scenario_matrix.py --roles trader,builder          # одна роль и больше
python3 scripts/scenario_matrix.py --full                          # все 55 (маркер полной)
python3 scripts/scenario_matrix.py --full --expensive skip         # дорогие сцены — мимо
python3 scripts/scenario_matrix.py --roles collector --turns 30    # перебить ходы
```

Без фильтров и без `--full` — **выборка** (первый по алфавиту класс каждой роли, 5 клеток):
так требует спек («по умолчанию — выборка, полная матрица — по маркеру»). Дорогой сценой
считается клетка, у которой «родных» ходов роли больше `--expensive-above` (по умолчанию
60): 90-ходовые профили Путешественника/Торговца/Городостроителя не нужны в быстрой
проверке, и вместо того чтобы тайком урезать им ходы (что меняет метрику), драйвер их
просто не гонит и пишет в отчёте причину пропуска.

## Отчёт

Путь к отчёту печатается в stdout: `MATRIX-REPORT|<путь>|cells=N|goal=…|survived=…`.
Клетка отчёта — форма спека плюс два поля истории и одно времени:

```json
{"class": "fighter", "role": "collector", "seed": 176800338, "turns": 1,
 "survived": true, "goal_met": true, "goal_turn": 1, "seconds": 4.68,
 "error": "", "metrics": {"rare_nodes": 1, "resources_extracted": 50, "…": 0}}
```

`goal_met`/`goal_turn` берутся из метки пилота (`goal_reached_turn`), которую он ставит
**до** конца прогона: цель, посчитанная посмертно, — тот же класс падения, что и метрики
на освобождённом герое (**T-207**). `seconds` — wall-clock клетки, его требует спек
(«время прогона») и без него в плоском отчёте «короткий прогон» неотличим от «медленного».
Старая сборка инструмента без `secs` даёт `seconds: null`, а не ноль: отсутствие
измерения — не измерение в ноль.

## История и сравнение

`--history docs/mvp/matrix/history.jsonl` дописывает в файл по строке на прогон: дата,
`head_sha`, область (`roles`, `classes`, `turns` по ролям, флаг дорогих сцен) и клетки.
`--compare` ищет **последнюю запись той же области** и печатает расхождения.

Регрессией считаются три перехода: `goal_met 1→0`, `survived 1→0`, «прогон стал ошибочным».
Уменьшение числа ходов регрессией **не** считается: цель, достигнутая на 12-м ходу вместо
40-го, — улучшение. Область входит в ключ сравнения, поэтому выборка из пяти клеток никогда
не «найдёт регрессию» против полной матрицы. Регрессия — это `MATRIX-CMP|regression|…` плюс
`MATRIX-WARNING` и **код выхода 0**: недобор цели это измерение, а не падение инструмента
(тот же разделитель, что у `game/tools/survival_report.gd`).

## Коды выхода

| Код | Строка | Когда |
| --- | --- | --- |
| 0 | `MATRIX-REPORT` (± `MATRIX-WARNING`) | прогон отработал; недобор цели и регрессии — сюда же |
| 1 | `MATRIX-ERRORS` | нет строки прогона, дубль строки, строка вне плана, процесс умер без `MATRIX-ERRORS`, инвентарь не читается |

Полнота — проверка, а не вежливость: `check_run` сверяет план с напечатанными строками, и
пропущенная клетка получает запись `error="нет строки прогона"`. Молчаливая дырка в отчёте
опаснее падающего прогона, потому что выглядит как «такого сценария нет».

## Регламент добавления сценария

Матрица подхватывает новую ячейку без правки драйвера, если добавлено:

1. **Класс** — строка в `HeroClasses.CLASSES` (`seed_for` выводит seed из пары сама,
   отдельной строки не требует).
2. **Роль** — запись в `ScenarioTargets.ROLES` (+ `max_turns`, если 60 не подходит) и
   скрипт роли с `goal_met()`/`metrics()` в `game/scripts/probe/`, зарегистрированный в
   `ScenarioPilot.make_role`.
3. **Тест формы метрик** — ещё один `test_*_metrics_shape` в
   `tests/unit/probe/test_scenario_pilot.gd`: строка матрицы печатает метрики роли как
   есть, и расхождение имени метрики заметнее всего именно там.

После этого `--list` обязан показать новую пару (или новые пары: класс добавляется всем
ролям сразу), `test_matrix_cell_product_has_no_duplicates` — остаться зелёным, а
`--full` — привезти на одну клетку больше. Драйвер и его самопроверку править не нужно:
они не знают имён ролей и классов.

## Чего это не делает

Не запускается из гейта: прогон матрицы — минуты живого Godot, а CI агенту запрещён;
в `scripts/doc_gates.sh` живёт только самопроверка разбора и плана
(`scripts/test_scenario_matrix.py`, 25 тестов на подставных строках, без Godot). Не
балансирует: `AutoBalancer` из старой фазы спек-цикла отчётом не подключён. Не заменяет
MCP e2e: матрица измеряет поведение автопилота, а не целостность UI. Не хранит пиксели:
в git идут строки и JSON, кадры — по-прежнему мимо (D-185).
