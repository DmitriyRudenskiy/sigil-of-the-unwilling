## 3. Гард имён темы (находка «неверное имя молча оставляет дефолт»)

`game/tests/unit/ui/test_theme_phase5_components.gd`:

- `_CRITICAL_ITEMS` — таблица из 10 движковых типов контролов и их стилевых
  имён; `test_critical_items_resolve_on_live_controls` инстанцирует каждый
  живой контрол, вешает тему и требует, чтобы **живой резолв** совпал со
  значением в теме (движок на неверное имя отдаёт дефолт — тест краснеет).
- `test_wrong_item_name_is_silent_not_error` держит сам замер молчания:
  `font_readonly_color` резолвится в чёрный дефолт, `font_uneditable_color` —
  в значение темы. Без этого ассерта «гард» через полгода снова станет пустым.
- `test_tabs_declared_on_tabbar_and_tabcontainer` — двойное объявление вкладок.

Мутационная проверка гарда: переименование `font_uneditable_color` →
`font_readonly_color` в `.tres` даёт новому гарду RED, а прежнему ассерту
`assert_object(...).is_not_null()` — GREEN (тот ассерт пустой, он имя не
проверяет). Правка откатана.

## 4. Механика двух PR (где живут §9/§9.6/§9.7, UI-5/UI-6, ASSET-2, CHANGELOG, кадры)

- **docs-PR** = `feat/art-bible-rev2` → `main`: `1f05750a`, `4bf890a2` (чистые docs).
- **Этот PR** = `feat/ui-phase5` → `main`: `efa29716` (шаг 0) + `d3334c45` (акт) +
  раунд ревизии. Он **построен поверх** docs-PR: `git merge-base --is-ancestor
  4bf890a2 HEAD` — истина, оба docs-коммита предки HEAD.
- Порядок: **сначала docs-PR, потом этот**. Cherry-pick не нужен и вреден:
  коммиты общие, git их дедуплицирует при мерже, дублей строк в `TICKETS.md` /
  `CHANGELOG.md` / гайде не возникает. Ничего не теряется: §9, §9.6, §9.7,
  UI-5/UI-6, ASSET-2, К-13, CHANGELOG и кадры 13–17 лежат только в этом PR
  (в docs-PR их нет).
- Если первым смержится этот PR, docs-PR становится пустым (его коммиты уже в
  main) и закрывается без изменений.
