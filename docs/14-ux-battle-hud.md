# UX-спека: боевой HUD (UI-2)

Экран: `scenes/battle.tscn`; HUD: `BattleUI` (CanvasLayer 10) +
`BattleSpellbookPanel` + `SettingsScreen`; постоянные панели: `ResourceBar`,
`ArmyPanel`. Канон экрана: [[07-ui-ux]] (K-M8, M1), правила боя: [[02-mechanics]] §3,
визуал: [[13-art-bible]]. Спецификация включает **дрейф** — текущий код уже растерял
часть канона (см. §3).

## 1. Контракт экрана

| Термин | Значение |
|---|---|
| Вопрос | «Что мне сделать этим ходом, чтобы стол склонился?» |
| Вход | Сталкивание армий на карте кампании → `BattleController.start_battle` |
| Выход | Только финал боя → «Продолжить» → карта кампании (K-M8: отдельного отчёта нет) |
| Видимое состояние | Чей ход; чьи фигуры; чьи HP; лестница исходов; что стоит сделать |
| Первый аффорданс | Кнопка действия активного юнита (Attack/Move), под курсором по умолчанию |
| Вход | Мышь (клик по клетке/кнопке) + клавиши (§5) + геймпад-навигация (фокус, UI-5) |
| Responsive | Фикс-раскладка 1920×1080, stretch canvas_items; минимум читаемости 1280×720 |
| Accessibility | Все состояния — форма+цвет; фокус-рамка; клавиатурная альтернатива каждой кнопки; текст ≥16 px @720p |

Инварианты канона: все влияющие на ход правила видны без подсказок (справка — по
клавише); нет допустимого хода → «Пропустить» доступен всегда; карточка врага всегда
показывает AC/HP/УДЧ/способности (M1).

## 2. Макет (зоны)

```
┌────────────────────────────────────────────────────────────┐
│ A: инициатива (очередь, активный выделен)      [13-art §5] │
├──────────────────────────────┬─────────────────────────────┤
│                              │ B: карточка цели (M1):      │
│    Клеточное поле боя        │ AC/HP/УДЧ/способности       │
│    (hex/square, юниты,       │ + C: лестница исходов       │
│     подсветки ходов)         │ (Триумф…Критпровал, порог)  │
├──────────────────────────────┴─────────────────────────────┤
│ D: нижняя панель: [⚙][Отступление][Ждать][Атака]           │
│    | лог строка ▲▼ [История] | [Оборона][Пропустить][Книга]│
├────────────────────────────────────────────────────────────┤
│ F: оверлей итога: «Победа/Поражение» · «Остаток: н/н» ·    │
│    [Продолжить] — единственный выход (полноэкранный)        │
└────────────────────────────────────────────────────────────┘
```

**Буквы зон (канон приёмки):** A — инициатива, B — карточка цели, C — лестница
исходов (реализована как тикет, вне UI-3b), D — нижняя панель, F — оверлей
итога. E не используется.

`ResourceBar`/`ArmyPanel` — постоянные панели кампании (не боевые): остаются на
городском/карточном экране; в бою скрыты (`battle.tscn` их не включает — проверено grep; живут в `adventure_ui.tscn`).

**Layout: V1 (карточка цели справа), референс — `prototypes/battle-hud/index.html`**
(приёмка владельца 2026-10-13): вертикаль 720p — дефицит, V2 съедал 53% высоты
полем по центру, V1 платит ~23% ширины за постоянную видимость B; HoMM-ожидание —
нулевое обучение. Fallback: если B перекрывает анимации поля — зона B переводится
в транзиентный оверлей (поведение V2 для одной зоны), полный переход на V2 не делается.

**Приём: error-chip.** Текст ошибки (`#e05a4a`) легален только на подложке
`#281c0f`/`#090b0e` (4.54/5.38); на панелях `#4a3423`/`#3a2415` — 3.17/3.97 ✗
([[13-art-bible]] §4.2). Значит значения урона/промаха рисуются чипом: текст
`#e05a4a` на плашке `#281c0f` внутри панели — не изобретать подложку заново на
каждом экране.

## 3. Дрейф: код против канона — data-source-статусы

Статусы (governance-пункт владельца 1): **live** — данные текут; **no-op** — метод
есть, данные не текут; **absent** — элемента нет.
**Правило UI-3: никаких фейковых чисел.** no-op-элементы скрыты по умолчанию
(не «ноль вместо данных»); на отсутствующую логику заводятся тикеты вне скоупа UI-3.

| Элемент | Канон (07-ui-ux) | Код сейчас | Статус | План UI-3 |
|---|---|---|---|---|
| A. Инициатива | сверху | `initiative_panel` и `update_initiative` удалены (`battle-99-hex-clean-hud`) | **снято решением** | возвратить зону нельзя: требования «Полоса порядка ходов», «Лента очереди хода» и «Кольцо инициативы» удалены спекой, лимит хода снят (D-283) |
| A. Счётчик хода | turn_line | узла нет (тот же removed-набор) | **снято решением** | — (D-283) |
| B. Карточка цели (M1) | всегда AC/HP/УДЧ | живая: `show_target_card` + `set_attack_preview` (`battle_ui.gd:179`), окно видно всегда (D-267) | **live** | — |
| C. Лестница исходов | индикатор перевеса | отсутствует | **absent** | тикет: формула перевеса вне скоупа UI-3; в UI-3 — скрыта |
| «Авто» | кнопка (02-mechanics §3.4) | отсутствует | **absent** | тикет: автобой-логика вне скоупа UI-3; кнопка не макетировать |
| D. Нижняя панель | кнопки+лог | живая, сигналы в `BattleController` | **live** | правки минимальны |
| D. «Пропустить» не глушится | 07-ui-ux:53 | **исправлено** пре-фиксом `fix/battle-skip-invariant` (025bacca) + тест | **live** | — |
| E. Книга заклинаний | слоты школ | живая (`BattleSpellbookPanel`) | **live** | стиль по библии |
| F. Финал боя | единственный выход | отсутствует | **absent** | оверлей из исхода `BattleState` (данные есть) |
| ResourceBar / ArmyPanel | панели кампании | живые, в бою скрыты (`battle.tscn` не включает — grep) | **live** | вне бокового скоупа |

Отсутствующая логика (лестница, автобой) — **тикеты**, не макеты: UI-3 не рисует
мёртвые цифры и не трогает «презентационный слой только».

## 4. Элементы

### A. Инициатива (верхняя полоса)
- Горизонтальная очередь портретов 48×48 (юнит-портрет, [[13-art-bible]] §8.2),
  активный — золотая рамка 2 px + подъём +2 px; мёртвые — десатурация 60%.
- Скролл колесом при >12 юнитов; тултип — имя+HP (не обязателен для решения).
- Счётчик хода — моно-шрифт 24 px справа полосы.

### B. Карточка цели (M1)
- Появляется при наведении/выборе любой вражеской фигуры, не исчезает пока цель
  валидна. Поля: имя (32 px), AC, HP текущ/макс, УДЧ (атака), способности (иконки 32).
- Числа — моно (прыгущая ширина HP убивает чтение).
- Недоступная цель — красная кромка `#e05a4a` + иконка ✗ (не только цвет, §4.3 библии).

### C. Лестница исходов
- Вертикальная шкала из 5 зон: Триумф/Успех/Частичный/Провал/Критпровал; текущий
  перевес — маркер; пороги подписаны числами (моно 16 px); сдвиг от Удачи —
  стрелкой-дельтой. Пересчёт — на каждое изменение состава.
- Зоны: успех — `#7aa85a`→`#c9a227`→нейтральный→`#e05a4a`→`#7a100c`; подписи
  текстом пергаментом (контраст-таблица библии §4.2).

### D. Нижняя панель (живая, правки минимальны)
- Состав (слева направо): ⚙, Отступление, Ждать, Атака | лог-строка + ▲▼ + История |
  Оборона, Пропустить, Книга. Порядок канона; подписи — кириллица (UI-6).
- Атака disabled, пока нет допустимой цели (`set_attack_enabled`); Ждать vs Пропустить
  разведены по ролям: Ждать = ход с ожиданием, Пропустить = нет допустимого хода —
  всегда активен.
- «Авто» — справа от Пропустить (новая кнопка, сигнал `auto_requested`).
- Лог: последняя строка + ▲▼ листают историю (живой механизм, 50 записей);
  панель «История» — ItemList, закрытие Esc.
- Стиль панелей — тема `game_theme.tres`; скругления привести к ≤2 px в UI-3
  (`army_panel.gd` ставит 4/3 — дрейф против библии §6).

### E. Книга заклинаний (живая)
- Слоты школ; недоступные — десатурация + причина в тултипе (не «серо и молча»).
- Выбор → `spell_chosen` → режим цели на поле; Esc закрывает.

### F. Финал боя (новый)
- Оверлей поверх поля: итог (та же лестница, итоговая зона), потери сторон
  (моно-таблица), единственная кнопка «Продолжить». Никаких «закрыть в никуда».

## 5. Ввод

| Действие | Мышь | Клавиша |
|---|---|---|
| Атака / ход | клик по цели/клетке | `A` |
| Оборона / Ждать / Пропустить | кнопки D | `D` / `W` / `S` |
| Книга | кнопка | `K` |
| История | кнопка/▲▼ | `H`, `↑`/`↓` (листание) |
| Настройки | ⚙ | `Esc` (приоритет: открытая панель → закрыть, иначе настройки) |
| Подтвердить финал | [Продолжить] | `Space`/`Enter` (`ui_accept`) или `F` |
| Авто | кнопка | `Q` — **deferred**: механики «Авто» нет, тикет в [[TICKETS]] |

Реализовано в UI-3b (`battle_ui.gd::_unhandled_input`); таблица — единственная,
канонизирована вслед за фактом (2026-10-13), как буквы зон §2.

## 6. Acceptance criteria (для UI-3)

1. Зона A показывает очередь; активный отличим формой (рамка+подъём), не только цветом.
2. Карточка цели (B) содержит AC/HP/УДЧ/способности без подсказок (M1); числа моно.
3. Лестница (C) обновляется до боя и в бою; зоны подписаны; colorblind-тест: различима без цвета.
4. `skip` не отключается никогда — **выполнено пре-фиксом** `fix/battle-skip-invariant`
   (тест `test_battle_ui_skip_invariant.gd`).
5. Финал: один выход «Продолжить»; тест перехода на карту.
6. Все кнопки D доступны с клавиатуры (§5); фокус-рамка видима (библия §6).
7. Тексты — ≥16 px @720p; контраст пар — из библии §4.2 (тест палитры в CI не обязателен, проверено расчётом).

## 7. Вне скоупа UI-2

Ребаланс лестницы (07-balance), AI-автобой (02-mechanics §3.4 реализация), локализация
строк (UI-6), геймпад-навигация целиком (UI-5), бой на нетипичных разрешениях (<1280×720).

## 8. Что в коде сегодня (реверс 2026-10-26, docs-code-sync)

Раздел описывает фактическое поведение, а не желаемое; источник указан для каждой
строки.

- **Поле боя и полосы HUD**: `scripts/systems/battle_view.gd` (`fit_camera`) вписывает
  поле в **вьюпорт минус полосы HUD** и сдвигает его центр на `(top − bottom) / 2z`,
  где запас приходит извне: `scripts/ui/battle_ui.gd` (`hud_bands`) читает
  `get_global_rect()` полос `hero_cards` и `bottom_bar` из `scenes/ui/battle_ui.tscn`, а
  `scripts/systems/battle_controller.gd` (`_apply_hud_reserve`) внедряет его во view.
  Носитель числа — сцена: правка панели правит и запас; констант разрешения больше нет
  (D-279 взамен множителя ×0.8 по порогу высоты окна, D-266). Замер после фикса: доля
  кадра 0.710 при 1920×1080 и 0.711 при 1280×720, верх поля совпадает с нижней границей
  верхних полос. Полосы `initiative_bar` в сцене больше нет: порядок ходов снят с экрана
  вместе с лимитом хода, `hud_bands()` возвращает `Vector2(top, bottom)` (D-283).
  **Остатка нет:** бейдж `turn_timer` удалён вместе с лимитом хода, поэтому T-230
  (бейдж накрывал верхний ряд поля в центральной колонке) закрыт как moot — резервировать
  верхний зазор не под что.
- **Задний план поля — по мировой местности** (D-283): тип местности гекса обороняющегося
  читается в `scripts/world/world_battle_coordinator.gd`
  (`handoff.enemy_terrain = map_gen.get_terrain_name(enemy_cell)`), едет через
  `BattleHandoff.enemy_terrain` в `BattleController.start_battle(..., enemy_terrain)` и
  ложится в `BattleView.set_background`. Таблица фонов — `BattleView.BACKGROUNDS` (снег,
  болото), отображаемых типов — `BattleView.BIOMES`; местность без утверждённого фона даёт
  пустую текстуру, и вид уходит в тайловое поле с обводкой доски
  (`ring = RING if _background.texture == null else 0`), а не в пустой или чёрный кадр.
  Режим «арт = поле» (`BattleView.ART_AS_FIELD`, по умолчанию выключен) включается только
  вердиктом владельца: **T-269**, кадры обоих вариантов и замеры — в
  `docs/mvp/matrix/2026-10-28/ux-battle-99.md`.
- **Карточка противника видна всегда**: `scripts/systems/battle_controller.gd`
  вызывает `BattleUI.show_default_enemy_card(state)` на `_ready()` и когда
  прицел снят (`_on_attack_target_updated(null)`); подпись окна — «Противник»,
  при активном прицеле — «Цель» (D-267). Пустая сторона скрывает окно, а не
  оставляет портрет последнего убитого.
- **Строка «Удача»** печатается со знаком (`+1`/`−1`) и только если у бойца есть
  **источник** значения (`BattleState.BattleUnit.has_luck()`, писатель —
  артефактный мод `luck` в `scripts/systems/battle_state_builder.gd`, D-268).
  Нуль «для красоты» не выводится: числа без источника запрещены.
- **Открытое раскладка-дефект**: при 1920×1080 нижняя панель HUD перекрывает
  нижние ряды поля (T-220) — резерв надо считать от высоты панели, а не от
  разрешения.
- **Клавиши боя** — прямые, не из `InputMap`: `A`/`D`/`W`/`S`
  (атака/защита/ждать/пропуск), `K` (книга), `H` + `↑`/`↓` (журнал), `Esc`
  (`scripts/ui/battle_ui.gd`). Полная таблица ввода — [[07-ui-ux#Управление (по input map)]].
