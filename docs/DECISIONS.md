### K-T6. Формула боя: без «10», без «+prof» (2026-10-02)
- **Канон:** 02d v1.2 §3.1: `Итог = мод(эффективная характеристика) + бонус ранга навыка + ситуативные модификаторы`; перевес = Итог − DC; лестница исходов §3.2; Удача двигает пороги зон.
- **Аннулировано (датой):** формула «10 + mod + prof + ранг + ситуативное» в 02-mechanics §3.4, 00-glossary (строка «формула»), MVP-scope — легаси-слой Ф1 (по образцу C1–C4).
- **Правило миграции (норматив для всех слоёв):** любая «10 + X» → «Удача + X′» (X′ — ступени лестницы); «+prof» элиминируется — мастерство живёт в каналах: +1 Удачи за 2 яруса, ступени лестницы (совместные атаки, фланкинг, дисциплина), ранг оружия. Prof остаётся ровно в одном месте — порог Долга судьбы (K-R1).
- **Калибровка:** DC/КБ не переносятся из кубиковой системы числом — пересчитываются от распределения Удачи: мирная типовая задача проходима на средней Удаче без ступеней; боевая против равного — требует ступеней или Долга. Числа — 02d, коридоры долей успешных проверок — метрика автобалансировщика.
- **DoD:** в путях резолюции нет «база-10» и «добавка мастерства»; CI-гейт — grep по «10+prof»-паттернам. Инварианты T17: (1) «нет автопобеды первого хода»; (2) «ни одна конфигурация характеристик не даёт гарантированной стабилизации в бессознательном состоянии: высокая Удача ускоряет выход, но не отменяет риск; пороги — 02d/07-balance» (вербатим, владелец, D-135); (3) «нет вечных боёв» (D-128: лимит боя 20 раундов → ничья; тест: две стороны со взаимно недосягаемыми параметрами → бой завершается на 20-м раунде ничьей, I1-детерминированный). Полная нумерация инвариантов T17 — Ф-план владельца.

### K-D5. Экономика = запасы и потоки; score запрещён (2026-10-02)
- **Канон:** модель запасов (06-economy): состояние = вектор запасов по реестру, разграниченный по носителям (город, империя, караван, обоз); изменение = потоки за ход (производство, потребление, призыв, эволюция, строительство, караваны, разбой, истощение); бартер — курсы торговых соглашений; UI оперирует натуральными величинами.
- **Аннулировано (датой):** score-модель 02g **как модель состояния**. Score сохраняется только как **производная аналитика** с обязательной трассировкой к натуральной корзине (панель «богатство города», метрики автобалансировщика, вход функции давления K-T5) — не является сущностью.
- **Запрещено:** score в транзакциях (призыв, стройка, торговля, разбой), в гейтинге контента, в UI как валюта.
- **DoD:** в транзакционных путях нет score-вызовов; балльные метрики снабжены трассировкой.

### K-T5. Рейды = функция давления; календарь аннулирован (2026-10-02)
- **Аннулировано (датой):** фиксированный график 7/10/14/17/21 (02e 13.2, TBD 02-mechanics §3.8 закрыт). Основание: календарь не зависит от состояния игрока — давление среды обязано быть ответом на действия, а не метрономом.
- **Канон:** `Давление_города(ход) = База(ход) × Богатство × Аномалии × История_региона × Глобальная_фаза`.
  - **База(ход)** — нарастающая кривая; ранние ходы — гарантированное затишье (floor-окно обучения).
  - **Богатство** — производная от натуральной корзины (K-D5): запасы + производство за ход.
  - **Аномалии** — число незакрытых в радиусе (радиус — в рёбрах, K-T7).
  - **История_региона** — счётчик региона (оккупации, разгромы лагерей; raid.source_camp).
  - **Глобальная_фаза** — поздняя эскалация: к контрольному ходу без приближения к победе — множитель на всю планету.
- **Механика выхода:** аккумулятор давления на город; пересечение порога тира → волна из лагеря-источника тира; после рейда — cooldown-окно. Всё — функции состояния (без кубиков, инвариант I1 применим к генератору угроз).
- **Пейсинг-инварианты (баланс-конфиг):** (1) floor/ceiling на интервалы между рейдами; (2) **обоюдная достижимость** — на одной кривой подготовленный город отражает рейд без потерь, неподготовленный несёт потери; (3) первый рейд города — обучающий тир, не способный разрушить необратимо.
- **Числа:** баланс-конфиг рейдов, не GDD.

### K-T7. Карта = граф регионов с планетарным замыканием (2026-10-02)
- **Аннулировано (датой):** сетка 24×24 (02e 4.1 [КАНОН]); процедурная генерация **как основа кампании**.
- **Канон:** карта = граф G(V,E): V — 40–48 региона суши с фиксированными границами, ≤ 1 города на регион (только суша); рёбра — проходимые границы; **восток смыкается с западом** (развёртка глобуса, карта без краёв). Вода — тип биома: водные регионы без вершин армий; рёбра через воду — только переправы (контент конкретной карты, не механика).
- **Регион** — вершина: биом, месторождения реестра, россыпи, шансы роскоши/данжей/аномалий. Узлы внутри региона: данжи, аномалии, месторождения, лагеря. Движение = стоимость входа в регион + внутрирегиональный шаг.
- **Караваны** — пути в графе; разбой — на неочищенных отрезках. **Радиус аномалии** — в рёбрах (k — баланс-конфиг).
- **Старты:** 8, по тематическим регионам Знаков; попарное расстояние ≥ k рёбер.
- **Базовая кампания** — фиксированная авторская карта; процедурная генерация — инструмент редактора сценариев и dev-тестов.
- **Фазовые якоря:** Ф3 + карта-граф v1 (регионы, рёбра, замыкание, месторождения, россыпи, стартовые позиции); Ф5а + узлы (данжи, аномалии, осады).
- **Системная поправка:** в Ф-плане — чек-лист покрытия «раздел GDD → фаза» (8 разделов), ревизия при каждом изменении GDD.

### K-A5. Статусная модель жителя (2026-10-02)
- **Канон:** один житель в каждый момент — ровно в одном статусе; «боец» и «житель» — одна сущность, не две. Статусы: **Ребёнок** (0–16, гибель исключена) / **Работник** (16–60, назначен на здание) / **Наставник** (60+, ускоряет обучение района) / **Рекрут** (16–60, рабочее место освобождено — вакансия; призыв = еда + железо) / **Боец** (эволюция по тройному условию) / **Герой** (класс 1–20; кандидат — ветеран высш. яруса или выдающийся выпускник; не занимает рабочее место) / **Партия в поле** (отряд ≤ 6, приписка к городу сохраняется).
- **Переходы:** житель → рекрут (призыв); рекрут → боец (эволюция); боец → кандидат (ярус 3 / выдающиеся характеристики); кандидат → герой (назначение класса, K1); герой → партия (≤ 6); герой → наставник (60+, «герои стареют по правилам населения»). Смерть в любом боевом статусе = потеря жителя («погибший юнит = погибший поселенец»).
- **Нормативные следствия (не новые механики):** (1) призыв опустошает производство — вакансия останавливает здание, массовый призыв = замкнутый цикл; (2) партия — не рабочая сила; (3) население считается непрерывно (жильё, семьи, настроение; город скорбит); (4) династии — только через демографию (дети героев — на общих основаниях).
- **Открыто:** **Q-Демоб** (боец → работник): до решения призыв необратим.

### K-A6. Водные расы = флаг происхождения (2026-10-02)
- **Канон:** расы дают модификаторы характеристик и наследственные черты; **расы не дают механик**. «Водность» — флаг `origin: aquatic` каталога, не группа и не класс.
- **Правила:** (1) список формирует контент-ревизия по наследственным чертам амфибийности/плавания — не GDD и не код; (2) распределение по производственной роли, «водных» групп нет, гетто запрещены; (3) жильё в городах как у всех — водные регионы не условие демографии (прибрежные районы — косметика); (4) акватические черты не создают боевых механик; (5) экономика — через группу, как у всех; (6) стартовый пул (9 рас) водных не содержит — водные входят через миграцию/пленных по мере открытия регионов.
- **Тикет A6-R:** ревизия 02e 9.4 — проставить `origin: aquatic`; результат — таблица «раса / группа / флаг» в Приложении А.

### K-R2. Реестр ресурсов = GDD 0.2.1 §4 (2026-10-02)
- **Канон — двухслойность:**
  - **Layer-1 (ресурсы, входы добычи):** 6 позиций — **дерево, железо, еда, ртуть, сера, кристаллы**.
  - **Layer-2 (товары, выходы зданий групп):** инструменты, ткани, зелья, провиант, **оружие** — потребляемы нуждами групп, уходят в караваны.
- **Аннулировано (датой):** реестр 06-economy (5 ресурсов) **в части реестра** (модель запасов/потоков — действует, K-D5). «Камень» — вне реестра до каменных цепочек (действующее K-решение). «Оружие» — не ресурс, а Layer-2-товар (исправление смешения сырья и продукции).
- **MVP-срез:** подмножество реестра {еда, дерево, железо} **при той же схеме данных**; ртуть/сера/кристаллы — контентные вехи (алхимия, аркана, осадная линия), не изменения схемы. MVP не вводит позиций вне реестра, не переопределяет идентификаторы. Роскошь по умолчанию вне MVP (включение — вопрос MVP-scope).

### K-R4. MVP-карта = связный подграф базовой (2026-10-02)
- **Канон:** MVP-карта — связный подграф из N (5–8) регионов базовой кампании, содержащий стартовые позиции MVP. **Один источник данных:** данные регионов (биом, месторождения, россыпи) идентичны базовым; отдельных данных MVP не существует — в базовой карте поле **MVP-маски** (аннотация регионов).
- **Границы выреза:** внешние границы подграфа — отсутствие рёбер (эквивалент водных регионов без переправ, K-T7); UI не рисует «край мира». Планетарное замыкание — свойство полной карты; в MVP не достигается и не обещается.
- **Фракции:** те же файлы Знаков, подмножество по составу; по умолчанию 1 игрок + 1–2 ИИ (количество — контент-вопрос MVP-scope); Совет и дипломатия — вне MVP (фаза 5б).
- **Следствие:** базовая карта v1 — вход трёх работ: Ф3 (карта-граф), MVP-кампании (K-R4), функции давления (K-T5/K-R3). Приоритет повышен.

## K-M записи (Фаза 4, резолюции MVP, 2026-10-02, владелец)

Три сквозных правила: (1) MVP — срез объёма, не срез канона: одна схема данных, различие — масками и стартовыми числами; «данных MVP не существует» — всё в аннотациях базовых сущностей; (2) verbatim-нормы GDD непоколебимы: где MVP-scope противоречит GDD — правится MVP-scope; (3) TBD-бюрократия: ратифицированное число снимает TBD-статус с датой; числа живут в баланс-конфигах, не в GDD (М1-А3).
