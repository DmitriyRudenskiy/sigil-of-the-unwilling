> (2752×1536, md5 `a5342e0a8022767c70f1ddee559de40c`, канон D-203, строка 10
> карты [[README|docs/reference]]). Кадр, переданный владельцем 2026-10-29
> (`_task_interface/1792001224620-…jpeg`), сверен побайтово: **это тот же файл**,
> нового стандарта нет — работа идёт по активному изменению
> `openspec/changes/map-screen-full-copy/` (группы 4–7).
>
> **Носитель экрана на `main`** — `game/scenes/main/main.tscn` → `game/scripts/main/main.gd`
> (`_init_campaign()`) → `game/scripts/ui/campaign_hud.gd`. Состав экрана хранит
> не код, а реестр `game/scripts/ui/campaign_screen_map.gd` (`const ROWS`, 37
> строк, 6 блоков): гард состава, приёмка и этот документ спрашивают у него.
>
> Порядок строк внутри блока = порядок макета слева направо; верхняя полоса
> обязана совпадать с `CampaignCounters.ROWS` (тест). Строка без носителя данных
> и без задачи = «немой писатель» и роняет `tests/unit/ui/test_campaign_screen_map.gd`
> (D-200). Литералы макета в узлах запрещены, строки — только через `GameText`.

## 1. Масштаб и адресная сетка

| Величина | Значение |
| --- | --- |
| Макет | 2752×1536 px (рамка кадра, `FRAME_W`/`FRAME_H` реестра) |
| Канва | корень `CampaignHud` — `Control` на полных якорях; окно проекта 1920×1080 (`project.godot:51`), референсный кадр съёмки — **1920×1080** (`game/tmp/shots/campaign-hud-d281.png`; пиксели в git не идут, D-185) |
| Макет → канва | **позиция каждой строки — доли кадра** (`rect` в `CampaignScreenMap.place()`, все четыре якоря при нулевых offset'ах). Экран не содержит ни одного собственного числа, с которым можно разойтись с макетом |
| Адресная сетка | 10×10, `A1..J10`, `python3 scripts/ui_grid.py <кадр> --cols 10 --rows 10` — одним числом ячеек размечаются и макет, и кадр; `cell` реестра вычислен из центра `rect`, тест сверяет объявленный адрес с вычисленным |
| Сверка кадра | `scripts/ui_diff.py` — гейт «ноль незарегистрированных расхождений»; покрытие — `COVERAGE n/m` (см. §5) |

## 6. Что не рисуется и почему

Рисовать элемент «как на макете» без носителя значения запрещено (D-200, немой
писатель): иконки восьми способностей (T-244), печенье/склянку таблички (T-246),
домик-щит обороны (T-248), малые кнопки узла хода и шестерню даты (T-245),
девятую валюту (T-243), три иконки валют (T-159). Портреты юнитов полосы —
персонажный контур, не UI-партия. Каждая строка остаётся в реестре с задачей:
«нет рисунка» ≠ «нет элемента».

## 7. Приёмка

1. Контактный лист партии → **вердикт владельца** (лист v1 заморожен на реестре
   шага 1, поздние сюжеты — аддендум v2).
2. Пост-процессинг → провенанс → атлас + бюджет (задача 4.3).
3. Проводка: строка `art` реестра = путь в атласе; съёмка кадра 1920×1080 →
   адресная сверка → `COVERAGE n/m` → `scripts/ui_diff.py` = ноль
   незарегистрированных расхождений.
4. ux-review машинным зрением по паре «макет/кадр» → сводка в треде → явное
   «мержи» владельца → push в `main` (D-224). Публикация **после** ux-review.
