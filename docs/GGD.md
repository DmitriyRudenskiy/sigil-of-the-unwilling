# GGD — верховный игровой канон

GGD — верхний слой канона проекта. Настоящие секции закрывают находки кросс-ревью [[CROSS_REVIEW_2026-11-10]] (5 Blocking + 9 Yellow). Тикеты (Q-M/T-) на эти находки не заводятся — вместо них применяются правки из §9. Маппинг «находка → решение» — в §8.

## 0. Иерархия канона

1. Приоритет источников: **GGD > proposal.md > пронумерованные доки (01…21) > комментарии в коде**. При конфликте побеждает верхний слой.
2. Спорный вопрос по канону закрывается правкой GGD (новая или изменённая секция), а не новой формулировкой в боковом доке. Боковые доки ссылаются на секцию GGD, а не переизлагают её.
3. Архивные отчёты ([[CROSS_REVIEW_2026-11-10]], CONFLICTS_REPORT.md) — фиксация состояния на дату: класс «архивный отчёт», без frontmatter, вне виклинк-графа; задним числом не редактируются.
4. Правило единого источника: у каждого числа, формулы и таблицы ровно один документ-источник (закреплён в §4 и §6); все прочие места — только ссылки.

## 1. Слои игры: кампейн-слой удалён из канона

**Закрывает:** CR-B1.

**Решение.** Кампейн-слой не существует в каноне. Единственный игровой контур — [[01-core-loop]] без кампейна; носители кампейна удаляются согласно remove-campaign-mechanic 3.2. Термины «кампания», «кампейн-карта», «сезон» из канонических доков удаляются или заменяются (сезон как механика вне канона — см. §3).

**Правки.**
- [[MVP_SCOPE]] §1/§2 — убрать кампейн-слой из объёма; MVP = один контур «ход → такт дня» без межсезонных переходов.
- [[01-core-loop]] — описать цикл без кампейн-шагов.
- [[06-economy]] — удалить кампейн-экономику (межсезонные накопления и производные); остаётся экономика сессии/хода.
- [[07-balance]] §1 — убрать кампейн-балансировку; баланс замыкается на константы §4/§6.
- [[07-ui-ux]]:118–124 — удалить кампейн-экраны/состояния из UI-потока.
- [[21-ux-map-screen]]:18–22 — экран карты переписать под граф регионов (см. §2).
- [[18-system-map]] — вычеркнуть кампейн-системы из карты систем (реестр систем — §5).
- AGENTS.md — убрать кампейн-упоминания из инструкций агенту, добавить иерархию канона из §0.
- `openspec/changes/remove-campaign-mechanic/proposal.md:29` (строка указана в исходном тексте как «proposal.md:60» — не совпала с носителем) — строка «контракты не меняются» удаляется и заменяется на: «контракты меняются: удаляются носители кампейна (перечень и следствия — §1 GGD)». Противоречие с remove-campaign-mechanic 3.2 устраняется в пользу 3.2.

## 2. Карта: граф регионов — канон, гексы — локальный слой

**Закрывает:** CR-B2.

**Решение.** Канон карты мира не меняется: **граф регионов** (K-T7; канон [[02e1-map]], [[02e1-base-map]]; глоссарий). Удаление RegionMap и map_screen_model — это удаление кампейн-носителя, а не смена канона: UI карты мира строится по графу регионов. Гексовая местность в `world/` — отдельный слой «локальная карта» внутри региона; на глобальную топологию не претендует.

**Правки.**
- [[02e1-map]], [[02e1-base-map]] — остаются каноном; пометить как источник карты мира.
- [[21-ux-map-screen]], [[18-system-map]] — разделить термины: «карта мира (граф регионов)» и «локальная карта (гексы, world/)».
- Глоссарий — внести оба термина, взаимно однозначно.
- **Поправка D-281 («гексы графа») аннулируется:** носителя в каноне нет. Если гексовое представление графа понадобится — новая K-запись с носителем (код + док). Настоящая секция выполняет роль акта: переканона нет, канон (граф) подтверждён, D-281 аннулирована.

## 3. Время: такт дня = конец хода = один игровой день

**Закрывает:** CR-B3 (бывший C-18).

**Решение.** Один триггер времени: **такт дня наступает в конце хода игрока (кнопка «Завершить ход»), один вызов на ход**. Один ход = один игровой день, конверсия 1:1. Константа DAYS_PER_SEASON и конверсия ×20 существуют только в кампейн-коде и удаляются вместе с ним; «все X в день» читаются буквально и применяются один раз за ход — замедления ×20 нет и не может возникнуть.

**Правки.**
- [[01-core-loop]]:40 — «каждый день» → «в конце хода (такт дня)».
- [[MVP_SCOPE]] — «тик дня» → «такт дня»; убрать любые упоминания конверсии дней.
- Код — единственная точка срабатывания: обработчик завершения хода; отдельных таймеров/расписаний такта дня нет. DAYS_PER_SEASON удалить вместе с кампейн-носителями.
- Глоссарий — «такт дня» = конец хода игрока; «день» = один ход; «сезон» вне канона (§1).
- C-18 считается закрытым настоящей секцией.

## 4. Ресурсы: один реестр

**Закрывает:** CR-B4.

**Решение.** Единственный словарь ресурсов — реестр в `resource_registry.gd` (строки 19–23). Ресурсы из [[races-economy]] вносятся в реестр: **grain, flour, bread, ore, scholar_points**; **gold** регистрируется как ресурс категории `currency`. Отдельный «кошелёк»/слой денег вне реестра не заводится; второй словарь в race_economy.json/.gd ликвидируется.

**Правки.**
- `resource_registry.gd` — добавить недостающие id в едином формате реестра (id, категория, базовые свойства).
- `race_economy.json` — хранит только коэффициенты/доли по id реестра; определений ресурсов не содержит.
- `race_economy.gd` — читает id только из реестра; собственный словарь удалить.
- [[races-economy]] — таблицы ссылаются на id реестра; формулировки «деньги как отдельный слой» заменить на «gold — ресурс категории currency».
- Правило на будущее: новый ресурс = новая строка в `resource_registry.gd`, нигде больше.
- **Точка сверки при применении:** если в реестре уже есть валютный id (монеты/золото) — выполняется маппинг gold на него, дубль не заводится.

## 5. Реестр систем: что существует, что аннулировано

**Закрывает:** CR-B5.

**Решение.** Док вправе ссылаться только на системы из утверждённого реестра. Текущее состояние:

| Объект | Статус | Действие |
| --- | --- | --- |
| zoning_system | не существует, носителя нет | упоминания как существующей системы удалить; при необходимости — новая K-запись с носителем |
| adjacency_system | не существует, носителя нет | то же |
| logistics_calculator | не существует, носителя нет | то же |
| мораль | аннулирована (K-M14) | все упоминания удалить, включая [[02e2-city]] и 02f-* (см. §6.5) |

Реестр «живых» систем ведётся в [[18-system-map]]; пока объект не появился там со статусом «существует», ссылаться на него в доках запрещено.

## 6. Единые источники чисел и формулировок

**Закрывает:** CR-Y1…CR-Y7.

### 6.1 XP-пороги (CR-Y1)
Источник — [[07-balance]]. Вторая таблица порогов удаляется; на её месте — ссылка на источник. Два «канона» XP-порогов существовать не могут.

### 6.2 Формула населения (CR-Y2)
Источник — [[06-economy]]. Дублирующие формулы в прочих доках заменяются ссылками; при расхождении чисел правится дубль, а не источник.

### 6.3 Лимит рейда (CR-Y3)
Двойственность «на рейд vs на день» устраняется разведением единиц: **размер и состав лимитируются «на рейд»** (на одно рейдовое действие); **частота — «в день (ход)»** (сколько рейдов допустимо за такт). Значения — в [[07-balance]]; в текстах всегда указывать единицу явно.

### 6.4 Еда партии (CR-Y4)
Еда считается **на члена партии в день (ход)**; суммарное потребление = ставка × состав партии. Ставка — в [[07-balance]]; формулировки «на партию» заменяются на «на члена партии × состав».

### 6.5 Мораль в [[02e2-city]] / 02f-* (CR-Y5)
Мораль аннулирована (K-M14) — упоминания удаляются без замены; связанные модификаторы переводятся на существующие механики или убираются до появления носителя (§5).

### 6.6 Ранги Престижа (CR-Y6)
Названия рангов — глоссарий; пороги рангов — [[07-balance]]. Прочие перечни рангов удалить и заменить ссылками.

### 6.7 Экономика [[02f-c-forest-city-economy]] (CR-Y7)
Собственная экономика в [[02f-c-forest-city-economy]] ликвидируется как вторая: док оставляет только ссылки на [[06-economy]] и расовые модификаторы через [[races-economy]] (id реестра, §4).

## 11. Примечания применения (сверка с носителем на 2026-11-10)

Записаны при заведении файла; отменяют не то, что решено, а то, что ошибочно в предпосылках.

- **§4 — реестр уже содержит все шесть id.** `resource_registry.gd` регистрирует `grain, flour, bread, ore, scholar_points, gold` (и `gold_ore`, `bog_iron`, `limonite`, `silver`…); `gold` есть и как городской ресурс (`CITY_RESOURCE_CAPACITIES`, `_add_city`). «Второго словаря» в смысле неизвестных реестру id нет: `race_economy.json` оперирует id, которые в реестре лежат. Остаток находки — не словарь, а **поля `morale` и `logistics`** в `race_economy.json` с читателями `RaceEconomy.conflict_morale()` / `synergy_logistics()`: первое — аннулированная шкала (K-M14), второе — система из §5 «не существует». Правки 1–2 §9 сводятся к этому и к строкам дока.
- **§3 — `DAYS_PER_SEASON` живёт не в кампейн-коде.** Константа объявлена в `scripts/systems/world_seasons.gd:27` (мировой слой), читатели: `scripts/campaign/**` (12 мест), `scripts/balance/balance_metrics.gd`, тесты `tests/unit/systems/`, `tests/campaign/`, `tests/smoke/`. Удаление вместе с кампейном задевает мировой слой и 7 тестов.
- **§1/§3 — «сезон вне канона» противоречит решению владельца.** `07-balance.md:27-28`: 4 сезона, `season_index = (turns − 1) % 4`, зима каждый 4-й ход, `enemy_mult 1.25` — строки помечены **MVP** (Q-M27, Q-M29); носитель `WorldSeasons` — вне `scripts/campaign/`. Из MVP сняты «сезоны-баланс» (`MVP-scope.md`), а не сезон как механика.
- **§6.4 — противоречие закрытому решению.** `07-balance.md:59`: «**1 еда/персонаж/переход** (Q-M75 → (б), владелец 2026-10-16, D-191: еда тратится в день перехода, а не каждый ход)». Формулировка §6.4 («на члена партии в день (ход)») возвращает ровно то, что владелец отверг.
- **§9.14 — проверка невыполнима в текущих конвенциях.** `DECISIONS.md`, `TICKETS.md`, `QUESTIONS.md`, `CHANGELOG.md` — append-only реестры, исторические цитаты в них не переписываются (D-283); слова «кампания», «сезон», «мораль» там остаются по определению. Мера возможна только как «0 вхождений вне GGD, реестров, архивов и `docs/mvp/matrix/`» и только по живым документам.
- **§2 — аннулирование D-281 требует записи в реестре.** Номера D- присваивает `docs/DECISIONS.md` (AGENTS.md, «Git-конвенции»); секция GGD не может быть единственным носителем аннулирования. Запись заведена: **D-323**.
