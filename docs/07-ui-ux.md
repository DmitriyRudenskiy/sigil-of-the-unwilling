## UI/UX flow

**Граф экранов — см. [[07-ui-ux.canvas]]** (JSON Canvas, 8 узлов: 7 экранов + обучение).

> [!note] **K-M8 (2026-10-02): финальный список экранов MVP = 8** — предыгра, меню, карта, город, бой, партия, хроника, настройки + **туториал-оверлей** (первые ходы, не сцена). «Отчёт» аннулирован как отдельный экран (результаты боя — финал боевого экрана, события хода — хроника; двойной учёт = расползание UI). «6 экранов» (MVP-scope) аннулировано; источник истины — этот файл с предыгрой.

**Карта экранов (7 экранов + предыгра = 8 в MVP, K-M8; у каждого один вопрос игрока):**

```
Главное меню → КАРТА (где я и что делать?)
                ├→ ГОРОД (почему мои здания работают так, а не иначе?)
                ├→ ПАРТИЯ (кого взять и кто готов?)
                ├→ БОЙ (что делать этим ходом? — лестница исходов, без кубиков)
                └→ ХРОНИКА (почему так вышло? — события хода)
```

**SM навигации:**

| Состояние | Переход | Условие |
|---|---|---|
| MENU | → MAP | новая/продолжить кампанию |
| MAP | → CITY | герой на клетке города (свой город всегда виден, туман на него не действует) |
| MAP | → BATTLE | ENGAGE подтверждён (02-mechanics §3.1) |
| MAP | → PARTY | anytime (горячая клавиша P) |
| CITY | → PARTY | вкладка «Наём» |
| BATTLE | → MAP | финал боя закрыт «Продолжить» (результаты — финал боевого экрана, K-M8) |
| MAP | → ХРОНИКА | anytime (события хода; «Отчёт» как экран аннулирован, K-M8) |
| * | → TUTORIAL | первый вход в экран (1 раз) |

**Спецификация экранов:**
- **КАРТА:** сетка, туман войны, узлы, герой; режимы-оверлеи (канон 15.1): «Военная сеть», «Районы», «Ресурсы».
- **ГОРОД:** гекс-сото 52 клетки (ядро 4 + кольца 1–3, [[02g-city-hex]] §2.1; «24×24» — пре-D1, устарело), тултип «Почему так?» (15.2: топ-3 (+) / топ-2 (−) с причинами), панель военной сети (15.3: роли, узкое место, прогноз).
- **ПАРТИЯ:** карточки персонажей D&D (класс, AC, hit dice, способности) + очередь тренировки (Q18: попутчики тренируются, не нанимаются; механика тренировки — TBD в реестре MVP_SCOPE; стоимость, время — красным, чего не хватает).
- **БОЙ:** клеточное поле (размер — [[07-balance#4. Бой (указатели)]], D4; «8×8–12×12» — устарело), инициатива сверху, **индикатор лестницы** (перевес → зона: Триумф/Успех/Частичный/Провал/Критпровал, пороги сдвинуты Удачей); кнопка «Авто» (02-mechanics §3.4). **Карточка врага всегда показывает AC/HP/УДЧ/способности (M1)** — неизвестного врага не существует.
- **ХРОНИКА:** финал боя (кто/чем/почему) — на боевом экране; пост-рейд (последствия по категориям, 02e 13.2); строки событий хода (04-narrative). «Отчёт» как отдельный экран аннулирован (K-M8).

**Обучение:** 6 уроков канона + урок 0 «лестница и удача за минуту» для игроков без D&D (одна проверка атаки, один спасбросок, что такое AC и Удача) — [ПРЕДЛОЖЕНИЕ, риск «D&D-порог»].

**Панель целей 3 первых дней (M3):** день 1 — построй ферму и барраки; день 2 — тренируй воина (базовый боец, K-M15; тренировка, не наём — Q18); день 3 — сходи в руины. Панель видна, пока не выполнены все цели: TTFD покрывает первое действие, цели — первые 3 дня.

**Цвета:** канон 15.4 (зелёный/красный/жёлтый/синий/фиолетовый) + новый: белый = события лестницы (Триумф/Критпровал).

**FS (per screen):**
- БОЙ: нет допустимого хода → «Пропустить ход» всегда доступен (зацикливание невозможно).
- БОЙ (финал): единственный выход — «Продолжить» (нет «закрыть в никуда»); отдельного экрана отчёта нет (K-M8).
- КАРТА: герой без движения (0 точек) → карта остаётся активной, фазы города доступны (02-mechanics §3.1 FS).
- ПАРТИЯ: очередь тренировки пуста и партия полна → экран показывает «что освободит слот» (ссылка на бой/смерть), не пустоту.

**EC:**
1. **Бой начинается, пока открыт тултип** → тултип закрывается принудительно, ввод блокируется до SETUP (двойное нажатие невозможно).
2. **Сохранение в середине раунда боя** → сейв только на границе раунда; внутри раунда кнопка заблокирована + tooltip «в конце раунда» (08-tech: формат сейва).
3. **Низкое разрешение (1280×720 миним.)** → сетка масштабируется, на основных экранах нет скролла; поле боя (размер — [[07-balance#4. Бой (указатели)]]) при 720p — масштаб ×0.8, иконки не слипаются (тест на 3 разрешения: 720p/1080p/1440p).
4. **Доступность:** цветослепость — цвета 15.4 дублируются иконками (канон); все действия доступны с клавиатуры (15.6); события лестницы (Триумф/Критпровал) — белый цвет + звук (не только визуал).

**Инварианты:** любой модификатор достижим за ≤2 клика до причины (столп 1); в бою все правила D&D, влияющие на ход, видны на экране без подсказок (справка — по клавише).

## Сцены UI: кто их поднимает

Раздел заведён как первый свод T-279: имя сцены в реестре (`docs/mvp/TICKETS.md`,
`docs/CHANGELOG.md`) документом не считается — документом считается этот раздел
([[DECISIONS]] D-291). Колонка «кто поднимает» — результат проверки ссылки точным
путём по `game/`, а не пересказ названий; тесты и `tools/theme_smoke.gd` в перечне
сознательно опущены, они поднимают сцены только ради проверки.

| Сцена | Кто поднимает | Что показывает |
| --- | --- | --- |
| `scenes/ui/save_load_screen.tscn` | `scenes/main_menu.tscn` | слоты сохранения/загрузки; выключенные слоты объясняют причину при монтировании (столп 1 `mvp-ui-flow` 3.3) |

| `scenes/ui/adventure_ui.tscn` | только `scenes/ui/world_ui.tscn` | легаси-раскладка приключения, смонтирована из семи панелей ниже |
| `scenes/ui/info_panel.tscn` | `scenes/ui/adventure_ui.tscn` | панель времени суток и статуса (`set_time`, `set_status`) |
| `scenes/ui/minimap_panel.tscn` | `scenes/ui/adventure_ui.tscn` | миникарта; геометрия 1:1 с `prototype_map.html` (рамка, поля, компас) |
| `scenes/ui/resource_bar.tscn` | `scenes/ui/adventure_ui.tscn` | полоса ресурсов (`update_resources`) |

| `scenes/ui/TeamDialogScreen.tscn` | `scenes/ui/adventure_ui.tscn` | диалог с последователем по стадиям с вариантами и эффектами (`team-romance-roleplay` 5.2/5.3) |
| `scenes/archive/world.tscn` | архив (D-157 cutover) | легаси-мир: hex-карта, герой, городской цикл, рейды; в рантайм-пути не участвует, тесты легаси-линии драйвят её по архивному пути |

Цепочка `archive/world.tscn → world_ui.tscn → adventure_ui.tscn → семь панелей` —
это **замороженная легаси-линия**, а не запасной экран: игрок в кампанийный контур
(`main_menu → character_creation → main.tscn`) в неё не попадает, ссылаются на неё
только архивная сцена, тесты и smoke-снапшоты тем. Панели живут в репо по
трёхисходному правилу исхода (a) (тот же акт, что и архив сцены), и этот раздел —
место, где их назначение перестаёт быть тайной для следующего, кто увидит их в
списке «названо только в реестрах».

## Классы интерфейса: кто их поднимает

Зеркало предыдущего раздела на один уровень ниже: не сцена, а скрипт-класс.
Заведён третьим сводом T-279 по тому же правилу — имя `class_name` в реестре
документом не считается ([[DECISIONS]] D-291). Колонка «кто поднимает» снята
двумя грепами: по имени класса и по пути `preload`/`.tscn` (класс мог быть
присвоен локальным именем, и по имени он тогда не находится).

**Три исхода, и все три уже названы.** 13 классов живёт кампанийным контуром
(`main_menu → character_creation → main.tscn`). Три (`AdventureUI`,
`MarkerLayer`, `MinimapPanel`) висят на цепочке
`archive/world.tscn → world_ui.tscn → adventure_ui.tscn`, то есть на том же
замороженном входе, чья диспозиция — [[QUESTIONS]] Q-M117; это не кандидаты
«дописать строчку», а часть одного акта. Один (`DecisionPanel`) — класс без
носителя: он пережил своего создателя и сцену, и его судьба уже ведётся отдельным
тикетом (Q-M83 / T-132), где носитель панели не выбран; второй путь молча не
изобретается.

## Управление (по input map)

Секция собрана из `game/project.godot` и обработчиков кода — это единственная
строка сверки «док ↔ движок» по вводу (гейт `scripts/audit_docs_vs_code.py`
требует, чтобы каждое имя из `[input]` было названо в `docs/`).

**Именованные действия `InputMap` — ровно пять** (`project.godot [input]`):

| Действие | Привязки | Кто читает |
| --- | --- | --- |
| `camera_up` | `W`, `↑` | `scripts/world/world_camera.gd` (`Input.is_action_pressed`) |
| `camera_down` | `S`, `↓` | `scripts/world/world_camera.gd` |
| `camera_left` | `A`, `←` | `scripts/world/world_camera.gd` |
| `camera_right` | `D`, `→` | `scripts/world/world_camera.gd` |
| `mute` | `M` | `scripts/autoload/sound_manager.gd` |

**Прямые клавиши сцен** — они в `InputMap` не объявлены, читаются как `event.keycode`:

| Клавиша | Экран | Действие | Источник |

## Пре-пивотный канон UI (15.x, перенос из GDD.md v2.1)

### 15.1. Режимы [КАНОН]

1. Обычный.
2. «Почему так?» — все модификаторы.
3. «Военная сеть» — роли, узкие места.
4. «Районы» — границы, бонусы.
5. «Ресурсы» — потоки.
6. «Карта/миникарта».

### 15.2. Тултип «Почему так?» [КАНОН]

```
Кузница: 134%
+20% орочья ковкая традиция
+10% рядом со складом снабжения
+8% прямая дорога к руднику
-4% шум от соседней казармы
```

### 15.3. Панель военной сети [КАНОН]

Список ролей, текущая эффективность каждой роли, узкое место (самая слабая роль), прогноз производства.

### 15.4. Цвета [КАНОН]

Зелёный — бонус; красный — штраф; жёлтый — предупреждение; синий — информация; фиолетовый — район.

### 15.5. Обучение [КАНОН]

6 уроков: 1) первое здание; 2) назначение рабочих; 3) соседство; 4) дорога; 5) военная сеть; 6) район.
