# 19. Контур фаз GDD

Контракт того, как секции [[00-overview]] проходят от черновика к зафиксированному
виду и обратно. Введён change `gdd-phase-workflow` (решения D-270…D-274 в
[[DECISIONS]]) после того, как одноимённый процесс уже проходил и встал: теги
`v3-grilled-pass3`, `v3-grilled-pass4`, `grill-v3-pass-5` есть, `v4-locked` — нет.

## Машина состояний секций

`draft → audited → deepened → verified → locked`

| Состояние | Значение | Куда двигается дальше |
| --- | --- | --- |
| `draft` | текст есть, аудита не было | `audited` |
| `audited` | пройдена фаза 1, дыры разнесены по типам, вопросы в реестре | `deepened` |
| `deepened` | пройдена фаза 2, термины в [[00-glossary]], числа в [[07-balance]] | `verified` |
| `verified` | каждое ✓ подтверждено ссылкой и цитатой | `locked` |
| `verified*` | то же, но часть решений `⏳` (ожидает владельца) | `verified` после `✅` |
| `locked` | зафиксировано, откат только по решению | `verified` по новой записи |

- `canon` в frontmatter — легаси-синоним `locked` (D-271): 11 canon-секций не
  переименовываются.
- **ПЕРЕСМОТР** зафиксированной секции оформляется новой записью в [[DECISIONS]],
  старая не правится (D-271). Откат состояния обязан ссылаться на эту запись.
- `verified*` — производное от `⏳` в реестре, отдельного значения `status:` нет
  (D-273): два описания одного факта разошлись бы за месяц.
- Роли вне машины: `reference`, `snapshot`, `archived`, `redirect` (реестры, аудиты,
  банк [[BANK]]).

Проверка: `python3 scripts/gdd_gate.py` — состояние из словаря, `verified`/`locked`
со ссылкой на `D-###`, полнота новых записей реестров, ratchet бэклога
(базлайн — `scripts/gdd_gate.baseline.json`), уникальность `R-##`, `blocked-on` у
тикетов, ждущих `⏳`-решение. С 2026-10-27 (аудит `gdd-economy-audit`) — ещё два
правила: каждая ссылка `Q-M##` в `docs/` существует в реестре `docs/QUESTIONS.md`
(банк исключён), а путь в backticks внутри живой GDD-секции лежит в репозитории
(реестры-истории исключены; счётчик мёртвых путей — часть ratchet).

С 2026-10-27 (T-226) в ratchet'е вместо «сколько номеров задвоено» стоит
**`q_ghost_rows` — сколько строк выглядят открытыми, хотя по их номеру есть закрытая**:
задвоенный номер сам по себе не дефект (история ре-опенов `Q-M18`, соседние id
`Q-M23`/`Q-M23b` — разные вопросы), дефект именно ложь об открытом вопросе. Признак
«строка закрыта» один для гейта и дайджеста (`gdd_gate.closed_row`, его импортирует
`gdd_grounding`): два носителя одного признака уже разъехались. Комплект ключей базлайна
сверяется с комплектом метрик и при расхождении даёт exit 2 — отсутствующий ключ молча
читался бы как «нулевой допуск», а лишний (опечатка) как «проверка есть».

## Четыре фазы

1. **Аудит.** Шаг 0 — ре-грундинг: `python3 scripts/gdd_grounding.py` (≤400 строк,
   отсечка `⚑ → ⏳ → 🔴`, D-274). «Перечитать целиком» на 2,62 МБ доков неисполнимо,
   а имитация чтения — причина, по которой предыдущий контур встал на проходе 3.5.
   Дыра классифицируется до вопроса, потому что у типа дыры разный носитель:

   | Тип | Что это | Куда идёт |
   | --- | --- | --- |
   | онтология | сущность названа, но не определена | `docs/QUESTIONS.md`, после ответа — `docs/00-glossary.md` |
   | противоречие | две секции говорят несовместимое | красная строка отчёта + вопрос владельцу, если затрагивает видение (`⚑`) |
   | число | параметр без значения | `docs/07-balance.md` §10, не вопрос |

   По одному уточняющему вопросу на дыру. Секция после аудита: `draft → audited`.
2. **Углубление.** Термины → [[00-glossary]], параметры → [[07-balance]] §10,
   риски → [[09-risks]] с номером `R-##`.
3. **Гриль-цикл.** Секция прогоняется по ontology-вопросам: сущность? состояние?
   переход? кто пишет значение? кто читает? Не больше трёх проходов; остановка —
   ноль новых онтологических дыр, или два прохода подряд ≤1 дыры, или третий проход
   завершён. Проходы дальше третьего допустимы только по новому `⚑`-решению владельца,
   иначе это бесконечная полировка (`v3-grilled-pass3`, `pass4`, `grill-v3-pass-5`
   при отсутствии `v4-locked` — контур умер от отсутствия критерия остановки, а не от
   нехватки проходов). Найденное пишется в реестр сразу: незаписанное = потерянное.
4. **Финализация.** Секция → `verified`/`locked`, эпики → `docs/mvp/EPICS.md`,
   тикеты → `docs/mvp/TICKETS.md`, запись → [[CHANGELOG]]. Эпик не создаётся, пока
   нет хотя бы одного тикета и спеки, из которой он следует. Тикет формулируется как
   наблюдаемое изменение («HUD не перекрывает нижние ряды поля при 1920×1080»), а не
   как activity, и обязан иметь носитель проверки — иначе он unverifiable.
   Запись в [[CHANGELOG]] — часть смены: коммит, меняющий поведение, без записи
   считается незавершённым; числа в ней фактические, а не желаемые
   («битые ссылки 40 → 0», а не «будет ноль»). Старые записи не переписываются:
   акты не редактируются (D-270), история правок — в git.

Правило **«БЕЗ СТОП»**: вопрос владельцу никогда не блокирует работу. Если ответ не
меняет видение, агент применяет рекомендацию и помечает запись
`⏳ **Предварительное (рекомендация).**`; запись, меняющая видение, помечается
`⚑ **Меняет видение.**` и проверяется первой.

## Форматы реестров

Идентификаторы не меняются (D-272): `Q-M##`, `D-###`, `T-###` — перенумерация уже
обходилась двумя тикетами и двумя решениями на одном номере.

- **Вопрос** (`docs/QUESTIONS.md`): `**[agent|human]**` + приоритет `🔴`/`🟡`/`🟢` +
  варианты + `Статус: открыт` / `⏳` / `закрыт (D-###)`.
- **Решение** ([[DECISIONS]]): остаётся строкой таблицы; обязательные слова
  `Контекст:`, `Отвергнутые:`, `Каскад:`, `Статус:`.
- **Риск** ([[09-risks]]): строка начинается с `R-## —`.
- **Тикет** (`docs/mvp/TICKETS.md`): ждёт `⏳`-решения → строка `blocked-on: D-xxx`.

Старые записи не переписываются: их число без полей — бэклог, который имеет право
только сокращаться (ratchet в `gdd_gate.py`).

## Шаг верификации

Правило: **«сделано» — это список доказательств, а не намерение.** Каждое ✓ — ссылка
`[[секция]]` + цитата ≤25 слов, доказывающая ровно это утверждение. Доказательства нет —
статус не поднимается: вместо `locked` остаётся `verified`/`deepened` с дописанным,
чего не хватает. `verified → locked` при незакрытом `⏳`-решении запрещено.
Машины проверки: `gdd_gate.py`, `check_docs_links.py`, `audit_docs_vs_code.py`
(справляется ли код с тем, что обещают доки), `game/run_tests.sh`.

«Задокументировано» для последней — «имя объяснено в живой заметке», а не «имя где-то
напечатано»: упоминание в `CHANGELOG` / `DECISIONS` / `QUESTIONS` / `docs/mvp/` кладёт
имя в опись «только в реестрах» и рэтчится базлайном (D-291, долг разбора — T-279).
