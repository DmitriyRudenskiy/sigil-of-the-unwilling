# scripts/concept_art — конвейер концепт-арта

Рисует **5 вариантов стиля × 77 сюжетов = 385** концепт-картинок через внешний ComfyUI+MCP-сервер
(`192.168.0.230`), чтобы владелец выбирал стиль по сравнительному борду, а не по одной картинке.

Канон стиля: `docs/13-art-bible.md` (семейства A/B2/B3/C/D), `docs/17-ui-style-guide.md`.
Задача: `openspec/changes/concept-art-style-variants/`.

## Что где лежит

| Путь | Что |
| --- | --- |
| `spec.json` | каталог: варианты стиля, категории, сюжеты, модели, размеры. **Сюжеты и стили — только здесь, в коде их нет** |
| `generate.py` | генератор: запрос → ожидание → загрузка → WEBP → проверки → манифест |
| `test_generate.py` | самопроверка (assert-ы, без сервера): `python3 scripts/concept_art/test_generate.py` |
| `concept_art/` (вне git) | вывод: `<вариант>/<категория>/<id>.webp`, `manifest.json`, `sheet_*.webp`, `generate.log` |

## Запуск

```bash
cd /Users/user/sigil-concept-art

python3 scripts/concept_art/test_generate.py            # самопроверка, 0 обращений к серверу
python3 scripts/concept_art/generate.py --dry-run       # 385 строк «вариант/категория/id размер seed»

# дымный прогон: по одному сюжету каждой категории в одном варианте
python3 scripts/concept_art/generate.py --variant v1_candlelight \
  --only levy_militiaman,shack,sign_time,cursor_default,res_gold,ui_start_screen

# полный прогон в фоне (≈9 ч серийной генерации на сервере)
mkdir -p concept_art
nohup python3 scripts/concept_art/generate.py >> concept_art/generate.log 2>&1 &

python3 scripts/concept_art/generate.py --sheet         # контактные листы (матрица + лист на вариант)
```

Флаги: `--variant a,b` `--category units,ui` `--only id1,id2` `--limit N` `--force`
`--timeout 900` (ожидание одного сюжета) `--spec <путь>`.

## Повтор и возобновление

Прогон **возобновляем с любого места**: файл существует → артефакт помечается `skip` и не тратит GPU.
Затравка выводится из идентификатора (`crc32("<вариант>/<категория>/<id>")`), поэтому перезапуск рисует
то же самое, а не другое. Отказ сюжета повторяется один раз, затем пишется `fail` с текстом ошибки,
прогон идёт дальше; повторный запуск дозаполняет пробелы. Итог — строка
`ИТОГ ok=… skip=… fail=…` и список отказавших id.

`--force` перегенеровать готовое; `rm concept_art/<вариант>/<категория>/<id>.webp` — точечный перезапуск.

## Машинные проверки результата

У каждого файла: ровно заданный размер (1024×1024 / 1280×720), декодируемость, WEBP q82.
Для изолированных категорий (units/buildings/signs/cursors/resources) — доля чистого белого в рамке 24 px
≥ 60 % и не менее 2 % не-белого в центральном окне 50 % (пустой белый лист — не результат).
Для экранов UI вместо белизны — средняя яркость в диапазоне 25…235.

## Модели

Krea-2 turbo — изолированные категории (1024² ≈ 80 с), Qwen Image 2.1 — экраны UI (1280×720 ≈ 170 с,
держит компоновку панелей и принимает `negative_prompt`). Имена чекпойнтов и шаги — в `spec.json`
в секции `models`; если модель снимут с сервера, правится только она. У Krea-2 нет параметра негатива —
негатив варианта дописывается в конец запроса.

Загрузка байтов идёт через `GET /history/<prompt_id>` → `GET /view`, а не через `asset_url`: сервер
отдаёт в `asset_url` `127.0.0.1` (с другой машины недоступно) и переиспользует имена файлов вывода
(чужая очередь перетирает результат).

## Чего здесь нет

Ни апскейла, ни SeedVR2, ни вырезания фона, ни нарезки на спрайты, ни записи в `game/assets/**`.
Концепт-арт — материал для решения о стиле; ассеты делаются отдельным изменением через `game/tools`
с гейтом провенанса.
