# Реестр якорных пар строк стиля

Строка без якорной пары не является мерой: `STY-%` по ней не считается,
десятка по ней не ставится. Пара — два конкретных файла и известный балл по
одной строке. `jobloop sty` отвергает цитату пары, которой здесь нет.

- Эталонный сет: `etalons-8cb5520558f8` (перерезка кропов 4.6, `jobloop cut`).
- Версия реестра: `anchors-<sha256 первых 12>` считается движком по таблице
  (`jobloop anchors stat`). Любая добавка — бамп версии; вердикты, сославшиеся
  на старую версию, при переприсмотр помечаются.
- Баллы выставлены судом по доске попыток. До слепого подтверждения вторым
  судьёй (`jobloop anchors show/score`) это черновик калибровки.

## Формат

Пара — полные имена кадров по конвенции лаборатории, пути относительно
`image-clone/`. Усечённая подпись (`qwen v1`) запрещена: она рождает коллизии,
когда одна версия встречается у двух юнитов.

Словарь направления дрейфа — обязательное поле. Пара обязана кодировать
направление, противоположное нижней полосе своей строки, иначе рубрика ловит
одну ошибку и пропускает противоположную.

`—` (эталон) · `мягче` (контур потерян, край размыт) · `контур-тяжелее` ·
`глянец` · `плоско` (живописная вариация сведена к ровному градиенту) ·
`cel` (одно жёсткое пятно тени без возврата) · `перенасыщ`

## Что пары учат судью

- **Полоса каждой строки двусторонняя.** 5–6 и 7 лежат по разные стороны
  эталона: `мягче`/`глянец` с одной, `контур-тяжелее`/`плоско`/`cel` с другой.
  Якорь только одного направления учит судью ловить одну ошибку и
  пропускать её противоположность.
- **Десятки гетерогенны по происхождению:** три `эталон↔эталон` и одна
  `эталон↔попытка` (AP-texture-1). Это не дефект: попытка на 10 доказывает,
  что десятка достижима генерацией, то есть 93 жива не только арифметически.
  Гетерогенность требует ослепления: судья, знающий, где эталон, ставит
  «эталон = 10» эвристикой, и десятки попыток задавливает.
- **Материал старше цепочки.** Девятки — все qwen21 (модели в цепочке нет),
  семёрки — все krea2 v2, `ernie` и `z-image` не представлены ни одной парой.
  Для калибровки уровней допустимо, для замера дрейфа новой модели — нет:
  её дрейфы лягут вне существующих категорий, и судья начнёт заталкивать их
  в чужие. Каждый новый экземпляр — строка здесь и бамп версии реестра.

## Подтверждение (протокол слепого второго прохода)

1. `jobloop anchors blind` — движок режет доски всех пар и печатает команды
   записи; заявленный уровень не показывается ни на одном шаге до записи.
   Лист = одна строка стиля и ОДИН персонаж: его эталон и его варианты
   (кадры того же юнита), а не две пары подряд — на листе не должно быть
   двух героев, иначе судья меряет сходство персонажей вместо строки.
   Контроль «эталон↔эталон» — отдельный общий лист на две картинки: он и
   существует для разных рисунков, в шапке перечислено, какими строками он
   меряется. Подпись кадра — id пары, роль и юнит, уровня там нет. Печать
   накрывает лист целиком: хеш всех его пар общий, подмена любого кадра
   ловится по всем парам листа сразу; пара без своего кадра выпадает из
   листа одна, не утаскивая соседей.
2. Судья ставит балл тем же инструментом, которым калибруют:
   `jobloop anchors score <AP-id> <row>=N --pass revision`.
3. Только после записи движок сравнивает с заявленным уровнем: попадание
   (для полосы 5–6 — в полосу) = пара подтверждена; расхождение = пара на
   переприсмотр, и непонятно ещё, что неточно: якорь или описание уровня.
4. Подтверждённые пары идут в боевые сессии вслепую как контроли (2–4 за
   сессию, `jobloop sty ... --control <AP-id>`): контроли легли в свои уровни
   — сессия валидна; контроли уехали — дрейфует судья, не картинка, и
   вердикты сессии помечаются.
5. Термостат десяток считается только по попыткам: контроли в долю не входят,
   иначе доля навсегда завышена калибровочным материалом.
