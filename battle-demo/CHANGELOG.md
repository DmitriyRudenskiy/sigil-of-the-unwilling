# Changelog — Sigil of the Unwilling: Battle Demo

Демо пошагового боя на Godot 4.7. Отдельный проект в `battle-demo/`,
не зависящий от `game/`. Все даты — 2026 год.

## [Не выпущено] — 2026-10-26

### Документация фазы 11 и ворота

- `docs/test-coverage-matrix.md` — разбор всех 70 сценариев четырёх спек
  (`turn-battle-core` 17, `roster-lineups` 9, `battle-demo-ui` 12,
  `battle-demo-sprites` 32): 51 PASS, 14 CONCERNS, 5 FAIL, плюс четыре конфликта
  «спека ↔ носитель».
- `docs/ui-read-judge-2026-10-26.md` — пятый раунд визуальной приёмки: восемь
  кадров приёмки с md5 (раунды r1–r4 хэшей не имели), контроль регресса против
  правок ревью диффа.
- `docs/gate-check.md` — вердикт **FAIL** по девяти пунктам DoD: два блокера
  уровня «спека ↔ носитель» (форма кадра и нейминг; размер пула и сдвиг наборов),
  кодовых блокеров нет.
- `docs/handoff.md`, `CHANGELOG.md`, `docs/vertical-slice.md` — документы
  передачи, журнал и вердикт по полному циклу.
- Ревью диффа (11.2): `assert` в тесте заменён на `guard` (`assert` вырезается в
  release-сборке, тест молча переставал что-либо проверять); артефакты вердикта
  листа экипировки и ген-кадров остались вне git — зафиксировано CONCERNS.

## Фаза 10 — приёмка UI и автономность (2026-10-25)

- Четыре раунда read-агента по живым кадрам (`docs/ui-read-judge-2026-10-25*.md`):
  из четырёх заявленных наложений два оказались ложными (проверено пикселем),
  четыре настоящих — исправлены и закреплены тестами.
- Панель поверженного, метка активного после боя, кадр ровно 1920×1080.
- `docs/qa-plan.md`, `docs/regression-suite.md`, `docs/scope-report.md`,
  `docs/known-issues.md` заполнен по факту (правило трёх итераций).
- Smoke-сценарий `tools/smoke_battle.gd`: оба набора доигрывают до победы.

## Фаза 9 — боевой UI (2026-10-25)

- Шестигранное поле и интерфейс боя по макету; путь игрока от выбора набора до
  экрана результата.
- Полосы HP, очередь ходов, фокус-точки и кнопки команд синхронно с `CombatState`
  (проверка после каждой серии действий, а не только после одного хода).
- Выбор набора: клавиатура (`ui_left`/`ui_right`/`ui_accept`), запись выбора в
  `DemoFlow`, смена набора без рестарта процесса.

## Фаза 8 — анимация и визуальная приёмка спрайтов (2026-10-24…25)

- Слой отображения юнита: `idle/walk/attack/hit/turn`, урон приходит на контактном
  кадре, гибель — последний кадр + обесцвечивание + крест, враг зеркалится.
- Врагом стал волк: звериный источник, пять дорожек, данные.
- Мера сноса клипа по ступням, A-pose-генератор первого кадра, `--reaudit`
  (пересчёт меры без повторной генерации).

## Фаза 7 — keying, нарезка, импорт в движок (2026-10-24)

- Ункей с деспиллом, пороги по хромакею и белому фону, нарезка клипа на кадры,
  сборка `*.sprite_frames.tres` (холст 128 px, силуэт 96 px, ступни в (64, 112)).
- Гейт комплекта дорожек: у каждого юнита пять дорожек по четыре кадра, дорожек
  `death` нет ни у кого.

## Фаза 6 — генерация спрайт-листов (2026-10-24…25)

- Клип-цепочка через ComfyUI: edit по источнику + DWPose-скелет, A-pose первого
  кадра, I2V-прогон, возобновляемый раннер, мерный отчёт по каждому клипу
  (`pivot_slide_x`, `contact_slide_x`, `motion_first_last`, `chroma_share`, …).
- 23 принятых клипа (idle+walk девяти юнитов и пять дорожек волка), манифест
  `artifacts/generation-manifest.json` (184 записи: путь, md5, seed, модель,
  промпт), реестр прогонов `docs/generation-log.md`, контактный лист.
- Покадровый путь (D5) остался фолбэком: лист поз 2×2 на анимацию (ADR-004).

## Фазы 4–5 — боевое ядро и данные наборов (2026-10-24)

- Пошаговое ядро без нод: очередь по инициативе, одно действие за ход, детерминизм
  по seed, статусы с длительностью и без стека, победа/поражение, ИИ противника.
- Данные наборов A/B: девять юнитов пула + волк, семь юнитов в каждом наборе,
  валидатор размера и дублей.
- 17 сценариев `turn-battle-core` размечены и закрыты тестами (задача 4.11).
