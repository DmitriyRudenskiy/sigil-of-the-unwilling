# UI spec — боевой интерфейс демо

Базовое разрешение 1920×1080, stretch `canvas_items`/`expand`. Всё — один экран
без прокрутки.

## Экраны

| Экран | Состав |
| --- | --- |
| `roster_select` | заголовок, две карточки набора (A / B) с составом из 7 имён и строкой отличия, подсказка клавиш |
| `battle` | арена (две линии по 7 и 1 юниту), полоса порядка ходов сверху, панель способностей снизу, имя активного юнита |
| `result` | исход («Победа» / «Поражение»), кнопка «Повтор», кнопка «Сменить набор» |

## Метрики читаемости

| Метрика | Требование |
| --- | --- |
| Кегль подписей | ≥ 24 px в масштабе вьюпорта |
| Контраст текста к подложке | ≥ 4.5:1 |
| HP-бар | 96×10 px над юнитом, заполнение = `hp / max_hp`, мёртвый — пустая полоса |
| Панель способностей | 4 слота максимум, недоступная — затемнена + подпись причины |
| Отступ элементов | ≥ 8 px, наложений нет (проверяется кадром) |

## Клавиатура

`←` / `→` — выбор набора и слота, `Enter` — подтвердить, `Esc` — сменить набор.
Мышь работает, но не является единственным путём (спека `battle-demo-ui`,
сценарий «выбор без мыши доступен»).

## Синхронность

Каждый элемент — подписчик сигналов модели (`turn_started`,
`action_performed`, `unit_died`, `battle_ended`). Прямого изменения состояния
из UI нет. Тест синхронности (задача 9.8) сверяет отображаемые значения с
моделью после серии ходов; рассинхрон = падение теста.

## Съёмка кадров

`tools/capture_screens.gd` проходит четыре состояния (выбор набора, старт,
середина, результат) для обоих наборов → `artifacts/screenshots/<roster>_<state>.png`
(8 кадров). Один GUI-процесс за раз, короткое время жизни; на macOS окно
поднимается нативно, `Xvfb` — только на Linux-раннере.
