# Design review — battle-demo

Ревью `design-brief.md` + `ui-spec.md` + `asset-spec.md` на полноту, внутреннюю
непротиворечивость и реализуемость. Вердикт по разделу: **PASS** / **REWORK**.

| Раздел | Вердикт | Основание |
| --- | --- | --- |
| Модель хода (очередь, одно действие) | PASS | покрывает спеку `turn-battle-core`; «ровно одно действие» согласовано со `stun` — при `stun` доступным остаётся «пропуск» |
| Формула урона | PASS | целая, нижняя граница 1, детерминированная при seed; тестуема без сцены |
| Ресурс `focus` | PASS | даёт панели содержательное состояние «недоступна по расходу» |
| Статусы (4) | PASS | у каждого длительность и правило ненакапливания; реализуются одним циклом в конце хода |
| Таблица персонажей | REWORK → принято с оговоркой | числа не сбалансированы (`barbarian` 22 atk / 105 hp сильнее `knight` по сумме); оговорка: демо калибруется дымовым прогоном 9.9, отдельного баланса не требуется |
| ИИ противника | PASS | найден при ревью как пробел (правила не говорили, кто ходит за врага) — закрыт разделом «Чей ход у противника» + требованием в спеке |
| Триггер `walk` | PASS | найден как пробел: хода перемещения в правилах нет → анимация осталась бы без применения; закрыт входом в бой |
| UI: состав экранов | PASS | три экрана покрывают спеку `battle-demo-ui` целиком |
| UI: метрики читаемости | PASS | кегль, контраст, размеры полос — проверяемы по кадру |
| UI: клавиатура | PASS | закрывает сценарий «выбор без мыши доступен» |
| Asset spec: реестр девяти | PASS | девять строк, девять файлов источника, девятый = враг, покрытие A∪B = весь пул |
| Asset spec: позы | PASS | у каждой анимации четыре описанных кадра; контактный кадр `attack` назван по номеру |
| Asset spec: нейминг | PASS | найдено расхождение (в выходных файлах была вторая схема имени) — исправлено на единственную схему из спеки |

**Итог:** к реализации допущено. Два пробела (ИИ противника, триггер `walk`)
и одно расхождение имён закрыты до кода; одно принято с оговоркой.
