```
doc/
├── task/              # Задачи и требования
│   ├── TASK_01.md     # [Описание задачи 1]
│   ├── TASK_02.md     # [Описание задачи 2]
│   └── ...            # Другие задачи
├── api/               # API документация (в разработке)
├── architecture/      # Архитектурные документы (в разработке)
└── guides/            # Руководства и туториалы (в разработке)
```

## Доступ к документации

### Для разработчиков

1. **Задачи**: Изучите файлы в `doc/task/` для понимания требований
2. **Спецификации**: См. `openspec/specs/` для технических деталей
3. **Предложения**: `openspec/changes/*/proposal.md` описывают планируемые изменения

### Для игроков

1. **Руководства**: Будут доступны в `guides/` после создания
2. **API**: Документация по моддингу будет в `api/`

## Формат задач

Каждый файл задачи следует структуре:

```markdown
# TASK_XX: Название задачи

## Описание
Краткое описание задачи.

## Требования
- Требование 1
- Требование 2

## Критерии приёмки
- [ ] Критерий 1
- [ ] Критерий 2

## Ресурсы
- Ссылки на связанные документы
- Ассеты и материалы

## Статус
[ ] Не начата
[ ] В работе
[ ] На проверке
[x] Завершена
```

## Обновление документации

При внесении изменений в проект:

1. Обновите соответствующие задачи в `doc/task/`
2. Создайте proposal в `openspec/changes/` для значительных изменений
3. Добавьте тесты для новых функций
4. Обновите README при изменении основных возможностей
